## Проверенные Scenario (первый круг — спека)

- **«Перетаскивание в другой столбец»**: dragstart (draggable=true, dataTransfer для Firefox, drag-ghost класс) → dragover preventDefault + подсветка `.drop-target` → drop → POST `/api/tasks/{id}/move` с целевым статусом → успех: `refreshBoard()` из ответа сервера. Эквивалентность ОГР-14: тот же эндпоинт, тот же pydantic TaskMove, серверные правила не тронуты (tasks.py:446 без изменений).
- **«Отпускание вне зоны столбца»**: drop вне `.board-column` — early return, preventDefault не вызывается, статус не отправляется, браузер возвращает визуал; исходная позиция — доска не менялась.
- **«Результат равнозначен переводу» (Д-6, 409)**: серверный 409 для done→актив при занятой fast line подтвержден в tasks.py (инвариант ≤1, транзакция); клиент: `showBoardError` + `refreshBoard` — плитка возвращается, инвариант не нарушается. Защита от двойного POST (dragInProgress) есть, но с гонкой (замечание 2).
- **«В Выполнено подчиняется архивации»**: drop в done вызывает тот же move с done-семантикой (done_at, отложенная автоархивация) — сервер не менялся.
- **«Touch не затрагивается» (ОВ-19)**: HTML5 DnD не срабатывает на touch, прежний способ (карточка задачи → селект) сохранен — task-detail.js не тронут.
- **Бамп static_v**: r2.1→r3.1 (урок DEF-002, З-2 учтено).
- **Негативные обработчики**: dragleave-мерцание погашено проверкой `relatedTarget`/`contains`; повторный dragstart во время перевода блокируется.
