## Независимая проверка (TestClient + прямые чтения БД, 39/39 PASS)

Ревьюером написан собственный смоук (вне репозитория): таблица переходов, `archived_at`
в БД после каждого шага, группировка `/api/board`, коды ошибок, поведение `is_fast`.

Таблица переходов (проверено и по телу ответа, и по строке БД):

| Из → в | Код | archived_at в БД | Комментарий |
|---|---|---|---|
| todo → in_progress | 200 | NULL | |
| in_progress → done | 200 | проставлен (UTC ISO) | прямой перевод из «В работе» |
| todo → done | 200 | проставлен | прямой из «Ожидает» |
| done → todo | 200 | снят (NULL) | обратный перевод |
| done → in_progress | 200 | снят (NULL) | |
| done → done | 200 | проставлен (обновлен) | контракт sdd §3.2 допускает все 3 цели |

- `/api/board`: todo/in_progress группировка верна; задача после move в done исчезает
  с доски; после обратного перевода возвращается. done-столбец без задач (done_note) — не задет.
- Ошибки: 404 `{ "error": "not found" }` на несуществующий id; 422 на недопустимый статус
  (`"cancelled"`), на лишнее поле в теле (`extra=forbid`), на пустое тело — все с телом
  `{"error", "details"}` (обработчик RequestValidationError); 401 middleware без сессии.
- is_fast: move не меняет флаг (fast-задача → done → обратно — `is_fast` сохранен);
  комментарии при move не затрагиваются (проверено чтением БД).
- UPDATE статуса+archived_at+updated_at — один параметризованный запрос, один commit:
  атомарно, расщепление «status=done, archived_at=NULL» в БД невозможно.

## Круг 1 — спека как закон

- Сценарии дельты board («Быстрый доступ к "Выполнено"», «Обратное перемещение») —
  покрыты: источник не проверяется, все три цели дают 200.
- FR-6 «и обратно» + биусловие sdd §4 (NOT NULL ⇔ в архиве): снятие archived_at при
  done→todo/in_progress обосновано и реализовано. Специфических сценариев «обратный
  перевод» в delta tasks/fastline с иными требованиями нет — противоречий не найдено.
- sdd §3.2 контракт тела/ответов — дословно; status из PATCH исключен ранее (4.2), обходной
  путь простановки статуса мимо archived_at отсутствует (единственная точка смены статуса — move).
- Поведения вне спеки нет.

## Круг 2 — best practices

- SQL параметризован; инъекций нет; секретов нет; БД/логи не в git.
- 404 проверяется до UPDATE — несуществующий id не мутирует БД.
- Соединение закрывается в `finally`; commit/rollback согласованы с соседними эндпоинтами.

## Круг 3 — integration-точки

- Комментарии/теги при move не трогаются (проверено).
- `GET /api/board` (4.3) и архивная логика (6.1) совместимы: после move в done задача
  отфильтрована (archived_at IS NOT NULL), обратный перевод возвращает.
- Смоук смежных требований (создание, карточка, комментарии) — в рамках прогона без регрессий.
