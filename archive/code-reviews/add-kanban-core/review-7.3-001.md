### Круг 2 — best practices / security
- ✅ XSS-рендер (особое внимание): **мой собственный jsdom-эксперимент** с результатами `<img src=x onerror=__pwned>`, `"><script>alert(1)</script>`, тег `<b>bold</b>`: `querySelectorAll("img,script")` в результатах → 0 элементов, `__pwned` не сработал, тег отрендерен текстом `<b>bold</b>`. Каждое поле (title, category, tags, priority-текст) проходит через `el()` → `textContent`. `innerHTML` в search.js — только в комментариях (строки 20, 43 подтверждены grep'ом; `document.write`/`outerHTML` отсутствуют — jsdom-смок PASS).
- ✅ Серверный XSS: страница `/search` не содержит данных из БД в HTML (все данные только через JS); мой интеграционный тест R10 — payload из title отсутствует в HTML ответа.
- ✅ 422-обработка: **найдено и закрыто** расхождение в моем первоначальном тесте: фактическое тело FastAPI — `details: [{loc: ["query","priority"], msg: ...}]` (массив). search.js ветвится `Array.isArray(details)` → `item.loc.join(".") + ": " + item.msg` — мой jsdom-прогон с ФАКТИЧЕСКИМ телом показал: `validation error. query.priority: Input should be 'low', 'medium' or 'high'` — корректно.
- ✅ Сеть: fetch `.catch` → «Сетевая ошибка...» (jsdom-смок не проверяет явно, код прочитан — ветка есть).
- ✅ SQL-инъекции: вне дифа 7.3 (парсер 7.2 approved), но подтверждено: search.js не конкатенирует пользовательский ввод в SQL (клиент вообще не строит SQL); `category = "<script>...` в advanced → 200 и пустой результат (R8), инъекция невозможна по построению parse() → SearchFilters.
- ✅ Секретов в дифе нет; smoke-скрипты используют temp-БД и тестовый SECRET_KEY (env, не хардкод паролей прод-среды).
