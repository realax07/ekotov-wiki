## Второй круг — best practices

- SQL: во всех операциях (SELECT/INSERT/UPDATE/DELETE, tags, get-or-create) только `?`-параметризация; единственный f-string в UPDATE — имена колонок из фиксированного белого списка (`model_fields_set` ∩ Known fields), значения параметризованы. Инъекций нет.
- Секреты: нет; конфиг через env (как ранее). Лишний `user_id` в POST отклоняется (extra=forbid) — не протекает в INSERT.
- Ошибки не глотаются: IntegrityError → 422 с rollback; прочие исключения не маскируются. Пользователь не видит стек-трейсы.
- Данные: .gitignore дополнен `.venv/`; *.sqlite* игнорировались ранее. Изменений схемы нет — sdd §4 соблюден.
- Транзакционность POST: INSERT + _set_tags + commit атомарны; при IntegrityError rollback.
- GET non-int id → 422 (валидация пути FastAPI): sdd §3.2 для GET фиксирует только 404; 422 на непарсируемый id — стандартное поведение каркаса, расхождением не считаю (minor не завожу; фиксирую как наблюдение).
