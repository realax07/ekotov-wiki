в карточке». Дев отложил поисковую часть и отметил это в самой строке задачи.

  sdd §3.5 описывает его как будущий эндпоинт, tasks.md §7 относит его к 7.1

- Признак архивности в выдаче поиска не может существовать раньше самого
  поиска: реализовывать его сейчас — вне трассировки, откладывать в 7.1 —
  естественно (Task-схема уже несет `archived_at`, 7.1 получит его без
  дополнительных изменений).
- Отклонение задокументировано в tasks.md (арбитре), а не спрятано —
  процедура скоуп-решения корректна. **Принимается.**

## Второй круг — best practices

- **XSS (особое внимание №3):** текст бейджа статический («Архивная»), данные
  задачи в него не попадают; проверено и jsdom-смоуком (textContent не меняется),
  и grep — `innerHTML` в рендере не используется. Чисто. ✅
- **Изоляция:** одна операция присваивания в существующем renderTaskDetail,
  глобальное состояние не мутируется, ошибок не глотается (null → `!null` →
  `hidden=true` — безопасное дефолтное поведение). ✅
- **Секреты/данные:** смоуки используют tempfile DB + тестовый SECRET_KEY;
  в git ничего нового из данных не попадает. ✅
- **Читаемость:** комментарий в JS и Jinja-комментарий в шаблоне ссылаются на
  6.2/FR-4 — трассируемость выдержана.

Minor-1 (стилистика, board.js): присваивание `hidden` стоит между
`addDetailRow(...)` и `task-move-select` — читается как «атрибуты», хотя бейдж
находится в шапке модалки рядом с `task-detail-title`. Не ошибка, расположение
рабочее; рекомендация: либо переместить присваивание выше, к `task-detail-title`
(рядом с реальным DOM-положением), либо оставить как есть — поведение идентично.

Minor-2 (тест-инфраструктура, smoke_6_2.py): проверка «XSS: innerHTML не
используется в рендере» — grep-эвристика по строкам с `innerHTML`; она слабее,
чем jsdom-проверка текста, и при появлении легитимного innerHTML в другом месте
файла может дать ложный сигнал. Не блокирует (jsdom-смоук покрывает суть);
рекомендация: при следующем касании смоука заменить на явный `assert
"innerHTML" not in render_section` по вырезанному телу renderTaskDetail.
