## Оценка методики

| Аспект | Оценка |
|---|---|
| SIGTERM как эмуляция systemd | Корректно: systemd stop/restart шлет именно SIGTERM (KillMode=control-group, далее SIGKILL по TimeoutStopSec — до него не доходит). Живой процесс + внешний urllib (никакого TestClient/in-process) — честный HTTP-цикл. |
| Полнота снимков | Полная: все пользовательские таблицы из sqlite_master + journal_mode, сравнение построчное (`snap_a[t] == snap_b[t]`), не только счетчики. Плюс сквозная API-проверка содержимого — снимок и поведение сверяются независимо. Сессии охвачены сверх требования NFR-3 (допустимо по design §2). |
| Распределение нагрузки | Реалистично: 1100 ≥ 1000 (NFR-2), статусы ~ рабочего борда, теги 1–3 на задачу, дедлайны ±30 дней; архив через штатную ленивую автоархивацию (прогрев отделен от замеров — корректно). Мутирующие тесты на «своих» задачах с уборкой после. |
| Замер | time.perf_counter вокруг полного запроса, 10 прогонов, порог по max (строже, чем avg). Мелкая задача пагинации `ORDER BY id` в подзапросе задокументирована в коде (поймана dev на прогоне). |
