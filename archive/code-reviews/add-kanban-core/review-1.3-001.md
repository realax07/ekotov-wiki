## Круг 2 — best practices / безопасность (seed credentials)

- Пароли не логируются и не эхо: вывод скрипта содержит только логины и статусы; `getpass` без эха (при не-tty — предупреждение интерпретатора и чтение stdin — это поведение самой библиотеки, задокументировано dev'ом, на tty отсутствует). ✅ (проверено фактом: stdout/stderr прогонов не содержат поданных паролей)
- Префикс `$2b$`, cost 12: подтверждено чтением БД — оба хеша `$2b$12$...`, длина 60. ✅ Cost 12 достаточен для 2 пользователей на VPS (≈250 мс/проверка).
- `IntegrityError` перехвачен точечно вокруг INSERT, остальные исключения (connect, commit) проходят наружу — не глотаются. ✅
- Жестко зашитых паролей/секретов в коде нет: `git grep` по паттерну литералов пароля по `backend/` — пусто; тестовые пароли ревьюера в репо отсутствуют. ✅
- Skip вместо перезаписи: существующий логин не трогается — безопасный дефолт (seed не может случайно затереть действующий пароль). ПМ подтвердил: reset пароля — отдельная задача при необходимости. Не блокирует. ✅
- SQL — единственный запрос, параметризованный (`VALUES (?, ?)`). ✅
- NFR-5: `*.db`, `*.sqlite*` в `.gitignore`; тестовые БД ревьюера созданы в `/tmp`, в репо не попали. ✅
- Зависимости: добавлен только `bcrypt==5.0.0` (пин), версионная политика дифа не нарушена. ✅
