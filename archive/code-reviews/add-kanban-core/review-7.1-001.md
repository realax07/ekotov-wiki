## Решения по вопросам dev

1. **Инклюзивность due-границ (<=/>=): ПРИНЯТЬ.** sdd §3.5 и спека search
   инклюзивность не оговаривают; выбор dev правомерен как доминирующая
   интерпретация («срок не позднее D» естественно включает D). Это не
   «улучшение мимо трассировки», а доопределение недоспецифицированной детали,
   помеченное в комментарии и отчете. Замечание к спеке не требуется; если
   Заказчику важна строгая граница — это правка спеки через ПМ, не блокер кода.

2. **Пустые tag=/category= → 0 результатов: ПРИНЯТЬ, 422 не требовать.**
   Фактическое поведение проверено: `tag=` → 200 с 0 результатами (предикат
   `t.name IN ('')` не совпадает), `category=` → аналогично, при этом `priority=`
   и `archived=` дают 422 (Literal). Это согласованно: 422 в sdd — «невозможное
   значение», а пустая строка — возможное значение фильтра, просто ничего не
   совпадающее (как поиск категории «qwerty»). Безопасно (параметризовано) и
   консистентно с search-семантикой. UI-конструктор (7.3) пустые значения не
   отправляет. Требовать 422 = вводить поведение вне спеки — не замечание к
   реализации.
