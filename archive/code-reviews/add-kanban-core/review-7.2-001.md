## Проверено (три круга скилла + независимая проверка)

### Круг 1 — спека как закон
- sdd-пример `priority = "high" AND tag IN ("home")` → 200, results верны (A + архивный E),
  `normalized_query` == build(parse(ввод)) — **PASS** (смоук 1, 1b).
- 400-формат дословно sdd §3.5: `filter syntax: position N: причина`, 11/11 классов
  синтаксических ошибок — **PASS** (незакрытая кавычка, неизвестный оператор, мусор,
  неизвестное поле, OR, незакрытая IN-скобка, невалидный priority, дата-мусор,
  tag без IN, archived-значение, хвост после условия).
- 401 без сессии — **PASS** (смоук 6; и 401 не требует валидного тела — проверено).
- Результаты advanced == эквивалентный GET на 9 парах фильтров — **PASS** (смоук 7).
- Scenario спеки search: все 4 Scenario «Режим advanced…» покрыты кодом/смоуком
  (синхронизация конструктор↔текст = build()/parse(); правка применяется; негативный —
  400 без порчи данных). 7.3 (UI) — вне этого диффа.

### Круг 2 — best practices / безопасность парсера (главный риск)
- **Построчное чтение parse → структура → build_where:** пользовательский текст физически
  не может попасть в SQL-строку. `_tokenize` → `_parse_condition` → `_apply_predicate`
  заполняют только поля `SearchFilters`; `build_where` — фиксированные шаблоны с `?`,
  имена полей зашиты, значения только в params. Единственные f-строки в SQL —
  плейсхолдеры `?` (:109-113) и `TASK_COLUMNS` (константа) — **PASS**.
- **Инъекция:** `category = "work; DROP TABLE tasks;--"` и `tag IN ("home; DROP TABLE …")`
  → 200, 0 совпадений, `DROP` отсутствует в WHERE, строка — в bind-параметрах, таблица
  цела; инъекция вне кавычек → 400 — **PASS** (смоук 5a-5f + независимый повтор).
- **normalized_query — сериализация структуры, не эхо:** `category = "x \" OR 1=1 --"`
  → normalized `category = "x \" OR 1=1 --"` (пересобрано build с экранированием),
  повторный parse(normalized) дает тот же фильтр; произвольные пробелы ввода не
  воспроизводятся (`priority   =   "high"` → канонично) — **PASS**.
- **Рекурсия:** парсер итеративен (while + индекс токенов, ни одна функция не рекурсивна);
  скобочные вложенности грамматикой не предусмотрены, `((...))` и `IN (("x"))` → 400.
  Стресс: `tag IN` с 5000 значений — итеративно, плейсхолдеры == параметрам — **PASS**
  (stack exhaustion недостижим по построению).
- **Escape-логика кавычек:** `\"` → `"`, `\\` → `\`, обратный слэш на конце → 400; build
  экранирует в обратную сторону, roundtrip — **PASS** (смоук 8d/8e + независимые пробы).
- **400 до всякого get_connection:** в `search_advanced` parse (:564) стоит до
  `get_connection()` (:573); после 11 ошибок данные целы (смоук «2:не-выполнен») — **PASS**.

### Круг 3 — integration
- `parse(build(x)) == x`: 12/12 фильтров смоука + независимо добавлены NE-варианты
  (`priority != …`, `category != …`, комбо с due/tag) — **PASS** (в смоуке NE не
  roundtrip-ились; сам проверил — 3/3).
- GET /api/search (7.1) не сломан: 32/32 смоука, пустой advanced == пустой GET,
  форма Task полная (11 полей, archived_at на месте, FR-10).
- due = D → `due_date <= ? AND due_date >= ?` [D, D] — **PASS**.
- `archived = all` → без предиката (и архив, и активные) — **PASS**.

## Решения dev — оценка ревьюера

| Решение | Оценка |
|---|---|
| OR NOT supported, явная 400 | **Принято.** Спека/design OR не оговаривают; И — единственная связка по design §6 и Scenario «Комбинация условий». Ошибка с позиций — корректный явный отказ. |
| `!=` с NULL-семантикой (X != v ⇔ X != v OR X IS NULL) | **Принято.** Интуитивная семантика «задача без признака условию не равна» — иначе `priority != "low"` молча терял бы все задачи без приоритета. Вне sdd, но это расширение грамматики advanced, GET его не выставляет; задокументировано в коде. |
| IN только для tag | **Принято.** Whitelist-грамматика повторяет модель данных: множественность легитимна только у тегов; у priority — CHECK из 3 значений, комбинировать = OR, которого нет. |
| Пустой текст = пустой фильтр (все задачи) | **Принято.** Симметрично GET без параметров (Scenario «Поиск без заданных условий»); whitespace-only — тоже 200 с пустым normalized — согласовано. |
| due = D как диапазон [D, D] | **Принято.** Границы включательные — согласовано с решением 7.1; каноническая сериализация `due = D` устойчива в roundtrip (проверено). |
