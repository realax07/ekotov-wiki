## Особое внимание (из постановки) — проверено

| Пункт | Результат |
|---|---|
| **NFR-7: единый текст без причины** | `POST /api/auth/login`: несуществующий логин и неверный пароль → идентичные `401 {"error":"invalid credentials"}` (прогнаны оба случая, тела побайтово совпадают). JS ошибку рендерит из **зашитого в разметку** `<p id="login-error" hidden>Неверный логин или пароль</p>`, показом/скрытием (`errorEl.hidden`), тело ответа не читает вовсе (нет `.json()`/`.text()` на response — сверено по исходнику и в браузере). Причина не раскрывается ни API, ни UI. ✅ |
| **Форма не уйдет нативным GET/POST** | `method="post" action="/api/auth/login"` (fallback не GET) + JS `addEventListener("submit")` с `event.preventDefault()` — в браузере проверено: `ev.defaultPrevented === true` при диспетче submit; нативная отправка не происходит, уходит fetch JSON. ✅ |
| **autocomplete** | `autocomplete="username"` на логине и `autocomplete="current-password"` на пароле — рекомендация для логин-форм, не сенситивный избыток. Никаких автозаполняемых секьюрных полей сверх нормы нет. ✅ |
| **CSRF login** | POST login без сессии — CSRF-риска не несет (атакующий не может выгодно действовать от имени жертвы: успешный вход лишь ставит куку жертве в ее же браузере). После логина защита — SameSite=Lax на session-куке (NFR-7 «CSRF-минимум через SameSite=Lax», design §2): кросс-сайтовые POST fetch/XHR с attaching куки Lax блокирует. Исходя из постановки sdd — соответствует; token-based CSRF не требуется спекой. ✅ |
| **Jinja2 autoescape** | `Jinja2Templates` (FastAPI) создает Environment с `autoescape=jinja2.select_autoescape()` — для `.html` включен по умолчанию, отключения нет (проверено инспекцией установленной версии). Шаблон не принимает переменных вовсе (`TemplateResponse` без context) — инъекций в рендер нет. ✅ |
| **XSS через URL-параметры** | `GET /login?next=<script>alert(1)</script>&x=<img onerror=…>` → параметры игнорируются полностью (роут не читает query), в теле ответа отражения нет (проверено, 0 вхождений), `Content-Type: text/html; charset=utf-8`. В JS нет чтения `location.search`/`URLSearchParams`. Вектор отраженной XSS через /login отсутствует. ✅ |

## Проверенные Scenario (воспроизведено лично)

Прогон ревьюера: uvicorn 8323 + браузер через статик-прокси (эмуляция nginx). Ключевое:

| Проверка | Результат |
|---|---|
| **S1. GET /login без сессии** (sdd §3.6 «страница входа… доступна без сессии») | `200`, `text/html; charset=utf-8`, форма с `id="login-form"`, поля login/password, кнопка, скрытый `role="alert"` с текстом ошибки. ✅ |
| **S2. Форма постит JSON на /api/auth/login** | Реальный submit в браузере: fetch POST, `Content-Type: application/json`, тело `{login, password}`, `credentials: "same-origin"`; нативная отправка предотвращена (`defaultPrevented=true`). ✅ |
| **S3. 401 — единый текст, без причины** | Оба кейса (несуществующий логин / неверный пароль) → `401 {"error":"invalid credentials"}`; UI показывает зашитый «Неверный логин или пароль», `role="alert"` становится видимым, кнопка разблокируется, тело 401 не анализируется. NFR-7 соблюден на обоих уровнях. ✅ |
| **S4. 200 → redirect на /board** | Реальный успешный логин в браузере → `window.location.href = "/board"`, URL сменился на `/board`; сет-кука сессии `HttpOnly; SameSite=lax; Secure; Max-Age=2592000; Path=/` подтверждена (приложение после логина авторизует: `/api/board` с сессией проходит middleware — 404 маршрутизации вместо 401, страница доски — задача 4.3). ✅ |
| **S5. Jinja2 рендер без ошибок** | Рендер в живом приложении — 200, валидный HTML, шаблон в логах uvicorn без ошибок; endpoint синхронный, без обращений к БД. ✅ |
| **S6. Регрессия middleware** (круг 3, смежные сценарии) | Без сессии: `/board`, `/search`, `/wiki`, произвольная страница → `302 Location: /login`; `/login` → 200 без редиректа. API: `/api/board`, `/api/tasks`, `POST /api/auth/logout` → `401 {"error":"unauthorized"}` (текст middleware не перепутан с login-текстом `invalid credentials`); `GET /api/health` → 200. Задача 2.2 не сломана. ✅ |
| **S7. Отсутствие утечек причин** | Тела 401 идентичны для обоих кейсов; в ответах нет имен полей БД/стеков; логирование запросов uvicorn не содержит тел/паролей (в коде логирования нет). ✅ |
| **Секреты/данные** | Тестовые учетки создавались ревьюером во временную БД в /tmp, вне репозитория; в дифе секретов нет; конфиг через env (без дефолтов). ✅ |

## Что НЕ проверено (честно)

- **Боевой HTTPS-контур nginx** — вне дифа (задача 1.4); статик-путь воспроизведен эквивалентным локальным прокси (те же семантики `/static/*` мимо приложения), но не самим nginx-конфигом из deploy/.
- **Визуал/UX формы** (CSS-верстка, мобильная вьюпорт-адаптация) — не предмет ревью спеки; проверена работоспособность, не внешний вид.
- **Поведение при отключенном JS** — нативный POST уйдет на `/api/auth/login` (method/action корректны), но обработку ответа форма без JS не имеет; graceful degradation вне спеки, не проверялась.
- **Локальный запуск без nginx** (статика 404) — зафиксировано как minor №2, отдельным прогоном не оформлялось (следует из отсутствия монтирования в `main.py`).
- **Браузеры кроме одного** (движок test-run); автозаполнение менеджером паролей не проверялось.
