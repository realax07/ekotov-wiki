## Проверка 1: consumed-фильтр в syncInputAndDom (FR-92/TC-UIP-109) — BLOCKER

Дифф заменяет rest-фильтр `committedTags.indexOf(tag) === -1` на исключение токена, «потребленного» выбором. Само решение семантики (потребление токена выбором расширения) соответствует диспозии TC-UIP-109 и открытому вопросу п.3 карточки: выбор по Enter «делается ради» недобранного токена, двойной чип — дефект. **Но реализация фильтра дефектна: `consumed` вычисляется один раз от последнего токена строки (`currentToken(input.value)`), а возвращаемое значение фильтра применяется ко ВСЕМ тегам rest.**

```js
// tag-combobox.js:241-253 (da32681)
var token = currentToken(input.value).toLowerCase();
var consumed = committedTags.some(function (selected) {
  return selected.toLowerCase().indexOf(token) !== -1;
});
return !consumed;   // ← отбрасывает КАЖДЫЙ rest-тег, включая несвязанные ранние
```

Комментарий в коде («Токены, не связанные с выбором… остаются как были») и отчет dev (п. «несвязанные ручные токены не затрагиваются», ссылка на TC-r6-comb-006) описывают семантику, которую код НЕ обеспечивает: при активном токене, совпадающем с выбранным значением, теряются ВСЕ прочие ручные токены строки.

**Подтверждение живыми пробами** (временный тест в worktree, удален после фиксации; стенд conftest da32681, chromium):

1. `tags.fill("QATprobelost, QATkb")` → Enter (выбор «QATkbдва», активный пункт): input = `'QATkbдва,'` — ручной несвязанный токен **«QATprobelost» исчез** (чип 1, «QATkbдва»). Далее end-to-end: сабмит формы → `GET /api/search` → сохраненные теги задачи = `['QATkbдва']` — **пользовательский тег потерян безвозвратно** (`AssertionError: потеря данных end-to-end, сохранено: ['QATkbдва']`).
2. Таб-путь (в точности строка 246 TC-r6-comb-005, `tags.fill(" QATkbодин, QATkbнов")` → Tab, выбор «+ Добавить тег «QATkbнов»»): input = `'QATkbнов,'` — ручной токен «QATkbодин» потерян (это же значение пользователь мог ввести руками и НЕ выбирать).

Нарушение: FR-92/TC-UIP-109 «множественное добавление… поле ввода работает» + семантика TC-r6-comb-006 (несвязанный токен переживает взаимодействие — сам сьют TC-006 ее проверяет только в unlucky-конфигурации, где связанный и несвязанный токены разнесены по разным фазам теста, поэтому 10/10 green при реальной потере). Требование CRIT «не задеваются ли несвязанные токены» — **не выполнено**.

**Рекомендация (blocker-1):** фильтровать rest per-tag — токен `tag` потреблен, только если он сам является подстрокой (case-insensitive) какого-либо committed-значения: `return !committedTags.some(s => s.toLowerCase().indexOf(tag.toLowerCase()) !== -1)` (проверку `currentToken` убрать — она и есть источник бага); точную границу семантики (в т.ч. behavior токена-префикса вроде «QAT» при выборе «QATkbдва») зафиксировать в карточке/TC и накрыть тестом мульти-токенового rest с end-to-end ассертом сохранности (текущий сьют потерю не ловит — мутационный пробел).
