## 3. Круг 3 — интеграция и тесты (включая три ПМ-фикса)

### 3.1 Фикс (1): прокси images_service — `static_url + path.partition("/static")[2]`

**Корректен.** Docroot http.server-статики = `frontend/static`, nginx-маппинг `/static/css/x.css → /css/x.css` (conftest `_to_static` — тот же partition:276). До фикса прокси отдавал бы 404 на все /static/*. Паритет с `_to_static` — байт-в-байт тот же выражение. Риск `partition` при `/static` в querystring отсутствует (партиция по первому вхождению в path — совпадает с behavior `_to_static`, оба проверены тестами на практике: статика грузится в image-кейсах).

### 3.2 Фикс (2): DB_PATH из env рантайма (`os.environ.get("EKOTOV_WIKI_DB_PATH")`)

**Корректен.** conftest ставит `EKOTOV_WIKI_DB_PATH` в `web_server` (session-scope) на 224 — то есть ПОСЛЕ импорта тестового модуля; константа на импорте была бы None/мусор. Чтение в теле fixture/теста — правильная модель. Тот же env-ключ, что у search-сервиса (181) — консистентно.

### 3.3 Фикс (3): `wait_for_load_state("networkidle")` в конце двух save-тестов

**Корректен как обход, слабоват как практика (F-4, minor).** Симптом реален: teardown Browser.close гоняет незавершенные route-fulfill'ы (`Route.fulfill: Fetch response has been disposed` — известная гонка pw). networkidle после `wait_for_url` действительно доливает фоновые запросы страницы-редиректа. Но это глобальный барьер «дождись ТИШИНЫ» — хрупко к любому долгому фону (аналитика, длинные поллинги) и маскирует, ЧЕЙ именно запрос доливается. Комментарий в коде честно объясняет причину — принято; рекомендация: точечное ожидание конкретного запроса (`page.wait_for_load_state` → `expect_response` на последний /static/* страницы) при следующей правке.

### 3.4 Изоляция/поведение сьюта

- **F-2 (major):** `test_wiki_empty_state_create_first_page` проходит только при лексикографически-прямом порядке файлов. При алфавитном порядке (editor → history → page → tree) редактор-сьют успевает создать страницу, teardown которой НЕ удаляет (у editor-сьютов cleanup неполный — см. F-1), и к моменту tree-сьютов tmp-БД стенда НЕ пуста → пустого состояния нет → fail. Это дефект изоляции тестовых данных СЬЮТА (общая session-scope tmp-БД + не полностью убирающиеся editor-кейсы). Продукт не сломан (прямой порядок — любой дефолт), но раннер с `-p no:randomly` и другим порядком аргументов получит красный набор.
- Свидетельство ловящей способности: 2/2 XSS-мутации пойманы; версии на каждое сохранение (v1 create / v2 edit) зафиксированы по API; revert-инварианты (id прежних, +1, контент V1) — по API, не по DOM.
- Отметка: `pytestmark = pytest.mark.usefixtures("web_server")` в tree/page и `[e2e, web, must]` в history — стилистический разнобой с остальными web-сьютами (у всех `[e2e, web, must]`); tree/page/editor без маркеров `must` выпадут из must-фильтра раннера — **F-6 (minor)**.
