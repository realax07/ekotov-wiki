## PR #49 — 2.3 комментарии + combobox (feature/p12-23-comments-combobox)

## Вердикт: **ВОЗВРАТИТЬ** (FR-91/92 в остальном чисто; blocker 1, minor 2)

FR-91: GET списка дополнен author_name (COALESCE(u.display_name, u.login), LEFT JOIN), POST-контракт не тронут — дословно design §5; юниты tests/api/test_comments_author_r8.py — прогон в чистом worktree: **5 passed**. XSS: все значения через `el()`/textContent, innerHTML нет. DOM-id не тронуты.

- **blocker** — `frontend/static/js/board/tag-combobox.js:446–462` + `task-form.js:397–407`: committed-леджер переживает закрытие формы и **утекает в чужую задачу**. `resetCommittedFromInput()` срабатывает только в `closeTagHints()`, но после сохранения задачи с тегами input непуст («Z, X, Y,») — условие сброса ложь, committedTags остается. Следующее `fillTaskForm()` пишет input напрямую (без input-события и без сброса леджера), чип «утерянного» тега не виден, но capture-хук `flushCommittedToInput` на submit дописывает его в payload. Проверено node-симуляцией кода 1:1: правка задачи A (теги X,Y + выбор Z) → сохранить → открыть задачу B (тег P) → сохранить без правок → PATCH B несет `tags: ["Z","P"]`. Тихая порча данных чужой задачи на обычном флоу «редактирую задачи подряд». Утвержденная диспозиция ПМ покрывает только отклонение от буквы FR-92 (непустое поле до сабмита), но не межформенную утечку — это отдельный дефект. Фикс-направление: сбрасывать committedTags в `fillTaskForm`/`clearTaskForm` (экспорт reset из комбобокса либо подписка на value-замену), плюс тест-красный «открытие формы сбрасывает леджер».
- **minor** — `tag-combobox.js:78–86`: `applySelection()` теперь мертвый код (выбор через него не идет) — функция вводит в заблуждение; удалить или пометить deprecated явно.
- **minor** — `tag-combobox.js:278–292`: `resyncCommittedAfterChipEdit` на `setTimeout 0` — хрупкая синхронизация с чужим bubbling-обработчиком. Кандидат: пересинхронизация на input-событии от правки task-form вместо таймера.
