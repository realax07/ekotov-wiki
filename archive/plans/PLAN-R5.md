Источник: `docs/ba/requirements-r5.md` (черновик, готов к передаче СА; дословные вводные Заказчика 2026-09-30; раунд вопросов Заказчику не открывался — 0 ОВ к Заказчику, ОВ-СА-1…6 решает СА).

## Решения Заказчика (дословно, 2026-09-30)

1. «сделаем более красивой и компактной страницу редактирования профиля, и надо чтобы загружаемое фото, при загрузке, можно было выбирать область отображения аватара в кружке, двигая фото под рамкой. Чисто логика фронта»

## Ключевые следствия решений (для БА/СА)

- **Кроп-виджет**: фото под круглой маской, drag, зум, live-предпросмотр; «Применить»/«Отмена» (отмена = прежний аватар). Только при новой загрузке; существующие center-crop-аватары не перекраиваются (ОГР-21).
- **«Чисто логика фронта»** — предпочтение, не жесткое ограничение (ОГР-24): вариант передачи результата (фронт-кроп vs сервер-координаты) — решение СА (ОВ-СА-1/2).
- **Единая карточка V3**: аватар + display_name + роль + bio + смена пароля в одном визуальном блоке по токенам V3; состав полей Р4 не расширяется.
- **Тач/клавиатура**: touch-drag, pinch/слайдер (NFR-13); клавиатура и aria для зума/перемещения (NFR-15); fallback без canvas — загрузка как в Р4 (NFR-14).
- **Лимиты**: исходник ≤2 МБ png/jpg без изменений (NFR-12); на сервер не гонять полноразмерник (NFR-11).
- **Дизайн**: живой макет в `design/` — обязательный артефакт пакета (J25, ОГР-25); релизный бамп `static_v` (ОГР-22).

## Решения СА (зафиксированы в пакете add-r5-avatar-crop-compact-profile/design.md)

| ОВ | Решение |
|---|---|

| ОВ-СА-2 | Сервер не доверяет клиенту: полная повторная валидация + безусловный resize 256×256 LANCZOS (конвейер Р4 сохранен) |

| ОВ-СА-5 | Тач: drag + pinch + слайдер (обязателен); клавиатура: слайдер-стрелки, стрелки на виджете двигают фото, +/− зум |
| ОВ-СА-6 | Смена пароля в той же карточке ниже профиля; подтверждение кнопкой «Сменить пароль», не по blur |
