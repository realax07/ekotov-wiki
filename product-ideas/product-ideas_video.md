# IDEA-001. Личный видеохостинг

**Статус:** идея (Заказчик, 2026-09-23)

**Суть:** создать в существующем сервисе новый продукт «Видеохостинг» для личной библиотеки видео.

## MVP

- Добавить «Видеохостинг» в sidebar.
- Хранить метаданные видео, категории и теги в БД.
- Видео загружаются владельцем напрямую на сервер.
- Автоматически импортировать видео и создавать thumbnails.
- Показывать библиотеку в виде плитки с превью.
- Сделать страницу просмотра с browser video player.
- Обеспечить streaming и перемотку видео.
- Реализовать поиск по названию, описанию и тегам.
- Добавить фильтрацию по категориям и тегам.
- На главной показывать наиболее подходящие и недавно добавленные видео.

## Критерий MVP

Положил видео на сервер → оно автоматически появляется в библиотеке → его можно найти → открыть и посмотреть в браузере.

## Пожелания к реализации (Заказчик, 2026-09-23)

### Техническая реализация

Реализовать MVP как отдельный модуль существующего сервиса, без усложнения инфраструктуры.

### Архитектура

Разделить систему на:

- frontend видеотеки;
- backend API;
- БД метаданных;
- файловое хранилище видео;
- thumbnails;
- модуль импорта и обработки видео.

Не хранить видео в БД.

### Хранение видео

Исходные видео хранить на файловой системе VPS.

Импорт должен:

1. находить новые файлы;
2. извлекать metadata через `ffprobe`;
3. создавать thumbnail через FFmpeg;
4. создавать/обновлять запись в БД;
5. корректно обрабатывать повторный запуск без дублей.

Не загружать целые видео в память приложения.

### Streaming

Использовать стандартный HTTP streaming с поддержкой `Range` requests.

Backend должен корректно поддерживать:

- `206 Partial Content`;
- `Content-Range`;
- `Accept-Ranges`;
- перемотку;
- потоковую передачу больших файлов.

На MVP не реализовывать HLS/DASH и transcoding в несколько качеств, если они не требуются текущим форматом видео.

### База данных

Хранить отдельно:

- видео;
- категории;
- теги;
- связи видео ↔ теги.

Предусмотреть полнотекстовый поиск по названию, описанию и тегам.

Для MVP использовать существующую БД проекта либо наиболее лёгкое решение, не добавляя отдельную инфраструктуру без необходимости.

### API

Предусмотреть API для:

- списка видео;
- получения видео;
- поиска;
- фильтрации;
- получения thumbnail;
- streaming видео;
- категорий и тегов.

API должен поддерживать pagination и сортировку.

### Frontend

Сделать:

- главную страницу видеотеки;
- поиск;
- фильтры;
- плитку карточек;
- страницу просмотра;
- блок похожих/релевантных видео.

Использовать стандартный browser `<video>` player, если он покрывает требования MVP.

### Производительность

Учитывать ограничения VPS:

- не держать видео в RAM;
- не выполнять тяжёлую обработку во время HTTP-запроса;
- импорт и генерацию thumbnails выполнять отдельно от пользовательских запросов;
- предусмотреть pagination/lazy loading каталога;
- thumbnails отдавать как обычные статические файлы.

### Архитектурный принцип

Не переусложнять MVP.

Не добавлять Kubernetes, отдельные search-сервисы, object storage, CDN, HLS и другие инфраструктурные компоненты без реальной необходимости.

При этом разделить storage, metadata и streaming так, чтобы в будущем их можно было вынести в отдельные сервисы.

### Definition of Done

Полный сценарий должен работать:

«файл на диске → импорт → metadata + thumbnail → БД → каталог → поиск → страницу видео → streaming → перемотка в браузере».

Сначала реализовать этот vertical slice, затем расширять функциональность.
