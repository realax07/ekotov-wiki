# Архитектурная карта ekotov-wiki («как есть»)

Статус: актуальна на 2026-09-26 (E11, архитектор; база — main `d619347`, прод — хотфикс `541e844`, прод отстает от клона, см. §1.3).
Задача выполнена по Флоу 4 (обслуживание). Артефакт только фиксирует факты и решения; задачи сюда не входят.
Источники: код `backend/app/`, `frontend/`; `sdd.md` r7; спеки `openspec/specs/*/spec.md`; `deploy/RUNBOOK.md` (E9, факты прода 2026-09-26); `PRODUCT_BACKLOG.md` (DEF-001…005); архив `openspec/changes/archive/`.

## 1. Компоненты и границы

### 1.1 Приложение (uvicorn, один процесс)

| Компонент | Файл(ы) | Ответственность |
|---|---|---|
| Точка входа | `backend/app/main.py` | Сборка FastAPI-приложения (`docs/redoc/openapi` отключены), подключение роутеров, `GET /api/health`, `POST /api/auth/logout` (логаут — здесь, не в auth-роутере) |
| Конфиг | `backend/app/config.py` | Только env: `DB_PATH`, `SECRET_KEY` обязательны, дефолтов нет — их отсутствие = падение старта |
| Auth middleware | `backend/app/middleware.py` | Единая точка проверки сессии для API (401) и страниц (302 → `/login`); exempt: `POST /api/auth/login`, `GET /api/health`, `GET /login`; скользящий TTL 30 дней |
| Auth | `backend/app/auth.py` | `POST /api/auth/login`: bcrypt, dummy-хеш против раскрытия существования логина, токен 256 бит в таблицу `sessions` |
| Роутеры (routes) | `tasks.py` (542 стр., CRUD+move+priority-lock+error handlers), `board.py` (доска + ленивая автоархивация по МСК), `categories.py`, `comments.py`, `search.py` (608 стр., builder+parse+advanced), `suggestions.py`, `pages.py` (Jinja2-страницы: login/board/search/wiki/settings) | Вся бизнес-логика — серверная: priority-lock, жесткая валидация категории по справочнику, инварианты fast line |
| DB-слой | `backend/app/db.py` | Схема (CREATE IF NOT EXISTS), per-connection `PRAGMA journal_mode=WAL` + `foreign_keys=ON`, рукопашная миграция `done_at` (MIGRATION_SQL_6_1); отдельные скрипты: `seed_users.py`, `migrate_categories.py` |
| Сервисный слой как отдельный модуль | отсутствует | Логика живет внутри роутеров; «services»-слоя нет — границы слоев: routes → sql inline → db.py (connection/schema) |

Границы приложения: приложение НЕ отдает статику (`StaticFiles`/`mount` в коде отсутствуют — проверено grep) и НЕ терминирует TLS.

### 1.2 Фронтенд

Jinja2-шаблоны `frontend/templates/` (6 шт: base, login, wiki, board, search, settings) + ванильный JS `frontend/static/js/` (ES-модули `board/*` — api/state/dom/cards/task-detail/task-form/priority-icons; отдельные login.js, search.js, settings.js, app.js) + CSS `frontend/static/css/` (токены дизайна V3 в app.css). UI = клиент REST API, в БД не лезет (ОГР-2). Шаблоны рендерит приложение (Jinja2Templates из `pages.py`), статику — nginx (§1.3).

### 1.3 Прод-топология (кратко; детали и процедуры — deploy/RUNBOOK.md, не дублируются)

```
Браузер ── https://194.58.34.122:10443 (TLS self-signed) ── nginx :10443
   ├── /static/ → alias /opt/ekotov-wiki/frontend/static/ (expires 7d, public)
   └── /        → proxy_pass http://127.0.0.1:8377
                    uvicorn (systemd-юнит ekotov-wiki, User=wiki, 1 воркер, без --workers)
                      └── SQLite /var/lib/ekotov-wiki/wiki.db (вне репозитория, владелец wiki)
```

Ключевое для архитектуры: `/opt/ekotov-wiki` — не git, обновление только rsync из клона `~/ekotov-wiki` (main) через `deploy/deploy.sh`; бэкап БД перед деплоем (`sqlite3 .backup`, без остановки); откат — снапшот кода + копия БД. Деплой запускает Заказчик; агент прод не пишет. Прочее (TLS-сертификат до 2028, порты, харднинг юнита, смоук) — RUNBOOK §1–2, §4.4.

### 1.4 Тестовый контур (не прод)

`tests/api` (pytest+requests, 115 тестов) и `tests/web` (playwright) против стенда: uvicorn + временная БД; web-стенд эмулирует роль nginx'а по статике вторым процессом `python -m http.server` (tests/web/conftest.py) — см. риск §6.3.

## 2. Потоки данных

**Основной запрос (API):**
```
Браузер (fetch, JSON) ──HTTPS──> nginx :10443 (TLS, security-заголовки, gzip)
  ──> uvicorn :8377 ── auth middleware (кука session → таблица sessions: валидация + скользящий TTL)
  ──> роутер (pydantic-валидация тела → серверные инварианты: priority-lock, категория по справочнику)
  ──> sqlite3 (параметризованный SQL; WAL; FK on) ──> JSON-ответ (200/401/404/409/422 по контрактам sdd §3)
```

**Страницы:** тот же путь, но на выходе Jinja2-рендер (base.html + страница, `?v={{ static_v }}` на статике). Без сессии — 302 на `/login` (middleware).

**Статика:** `/static/*` перехватывает nginx (alias на `frontend/static/`), **до приложения не доходит** (допущение Д-а, §4). Кеш браузера 7 дней; инвалидация — только сменой URL через бамп `static_v` в `pages.py`.

**Данные (жизненный цикл задачи):** создание/правки — через tasks-роутер; перевод в done фиксирует `done_at`; ленивая автоархивация при чтении доски (задачи выполненные до начала текущего МСК-дня получают `archived_at`) — фоновой задачи/крона нет, время — фиксированный UTC+3 в коде, независимо от TZ сервера. Категории хранятся у задач **по значению** (tasks.category TEXT), переименование в справочнике переносит значение UPDATE'ом всех задач в одной транзакции.

**Запись:** все мутирующие операции — короткие транзакции sqlite3 с commit в роутере; соединение открывается на запрос и закрывается (нет пула).

## 4. Архитектурные допущения (явный список)

Каждое — с пометкой «проверено на проде» (чтение конфигов/кода прода, RUNBOOK E9) или «НЕ проверено» (не верифицировалось боевой нагрузкой/эксплуатацией).

| # | Допущение | Пометка |
|---|---|---|
| Д-а | Статику отдаёт nginx (`location /static/` + alias), приложение не имеет StaticFiles/mount — статика до uvicorn не доходит | **Проверено на проде**: код (grep StaticFiles/mount — пусто), nginx-конфиг `/etc/nginx/sites-enabled/ekotov-wiki`, смоук RUNBOOK §4.4 (200 на /static через прод-URL). Нюанс: само допущение архитектурно корректно; продом оно «ударило» косвенно — DEF-002/DEF-003 были про кеш браузера на этих же URL (nginx `expires 7d`), т.е. риск зоны статики реален, но в слое доставки/кеша, не в приложении |
| Д-б | SQLite (WAL) достаточен для односемейной нагрузки (2 пользователя, 1000+ задач, NFR-2) | **Частично проверено**: замер NFR-1 на 1000 задач выполнен в R1 (tasks 8.2, sdd §5); WAL включается кодом на каждом соединении (db.py). **НЕ проверено**: поведение под реальным многолетним объемом (комментарии, архив); на момент E9 файлов `-wal/-shm` в каталоге БД прода не наблюдалось (RUNBOOK §2) — согласуется с короткоживущими соединениями (wal-файл исчезает после закрытия последнего соединения), но конкурентность двух пользователей под WAL в бою не подтверждена наблюдением |
| Д-в | Сессии живут в БД (таблица sessions), не в памяти: рестарт сервиса сессии НЕ инвалидирует | **Проверено на проде по коду** (auth.py INSERT, middleware SELECT — сессия это строка в том же SQLite-файле; in-memory кеша сессий в коде нет). Примечание: sdd §5 (NFR-3) допускает «инвалидацию сессий при рестарте» как допустимую, не обязательную — противоречия нет, но формулировка sdd описывает несуществующий in-memory кеш |
| Д-г | Self-signed TLS допустим (личный продукт, домена нет → Let's Encrypt недоступен; HSTS включен, пользователь один раз принимает исключение) | **Проверено на проде**: сертификат CN=194.58.34.122, notAfter 2028-12-22 (RUNBOOK §2); решение зафиксировано в шапке deploy/nginx-ekotov-wiki-10443.conf |
| Д-д | Kалендарь доски — фиксированный UTC+3 (МСК) без учета TZ сервера/клиента; DST не вводится | Проверено в коде (board.py, `timezone(timedelta(hours=3))`), на проде — следствие кода; **НЕ проверено** поведение при смене решения о часовом поясе (переезд пользователя) |
| Д-е | Общая доска без разделения по владельцу; обе учетки (owner, wife) видят все задачи; регистрации нет (seed) | Проверено в коде (seed_users.py, отсутствие user_id-фильтров в tasks/board) и в спеках (sdd §7); на проде — используется Заказчиком (обратной связи об обратном нет) |
| Д-ж | `SECRET_KEY` сейчас фактически не используется механизмом сессий (токены — `secrets.token_urlsafe`, не подпись) — обязательность переменной это будущий задел, а не работающая криптография | Проверено в коде (config.py требует; grep использования settings.secret_key — не находится) |
| Д-з | Один процесс uvicorn (без --workers) достаточен | Проверено на проде (ExecStart в юните без --workers, RUNBOOK §2); достаточность под нагрузкой НЕ проверена (наследует Д-б) |

## 5. Принятые решения (что / почему / источник)

| Решение | Почему | Источник |
|---|---|---|
| Серверная сессия (таблица sessions + кука HttpOnly/SameSite=Lax/Secure) вместо JWT | Явный механизм без фреймворковой «магии»; revocation тривиален (DELETE строки); TTL скользящий 30 дней; JWT дал бы невозможность отзыва и лишнюю криптографию для 2 пользователей | design.md §2 (архив add-kanban-core), sdd §3.1, код auth.py/middleware.py |
| FastAPI + Jinja2 SSR, ванильный JS — без SPA-фреймворка | «Несоразмерно личному проекту на 2 пользователей» (ОГР-1); REST API сохранен (ОГР-2), UI — тонкий клиент поверх него; FastAPI выбран вместо Flask как равно легковесный с готовыми pydantic-контрактами | sdd §1 (таблица стека) |
| SQLite WAL, файл вне репозитория | Прямое пожелание Заказчика (ОГР-1 «lite DB», NFR-5); для 2 пользователей серверная БД — лишняя эксплуатационная сущность; ноль демонов, бэкап = копия файла | sdd §1, §5; ОГР-1/NFR-5 |
| Категории у задач — по значению (TEXT), без FK по id | Простота модели и поиска; целостность держится серверной валидацией (422 если значения нет в справочнике) + переносом значения при переименовании + отказом удаления используемой категории (409, Д-1) | sdd §3.7, §4; код categories.py, tasks.py |
| Priority-lock fast line — серверной валидацией (is_fast ⇒ priority='high' или NULL), не UI | Инвариант принадлежит домену, UI не является границей доверия (ОГР-10, FR-27); единая точка — tasks-роутер | sdd §3.2/§3.4; код tasks.py `_priority_lock_422` |
| Кеш-бастинг через `?v={{ static_v }}` (глобал в pages.py, бамп вручную при релизе со статикой) вместо переименования файлов | Хотфикс DEF-002/DEF-003: минимальное изменение (5 шаблонов), не трогает пути статики в nginx; content-hash отклонен как избыточный на текущем объеме | PRODUCT_BACKLOG DEF-002/DEF-003; код pages.py (`static_v = "r2.1"`) |
| Ленивая автоархивация при чтении доски (без крона) | «Задержка до первого чтения после полуночи неотличима от фоновой задачи» — минус один демон (ОГР-1); done_at+archived_at в схеме | sdd r5 §3.3; код board.py |

## 6. Технический долг / риски (наблюдения, не задачи)

1. **Расхождение тестовый стенд / прод.** Web-стенд эмулирует роль nginx'а по статике `python -m http.server` (tests/web/conftest.py): нет TLS, нет `expires`-заголовков, нет security-заголовков и gzip. Класс рисков nginx-слоя (кеш, заголовки, TLS) веб-сьютом не ловится — прецедент DEF-002/003. Смягчение сейчас: пост-деплойный смоук по прод-URL (RUNBOOK §4.4, урок E10).
2. **Нет миграционного фреймворка.** Изменения схемы — рукопашные: проверка колонки в db.py (done_at), отдельный `migrate_categories.py`, идемпотентный CREATE IF NOT EXISTS. Работает при ручной дисциплине; каждое следующее изменение схемы требует снова ручного ALTER-кода и согласования с деплой-скриптом (RUNBOOK: упавший после миграции деплой требует отката и кода, и БД).
3. **`static_v` — ручной бамп.** Человеко-зависимый шаг: забыли бампнуть при релизе со статикой → у пользователей до 7 дней старый JS/CSS (именно это случилось в DEF-002). Скрипт деплоя этого не проверяет.
4. **Прод отстает от клона, прод — не git.** Код в бою (`541e844`) старее main (`d619347`); расхождение между картой/спеками («как есть») и боем — нормальное состояние между релизами, отслеживается dry-run rsync. Риск: дрейф «документация ≠ прод» без регулярных деплоев.
5. **Снапшот отката устарел** (RUNBOOK §4.3): `~/ekotov-wiki-R1-snapshot` эпохи R1; до следующего деплоя подлежит пересозданию, иначе откат кода вернет R1.
6. **Зависимости запинены, но аудита уязвимостей нет** — requirements.txt с `==` (факт проверен), но без dependabot/pip-audit; уровень риска для личного продукта низкий, поверхность (нет внешних вызовов, 1 TLS-вход) мала.
7. **Logout-роутер живет в main.py**, а не в auth-роутере (комментарий в коде называет это намеренным) — структурная шероховатость: контракт §3.1 разнесен по двум файлам.
8. **X-Forwarded-* не читаются приложением**: клиент всегда видит себя как 127.0.0.1; сейчас IP нигде не используется (логирования IP нет) — риск нулевой, пока не появятся функции по IP/аудит.
9. **CSRF — только SameSite=Lax** (sdd §5, NFR-7 «CSRF-минимум»): без CSRF-токенов; допустимо при текущем профиле (куки Secure+Lax, нет стороннихembedding'ов), пересмотреть при появлении публичных форм/интеграций.
