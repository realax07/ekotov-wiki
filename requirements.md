## 1. Общее описание

Полноценный wiki-функционал уровня «Confluence-минимум» в монолите (приложение
:8377, БЕЗ нового сервиса): иерархия страниц (дерево parent_id, вложенность
неограниченная, breadcrumb), WYSIWYG-редактор на contenteditable (vanilla JS,
без внешних CDN и сборщиков — принцип продукта ОГР-8), изображения в контенте
через существующий images-сервис, LIKE-поиск по заголовку и тексту, версии
(каждая правка = запись в `page_versions`: автор, время, контент; история,
просмотр версии, откат).

Данные — таблицы `pages` + `page_versions` в общей `wiki.db`, миграция по
паттерну `app.migrate_gallery` (идемпотентно, CREATE IF NOT EXISTS, одна
транзакция, автосверка). Индексация wiki в search-сервис — отдельное будущее
решение, в скоуп пакета НЕ входит. Данный пакет МОДИФИЦИРУЕТ спеку
`openspec/specs/navigation/spec.md`: снимается Won't по wiki-функционалу
(FR-13, Requirement «Пустой раздел Wiki с пометкой todo»), раздел «Wiki»
сайдбара перестает быть заглушкой и ведет на рабочую страницу `/wiki`; плюс
создается НОВЫЙ домен `openspec/specs/wiki/`.

Нумерация продолжает сквозную: последние использованные — FR-106
(add-responsive-mobile), NFR-29. Настоящий пакет: FR-107…FR-116, NFR-30…NFR-34.

## 2. Аудитория

Пользователи wiki — оба пользователя системы: владелец (учетка `owner`) и
вторая пользовательница (учетка `wife`) — **равноправно** (решение 7): любая
авторизованная сессия читает и редактирует все страницы; разделения прав НЕТ.
Неавторизованные: страница — редирект на `/login`, API — 401. Исполнители
пакета: ui_designer (мокапы вида, зона `design/**`), dev (монолит: миграция,
API, фронтенд), QA (pytest+requests API, playwright web, порты стендов явные —
E7), Заказчик (утверждение мокапов, прод-приемка).

## 3. Функциональные требования (FR)

- **FR-107** (Must): Дерево страниц: пользователь видит в разделе Wiki дерево
  всех страниц, построенное по иерархии parent_id, с неограниченной
  вложенностью; узлы дерева раскрываются/сворачиваются; страница `/wiki` без
  параметров показывает список корневых страниц (parent_id = NULL) с
  поддеревьями; при отсутствии страниц — пустое состояние с кнопкой создания
  первой страницы.
- **FR-108** (Must): Создание страницы: авторизованный пользователь создает
  страницу (заголовок непустой, контент), при создании указывает родительскую
  страницу (или «без родителя» — корневая); созданная страница появляется в
  дереве на выбранном месте.
- **FR-109** (Must): Breadcrumb: на странице статьи отображается цепочка
  предков от корня до текущей страницы; каждый элемент цепочки кликабелен и
  ведет на соответствующую страницу.
- **FR-110** (Must): WYSIWYG-редактор на contenteditable (vanilla JS, без
  внешних CDN/библиотек/сборщиков — ОГР-8) с тулбаром: заголовки H1–H3,
  жирный, курсив, подчеркивание, нумерованный и маркированный списки, цитата,
  код-блок, ссылка, таблица, изображение, отмена/повтор (undo/redo).
  Отредактированный вид соответствует сохраненному (WYSIWYG).
- **FR-111** (Must): Изображения в контенте: вставка изображения в текст —
  выбором из существующей галереи (images-сервис) или загрузкой с диска через
  существующий `POST /api/images`; в контенте хранится ссылка на раздачу
  `/images/{id}`; файлы НЕ дублируются в БД wiki.
- **FR-112** (Must): Редактирование страницы: авторизованный пользователь
  редактирует заголовок и контент; каждое сохранение правки создает запись в
  `page_versions` (author, timestamp, content) — история полная, правки не
  теряются.
- **FR-113** (Must): История версий: пользователь открывает список версий
  страницы (автор, дата-время, порядок — от новых к старым); просмотр
  содержимого любой версии доступен read-only; откат к версии возвращает ее
  контент как СНОВА последнюю версию (создается новая запись в
  `page_versions`; история не переписывается и не удаляется).
- **FR-114** (Must): Поиск по wiki: авторизованный пользователь ищет
  подстрокой по заголовку И тексту страниц (SQL LIKE через API монолита);
  результаты — список страниц (заголовок, путь в иерархии, фрагмент с
  подсветкой совпадения); поиск НЕ по версиям — только по текущему контенту
  (ОВ-3); индексация в search-сервис — вне скоупа (решение 4).
- **FR-115** (Must): Права (решение 7): любая авторизованная сессия (owner,
  wife) читает и редактирует все страницы wiki и версии — без разделения прав;
  анонимный запрос страницы — редирект на `/login`, анонимный вызов API — 401.
- **FR-116** (Should): Удаление страницы: авторизованный пользователь удаляет
  страницу после подтверждения; удаление страницы, у которой есть дочерние,
  ЗАПРЕЩЕНО до их переноса/удаления (дефолт по ОВ-2). Удаление самой страницы
  не удаляет файлы изображений в галерее.

## 4. Нефункциональные требования (NFR)

- **NFR-30** (Must): Производительность: ответы wiki-API (открытие страницы,
  дерево, список версий) p95 < 300 мс, поиск p95 < 500 мс — на корпусе до
  1000 страниц / 10 000 версий (эталон порога поиска — формулировка FR-спеки
  поиска).
- **NFR-31** (Must): Безопасность: контент страниц — HTML из редактора; при
  отображении применяется серверная санитизация по whitelist тегов/атрибутов
  редактора (FR-110) — скрипты, обработчики on* и внешние embed не проходят;
  сессионные куки — как у доски (Secure в проде, паттерн `board.py`).
- **NFR-32** (Must): Миграция `pages` + `page_versions` — по паттерну
  `app.migrate_gallery`: идемпотентно (CREATE TABLE/INDEX IF NOT EXISTS), все
  DDL в одной явной транзакции BEGIN IMMEDIATE, автосверка схемы (exit 1 при
  расхождении), обязательная репетиция на копии прод-БД до боевой накатки
  (правило deploy-спеки, урок Р4).
- **NFR-33** (Must): Фронтенд без внешних зависимостей (ОГР-8): редактор,
  дерево, история — vanilla JS; вид — на дизайн-токенах V3 «Бумага»
  (app.css :root, без хардкода цветов); работа редактора проверяется в
  актуальных Chrome и Firefox.
- **NFR-34** (Must): Изображения в контенте переиспользуют лимиты
  images-сервиса (NFR-21: ≤ 10 МБ, JPEG/PNG/GIF/WebP, 422 при нарушении) —
  новые лимиты и хранение в wiki НЕ вводятся.

## 6. Ограничения

- Wiki живет в монолите app :8377 (решение 1) — НОВЫЙ контейнер/сервис не
  создается; таблицы — в общей `wiki.db` (ядро мигрирует, паттерн
  migrate_gallery).
- Редактор — contenteditable, vanilla JS (решение 2): без ProseMirror/Quill и
  любых внешних CDN/сборщиков (ОГР-8).
- Изображения — только через существующий images-сервис (`POST /api/images`,
  раздача `/images/{id}` через nginx; решение 3); в БД wiki — только HTML
  контента со ссылками.
- Поиск — LIKE по заголовку+тексту через API монолита (решение 4);
  search-сервис не трогаем.
- Права — как у доски (решение 7): паттерн `board.py`, сессионные куки.
- Вид страниц/редактора — по мокапам ui_designer, утвержденным Заказчиком ДО
  dev (Д-паттерн Р4/Р5, прецедент галереи); после dev соответствие проверяет
  design_validator.
- Спека navigation модифицируется (снятие Won't по FR-13/wiki) + новый домен
  `openspec/specs/wiki/` — оформление дельт на этапе openspec-авторинга.
- Тесты: pytest+requests (API), playwright (web); стенды на явных портах (E7).

## 7. Открытые вопросы

Максимум один раунд; по непринципиальным пунктам БА зафиксировал дефолт —
Заказчик имеет право возражения до утверждения (молчание = согласие с
дефолтом). Ответы — в `docs/ba/answers_round1.md`.

- **ОВ-1** (дефолт: `/wiki/{id}`, числовой id; slug-адреса НЕ вводим): схема
  URL страниц. Влияет только на красоту адресов, функционал не меняет.
- **ОВ-2** (дефолт: удаление запрещено, пока у страницы есть дочерние —
  FR-116 Should): поведение удаления страницы с поддеревом. Альтернатива —
  каскадное удаление поддерева с подтверждением.
- **ОВ-3** (дефолт: поиск только по текущему контенту, не по версиям): охват
  поиска. Зафиксировано в FR-114.
- **ОВ-4** (дефолт: отдельная «главная страница» wiki НЕ вводится; `/wiki`
  показывает дерево от корневых страниц): нужна ли фиксированная точка входа
  (home page), на которую попадает пользователь из сайдбара.
