# weather-ui Specification

## Purpose
Погодный интерфейс: отображение погоды на дашборде с обновлением и обработкой недоступности сервиса.

## Requirements

### Requirement: Экран «Погода» в стиле «Пульт» (FR-127)

Экран «Погода» MUST следовать токенам «Пульт» и mission-control-приемам
итерации 2 при неизменной действующей функциональности сервиса погоды:
страница — pagehead с h1 и терминальным readout; карточка текущей погоды —
панель с HUD-уголками и крупным mono-значением температуры; параметры —
микро-лейблами капсом с mono-значениями; прогноз — ряд/таблица на токенах;
экстремальные значения могут подсвечиваться статусными цветами, не декоративно.
DOM-хуки экрана сохраняются (ОГР-28).

#### Scenario: Текущая погода как readout панели

- **GIVEN** сервис погоды возвращает актуальные данные
- **WHEN** открывается экран «Погода»
- **THEN** карточка — панель `--p-bg-100` с HUD-уголками, температура крупно
  mono (`--font-size-display`), параметры (ветер, влажность, давление) —
  микро-лейблами капсом с mono-значениями; readout в pagehead (точка
  наблюдения, время обновления, teal-LED); вид соответствует токенам «Пульта»

#### Scenario: Ошибка/пустые данные в стиле «Пульта»

- **GIVEN** сервис погоды недоступен или данных нет
- **WHEN** открывается экран «Погода»
- **THEN** существующее сообщение о недоступности отображается на токенах
  (`--status-error`, AA), без «поломанной» верстки

#### Scenario: Тесты погоды без цветовых правок проходят

- **GIVEN** редизайн применен
- **WHEN** прогоняется test_weather_ui (нецептовые и нецветовые ассерты)
- **THEN** проходит без правок селекторов
