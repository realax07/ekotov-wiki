# board Specification

## Purpose
Канбан-доска: три столбца (Ожидает, В работе, Выполнено), выделенная fast line сверху, группировка и сортировка, подсветка быстрой линии в UI.

## Requirements

### Requirement: Отображение канбан-доски

Приложение MUST показывать авторизованному пользователю страницу канбан-доски со всеми задачами, разложенными по столбцам (FR-1). На каждой карточке задачи (все столбцы и fast line) MUST отображаться исполнитель (assigned) и создатель (creator) (FR-45): при назначенном исполнителе — имя пользователя; при пустом assigned — строка исполнителя отображается всегда, курсивом «Unassigned» (ОВ-24). При наведении курсора на карточку MUST появляться всплывашка (tooltip) с assigned и creator задачи (FR-44) — единый механизм всплывашек с tooltip'ом профиля (ОГР-17); при системной настройке уменьшения движения анимации всплывашки MUST отключаться (ОГР-17).

#### Scenario: Открытие доски с задачами

- **GIVEN** пользователь авторизован и в системе есть задачи в разных столбцах
- **WHEN** пользователь открывает страницу доски
- **THEN** все задачи отображаются в столбцах, соответствующих их текущему статусу; на каждой карточке отображаются assigned и creator (FR-45)

#### Scenario: Открытие пустой доски

- **GIVEN** пользователь авторизован и в системе нет ни одной задачи
- **WHEN** пользователь открывает страницу доски
- **THEN** доска отображается с тремя пустыми столбцами без ошибок

#### Scenario: Строка исполнителя на карточке без assigned

- **GIVEN** существует задача без исполнителя (assigned пуст, ОВ-23/nullable FR-37)
- **WHEN** пользователь открывает доску
- **THEN** на карточке этой задачи строка исполнителя отображается всегда, курсивом «Unassigned» (ОВ-24)

#### Scenario: Строка исполнителя на карточке с assigned

- **GIVEN** существует задача с назначенным исполнителем
- **WHEN** пользователь открывает доску
- **THEN** на карточке отображается имя исполнителя (FR-45)

#### Scenario: Tooltip карточки показывает assigned и creator

- **GIVEN** пользователь авторизован; существует задача с creator «owner» и исполнителем «wife»
- **WHEN** пользователь наводит курсор на карточку задачи
- **THEN** появляется всплывашка с assigned («wife») и creator («owner») задачи (FR-44)

#### Scenario: Единый механизм всплывашек

- **GIVEN** на доске есть карточки задач; блок профиля внизу сайдбара присутствует
- **WHEN** пользователь наводит курсор на карточку и на блок профиля
- **THEN** обе всплывашки выполнены одним и тем же механизмом (ОГР-17)

#### Scenario: Уменьшение движения отключает анимации всплывашек

- **GIVEN** в системе пользователя включена настройка уменьшения движения (prefers-reduced-motion)
- **WHEN** пользователь наводит курсор на карточку и на блок профиля
- **THEN** всплывашки появляются без анимации; содержание всплывашек не изменяется (ОГР-17, TC-vis-105)

### Requirement: Три фиксированных столбца
Доска MUST содержать ровно три столбца: «Ожидает», «В работе», «Выполнено» (FR-2). Состав столбцов MUST быть неизменяемым пользователем (ОГР-3).

#### Scenario: Состав столбцов доски
- **GIVEN** пользователь авторизован
- **WHEN** пользователь открывает страницу доски
- **THEN** доска содержит ровно три столбца с названиями «Ожидает», «В работе», «Выполнено» и никакие другие

### Requirement: Столбец «Выполнено» показывает задачи текущего МСК-дня
Столбец «Выполнено» MUST отображать задачи в статусе done, момент перевода которых в done приходится на текущий календарный день по МСК (UTC+3). Задачи, выполненные в предыдущие календарные дни по МСК, MUST НЕ отображаться на доске (автоархивация, FR-4). Архивные задачи MUST НЕ отображаться ни в одном столбце (без изменений).

#### Scenario: Выполненная сегодня задача видна в столбце «Выполнено»
- **GIVEN** пользователь авторизован и сегодня по МСК перевел задачу в «Выполнено»
- **WHEN** пользователь открывает страницу доски
- **THEN** задача отображается в столбце «Выполнено»

#### Scenario: Выполненная вчера задача не видна на доске
- **GIVEN** пользователь авторизован и задача была переведена в «Выполнено» вчера по МСК (или ранее)
- **WHEN** пользователь открывает страницу доски
- **THEN** задача отсутствует во всех столбцах доски (архивирована автоматически)

### Requirement: Перемещение задач между столбцами
Пользователь MUST иметь возможность перемещать задачу между столбцами «Ожидает» → «В работе» → «Выполнено» и обратно (FR-6). Перевод в «Выполнено» НЕ удаляет задачу с доски: она остается в столбце «Выполнено» до следующего календарного дня по МСК, после чего автоматически архивируется (FR-4; изменение Заказчика).

#### Scenario: Прямое перемещение по цепочке столбцов
- **GIVEN** задача находится в столбце «Ожидает»
- **WHEN** пользователь перемещает задачу в «В работе», затем в «Выполнено»
- **THEN** задача последовательно занимает целевые столбцы и остается видимой в столбце «Выполнено»

#### Scenario: Обратное перемещение
- **GIVEN** задача находится в столбце «В работе»
- **WHEN** пользователь перемещает задачу обратно в «Ожидает»
- **THEN** задача отображается в столбце «Ожидает»

### Requirement: Быстрый доступ к действию «Выполнено»
Перевод задачи в «Выполнено» MUST быть доступен из любого столбца доски (FR-4); действие завершает рабочий цикл задачи — задача остается в столбце «Выполнено» до автоархивации следующим МСК-днем.

#### Scenario: Завершение задачи из столбца «Ожидает»
- **GIVEN** задача находится в столбце «Ожидает»
- **WHEN** пользователь выполняет действие перевода задачи в «Выполнено»
- **THEN** задача занимает столбец «Выполнено» (без прохода через промежуточный столбец) и остается на доске до наступления следующего календарного дня по МСК

### Requirement: Перемещение карточки перетаскиванием (drag-and-drop)

Пользователь MUST иметь возможность переместить карточку задачи между столбцами доски перетаскиванием мышью (FR-31, ОВ-19): при зажатии карточка прикрепляется к курсору и исчезает с исходного места на доске; при отпускании над столбцом карточка попадает в этот столбец; при отпускании вне зоны столбца (зона-приемник отсутствует) карточка возвращается на исходное место, статус задачи НЕ меняется. Результат перетаскивания MUST быть равнозначен переводу задачи существующим способом: применяются те же серверные проверки, правила столбцов, fast line (ОГР-5) и архивации (FR-4) — серверные правила перетаскиванием не меняются (ОГР-14). Перетаскивание MUST быть доступно мышью на десктопе; на touch-устройствах перенос задачи остается прежним способом (ОВ-19: «принимаю»). Отпускание fast-карточки в активную фазу («Ожидает»/«В работе») при занятой fast line MUST отклоняться сервером (409) с показом ошибки в UI и возвратом плитки на исходное место (Д-6).

#### Scenario: Перетаскивание карточки в другой столбец

- **GIVEN** пользователь авторизован; задача находится в столбце «Ожидает»
- **WHEN** пользователь зажимает карточку мышью и отпускает ее над столбцом «В работе»
- **THEN** карточка прикрепляется к курсору и исчезает с исходного места при зажатии, а после отпускания отображается в столбце «В работе»; статус задачи изменен так же, как при переводе существующим способом

#### Scenario: Отпускание вне зоны столбца возвращает карточку

- **GIVEN** пользователь зажал карточку мышью (карточка прикреплена к курсору, с исходного места исчезла)
- **WHEN** пользователь отпускает карточку вне зоны какого-либо столбца
- **THEN** карточка возвращается на исходное место, статус задачи не меняется

#### Scenario: Результат перетаскивания равнозначен переводу прежним способом

- **GIVEN** пользователь авторизован; в активных статусах находится fast-задача (fast line занята)
- **WHEN** пользователь перетаскивает другую задачу с флагом fast в активную фазу («Ожидает»/«В работе»)
- **THEN** сервер отклоняет перевод (409), UI показывает ошибку, плитка возвращается на исходное место; инвариант «не более одной fast-задачи в активных статусах» сохранен (Д-6)

#### Scenario: Перетаскивание в «Выполнено» подчиняется правилам архивации

- **GIVEN** пользователь авторизован; задача находится в столбце «В работе»
- **WHEN** пользователь перетаскивает карточку в столбец «Выполнено»
- **THEN** результат тот же, что при переводе существующим способом: задача остается в столбце «Выполнено» до автоархивации следующим МСК-днем (FR-4, ОГР-14)

#### Scenario: На touch-устройстве перенос выполняется прежним способом

- **GIVEN** пользователь открывает доску на устройстве с сенсорным экраном (touch)
- **WHEN** пользователь переносит задачу между столбцами
- **THEN** перенос выполняется прежним способом (существующим элементом управления); touch-перетаскивание не требуется (ОВ-19)

### Requirement: Визуальные эффекты доски поверх токенов V3

Доска MUST быть оформлена визуальными эффектами и стилями поверх действующих дизайн-токенов V3 «Бумага» (FR-32, ОГР-12 — эффекты являются надстройкой над токенами, а не новой темой). Обязательный минимум: hover-переходы карточек и оформленный пустой state пустого столбца. При утвержденном Заказчиком пресете (выбор из 2–3 пресетов ПМ, ОВ-20) — полный состав пресета: плавное отображение перемещения карточки между столбцами, связанное с перетаскиванием (карточка не «телепортируется», а перемещается видно), анимация появления карточек, тени/глубина. При включенной у пользователя системной настройке уменьшения движения анимации MUST отключаться.

#### Scenario: Обязательный минимум — hover-переходы карточек

- **GIVEN** пользователь авторизован и на доске есть карточки
- **WHEN** пользователь наводит курсор на карточку
- **THEN** карточка визуально реагирует на наведение (hover-переход по токенам V3)

#### Scenario: Обязательный минимум — оформленный пустой state столбца

- **GIVEN** пользователь авторизован; один из столбцов доски не содержит задач
- **WHEN** пользователь открывает доску
- **THEN** пустой столбец отображается с оформленным пустым state («красивый пустой state» — слово Заказчика), а не как пустая неоформленная область

#### Scenario: Плавное перемещение карточки по пресету

- **GIVEN** утвержден пресет эффектов с плавным перемещением; пользователь авторизован
- **WHEN** пользователь перемещает карточку между столбцами (перетаскиванием или прежним способом)
- **THEN** карточка перемещается между столбцами плавно и видимо, без мгновенного «телепорта»

#### Scenario: Анимация появления карточек по пресету

- **GIVEN** утвержден пресет эффектов с анимацией появления; пользователь авторизован
- **WHEN** пользователь создает задачу или обновляет доску
- **THEN** карточки появляются с анимацией в рамках утвержденного пресета

#### Scenario: Уменьшение движения отключает анимации

- **GIVEN** в системе пользователя включена настройка уменьшения движения (prefers-reduced-motion)
- **WHEN** пользователь открывает доску и перемещает карточки
- **THEN** анимации эффектов отключены; функциональность доски (столбцы, перемещение, hover-состояние переходов) сохраняется

### Requirement: Просмотр карточки задачи — модальное окно read-only

Просмотр карточки задачи MUST выполняться модальным окном read-only, отличным от форм создания и редактирования (FR-47, решение Заказчика «модальным окном»): все данные задачи — название, описание, приоритет, категория, срок, теги, assigned, creator, комментарии — отображаются только для чтения, без полей ввода и сохранения. Окно просмотра MUST визуально отличаться от форм создания/редактирования на действующих токенах V3 (ОГР-18). Из окна просмотра MUST быть доступен переход к редактированию — кнопка «Редактировать» открывает существующую форму редактирования (Д-9). Клик по карточке открывает окно просмотра; редактирование остается доступным через кнопку «Редактировать» (FR-7 не деградирует).

#### Scenario: Клик по карточке открывает окно просмотра

- **GIVEN** пользователь авторизован; на доске есть задача со всеми заполненными признаками и комментариями
- **WHEN** пользователь кликает по карточке задачи
- **THEN** открывается модальное окно просмотра со всеми данными задачи, включая assigned, creator и комментарии; поля только для чтения — ввод и сохранение недоступны (FR-47)

#### Scenario: Окно просмотра отлично от форм создания/редактирования

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь сравнивает окно с формой создания/редактирования
- **THEN** окно просмотра визуально отлично от форм (ОГР-18) и не содержит элементов редактирования (полей ввода, кнопки сохранения), кроме кнопки «Редактировать» (Д-9)

#### Scenario: Переход к редактированию из окна просмотра

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь нажимает кнопку «Редактировать»
- **THEN** открывается существующая форма редактирования этой задачи; изменения после сохранения отображаются в окне просмотра и на карточке (Д-9, FR-7)

#### Scenario: Окно просмотра отображает assigned, creator и комментарии

- **GIVEN** существует задача с creator, назначенным исполнителем и комментариями
- **WHEN** пользователь открывает окно просмотра этой задачи
- **THEN** в окне отображаются creator, assigned (или «Unassigned») и все комментарии задачи — только для чтения (FR-47)

#### Scenario: Закрытие окна просмотра не изменяет данные

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь закрывает окно (крестик или клик вне окна)
- **THEN** окно закрывается; данные задачи не изменяются; доска отображается в прежнем состоянии (FR-47)
