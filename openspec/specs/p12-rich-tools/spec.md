## Requirements

### Requirement: Спойлер (FR-118)

Редактор MUST позволять вставить спойлер кнопкой тулбара: шапка (шеврон +
название) и зона содержимого. Название MUST переименовываться инлайн.
Сворачивание/разворачивание — кликом по ВСЕЙ шапке, в редакторе и в статье
(ОВ-1). Спойлер MUST вставляться по тексту и в ячейку таблицы (компактный
вариант). Внутри разрешен любой контент, включая другой спойлер, код-блок,
табуляцию, таблицу (design.md §6). Свернутость — состояние отображения:
содержимое MUST сохраняться всегда.

#### Scenario: Вставка и переименование спойлера

- **GIVEN** пользователь авторизован и редактирует страницу в WYSIWYG-редакторе
- **WHEN** пользователь нажимает кнопку «Спойлер» тулбара, кликает по
  названию и вводит «Скрытые детали», затем сохраняет страницу
- **THEN** в статье отображается спойлер с названием «Скрытые детали» и зоной
  содержимого (FR-118, мокап tool-1-spoiler-edit.png)

#### Scenario: Сворачивание и разворачивание кликом по шапке

- **GIVEN** в статье есть спойлер с непустым содержимым
- **WHEN** пользователь кликает в любое место шапки спойлера (не только по
  шеврону — ОВ-1, решение Заказчика 2026-10-20)
- **THEN** спойлер сворачивается (содержимое скрыто, шеврон повернут);
  повторный клик по шапке разворачивает его с тем же содержимым (FR-118)

#### Scenario: Спойлер внутри ячейки таблицы

- **GIVEN** пользователь редактирует таблицу
- **WHEN** пользователь устанавливает курсор в ячейку и вставляет спойлер,
  заполняет и сохраняет страницу
- **THEN** спойлер в ячейке — компактный вариант (без внешних отступов,
  уменьшенный шрифт названия); в статье он сворачивается/разворачивается и
  не ломает раскладку таблицы (FR-118, «вставлялся… например таблицу»)

#### Scenario: Спойлер в спойлере

- **GIVEN** пользователь редактирует спойлер
- **WHEN** пользователь вставляет второй спойлер внутрь зоны содержимого
  первого, заполняет оба и сохраняет
- **THEN** оба спойлера работают независимо: сворачивание внешнего скрывает
  внутренний целиком, разворачивание показывает внутренний с его состоянием;
  контент обоих сохраняется без потерь (FR-118, урок rich-v1 «потеря
  контента при вложении» — не повторяется)

#### Scenario: Свернутый спойлер сохраняет содержимое

- **GIVEN** пользователь свернул спойлер в редакторе
- **WHEN** пользователь сохраняет страницу и переоткрывает её
- **THEN** содержимое спойлера сохранено; при открытии статьи спойлер
  развернут (состояние отображения в контенте не хранится)

### Requirement: Блок кода с подсветкой синтаксиса (FR-119)

Редактор MUST позволять вставить блок кода кнопкой тулбара: черный фон в
рамке, в шапке — выбор языка (python, js, bash, json, sql, plain — ОВ-2) и
кнопка «Копировать». Код MUST подсвечиваться самописным лексером на клиенте
(ОГР-8, design.md §5); нумерация строк — ДА (ОВ-2). «Копировать» — чистый
текст кода. Язык сохраняется с блоком; нераспознанный — plain без потери
текста. Внутри код-блока другие блоки НЕ вставляются; спаны подсветки в
сохраняемом контенте НЕ хранятся.

#### Scenario: Вставка кода с выбором языка и подсветкой

- **GIVEN** пользователь редактирует страницу
- **WHEN** пользователь вставляет блок кода, выбирает язык «python» и вводит
  функцию с ключевыми словами, строкой, числом и комментарием
- **THEN** код отображается с нумерацией строк и подсветкой (ключевые
  слова/строки/числа/функции/комментарии различимы цветом); после сохранения
  в статье — тот же вид (FR-119, мокап tool-2-code-view.png)

#### Scenario: Кнопка «Копировать»

- **GIVEN** в статье есть блок кода
- **WHEN** пользователь нажимает «Копировать»
- **THEN** в буфер обмена попадает чистый текст кода (без нумерации строк и
  спанов); на 1,5 с кнопка показывает «✓ Скопировано» (FR-119)

#### Scenario: Код-блок внутри спойлера

- **GIVEN** пользователь редактирует спойлер
- **WHEN** пользователь вставляет код-блок внутрь зоны содержимого спойлера
- **THEN** блок кода работает внутри спойлера (подсветка, копирование);
  сворачивание/разворачивание спойлера не теряет код (FR-119, FR-118)

#### Scenario: Нераспознанный язык деградирует в plain

- **GIVEN** блок кода имеет язык вне списка подсветки (например, значение
  data-lang повреждено при внешней правке контента)
- **WHEN** статья отображается
- **THEN** код показывается моноширинным без подсветки и без ошибок — текст
  полностью сохранен (FR-119, NFR-39)

### Requirement: Табуляция (FR-120)

Редактор MUST позволять вставить таб-виджет кнопкой тулбара: таб-бар и зона
содержимого активной вкладки. Вкладки MUST переключаться кликом — в
редакторе и в статье. В редакторе: добавление («+»), удаление (крестик;
последнюю вкладку удалить нельзя), переименование двойным кликом. Лимит —
8 вкладок; переполнение таб-бара — горизонтальный СКРОЛЛ (ОВ-3). Содержимое
вкладок — независимые зоны с любым контентом, включая другие блоки.
Активная вкладка не сохраняется — при открытии активна первая.

#### Scenario: Переключение вкладок в статье

- **GIVEN** в статье есть таб-виджет с тремя заполненными вкладками
- **WHEN** пользователь кликает по второй вкладке
- **THEN** активной становится вторая вкладка: подсветка (терракотовая
  черта) перемещается, в зоне содержимого — содержимое именно второй вкладки
  (FR-120, мокап tool-3-tabs-view.png)

#### Scenario: Добавление, переименование и ограничение удаления

- **GIVEN** пользователь редактирует таб-виджет с одной вкладкой «Обзор»
- **WHEN** пользователь добавляет вкладку «+», переименовывает её двойным
  кликом в «Детали», затем пытается удалить вкладку «Обзор»
- **THEN** вкладка создается и переименовывается; удаление единственной
  оставшейся вкладки заблокировано (FR-120)

#### Scenario: Лимит вкладок и переполнение таб-бара

- **GIVEN** пользователь редактирует таб-виджет с восемью вкладками
- **WHEN** пользователь нажимает «+» и вводит длинные названия вкладок
- **THEN** девятую вкладку добавить нельзя (лимит 8); при превышении ширины
  таб-бара вкладки прокручиваются горизонтально — без переноса и без
  выпадающего списка (ОВ-3, решение Заказчика 2026-10-20)

#### Scenario: Табы внутри вкладки

- **GIVEN** пользователь редактирует таб-виджет
- **WHEN** пользователь вставляет второй таб-виджет в содержимое первой
  вкладки, заполняет оба и сохраняет
- **THEN** оба виджета работают независимо в статье; контент всех вкладок
  сохраняется без потерь (FR-120, design.md §6)

### Requirement: H-заголовки как переключатель (FR-121)

Кнопки H1/H2/H3 тулбара MUST работать как переключатели: повторный клик по
активной кнопке снимает форматирование — текст становится обычным абзацем,
не теряясь; клик по соседней кнопке заменяет уровень. Одновременное
действие двух уровней заголовка недопустимо (баг «отжимание H заголовков»
устраняется, PRODUCT_BACKLOG P12 п.4). Backspace в пустом заголовке MUST
снимать формат (ОВ-5, канон Notion/GDocs — решение ПМ 2026-10-20).
Состояние кнопок MUST отражать блок под курсором.

#### Scenario: Повторный клик снимает заголовок без потери текста

- **GIVEN** пользователь редактирует абзац, оформленный как H2
- **WHEN** пользователь повторно нажимает кнопку H2
- **THEN** кнопка отжимается, текст становится обычным абзацем без
  изменений; ни одна кнопка H1/H2/H3 не нажата (FR-121, CLEAR-состояние
  мокапа tool-4-headings.html)

#### Scenario: Замена уровня заголовка

- **GIVEN** пользователь редактирует абзац, оформленный как H1
- **WHEN** пользователь нажимает кнопку H3
- **THEN** абзац становится H3; нажата только кнопка H3 — одновременных
  нажатий нет (DON'T-состояние мокапа невозможно) (FR-121)

#### Scenario: Backspace в пустом заголовке снимает формат

- **GIVEN** курсор стоит в пустом заголовке H2
- **WHEN** пользователь нажимает Backspace
- **THEN** формат снимается: строка становится пустым абзацем с курсором;
  текст не теряется (FR-121, ОВ-5)

#### Scenario: Состояние кнопок отражает позицию курсора

- **GIVEN** пользователь перемещает курсор между абзацами H1, H2 и обычным
- **WHEN** курсор входит в каждый из блоков
- **THEN** нажата ровно одна соответствующая кнопка (для обычного абзаца —
  ни одной) (FR-121)

### Requirement: Редактирование таблиц — строки и столбцы (FR-122)

Для таблицы редактор MUST предоставлять контекстное управление при фокусе
внутри: добавление/удаление строк и столбцов относительно целевой ячейки
(подсветка целевого столбца). Удаление последней строки/столбца ЗАПРЕЩЕНО.
Удаление таблицы целиком — ОТДЕЛЬНОЙ кнопкой (ОВ-4). Tab — следующая
ячейка, Enter — перенос внутри ячейки. Таблица в таблице не вставляется
(design.md §6). Рендер — существующие стили `.article-body table`.

#### Scenario: Добавление и удаление строки и столбца

- **GIVEN** пользователь редактирует таблицу 3×3, курсор в ячейке [2,2]
- **WHEN** пользователь нажимает «+» строк, «+» столбцов, затем «−»
  добавленной строки и «−» добавленного столбца
- **THEN** строки/столбцы добавляются ниже/правее целевой ячейки и
  удаляются обратно; содержимое остальных ячеек не изменилось (FR-122,
  мокап tool-5-table-edit.png)

#### Scenario: Последняя строка и столбец не удаляются

- **GIVEN** таблица 1×1 (единственная ячейка)
- **WHEN** пользователь пытается нажать «−» строки и «−» столбца
- **THEN** контролы неактивны с подсказкой «последняя строка/столбец не
  удаляется»; таблица не исчезает (FR-122)

#### Scenario: Удаление таблицы отдельной кнопкой

- **GIVEN** пользователь редактирует таблицу с заполненными ячейками
- **WHEN** пользователь нажимает отдельную кнопку «Удалить таблицу»
- **THEN** таблица удаляется целиком; остальной контент страницы не
  затронут; после сохранения таблицы в статье нет (FR-122, ОВ-4)

#### Scenario: Навигация и ввод в ячейках

- **GIVEN** курсор в ячейке таблицы
- **WHEN** пользователь нажимает Tab, затем Enter с вводом текста
- **THEN** Tab переводит курсор в следующую ячейку; Enter дает перенос
  строки внутри ячейки (новая строка таблицы не создается); переносы
  отображаются в сохраненной статье (FR-122)

### Requirement: Безопасность и деградация rich-блоков (NFR-39)

Блоки MUST проходить серверную санитизацию по расширенному whitelist'у:
data-атрибуты — фиксированный словарь с валидацией значений (design.md
§1–§2); прочие data-*/on*/style/id снимаются; script/style вырезаются с
содержимым; URL-фильтр прежний. Глубина вложенности ≤5 — глубже блоки
разворачиваются, содержимое сохраняется. Неизвестный/поврежденный блок
MUST деградировать в обычный контент без потери текста и ошибок JS.
Генерируемые id в контенте НЕ хранятся (урок rich-v1).

#### Scenario: Скрипт внутри блока вырезается

- **GIVEN** через вставку HTML в зону спойлера помещен
  `<script>alert(1)</script>` и атрибут `onclick` на шапке
- **WHEN** страница сохраняется и отображается
- **THEN** script отсутствует (с содержимым), onclick снят, сам спойлер
  работает (NFR-39, NFR-31)

#### Scenario: Подмена значений data-атрибутов

- **GIVEN** в контент вручную внесен
  `<div data-block="evil" data-lang="javascript">текст</div>`
- **WHEN** страница сохраняется
- **THEN** невалидные значения сняты: блок деградирует в обычный контент
  «текст», исполнение кода невозможно (NFR-39)

#### Scenario: Глубина вложенности ограничена

- **GIVEN** контент содержит цепочку из 7 вложенных спойлеров
- **WHEN** страница сохраняется и отображается
- **THEN** первые 5 уровней работают как спойлеры; на уровнях 6–7 содержимое
  остается видимым без виджета; текст не потерян (NFR-39)

#### Scenario: Неизвестный блок деградирует без потери контента

- **GIVEN** в контенте блок с неизвестным `data-block="future-widget"`
- **WHEN** статья отображается
- **THEN** содержимое показывается как обычный контент; ошибок в консоли
  нет (NFR-39)

### Requirement: Рендер блоков без внешних зависимостей (NFR-40)

Активация блоков при отображении статьи (спойлеры, табы, подсветка кода)
MUST выполняться локальной статикой — vanilla JS, без запросов к внешним
CDN/доменам (ОГР-8); подсветка — самописный лексер (design.md §5). Статья
с 20 блоками MUST активироваться за ≤150 мс без блокировки UI (крупные
листинги — вне основного потока). Страницы без блоков проходят путь
рендера без изменений.

#### Scenario: Статья с блоками без внешних запросов

- **GIVEN** статья содержит спойлер, код-блок и таб-виджет
- **WHEN** статья открывается с включенным логом сети
- **THEN** все запросы — к собственному origin; подсветка и интерактив
  работают (NFR-40, ОГР-8)

#### Scenario: Активация не блокирует отображение статьи

- **GIVEN** статья с 20 блоками, среди них код-блок на 1000+ строк
- **WHEN** статья открывается
- **THEN** текст статьи отображается до завершения подсветки; активация
  блоков укладывается в ≤150 мс без «заморозки» прокрутки (NFR-40)

#### Scenario: Статья без блоков не меняет поведение

- **GIVEN** существующая статья без rich-блоков (до P12)
- **WHEN** статья открывается после релиза
- **THEN** отображение идентично прежнему (регресс, NFR-40)
