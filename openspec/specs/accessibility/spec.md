## Requirements

### Requirement: Контраст WCAG 2.1 AA на токенах «Пульт» (NFR-41)

Все текстовые пары «текст/фон» фронта MUST иметь контраст ≥ 4.5:1 (WCAG 2.1
AA) на токенах «Пульт». Проверка MUST выполняться программно (скрипт
WCAG-формулы) при переносе токенов и в QA. Текст на янтарных заливках —
`--p-bg-000` (цвет `--color-text-on-accent`).

#### Scenario: Программная проверка всех пар

- **GIVEN** токены «Пульта» перенесены в app.css
- **WHEN** скрипт контраста прогоняет все текстовые пары токенов и ключевые
  составные поверхности (hover-подложки, бейджи, кнопки)
- **THEN** каждая пара ≥ 4.5:1 (эталон README redesign-pro §Верификация:
  text-900 15.4:1, text-600 8.87:1, text-500 5.98:1 на bg-000; янтарь 9.86:1,
  cyan 10.7:1, статусные ≥ 6.67:1); REPORT с числами приложен к волне

#### Scenario: Подписи на hover-подложке не проседают

- **GIVEN** карточка задачи с мета-подписью text-500
- **WHEN** курсор наведен (подложка bg-300)
- **THEN** подпись переключается на text-600 (5.6:1 — паттерн мокапа
  `.task:hover .task-meta`), контраст ≥ 4.5:1

### Requirement: Фокус с клавиатуры — cyan-фокус-ринг (NFR-42)

Любой интерактивный элемент MUST показывать видимый фокус ТОЛЬКО при
клавиатурной навигации (`:focus-visible`): `outline` отключен, вместо него
`--focus-ring` (двойное кольцо: bg-000 2px + cyan 4px + мягкое cyan-свечение)
и радиус 4px; `::selection` — cyan фон с текстом bg-000. Мышной клик НЕ
показывает фокус-ринг (семантика focus-visible), таб-навигация последовательно
проходит все интерактивные элементы без ловушек (действующее поведение
сохраняется).

#### Scenario: Таб-навигация видит фокус

- **GIVEN** пользователь навигирует табом по сайдбару и доске
- **WHEN** фокус попадает на пункт меню, кнопку, поле, спойлер
- **THEN** каждый элемент показывает cyan-фокус-ринг `--focus-ring`; порядок
  табов логичный, skip-link — первый

#### Scenario: Клик мышью без ринга

- **GIVEN** пользователь кликает мышью по кнопке «Новая задача»
- **WHEN** кнопка получает фокус
- **THEN** cyan-ринг не отображается (focus-visible не сработал), действие
  выполняется

### Requirement: prefers-reduced-motion (NFR-43)

При `prefers-reduced-motion: reduce` MUST отключаться вся анимация и переходы
фронта (blink LED, трек отсчета, hover-переходы, модальные анимации):
`* { animation: none !important; transition: none !important }` — паттерн
мокапа. Информативность не должна теряться: состояние, которое передавалось
миганием (LED «в работе», метка фастлайна), остается различимым цветом/свечением.

#### Scenario: Сокращенное движение отключает анимации

- **GIVEN** ОС пользователя установила prefers-reduced-motion: reduce
- **WHEN** открывается доска с fast-задачей и LED-статусами
- **THEN** ни один элемент не анимируется (blink/transition отключены);
  LED «в работе» и фастлайн различимы статично (цвет + свечение)

### Requirement: Skip-link (NFR-44)

Первым фокусируемым элементом каждой страницы MUST быть skip-link («К
основному содержимому» — на главный контент раздела): вне фокуса — за
пределами экрана, при фокусе — появляется в левом верхнем углу (bg1-панель,
видимый текст AA, z-index над контентом); активация переводит фокус на
основной контент (мокап: `.skip`, href на якорь главной секции).

#### Scenario: Skip-link первый в таб-порядке

- **GIVEN** открыта любая страница фронта
- **WHEN** пользователь нажимает Tab первый раз
- **THEN** появляется skip-link; Enter переводит фокус в основной контент,
  минуя сайдбар

#### Scenario: Skip-link невидим без фокуса

- **GIVEN** страница загружена, фокуса нет
- **WHEN** страница отображается
- **THEN** skip-link не виден (вынесен за экран), не мешает верстке и
  не считывается как видимый контент
