# navigation Specification

## Purpose
Навигация приложения сайдбаром: доска, поиск, wiki (заглушка todo), настройки; редирект неавторизованных на /login.


## Requirements

### Requirement: Навигация через сайдбар
Навигация по функционалу системы MUST выполняться через сайдбар (FR-13): сайдбар содержит разделы (доска, вкладка поиска и другие разделы) и доступен на страницах функционала для авторизованного пользователя.

#### Scenario: Переход на доску через сайдбар
- **GIVEN** пользователь авторизован и находится на любой странице функционала
- **WHEN** пользователь выбирает в сайдбаре раздел «Доска»
- **THEN** открывается страница канбан-доски

#### Scenario: Переход на вкладку поиска через сайдбар
- **GIVEN** пользователь авторизован и находится на странице доски
- **WHEN** пользователь выбирает в сайдбаре раздел поиска
- **THEN** открывается вкладка поиска по старым задачам

#### Scenario: Сайдбар доступен со всех страниц функционала
- **GIVEN** пользователь авторизован
- **WHEN** пользователь открывает любую страницу функционала (доска, поиск)
- **THEN** сайдбар отображается и позволяет перейти в любой другой раздел

### Requirement: Пустой раздел Wiki с пометкой todo
Сайдбар MUST содержать раздел «Wiki» — пустой, с пометкой todo (FR-13). Wiki-функционал в этом релизе MUST отсутствовать (Won't): раздел не предоставляет функций создания/редактирования страниц и поиска по статьям.

#### Scenario: Раздел Wiki отображается как заглушка
- **GIVEN** пользователь авторизован и видит сайдбар
- **WHEN** пользователь просматривает сайдбар
- **THEN** в сайдбаре присутствует раздел «Wiki» с пометкой todo

#### Scenario: Раздел Wiki не дает wiki-функций
- **GIVEN** пользователь авторизован
- **WHEN** пользователь выбирает раздел «Wiki» в сайдбаре
- **THEN** wiki-страницы создать, редактировать или найти нельзя — раздел не предоставляет никаких функций (заглушка)

### Requirement: Раздел «Настройки» в сайдбаре

Сайдбар MUST содержать раздел «Настройки», расположенный внизу слева, рядом с кнопкой выхода (FR-23). Раздел MUST открывать страницу настроек, доступную только авторизованным пользователям.

#### Scenario: Раздел настроек отображается внизу слева

- **GIVEN** пользователь авторизован и находится на любой странице функционала
- **WHEN** пользователь просматривает сайдбар
- **THEN** в сайдбаре присутствует раздел «Настройки», расположенный внизу слева, рядом с кнопкой выхода

#### Scenario: Переход в настройки через сайдбар

- **GIVEN** пользователь авторизован и видит сайдбар
- **WHEN** пользователь выбирает раздел «Настройки»
- **THEN** открывается страница настроек

#### Scenario: Раздел настроек доступен со всех страниц функционала

- **GIVEN** пользователь авторизован
- **WHEN** пользователь открывает любую страницу функционала (доска, поиск, настройки)
- **THEN** раздел «Настройки» отображается в сайдбаре и позволяет перейти на страницу настроек

### Requirement: Профиль текущего пользователя внизу сайдбара

Сайдбар MUST содержать внизу блок профиля текущего пользователя (FR-33): цветной кружок с первой буквой логина и текстовой подписью — логин пользователя целиком (Д-7). Текущий пользователь MUST определяться через `GET /api/auth/me` (FR-33). Аватарки-файлы и смена пароля MUST отсутствовать (дословное исключение Заказчика, ОГР-13, Won't); настройка профиля (display_name и прочее) MUST отсутствовать (за границей P3-минимум). Блок профиля MUST быть доступен на всех страницах функционала для авторизованного пользователя.

#### Scenario: Профиль отображается внизу сайдбара

- **GIVEN** пользователь авторизован (логин «owner») и находится на любой странице функционала
- **WHEN** пользователь просматривает сайдбар
- **THEN** внизу сайдбара отображается профиль: цветной кружок с буквой «o» (первая буква логина) и подпись с логином «owner» целиком (Д-7)

#### Scenario: Профиль показывает сессионного пользователя

- **GIVEN** второй пользователь (жена владельца) авторизован в своей сессии
- **WHEN** второй пользователь открывает любую страницу функционала
- **THEN** внизу сайдбара отображается профиль второго пользователя — кружок с первой буквой и подпись с логином его сессии (не логин другого пользователя)

#### Scenario: В профиле нет аватарок-файлов и смены пароля

- **GIVEN** пользователь авторизован и просматривает блок профиля
- **WHEN** пользователь осматривает доступные действия блока профиля
- **THEN** блок профиля не содержит загрузки/выбора аватарки-файла и смены пароля; настройка профиля отсутствует (ОГР-13, Won't)

#### Scenario: Профиль не нарушает верстку сайдбара

- **GIVEN** пользователь авторизован и находится на странице настроек (внизу сайдбара — раздел «Настройки» и кнопка выхода)
- **WHEN** пользователь просматривает сайдбар
- **THEN** блок профиля размещен внизу сайдбара и не вытесняет существующие разделы (доска, поиск, Wiki, настройки, выход)
