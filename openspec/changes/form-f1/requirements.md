# PLAN-FORM-F1 — Переработка карточки создания/редактирования задач по мокапу F1 «Быстрый поток»

Заказчик утвердил вариант F1 из design-forge/extra/form-v1/ (create.html/edit.html —
десктоп-модалка 720px + мобильный bottom-sheet).

## Флоу: 2 (правки формы + QA)

Объем: одна форма (создание/редактирование), визуальный/UX-слой, контракты полей
сохраняются.

## Состав

- **UX-улучшения (из мокапа F1)**:
  - заголовок — крупное поле с автофокусом и счётчиком 0/500
  - приоритет — визуальный СЕГМЕНТ из 3 кнопок (Низкий/Средний/Высокий) поверх
    СОХРАНЕННОГО нативного select (контракт task-form.js 4.5 и e2e — select скрытый,
    сегмент синхронизирует его значение)
  - срок — quick-чипы (Сегодня/Завтра/+7/Календарь) поверх нативного date-инпута
  - категория + исполнитель — 2 селекта в одну строку (десктоп)
  - фастлайн — тумблер-карточка с подписью гейта (контракт 409 «fast line занята» —
    в task-form-error как раньше)
  - ошибки — инлайн под полями (красная рамка + текст), сумма не нужна
  - подсказка под названием — НЕЙТРАЛЬНЫЙ цвет (не красный — правка дефекта мокапа)
  - липкий футер: Отмена (тихая) + Сохранить (золото); в редактировании — «Удалить»
- **Мобильный bottom-sheet** (≤760px): грейб, поля стёком, липкий футер — по эталону
- **Режимы**: создание и редактирование (edit: заголовок «Редактирование», предзаполнение,
  кнопка «Удалить» в футере)

## Не трогается

- Контракты полей (id/name), валидация 422 категории, 409 фастлайна, API
- Комментарии ( живут в карточке просмотра, не в форме)
- task-form.js логика отправки — меняется только рендер/синхронизация сегмента и чипов

## Тесты

- Контракт-тесты task-form (нативный select, 422/409) — должны остаться зелёными
- Правка: только визуальные ассерты (радиусы, классы сегмента, счётчик)
- Прогон: тесты формы + fastline + мобильные сьюты

## Критерии готовности

- Форма соответствует мокапу F1 в обеих темах на 1440 и 390 (browser-сверка)
- Контракт-тесты зелёные, regress затронутых сьютов зелёный
