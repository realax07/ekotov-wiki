## 1. Общее описание

Адаптивная верстка mobile-first для всех разделов wiki: представление
существующего отполированного UI (r8-polish, токены V3) на телефоне, без
новых функций. Первичный брейкпоинт — **≤480px** (телефон portrait,
минимальный вьюпорт **375px** — iPhone 11, ОВ-6); **768px** — вторичная
утилитарная ветка «не разваливается» (Z Fold 7 раскрытый трактуется так же,
ОВ-5/ОВ-6). Состав: бургер/drawer-навигация (переиспользует существующий
`.sidebar`), доска со свайпом колонок scroll-snap, fullscreen-модалка тикета
(просмотр → «Редактировать» одной модалкой), mobile-ветки поиска и настроек,
свайп-листание лайтбокса. Сквозные НФТ: тач-таргеты ≥44px, инпуты ≥16px,
safe-area, без горизонтальной прокрутки страницы на 375px (исключение —
осознанный свайп-контейнер колонок доски, санкция ОВ-3).

Нумерация продолжает сквозную: последние использованные — FR-98, NFR-22
(add-ui-polish-r8).

## 2. Аудитория

Пользователи — оба пользователя системы: владелец (учетка `owner`, iPhone
Galaxy Z Fold 7 — foldable) и жена (учетка `wife`, iPhone 11, 375×812).
Мобильные сценарии (ОВ-1):

- **С1 (Must)** — вечером с телефона глянуть доску и закрыть задачу;
- **С2 (Must)** — быстро найти задачу или wiki-заметку одной рукой;
- **С3 (Should)** — показать фото жене с телефона (галерея вторична);
- **С4 (Should)** — добавить задачу вне дома (модалка тикета);
- **С5 (Could)** — сменить настройки/профиль с телефона.

Исполнители пакета: ui_designer (мокапы, `design/**`), dev (CSS/JS
фронтенда), QA (в т.ч. design_validator), Заказчик (утверждение мокапов +
приемка вживую на проде с телефона). Критерий приемки — как у галереи:
«вживую», не лабораторные метрики.

## 3. Функциональные требования (FR)

- **FR-99** (Must): Каркас мобильной навигации (ОВ-2): на ширинах ≤768px
  сайдбар MUST скрываться и открываться по кнопке-бургеру в шапке как
  выезжающая панель (drawer) с затемнением подложки; навигация ДОЛЖНА
  переиспользовать существующий DOM `.sidebar` (без дублирования
  навигации); закрытие — выбор пункта, клик по подложке, повторный бургер
  или Esc; сцена MUST занимать всю ширину вьюпорта.
- **FR-100** (Must): Индикация активного раздела на мобиле: при закрытой
  навигации пользователь MUST видеть, в каком разделе находится (заголовок
  в шапке или активная метка); активность ДОЛЖНА быть читаема на 375px.
- **FR-101** (Must, санкция ОВ-3 на дельту FR-62): Доска ≤480px: колонки
  MUST располагаться горизонтально с фиксированной шириной (~80–85vw) и
  листаться свайпом со scroll-snap (snap по колонке) и видимым индикатором
  текущей колонки; горизонтальная прокрутка ограничена контейнером колонок
  (страница вне него MUST оставаться без прокрутки по X); быстрое действие
  «Выполнено» MUST оставаться доступным без drag-and-drop. Тач-DnD не
  входит — перенос карточки на таче через существующие действия.
- **FR-102** (Must, ОВ-4): Модалка тикета ≤480px: MUST открываться на весь
  вьюпорт (fullscreen) с шапкой и кнопкой закрытия, скроллом контента;
  просмотр read-only → явное действие «Редактировать» переводит в
  редактирование **в той же fullscreen-оболочке** (одна модалка, паттерн
  Д-9 сохраняется); закрытие возвращает пользователя на прежнее место
  доски.
- **FR-103** (Should): Поиск ≤480px: страница поиска MUST перестраиваться в
  одну колонку (инпут, фильтры, выдача — вертикально, full-width), без
  горизонтальной прокрутки; строка выдачи MUST читаться без обрезки.
- **FR-104** (Should): Настройки/профиль ≤480px: страница настроек и
  настроек пользователя MUST перестраиваться в одну колонку; существующая
  768px-ветка профиля (FR-56) MUST сохраниться без регресса (кроп-виджет
  полнофункционален на таче).
- **FR-105** (Should, ОВ-1/С3): Лайтбокс галереи на тач-устройствах: свайп
  по области изображения MUST листать к следующему/предыдущему изображению
  (порог ~50px, горизонтальный жест); вертикальный скролл панели
  комментариев MUST NOT перехватываться жестом листания; стрелки-зоны и
  клавиатура desktop MUST сохраниться. Зум-жесты (double-tap, pinch) не
  реализуются (anti-scope); нативный pinch браузера сохраняется.
- **FR-106** (Must): Мобильный вид всех разделов — **по мокапам
  ui_designer, утвержденным Заказчиком ДО dev** (дизайн-фаза волна 0,
  преемственность FR-86/FR-90, паттерн Р4/Р5); после dev соответствие
  мокапам проверяет design_validator.

### Уточнение существующих требований (дельты, без переоткрытия)

- **FR-62 / board / tasks** (санкция ОВ-3): формулировка «без горизонтальной
  прокрутки» на ≤480px уточняется — она про **страницу**; осознанный
  свайп-контейнер колонок доски (FR-101) не является нарушением. Форма
  задачи (одна колонка, full-width — действующая ветка) сохраняется,
  дополняется тач-требованиями NFR-23/24.
- **gallery** (FR-83/FR-97): листание кнопками ←/→ и клавиатурой сохраняется;
  свайп (FR-105) — дополнительный способ на тач-устройствах.

## 4. Нефункциональные требования (NFR)

- **NFR-23** (Must): Тач-таргеты: все интерактивные цели на ≤480px (кнопки,
  пункты drawer, зоны листания, кнопки модалок и форм) MUST иметь
  эффективную область ≥44×44px.
- **NFR-24** (Must): Инпуты, textarea, select на ≤480px MUST иметь
  font-size ≥16px — чтобы iOS не включал авто-зум при фокусе (форма тикета,
  поиск, настройки/профиль, комментарий галереи).
- **NFR-25** (Must): Safe-area: контент и фиксируемые панели MUST учитывать
  `env(safe-area-inset-*)` (низ — футер/модалки, бока — notch iPhone).
- **NFR-26** (Must): На минимальном целевом вьюпорте **375px** ни один
  раздел MUST NOT иметь горизонтальной прокрутки **страницы** (portrait);
  исключение — осознанный свайп-контейнер колонок доски (FR-101, санкция
  ОВ-3). На 768px (в т.ч. Z Fold 7 раскрытый) — «не разваливается»: макет
  читаем, все действия доступны, новых планшетных макетов нет (ОВ-5/ОВ-6).
- **NFR-27** (Should): Единая система брейкпоинтов: 480px (мобильный) и
  768px (вторичный) во всех файлах CSS; новые «магические» одноразовые
  ширины не вводятся.
- **NFR-28** (Must): `<meta viewport>` остается единственным источником
  масштабирования: ограничения `user-scalable=no` / `maximum-scale` MUST
  отсутствовать (доступность; нативный pinch сохраняется).
- **NFR-29** (Must): Правки адаптива не деградируют desktop-вид и
  существующее поведение (преемственность NFR-22): все действующие ветки
  (FR-56 — 768px, FR-62 — форма, FR-87…FR-98 r8-polish) сохраняются;
  desktop-регресс — смоук всех разделов на ширине ≥1024px в каждой волне.

## 6. Ограничения

- **ОГР-8**: без внешних файлов/библиотек — свайпы и drawer только на
  нативных событиях touch/pointer и ванильном JS/CSS.
- Адаптив ложится **поверх** существующего UI (токены V3, r8-polish), не
  переписывает его (зависимость P14 ← P12, выполнена).
- Существующие адаптивные ветки (FR-56, FR-62, галерея) — работающее
  поведение: не откатывать, встраивать в единую систему брейкпоинтов.
- Дизайн-фаза обязательна и перва: мокапы — ui_designer (`design/**`),
  утверждение — Заказчик, ревью — design_validator (паттерн Р4/Р5).
- Backend не меняется: только представление (frontend-ассеты и base.html).
- Приемка Заказчиком — «вживую на проде с телефона» (критерий галереи).

- Разделение зон жеста «свайп-листание» и «скролл комментариев» лайтбокса —
  design §5.
