# tasks.md — add-responsive-mobile

Флоу 1 (полный: СА → дизайн → dev → QA → приемка Заказчика). Паттерн
дизайн-фазы Р4/Р5 (преемственность add-gallery-service /
add-netdata-monitoring): мокапы — **ui_designer** (`design/**`), утверждение
мокапов — развилка Заказчика ДО dev, ревью вида — **design_validator**.
Формат задач — sp-writing-plans: задача = наблюдаемый результат + критерий
проверки + зона файлов + трассировка. Правило: 1 задача = 1 сабагент +
независимый ревьюер; ворота — `openspec validate --all --strict` green на
каждом шаге. Зависимости волн: **0 → 1 → (2 ∥ 3 ∥ 4) → 5**; волна 1 — каркас,
от нее зависят все остальные.

## Волна 2. Доска и модалка тикета [M] (после 1.1; может параллелиться с волнами 3/4)

- [ ] 2.1 [M] Dev: доска ≤480px — свайп-колонки со scroll-snap — (а) `board.css` ≤480px: контейнер колонок `flex` + `overflow-x: auto` + `scroll-snap-type: x mandatory`, колонка `flex-basis ~82vw` + `scroll-snap-align: start` (точное значение по мокапу); страница вне контейнера — без прокрутки по X (NFR-26; случайный стек колонок заменяется осознанным контейнером — санкция ОВ-3 на уточнение FR-62); (б) `board/*` JS: индикатор точек — активная точка синхронна scroll-позиции, тап по точке скроллит к колонке (без анимации при `prefers-reduced-motion`, ОГР-17); (в) быстрое «Выполнено» на карточке — тач-таргет ≥44px; тач-DnD не реализуется. Проверка: device-эмуляция 375×812 — три колонки листаются свайпом, прилипание по колонке, индикатор следует; «Выполнено» работает с тача; desktop ≥1024px — доска без изменений. Зона: `frontend/static/css/board.css`, `frontend/static/js/board/*`. (design §3; board MODIFIED: «Канбан-доска на мобильном…»)
- [ ] 2.2 [M] Dev: модалка тикета fullscreen ≤480px — (а) общий fullscreen-контейнер для просмотра (read-only, Д-9) и редактирования: `position: fixed; inset: 0`, шапка с крестиком, скролл тела, подложка `overflow: hidden`; (б) «Редактировать» заменяет содержимое на форму той же оболочки, возврат — в просмотр; закрытие возвращает доску в прежнюю scroll-позицию; (в) фокус инпута — `scrollIntoView` активного поля (клавиатура iOS), поля `font-size ≥16px` (NFR-24), кнопки ≥44px (NFR-23); (г) действующая 480px-ветка формы FR-62 (одна колонка, full-width) сохраняется. Проверка: device-эмуляция 375×812 — создание и просмотр тикета без зума при фокусе полей, клавиатура не перекрывает активное поле, закрытие возвращает на место; Escape/грязная форма (FR-61) работают; desktop — модалки без изменений. ## Ворота и правила

- `openspec validate --all --strict` — green на каждом шаге.
- Дизайн-фаза Р4/Р5: ui_designer (`design/**`) → Заказчик (развилка) → dev
  по мокапам → design_validator. СА/dev мокапы не рисуют; J10: приемка
  мокапа — утверждение Заказчика.
- Волны 1–4 не стартуют без утверждения мокапов 0.1 (прецедент Д-5).
- Правки только внутри @media-веток и мобильных JS-путей; desktop-регресс —
  в каждой dev-задаче (NFR-29).
- Без внешних библиотек (ОГР-8); тач-логика — нативные touch/pointer-события.
- [ops]-задача 5.2 — только с явным участием Заказчика; фиксация приемки —
  протокол (по образцу acceptance-протокола галереи).
