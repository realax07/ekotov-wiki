## 2. Существующие спека-контракты, затронутые адаптивом

- **navigation**: Requirement «Навигация через сайдбар» — мобильного
  поведения нет вовсе; drawer — ADDED-дельта (не ломает desktop-сценарии).
- **board**: «Отображение канбан-доски», «Перемещение… drag-and-drop»,
  «Быстрый доступ к действию „Выполнено"», «Просмотр карточки… read-only»
  (Д-9, FR-47) — модалка просмотра уже с переходом «Редактировать»;
  fullscreen на мобиле — надстройка над Д-9, не новая модель.
- **tasks**: «Формы создания и редактирования по дизайну V3» — сценарий
  «Адаптив одной колонкой на узких экранах» (FR-62, СЦ-9) уже есть; дельта —
  только уточнение «страница ≠ жест-контейнер» + тач-дополнения.
- **search/settings**: mobile-поведения нет — ADDED-дельты.
- **gallery**: «Full-screen просмотр с листанием» (FR-83 + rename FR-97) —
  листание кнопками/клавиатурой; свайп — MODIFIED-дельта (дополнительный
  способ, desktop-способы сохраняются).
- Потолок сквозной нумерации: FR-98, NFR-22 (add-ui-polish-r8) ⇒ пакет
  нумерует FR-99…, NFR-23….

## 3. Альтернативы ключевых решений (замыкание развилок БА)

| Развилка | Альтернативы | Решение (утверждено Заказчиком) |
|---|---|---|
| Р-1 навигация | A: бургер/drawer (один DOM, все 7 пунктов, дешевая QA) vs B: нижний таб-бар (thumb-reach, но дубль навигации, safe-area, [L]) | **A (ОВ-2)** |
| Р-2 доска ≤480px | A: стек колонок (статус-кво, «Выполнено» уезжает за скролл) vs B: свайп-колонки scroll-snap + индикатор (канбан-метафора, родной жест; требует дельты FR-62) | **B (ОВ-3, санкция на дельту дана)** |
| Р-3 модалка тикета | A: fullscreen (паттерн ОС, продолжение 480px-ветки формы) vs B: компактная карточка (тесно на 375px, риск зума, двойной скролл) | **A, просмотр → «Редактировать» одной модалкой (ОВ-4)** |
| Р-4 лайтбокс | A: свайп по изображению + сохранение стрелок vs B: только кнопки | **A, порог ~50px, без зум-жестов (ОВ-1/С3)** |

## 4. Проверка совместимости с ограничениями

- **ОГР-8** (без внешних библиотек): scroll-snap — чистый CSS
  (`scroll-snap-type`/`scroll-snap-align`, деградация к обычному скроллу без
  JS); drawer и свайпы — нативные touch/pointer-события ванильного JS.
  Подтверждено: существующий код (комбобокс, кроп) уже следует этому.
- **Токены V3**: mobile-ветки переиспользуют `:root`-токены app.css; новых
  цветов/шрифтов не вводится.
- **`<meta viewport>`**: проверка NFR-28 — правка не требуется, если
  ограничений масштабирования нет (проверить в волне 1).
- **Playwright device-эмуляция**: web-сьюты уже на playwright
  (`tests/web`), добавление viewport-профилей 375×812/480×800 не требует
  новых зависимостей.

## 5. Риски/неопределенности, передаваемые в design

- Конфликт жестов «свайп картинки vs скролл комментариев» лайтбокса — зоны
  жеста решаются в design §5.
- Поведение scroll-snap на iOS Safari (резиновость, momentum) — проверить в
  device-эмуляции волны 2.
- Клавиатура iOS поверх fullscreen-модалки (visualViewport) — решение в
  design §4.
