# Дельта specs: navigation — мобильная навигация P14

## ADDED Requirements

### Requirement: Мобильная навигация — бургер и drawer

На ширинах вьюпорта ≤768px сайдбар MUST скрываться и открываться по
кнопке-бургеру в шапке как выезжающая панель (drawer) с затемненной
подложкой (ОВ-2, FR-99). Навигация MUST переиспользовать существующий DOM
сайдбара — дублирование списка разделов НЕ допускается. Drawer MUST
закрываться: при выборе пункта, клике по подложке, повторном нажатии бургера
и по Escape. На ≤768px сцена контента MUST занимать всю ширину вьюпорта.
На ширинах >768px вид НЕ меняется (desktop-сайдбар сохраняется, NFR-29).

#### Scenario: Открытие drawer по бургеру

- **GIVEN** пользователь авторизован; ширина вьюпорта ≤768px (проверка
  375×812, device-эмуляция)
- **WHEN** пользователь нажимает кнопку-бургер в шапке
- **THEN** сайдбар выезжает как панель поверх затемненной подложки; все
  разделы (включая footer-зону профиля и Мониторинг для owner) доступны

#### Scenario: Закрытие drawer

- **GIVEN** drawer открыт
- **WHEN** пользователь выбирает пункт ИЛИ кликает по подложке ИЛИ нажимает
  бургер повторно ИЛИ нажимает Escape
- **THEN** drawer закрывается; при выборе пункта выполняется переход в
  соответствующий раздел

#### Scenario: Навигация не дублируется

- **GIVEN** страница открыта на ширине ≤768px
- **WHEN** проверяется DOM мобильного drawer
- **THEN** используется тот же список разделов, что и в desktop-сайдбаре —
  второго независимого списка навигации нет (единый источник, ОВ-2)

#### Scenario: Сцена занимает всю ширину

- **GIVEN** ширина вьюпорта ≤768px
- **WHEN** пользователь открывает любой раздел при закрытом drawer
- **THEN** контент занимает всю ширину вьюпорта — пустой колонки под
  скрытый сайдбар нет

#### Scenario: Desktop-вид не меняется

- **GIVEN** ширина вьюпорта >768px (проверка ≥1024px)
- **WHEN** пользователь работает с любым разделом
- **THEN** сайдбар постоянный, кнопки-бургера нет — вид совпадает с
  существующим desktop-поведением (NFR-29)

### Requirement: Индикация активного раздела на мобильном

При закрытой мобильной навигации пользователь MUST видеть, в каком разделе
находится: заголовок раздела в шапке (или эквивалентная читаемая метка) —
проверяемо на 375px (FR-100). Активный пункт в drawer MUST подсвечиваться
существующим стилем активного раздела.

#### Scenario: Активный раздел читаем при закрытом drawer

- **GIVEN** пользователь авторизован; вьюпорт 375×812; drawer закрыт
- **WHEN** пользователь находится в любом из разделов (доска, поиск, wiki,
  галерея, настройки)
- **THEN** в шапке отображается заголовок текущего раздела, читаемый на
  375px без зума

#### Scenario: Активный пункт в drawer подсвечен

- **GIVEN** пользователь находится в разделе «Поиск» на ширине ≤768px
- **WHEN** пользователь открывает drawer
- **THEN** пункт «Поиск» визуально выделен как активный (существующий стиль
  активного раздела сайдбара)

### Requirement: Мобильный вид разделов по утвержденным мокапам

Мобильный вид всех разделов (каркас, доска, модалка тикета, поиск,
настройки, лайтбокс) MUST соответствовать мокапам ui_designer, утвержденным
Заказчиком ДО dev (дизайн-фаза волна 0, преемственность FR-86/FR-90,
паттерн Р4/Р5); после dev соответствие мокапам проверяет design_validator
(FR-106).

#### Scenario: Мокапы утверждены до dev

- **GIVEN** пакет add-responsive-mobile в dev-фазе
- **WHEN** проверяется история утверждения мокапов
- **THEN** мокапы волны 0 утверждены Заказчиком до старта dev-задач
  (прецедент Д-5); фактический вид сверен design_validator'ом после dev

#### Scenario: Вид совпадает с мокапами

- **GIVEN** мокапы волны 0 утверждены; dev-задачи выполнены
- **WHEN** design_validator сверяет фактический мобильный вид на 375px с
  мокапами
- **THEN** токены, состояния и компоновка соответствуют эталону (вердикт
  approve) либо возвращены на доработку (return) с баг-репортами
