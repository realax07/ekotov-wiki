# Proposal: add-gallery-service

## Change ID

`add-gallery-service`

## Why

Пакет 2 цикла R7 (PLAN-R7.md; решение Заказчика
`decisions/2026-10-05-r7-launch-gallery`, Telegram 2026-10-05):
**сервис изображений «Галерея»**. Вводные Заказчика:

- дословно: **«Нужно реализовать сервис по загрузке и работе с изображениями.
  Он должен содержать категории и теги»**;
- **ОВ-3** = Галерея как **ЧЕТВЕРТЫЙ раздел сайдбара**, не связанная с
  трекером (только общий фронт сайдбара); просмотр «как в галлерее» —
  модальное окно на весь экран, листание (←/→), лайк/дизлайк, скачивание,
  комментарии;
- **ОВ-4** = доступ **общий** (оба пользователя, без разделения прав);
- критерий приемки Заказчика: загрузка, просмотр, лайк, комментарий вживую
  на проде (задача [ops] 2.2);
- дизайн-фаза обязательна (преемственность пакета 1: «Дизайн не забудь» /
  «У нас есть дизайнер», прецедент Д-5).

Прод — матричный контейнерный стек p12-rc1 (compose-проект
`ekotov-wiki-par`: app + frontend/nginx (TLS :10443, единственная наружная
точка) + search + backup + netdata; тома `wiki-data`). Существующие
capabilities: `deploy`, `navigation`, `services`. Новый раздел сайдбара —
в существующей capability `navigation`.

## What Changes

Дельты: **новая capability `gallery`** (сервис изображений: загрузка,
категории/теги, реакции, комментарии, full-screen просмотр) +
**ADDED Requirement в capability `navigation`** (4-й пункт сайдбара для
всех) + **MODIFIED Requirement в capability `deploy`** (лимиты памяти:
+images 128m) + **ADDED Requirement в capability `services`** (второй
профиль данных — сервис-писатель, том `images-data`).

## Scope

### In scope

- Сервис `images` (FastAPI, по образцу `services/search`): порт 8379,
  upload multipart, list с фильтрами категории/тега, get, like/unlike,
  comments CRUD; healthcheck `/api/health`; mem_limit 128m; том
  `images-data` (RW — файлы изображений + превью); общая БД — RW-профиль
  (первый сервис-писатель; таблицы gallery).
- Миграция ядра: новые таблицы gallery (images, image_categories,
  gallery_tags, image_tags, image_reactions, image_comments) — one-shot из
  образа ядра, идемпотентно, с репетицией на копии прод-БД.
- nginx-маршрутизация: `/api/images*` (пара `=` + `^~`, паттерн
  search-семейства, resolver+переменная) → images:8379; отдача файлов
  `/images/` из тома `images-data` (паритет `/avatars/`, кеш-заголовки).
- Фронтенд: страница `/gallery` — сетка превью, фильтры категория/тег,
  форма загрузки (multipart); full-screen модалка с листанием ←/→,
  лайк/дизлайк, скачивание, комментарии — по утвержденным мокапам
  (токены V3 «Бумага», без внешних библиотек).
- Сайдбар: 4-й пункт «Галерея» (после «Wiki») — для всех авторизованных
  (шаблон base.html, не по роли).
- Дизайн-фаза Р4/Р5: [design] ui_designer мокапы → утверждение Заказчиком
  → dev по мокапу → design_validator.
- QA (стенд) и прод-выкатка с миграцией ядра и приемкой Заказчика ([ops]).

### Out of scope

- Удаление изображений, редактирование метаданных после загрузки — не в
  ТЗ; **предложение Заказчику** (нижеследующее, не реализуется без
  решения): удалить изображение мог бы его загрузивший или owner,
  вместе с файлами и метаданными, через кнопку в full-screen просмотре.
- Переименование/удаление категорий галереи — предложение Заказчику
  (создание категорий при загрузке — в скоупе).
- Альбомы/подборки, привязка изображений к задачам трекера — ОВ-3
  («не связана с трекером»).
- Приватность/разделение прав — ОВ-4 («доступ общий»).
- SPA-фреймворки, внешние библиотеки/шрифты/CDN — ОГР-8.
- Изменение существующих маршрутов и поведения трекера — только добавление
  `/gallery`, `/api/images*`, `/images/` и одного пункта сайдбара.

## Impact

- **Код/инфра:** `services/images/**` (новый сервис: app, Dockerfile,
  README), `backend/app/migrate_gallery.py` (миграция таблиц gallery) +
  шаг в `deploy/deploy.sh`/RUNBOOK, `deploy/compose.yaml` +
  `deploy/compose.test.yaml` (сервис images, том images-data),
  `services/frontend/nginx/ekotov-wiki.conf` (+локации `/api/images*`,
  `/images/`), `frontend/templates/base.html` (+пункт сайдбара),
  `frontend/static/**` (страница `/gallery`, модалка, стили).
- **Спеки:** новая `openspec/specs/gallery/` (после архивации), дельта
  navigation (+1 Requirement), дельта services (+1 Requirement), дельта
  deploy (MODIFIED «Лимиты памяти»).
- **Данные:** ядро БД дополняется 6 таблицами gallery (миграция one-shot,
  без изменения существующих); новый именованный том `images-data`.
- **Ресурсы:** +128m лимит; суммарно 1.54 GB при 3.9 GB хоста (design §5).
- **Пользователи:** для обоих — новый раздел сайдбара и галерея; поведение
  существующих разделов не меняется.

## Risks

- **Первый сервис-писатель в общую БД** (search — RO): риск блокировок
  WAL-записи между ядром и images. Смягчение: короткие транзакции,
  busy_timeout, файлы НЕ в БД (том images-data); метаданные — легкие
  записи. Деградация недоступного images — 503 по паттерну search.
- **Миграция ядра** — новый шаг релиза с риском для живой БД: правило
  deploy-спеки (one-shot до подъема, идемпотентность, **репетиция на
  копии прод-БД**) обязательно; откат — пара «код+БД» из пред-деплойного
  бэкапа.
- **Место на диске** (оригиналы + превью в томе images-data): лимит 10
  МБ/файл (NFR-21); масштаб 2 пользователей — риск низкий; контроль
  занятости тома — в смоук/приемку.
- **RAM images** — FastAPI+Pillow в лимите 128m: факт-замер на стенде до
  прод-выкатки (урок «вес меряем по факту»); стабильное превышение —
  эскалация Заказчику до выкатки.
