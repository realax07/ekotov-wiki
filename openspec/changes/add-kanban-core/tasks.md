# Tasks: add-kanban-core

Атомарные задачи; каждая выполнима за одну сессию агента-разработчика. Порядок учитывает зависимости: каркас и auth раньше фич.

## 1. Каркас и инфраструктура

- [x] 1.1 Инициализировать проект: структура репозитория (backend/, frontend/, deploy/), выбранный фреймворк, конфиг с путем к БД вне репозитория, `.gitignore` дополнен `*.db`, `*.sqlite*` (NFR-5). Проверка: пустой каркас стартует и отвечает health-запросом.
- [x] 1.2 Создать схему SQLite (миграция/seed-init): таблицы users, tasks, tags, task_tags, comments, sessions — по модели данных sdd.md. Проверка: скрипт создает БД с нуля, повторный запуск идемпотентен.
- [ ] 1.3 Seed-скрипт заведения 2 пользователей (владелец, жена): интерактивный ввод паролей, запись хешей (не в открытом виде). Проверка: после запуска в users два пользователя, паролей в открытом виде нет.
- [ ] 1.4 Развертывание: systemd-юнит + конфиг nginx (reverse-proxy, TLS Let's Encrypt). Проверка: приложение доступно извне по HTTPS на VPS-заготовке (или локально эмулировано nginx'ом).

## 2. Авторизация (домен auth) — раньше фич

- [ ] 2.1 POST /api/auth/login: проверка логина/пароля (хеш, константное время), выдача сессионного токена в куку HttpOnly/SameSite/Secure, запись сессии в БД. Ошибки: 401 при неверном логине или пароле (единый текст без раскрытия причины). (FR-14, NFR-4, NFR-7)
- [ ] 2.2 Middleware авторизации: все страницы и /api/* (кроме login) требуют валидную сессию; страницы без сессии — редирект на /login, API — 401; TTL со скольжением и продлением; logout (POST /api/auth/logout) удаляет сессию и куку. (FR-14, NFR-7)
- [ ] 2.3 Страница входа (форма логин/пароль, ошибки входа без раскрытия причины) и выход. (FR-14)
