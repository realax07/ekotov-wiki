# Proposal: add-wiki

## Change ID

`add-wiki`

## Why

Пакет **P15 «Wiki-функционал»** — ТЗ `requirements.md` (корень репо), статус
**УТВЕРЖДЕН r1** (Заказчик, Telegram 2026-10-10: «Утверждаю. Не забывай что нам
макеты дизайна нужны» — мокапы дизайн-этапа обязательны для UI-задач пакета).
Раздел «Wiki» сайдбара сегодня — заглушка с пометкой todo (Won't по FR-13,
Requirement «Пустой раздел Wiki с пометкой todo» в `openspec/specs/navigation/spec.md`);
wiki-функции в этом релизе отсутствуют. Все ключевые развилки закрыты 7
решениями Заказчика (2026-10-10, учтены дословно в requirements.md §3);
непринципиальные дефолты ОВ-1…ОВ-4 (URL `/wiki/{id}`, удаление с дочерними
запрещено, поиск только по текущему контенту, без home page) зафиксированы в
`docs/ba/answers_round1.md`.

Продукт — личная wiki на двоих фиксированных пользователей (owner и wife,
доступ **общий** — решение 7). Ключевой наблюдаемый результат: пользователь
из сайдбара попадает в рабочий раздел Wiki — создает иерархию страниц,
редактирует их в WYSIWYG со вставкой изображений из галереи, находит страницы
поиском, видит полную историю правок и откатывается к любой версии.

## What Changes

Wiki-функционал уровня «Confluence-минимум» **в монолите** (приложение :8377,
БЕЗ нового сервиса/контейнера — решение 1): иерархия страниц (дерево по
parent_id, вложенность неограниченная), breadcrumb, WYSIWYG-редактор на
contenteditable (vanilla JS — ОГР-8, решение 2), изображения через
существующий images-сервис (решение 3), LIKE-поиск (решение 4), версии с
откатом (решение 6), общие права по паттерну `board.py` (решение 7). Данные —
таблицы `pages` + `page_versions` в общей `wiki.db`, миграция по паттерну
`app.migrate_gallery` (NFR-32).

Дельты по **2 capability**:

| Группа | Что меняется | Тип дельты | Capability | Источник |
|---|---|---|---|---|
| Сайдбар | Раздел «Wiki» перестает быть заглушкой: пункт ведет на рабочую страницу `/wiki` (дерево) | MODIFIED | navigation | FR-13 → FR-107 (снятие Won't) |
| Wiki-функционал | НОВЫЙ домен: дерево, создание, breadcrumb, WYSIWYG, изображения, версии/откат, LIKE-поиск, права, удаление | ADDED | wiki (новый) | FR-107…FR-116, NFR-30…NFR-34 |

Сквозные NFR: производительность (p95 < 300 мс API, поиск < 500 мс на корпусе
до 1000 страниц — NFR-30), серверная санитизация HTML по whitelist (NFR-31),
миграция идемпотентно + репетиция на копии прод-БД (NFR-32), фронтенд без
внешних зависимостей на токенах V3 «Бумага» (NFR-33), переиспользование лимитов
images-сервиса (NFR-34).

Нумерация продолжает сквозную: последние использованные — **FR-106, NFR-29**
(add-responsive-mobile). Настоящий пакет: FR-107…FR-116, NFR-30…NFR-34.
Полное ТЗ — `requirements.md` этого пакета (статус ставит Заказчик).

Дизайн-фаза (директива Заказчика «Не забывай что нам макеты дизайна нужны»):
мокапы — **ui_designer** (`design/wiki-*.html`, токены V3), утверждение —
развилка Заказчика ДО dev-волн, ревью вида после dev — **design_validator**
(паттерн Р4/Р5, прецедент add-gallery-service).

## Scope

### In scope

- Миграция `pages` + `page_versions` (+ индексы) в общей `wiki.db` — one-shot
  скрипт по паттерну `backend/app/migrate_gallery.py`: идемпотентно
  (CREATE TABLE/INDEX IF NOT EXISTS), одна транзакция BEGIN IMMEDIATE,
  автосверка схемы (exit 1), репетиция на копии прод-БД до боевой накатки.
- Backend-модуль wiki в монолите: REST API страниц, дерева, breadcrumb,
  версий/отката, LIKE-поиска, удаления (Should).
- Серверная санитизация HTML: whitelist тегов/атрибутов редактора (FR-110) —
  собственный sanitizer на `html.parser` stdlib, без внешних библиотек (ОГР-8).
- Фронтенд: страница `/wiki` (список корневых + дерево), просмотр статьи с
  breadcrumb, WYSIWYG-редактор на contenteditable (тулбар FR-110), история
  версий + просмотр версии read-only + откат, поиск внутри раздела Wiki.
- Изображения в контенте: вставка выбором из галереи или загрузкой через
  существующий `POST /api/images`; в контенте — ссылка `/images/{id}`; файлы
  НЕ дублируются в БД wiki.
- Права: обе авторизованные учетки (owner, wife) — равноправно; аноним:
  страница — редирект `/login`, API — 401 (паттерн `board.py`, middleware).
- Дизайн-фаза: мокапы ui_designer → утверждение Заказчиком → dev по мокапам →
  design_validator.
- Тесты: pytest+requests (API), playwright (web), стенды на явных портах (E7).

### Out of scope (Won't, requirements §5)

- Индексация wiki в search-сервис (решение 4 — отдельное будущее решение).
- Отдельный wiki-сервис/контейнер (решение 1 — монолит).
- SPA-фреймворки, внешние редакторы и CDN (ОГР-8, решение 2).
- Глобальный поиск по wiki со страницы «Поиск» (только внутри раздела Wiki).
- Права по страницам/ролям (решение 7 — доступ общий).
- Переименование/слияние страниц; экспорт в PDF/Markdown.
- Поиск по версиям (ОВ-3 — только текущий контент); home page wiki (ОВ-4 —
  `/wiki` показывает дерево от корневых); slug-адреса (ОВ-1 — `/wiki/{id}`).
- nginx/compose/топология — без изменений (новых маршрутов раздачи нет:
  `/images/{id}` уже отдается nginx'ом, страницы идут через монолит).
