# Proposal: coverage-backfill-1

## Change ID

`coverage-backfill-1`

## Why

QA-чистка qa-cleanup-1026
(`test-model/reports/qa-cleanup-1026/REPORT-qa-cleanup.md`, раздел «(г)
Реальные разрывы») зафиксировала реальные разрывы автотест-покрытия: 85
утвержденных кейсов из `test-model/approved/` не имеют автотестов нигде в
репо (проверено полнотекстово), из них 74 — приоритета Must. Решение ПМ по
итогам чистки: написать автотесты отдельным change-пакетом (сами кейсы
утверждены Заказчиком и не пересматриваются).

Цель — добить Must-покрытие: каждый кейс получает тест-файл с TC-ID
маркером, находимым qa-инвентаризацией (маркер = покрытие).

Разрывы по change-источникам (кейсы — источник истины, дословно):

| Группа | Change | Кейсов | Список |
|---|---|---|---|
| A | p12-rich-tools | 39 (32 Must + 7 Should) | TC-rich-001…039 |
| B | p23-fastline | 13 (12 Must + 1 Should) | TC-p23-109…121 |
| C | weather-service | 12 Must | TC-weather-001, 005–008, 015–019, 023, 025 |
| D | add-responsive-mobile | 10 (7 Must + 3 Should) | TC-P14-101…110 |
| E | add-ui-polish-r8 | 11 Must | TC-P12G-003/008–011, P12N-005/008/009, UIP-102/107/114 |

Should-кейсы включены по спискам разрывов отчета; для заведомо
неправтоматизируемых (TC-p23-116 — визуальный ОВ-4) допускается
документированное Should-решение в coverage-отчете F.2 вместо теста.

## What Changes

Дельта: новая capability `autotest-coverage` — один Requirement ADDED
(автотест-покрытие утвержденных Must-кейсов, сценарии по группам A–E) +
трассировка. Никакие существующие capability не модифицируются: поведение
продукта не меняется, меняется только тестовый актив.

Задачи — в `tasks.md`: 85 чек-боксов (по одному на будущий тест-файл) в
пяти группах по change-источникам + прогон и coverage-отчет (группа F).

## Scope

**In:**

- `tests/web/`, `tests/api/`, `services/*/tests/` — новые тест-файлы
  (TC-ID в docstring, существующие ассерты не ослабляются);
- `test-model/reports/coverage-backfill-1/` — отчет о прогоне и карте
  покрытия;
- `openspec/changes/coverage-backfill-1/**` — настоящий пакет.

**Out:**

- прод-код: `backend/`, `services/*/app`, `frontend/`, `deploy/` — не
  меняется ни одной задачей;
- существующие тест-сьюты не переписываются
  (например, `tests/web/test_board_fastline.py`, покрывающий p23-101…108);
- инфраструктура стенда, миграции, master-specs (кроме дельты этого пакета).

## Impact

**Tests-only.** Рисков для прод-контрактов нет: диф не касается прод-кода,
поведение системы не меняется (нотация для ревьюеров и CI — проверять
только тестовые зоны). Регресс возможен только в тестовой инфраструктуре
(conftest/фикстуры — в рамках существующих механизмов, без их ослабления).
Вскрытые кейсами дефекты продукта оформляются баг-репортами
`test-model/bugs/`, а не фиксами в этом change.
