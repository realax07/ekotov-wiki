# Tasks: add-r6-task-form-ux

Задачи пакета «Task form UX» — из сводки объема ТЗ (requirements-r6 §9: S×5 + M×2). Одна задача = одна сессия dev-агента. Порядок: backend S → frontend M (комбобокс) [P] ∥ единая зона M [P] → полиш S → Escape S → адаптив S → QA + финальный бамп. `[P]` — независимые задачи, можно параллелить (каждая в своем worktree): комбобокс = новый js-модуль + `task-form.js`, единая зона = `board.html` разметка + `board.css` — зоны не пересекаются. Объемы S/M — по §9 ТЗ. Трассировка: задача → FR/NFR/ОВ/ОГР → Requirement дельты.

## 1. Backend (S)

- [ ] 1.1 [S] Backend: `backend/app/suggestions.py` — опциональный query-параметр `kind` в `GET /api/suggestions`: без параметра — прежний `_SUGGESTIONS_SQL` (UNION тегов и категорий, дословно прежний контракт — ОГР-26, TC-API-SUGG-001/004 не меняются); `kind=tags` — только теги (ветка DISTINCT tags JOIN task_tags, осиротевшие исключены); иной `kind` — 422 (явный отказ, не тихий UNION); docstring модуля дополнен контрактом параметра; авторизация без изменений (401 без сессии при любом kind). Тест: API — `?kind=tags` только теги; без параметра — UNION; неизвестный kind → 422; 401 без сессии. (FR-57, ОГР-26, Д-14 → suggestions: «Параметр kind фильтра подсказок»; СЦ-1, СЦ-10)
