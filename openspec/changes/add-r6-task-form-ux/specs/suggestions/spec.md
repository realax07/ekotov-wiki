# Delta: suggestions — параметр kind для фильтра множества подсказок

## ADDED Requirements

### Requirement: Параметр kind фильтра подсказок

`GET /api/suggestions` MUST поддерживать опциональный query-параметр `kind` (FR-57, ОГР-26, Д-14): запрос без параметра возвращает прежнее множество — объединение тегов И категорий существующих задач (`{suggestions: [tags ∪ categories]}`, set-семантика, сортировка по возрастанию) — контракт дословно сохранен (уточнение Заказчика, тесты TC-API-SUGG-001/004, docstring `suggestions.py`); потребитель без параметра — поиск (search.js, datalist `#tag-hints`) — не затронут. Запрос с `kind=tags` MUST возвращать только существующие теги проекта (категории не участвуют) — источник подсказок поля «Теги» формы задачи (FR-57, ОВ-1). Запрос с явным неизвестным значением `kind` MUST отклоняться с 422 — явный отказ, не тихий UNION (ОГР-26). Получение подсказок при любом значении параметра MUST требовать действующую сессию: без нее — 401 (преемственность FR-18/NFR-7).

#### Scenario: Без параметра — прежний UNION (контракт поиска цел)

- **GIVEN** на существующих задачах заведены теги «home», «urgent» и категория «work»
- **WHEN** вызывающий запрашивает `GET /api/suggestions` без параметров
- **THEN** ответ 200 `{"suggestions": ["home", "urgent", "work"]}` — объединение тегов и категорий, set-семантика, сортировка; тело содержит единственный ключ «suggestions» (ОГР-26, Д-14, СЦ-10; TC-API-SUGG-001/004 зеленые без изменений)

#### Scenario: kind=tags — только теги

- **GIVEN** на существующих задачах заведены теги «home», «urgent» и категория «work»
- **WHEN** вызывающий запрашивает `GET /api/suggestions?kind=tags`
- **THEN** ответ 200 содержит только теги — «home», «urgent»; категории в ответе нет (FR-57, ОВ-1, СЦ-1, СЦ-10)

#### Scenario: Негативный: неизвестный kind — 422

- **GIVEN** вызывающий авторизован
- **WHEN** вызывающий запрашивает `GET /api/suggestions?kind=users`
- **THEN** API отвечает 422 — явный отказ на неизвестное значение фильтра, прежнее множество не возвращается (ОГР-26, СЦ-10)

#### Scenario: Негативный: без сессии — 401

- **GIVEN** вызывающий не имеет действующей сессии
- **WHEN** вызывающий запрашивает `GET /api/suggestions` (с параметром `kind` или без)
- **THEN** API отвечает 401 `{"error": "unauthorized"}`; подсказки не возвращаются (преемственность FR-18, NFR-7)

#### Scenario: Механизм «значения из данных» сохранен

- **GIVEN** тег остался только у удаленных задач (осиротевший), категория пуста
- **WHEN** вызывающий запрашивает `GET /api/suggestions?kind=tags`
- **THEN** осиротевший тег в ответе отсутствует — в подсказки попадают только теги существующих задач (преемственность FR-16/FR-17, единый механизм «значения из данных»)
