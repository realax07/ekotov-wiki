# Дельта specs: board — модалка просмотра тикета по общему дизайну (P12 п.2)

## MODIFIED Requirements

### Requirement: Просмотр карточки задачи — модальное окно read-only

Просмотр карточки задачи MUST выполняться модальным окном read-only, отличным от форм создания и редактирования (FR-47, решение Заказчика «модальным окном»): все данные задачи — название, описание, приоритет, категория, срок, теги, assigned, creator, комментарии — отображаются только для чтения, без полей ввода и сохранения. Окно просмотра MUST визуально отличаться от форм создания/редактирования на действующих токенах V3 (ОГР-18). Вид окна просмотра MUST соответствовать общему дизайну системы — строго по мокапу ui_designer, утвержденному Заказчиком ДО dev (P12 п.2, FR-90; дизайн-фаза Д-паттерн); после dev соответствие мокапу MUST проверяться design_validator. В шапке каждого комментария окна — автор и человекочитаемая дата/время (P12 п.3, преемственность FR-91). Из окна просмотра MUST быть доступен переход к редактированию — кнопка «Редактировать» открывает существующую форму редактирования (Д-9). Клик по карточке открывает окно просмотра; редактирование остается доступным через кнопку «Редактировать» (FR-7 не деградирует).

#### Scenario: Клик по карточке открывает окно просмотра

- **GIVEN** пользователь авторизован; на доске есть задача со всеми заполненными признаками и комментариями
- **WHEN** пользователь кликает по карточке задачи
- **THEN** открывается модальное окно просмотра со всеми данными задачи, включая assigned, creator и комментарии; поля только для чтения — ввод и сохранение недоступны (FR-47)

#### Scenario: Окно просмотра отлично от форм создания/редактирования

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь сравнивает окно с формой создания/редактирования
- **THEN** окно просмотра визуально отлично от форм (ОГР-18) и не содержит элементов редактирования (полей ввода, кнопки сохранения), кроме кнопки «Редактировать» (Д-9)

#### Scenario: Вид окна по утвержденному мокапу

- **GIVEN** мокап окна просмотра утвержден Заказчиком (дизайн-фаза пакета)
- **WHEN** dev реализует окно просмотра
- **THEN** фактический вид окна (шапка, признаки, комментарии, футер)
  соответствует утвержденному мокапу на токенах V3; соответствие проверяет
  design_validator (P12 п.2, FR-90)

#### Scenario: Переход к редактированию из окна просмотра

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь нажимает кнопку «Редактировать»
- **THEN** открывается существующая форма редактирования этой задачи; изменения после сохранения отображаются в окне просмотра и на карточке (Д-9, FR-7)

#### Scenario: Окно просмотра отображает assigned, creator и комментарии

- **GIVEN** существует задача с creator, назначенным исполнителем и комментариями
- **WHEN** пользователь открывает окно просмотра этой задачи
- **THEN** в окне отображаются creator, assigned (или «Unassigned») и все комментарии задачи — только для чтения (FR-47)

#### Scenario: Шапка комментария в окне просмотра — автор и дата

- **GIVEN** окно просмотра задачи с комментариями открыто
- **WHEN** пользователь осматривает комментарии
- **THEN** в шапке каждого комментария — имя автора и человекочитаемые дата
  и время (без id и сырого timestamp; P12 п.3, преемственность FR-91)

#### Scenario: Закрытие окна просмотра не изменяет данные

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь закрывает окно (крестик или клик вне окна)
- **THEN** окно закрывается; данные задачи не изменяются; доска отображается в прежнем состоянии (FR-47)
