Правило плана §6: **никогда два изменения инфры в одном шаге** — каждый шаг несет ровно одно инфраструктурное изменение; каждая выкатка начинается бэкапом БД и заканчивается смоуком; RUNBOOK обновляется тем же пакетом. Объемы S/M — по плану §6. Трассировка: задача → FR/NFR → Requirement дельты (`specs/deploy/spec.md`).

## Зависимости и порядок

ЭТАП 0: 0.1 ∥ 0.2 → 0.3 (экспорт требует включенной схемы 0.2) ∥ 0.4 ([P] — каталоги, не пересекаются). ЭТАП 1: 1.1 → 1.2 (образы последовательны — правило «одно инфраизменение в шаге») → 1.3 (compose собирает образы) → 1.4 → 1.5 ∥ 1.6 ([P] — e2e-сьют и deploy.sh не пересекаются) → 1.7 (CI-job подключает уже стабилизированный 1.5). Переход: 2.1 → 2.2 → 2.3 → 2.4 → 2.5 (строго последовательно, каждая — отдельная выкатка/проверка; 2.3/2.4 — с явным участием Заказчика). Ворота: `openspec validate --all --strict` green на каждом шаге; миграционный шаг (1.6) не активируется до 2.1 (репетиция обязательна — урок Р4).
