# Дельта specs: video-service (новая capability)

## ADDED Requirements

### Requirement: Раздел «Видео» в сайдбаре и страница сервиса

Пункт «Видео» MUST отображаться в сайдбаре после «Галерея» для всех
авторизованных пользователей (паритет owner и PE; прецедент FR-85) и вести
на страницу `/video`. Страница `/video` без валидной сессии MUST выполнять
редирект на `/login`. Вставка видео в статьи wiki MUST NOT реализовываться —
сервис изолирован от wiki-редактора (ОВ-3).

#### Scenario: Пункт сайдбара виден авторизованным

- **GIVEN** авторизованный пользователь (owner или PE) открыл любую страницу
- **WHEN** сайдбар отрисован
- **THEN** в нем есть пункт «Видео» после «Галерея» с иконкой в едином стиле
  (эталон «Мониторинг»/«Галерея»), ведущий на страницу `/video`

#### Scenario: Неавторизованный — редирект на login

- **GIVEN** сессия отсутствует
- **WHEN** пользователь открывает `/video`
- **THEN** происходит редирект на `/login`; после входа раздел доступен

#### Scenario: Видео не встраивается в статьи

- **GIVEN** пользователь редактирует статью wiki
- **WHEN** он открывает инструменты вставки
- **THEN** инструмента вставки видео из сервиса «Видео» нет; статьи wiki не
  изменяются пакетом (ОВ-3)

### Requirement: Отдельный контейнерный сервис video, файлы вне БД

Загрузка, список, playback и удаление видео MUST обслуживаться отдельным
контейнерным сервисом `video` по образцу `services/images` (паттерн
FR-79): compose-контейнер за nginx, healthcheck, без публикации портов;
маршруты `/api/videos*` и `/videos/` MUST маршрутизироваться nginx,
при отказе сервиса — быстрый управляемый 503, остальное MUST работать.
Файлы видео (оригинал, mp4, превью) MUST храниться в томе `videos-data`
вне репозитория и БД; в БД — только метаданные.

#### Scenario: Маршрутизация и деградация

- **GIVEN** прод-стек поднят
- **WHEN** авторизованный пользователь вызывает `/api/videos`, затем
  контейнер `video` останавливают
- **THEN** до остановки запрос проксируется сервису `video`; после остановки
  nginx отвечает на `/api/videos*` и `/videos/` быстрым 503 (не таймаут),
  доска/поиск/wiki/галерея работают как прежде

#### Scenario: Файлы в томе, метаданные в БД

- **GIVEN** пользователь успешно загрузил видео ≤ 500 МБ
- **WHEN** загрузка завершена
- **THEN** файл(ы) появились в томе `videos-data` (не BLOB, не в репо), в БД —
  запись метаданных со статусом; файлы переживают пересоздание контейнеров

#### Scenario: API без сессии

- **GIVEN** запрос к `/api/videos` без валидной сессии
- **WHEN** middleware обрабатывает запрос
- **THEN** ответ 401 `{"error": "unauthorized"}` — паттерн NFR-7 ядра

### Requirement: Загрузка видео — любой формат, до 500 МБ

Авторизованный пользователь MUST иметь возможность загрузить видеофайл
любого формата (ОВ-4 — без белого списка mime/расширений) размером до
500 МБ включительно (ОВ-1). Лимит размера MUST проверяться ДО записи на
диск (паритет images: превышение — 422, файл не сохраняется); лимит
nginx-локации загрузки MUST быть согласован с лимитом сервиса. Загрузка
MUST NOT блокироваться идущей фоновой конвертацией других файлов.

#### Scenario: Успешная загрузка в пределах лимита

- **GIVEN** авторизованный пользователь выбрал видеофайл 499 МБ (формат, не
  входящий в «типовые», например MKV)
- **WHEN** он отправляет форму загрузки
- **THEN** файл сохранен, в списке появилось видео со статусом «загружено»
  (ожидает/начинает конвертацию)

#### Scenario: Отказ при превышении лимита

- **GIVEN** пользователь выбрал файл 501 МБ
- **WHEN** загрузка отправлена
- **THEN** ответ 422 «файл больше 500 МБ», файл на диск НЕ записан, записи в
  списке нет

### Requirement: Список видео и playback

Авторизованный пользователь MUST видеть список загруженных видео
(превью-кадр, имя, статус конвертации, размер, дата загрузки) и MUST иметь
возможность воспроизвести видео в статусе «готово» во встроенном
HTML5-плеере `<video>`. Отдача файлов MUST идти только авторизованным
пользователям через аутентифицированный маршрут — публичные ссылки MUST
NOT существовать (ОВ-2): доступ к файлу без сессии запрещен (401/редирект).
В списке и плеере — паритет обоих пользователей.

#### Scenario: Playback готового видео

- **GIVEN** видео сконвертировано (статус «готово»)
- **WHEN** авторизованный пользователь открывает его в списке
- **THEN** видео воспроизводится во встроенном плеере `<video>`; скачивание/
  воспроизведение по прямой ссылке без сессии — запрещено (401/редирект)

#### Scenario: Не готовое видео не проигрывается

- **GIVEN** видео в статусе «загружено» или «конвертируется»
- **WHEN** пользователь открывает его в списке
- **THEN** плеер не запускается — отображается текущий статус конвертации

### Requirement: Удаление видео

Авторизованный пользователь MUST иметь возможность удалить видео (паритет
галереи FR-84 — оба пользователя без разделения прав; подтверждение — по
утвержденному макету): удалению подлежат файлы в томе (mp4, превью-кадр,
оригинал при наличии) и запись метаданных. Удаление видео в статусе
«конвертируется» MUST отменять/отбрасывать идущую конвертацию и ее
артефакты. Несуществующее видео — 404; без сессии — 401.

#### Scenario: Удаление готового видео

- **GIVEN** видео в статусе «готово», файлы в томе
- **WHEN** авторизованный пользователь подтверждает удаление
- **THEN** mp4, превью-кадр и запись метаданных удалены; в списке видео нет;
  повторный запрос по id — 404

#### Scenario: Удаление недоконченного видео

- **GIVEN** видео в статусе «конвертируется»
- **WHEN** пользователь удаляет его
- **THEN** фоновая конвертация этого файла отменяется/ее результат
  отбрасывается, артефакты (оригинал, частичный mp4) удаляются

### Requirement: Серверная конвертация в mp4 со статусами

Каждый загруженный файл MUST конвертироваться сервером в mp4 (ffmpeg —
статический бинарь в контейнере, без apt) фоновой задачей по циклу
статусов «загружено» → «конвертируется» → «готово»; при исчерпании
повторов — «ошибка». Ответы API MUST NOT ждать завершения конвертации.
При неудаче MUST выполняться ровно один автоматический повтор; после
второй неудачи — «ошибка», оригинал сохраняется (можно удалить вручную).

#### Scenario: Успешная конвертация

- **GIVEN** загружен MKV 200 МБ, статус «загружено»
- **WHEN** фоновая задача завершает ffmpeg-конвертацию успешно
- **THEN** статус в UI меняется на «готово» без перезагрузки страницы при
  обновлении списка; в томе появились mp4 и превью-кадр; playback доступен

#### Scenario: Неудача и автоматический ретрай

- **GIVEN** ffmpeg завершился с ошибкой на файле (поврежденный/нечитаемый)
- **WHEN** задача фиксирует неудачу
- **THEN** выполняется ровно один автоматический повтор; после второй неудачи
  — статус «ошибка», оригинал сохранен в томе, остальные видео работают

#### Scenario: Конвертация не блокирует сервис

- **GIVEN** идет конвертация файла 500 МБ
- **WHEN** пользователи загружают другой файл и открывают список
- **THEN** загрузка и список отвечают без ожидания конвертации (NFR-37)

### Requirement: Удаление оригинала после успешной конвертации

После успешной конвертации оригинальный файл MUST удаляться из тома
(экономия диска; Заказчик уведомлен — PLAN, ОВ-4). До успеха (статусы
«конвертируется», «ошибка», ретрай) оригинал MUST сохраняться. В томе
после успеха остаются только mp4 и превью-кадр; размер в метаданных
отражает актуальные файлы.

#### Scenario: Оригинал удален после успеха

- **GIVEN** конвертация завершилась успешно
- **WHEN** статус меняется на «готово»
- **THEN** файла оригинала в томе нет (остались mp4 + превью-кадр); размер,
  хранимый в метаданных, отражает актуальные файлы

#### Scenario: Оригинал сохранен при ошибке

- **GIVEN** конвертация завершилась статусом «ошибка»
- **WHEN** файлы тома проверяются
- **THEN** оригинал присутствует в томе (повтор конвертации/удаление
  пользователем возможны)

### Requirement: Превью-кадр, сортировка и поиск по имени

Для каждого сконвертированного видео SHOULD извлекаться превью-кадр —
первый кадр видео (ffmpeg, при конвертации). Список SHOULD поддерживать
сортировку по имени в обе стороны и поиск по подстроке имени без учета
регистр; пустой поиск SHOULD показывать все видео. У несконвертированного
видео в списке MUST отображаться плейсхолдер по утвержденному макету
(кусок C — Should MoSCoW).

#### Scenario: Превью-кадр в списке

- **GIVEN** видео сконвертировано
- **WHEN** список отображается
- **THEN** у карточки есть превью первого кадра (файл из тома, отдается через
  nginx); у несконвертированного — плейсхолдер по макету

#### Scenario: Поиск и сортировка

- **GIVEN** в сервисе ≥ 3 видео с разными именами
- **WHEN** пользователь вводит подстроку имени и переключает сортировку
- **THEN** список фильтруется по подстроке (регистр не учитывается) и
  сортируется по имени в выбранном направлении; очистка поиска возвращает
  полный список

### Requirement: Вид интерфейса по утвержденному макету

Вид страниц сервиса (сайдбар-пункт, список, форма загрузки, плеер, статусы,
подтверждение удаления) MUST соответствовать мокапам ui_designer,
утвержденным Заказчиком ДО dev (Д-паттерн Р4/Р5, прецедент FR-86);
соответствие после dev MUST проверяться design_validator.

#### Scenario: Дизайн-фаза перед dev

- **GIVEN** мокапы страниц «Видео» подготовлены ui_designer
- **WHEN** Заказчик утверждает вариант
- **THEN** dev-задачи куска A стартуют только после утверждения; после dev
  design_validator сверяет вид с мокапом

### Requirement: Ресурсы и здоровье сервиса video (NFR-35)

Контейнер `video` MUST иметь healthcheck, `mem_limit` и ротацию логов
(json-file 10m×3 — паритет стеку); суммарные лимиты стека MUST сохранять
резерв хосту ≥ 2 GB (прецедент NFR-20). Фактическое потребление RAM и CPU
при фоновой конвертации MUST быть замерено на стенде до прод-выкатки;
стабильное превышение лимита блокирует выкатку до решения Заказчика.

#### Scenario: Здоровье и лимиты на стенде

- **GIVEN** контейнер `video` запущен с mem_limit и healthcheck
- **WHEN** выполняется конвертация файла ~200 МБ и проверяется стек
- **THEN** healthcheck отвечает, потребление RAM в пределах лимита; замеры
  зафиксированы в REPORT до выкатки

### Requirement: Доступ только авторизованный, без публичных ссылок (NFR-36)

Все маршруты сервиса (API, отдача файлов, превью) MUST требовать валидную
сессию; без сессии — 401 (API) / редирект на `/login` (страницы).
Механизм публичных ссылок по токену MUST NOT реализовываться (ОВ-2,
вне скоупа).

#### Scenario: Файл не отдается без сессии

- **GIVEN** известен URL mp4 в томе
- **WHEN** запрос выполняется без валидной сессии
- **THEN** ответ 401/редирект на `/login`; с валидной сессией файл отдается

### Requirement: Отзывчивость при фоновой конвертации (NFR-37)

Пока выполняется фоновая конвертация, синхронные операции сервиса MUST
сохранять отзывчивость: p95 ответов API загрузки/списка — < 500 мс
(замер на стенде при одной идущей конвертации файла ~200–500 МБ); UI
MUST NOT блокироваться.

#### Scenario: Замер отзывчивости на стенде

- **GIVEN** запущена конвертация файла ~300 МБ
- **WHEN** выполняются 20 запросов списка и 5 загрузок малого файла
- **THEN** p95 ответов < 500 мс; ни один запрос не ожидает завершения
  конвертации
