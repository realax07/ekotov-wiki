# Proposal: weather-service

## Change ID

`weather-service`

## Why

Пакет P18 «Погода» (PRODUCT_BACKLOG P18; PLAN-p18-weather.md, решения
Заказчика 2026-10-19). Вводные Заказчика (ОВ-1…ОВ-4, все развилки решены —
блокирующих вопросов нет):

- **ОВ-1** = раздел доступен **только после входа** (auth-only, 401
  анониму на API / редирект на страницах);
- **ОВ-2** = пункт **«Погода» в сайдбаре** (после «Видео»);
- **ОВ-3** = **все метрики** на карточке «Сегодня»: температура, описание,
  ощущается как, максимум/минимум, осадки, ветер, влажность, давление;
- **ОВ-4** = данные **кэшируются, обновление раз в час** (60 мин).

Провайдер: **Open-Meteo** (публичный API без ключа и секретов).
Дизайн: **вариант A** (сетка карточек — карточка «сегодня» сверху,
7 дней карточками 4-в-ряд), утвержден Заказчиком 2026-10-19
(`design/p18-weather/variant-a.*`). Один город — Москва
(55.7539, 37.6208); параметризация городов вне скоупа (продуктовое
решение на будущее).

Паттерны-прецеденты: `services/video` (контейнерный сайдкар-сервис за
nginx, сессионный middleware, auth_request-отдача, деградация 503),
FR-85-прецедент (пункт сайдбара), NFR-7-паттерн (401 анониму).

`weather-service` (прецедент video/search/images); сайдбар-пункт входит в

## Scope

### In scope

- Контейнерный сервис `weather` (FastAPI, `services/weather/`, порт
  8381, по образцу `services/video`): `GET /api/weather` (JSON: карточка
  «сегодня» + 7 дней + `fetched_at` + флаг `stale`), `/api/health`,
  `/api/weather/authcheck` для nginx auth_request; сессионный
  middleware (паттерн images/video, без права писать в sessions).
- Интеграция Open-Meteo: фиксированные координаты Москвы
  (55.7539, 37.6208), `timezone=Europe/Moscow`, `forecast_days=7`,
  текущие поля (температура, ощущается, осадки, код погоды, влажность,
  давление, ветер) + daily-поля (max/min, вероятность осадок, ветер);
  таймаут 5 с, ровно один автоматический повтор, пользовательский
  User-Agent в конфиге.
- Кэш-файл в named volume `weather-cache` (атомарная запись tmp+rename),
  TTL 60 минут; провайдер недоступен → отдача кэша с флагом устаревания;
  пустой кэш + недоступен провайдер → управляемая ошибка API и честное
  сообщение в UI. **БД нет** — миграций не требуется (граница PLAN).
- deploy: сервис в `deploy/compose.yaml` (mem_limit, healthcheck,
  ротация логов, порты не публикуются), том `weather-cache`; nginx:
  `/weather` (страница, статика) + `/api/weather*` (JSON) с
  auth_request по образцу видео, деградация 503 по паттерну `@*_down`.
- Фронтенд: страница `/weather` по утвержденному мокапу A — карточка
  «сегодня» (8 метрик), сетка 7 дней (день/ночь, осадки %, ветер),
  пункт сайдбара «Погода» после «Видео»; поставка статикой через
  static_v-бамп (обязанность ПМ, волна деплоя).
- Замеры NFR на стенде до прод-выкатки (REPORT).

### Out of scope

- БД-схема и миграции (кэш — файл в томе; граница PLAN).
- Секреты/ключи API (Open-Meteo без ключа); параметризация городов,
  выбор локации, геолокация, избранное (продуктовое решение на будущее).
- Виджеты погоды в статьях wiki, на дашборде и в других разделах —
  изолированный раздел (паритет ОВ-3 пакета video).
- Прогноз дальше 7 дней, исторические данные, UV-индексы и качество
  воздуха.

## Approach

Дизайн-фаза выполнена — мокап **A утвержден Заказчиком 2026-10-19**
ДО dev-задач (Д-паттерн Р4/Р5); dev идет строго по мокапу A, после dev —
design_validator против мокапа. Техрешения — `design.md`; декомпозиция по
волнам СА→dev→QA — `tasks.md`. Архитектурное ревью пакета — волна 2
(VALID_GATE) до старта dev.
