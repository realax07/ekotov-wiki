# Дельта specs: wiki-sanitize — НОВЫЙ домен (P12)

## Purpose

Санитизация rich-контента (FR-126, NFR-35): расширение sanitize-домена
отдельной главой — обязательные XSS-сценарии по каждому вектору
(прецедент BUG-AF-RECHECK-004: sanitize-домен уже ловил инъекции).
Rich-контент проходит серверную санитизацию НА СОХРАНЕНИИ (POST/PUT/revert —
путь существующего `sanitize.py`); рендер rich-пути структурно безопасен:
DOM строится без innerHTML, пользовательский контент не интерпретируется
как HTML (конечная грамматика диалекта). Отдельного слоя санитизации при
отдаче (GET) нет — контент отдается как сохранен (ревью A-1). Каждый
XSS-вектор — проверяемый сценарий и автотест. Существующие sanitize-тесты wiki
продолжают проходить без ослабления.

## ADDED Requirements

### Requirement: Санитизация rich-контента на сохранении и структурная безопасность рендера

Rich-контент при сохранении MUST проходить серверную санитизацию:
исполняемый код, внедренный в содержимое блоков, MUST NOT попадать в DOM
страницы (FR-126). Рендер rich-пути MUST быть структурно безопасен:
DOM rich-блоков строится только через createElement/textContent, текстовый
ввод пользователя никогда не интерпретируется как HTML (конечная грамматика
диалекта). Существующий legacy-HTML путь не меняется: санитизация на записи,
рендер как до внедрения пакета (NFR-38).

#### Scenario: Скрипт в содержимом нейтрализован

- **GIVEN** пользователь вводит в содержимое блока текст, содержащий
  `<script>alert(1)</script>`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** исполняемый скрипт отсутствует в DOM; alert не выполняется;
  текстовый ввод отображается безопасным образом (FR-126)

#### Scenario: Инъекция нейтрализована на записи, рендер rich-блоков структурно безопасен

- **GIVEN** rich-контент с инъекцией проходит через сохранение страницы
- **WHEN** страница открывается на просмотр любым читателем
- **THEN** исполнение кода невозможно двойным образом: серверная
  sanitize-обработка на записи нейтрализовала векторы, а рендер rich-блоков
  строит DOM без интерпретации пользовательского контента как HTML
  (createElement/textContent, конечная грамматика) — исполнение невозможно
  даже для контента, сохранившего исходный вид (FR-126)

### Requirement: Нейтрализация тегов script, iframe, object

Санитизация rich-контента MUST нейтрализовать теги `<script>`, `<iframe>`,
`<object>` во всех поддерживаемых типах блоков (таблицы, колонки, callout,
врезки, спойлеры, код, подписи изображений). В DOM MUST отсутствовать
исполняемые элементы этих тегов (NFR-35).

#### Scenario: Script в содержимом блока

- **GIVEN** пользователь вводит в callout-блок разметку с тегом `<script>`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** элемент `script` отсутствует в DOM; код не выполняется (NFR-35)

#### Scenario: Iframe в содержимом блока

- **GIVEN** пользователь вводит в таблицу разметку с тегом `<iframe>`
  (внешний embed)
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** элемент `iframe` отсутствует в DOM; внешний embed не загружается
  (NFR-35)

#### Scenario: Object в содержимом блока

- **GIVEN** пользователь вводит в врезку разметку с тегом `<object>`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** элемент `object` отсутствует в DOM; встроенный объект не
  исполняется (NFR-35)

### Requirement: Нейтрализация инлайн-обработчиков событий

Санитизация rich-контента MUST нейтрализовать инлайн-обработчики событий
(`onerror=`, `onclick=` и т.п.) во всех поддерживаемых типах блоков. Атрибуты
обработчиков MUST отсутствовать в DOM; код обработчиков MUST NOT выполняться
(NFR-35).

#### Scenario: Обработчик события в таблице

- **GIVEN** пользователь вводит в ячейку таблицы разметку с `onerror=`
  обработчиком
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** атрибут обработчика отсутствует в DOM; код обработчика не
  выполняется (NFR-35)

#### Scenario: Обработчик события в спойлере

- **GIVEN** пользователь вводит в заголовок спойлера разметку с `onclick=`
  обработчиком
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** атрибут обработчика отсутствует в DOM; код обработчика не
  выполняется (NFR-35)

### Requirement: Нейтрализация javascript-URL

Санитизация rich-контента MUST нейтрализовать URL со схемой `javascript:`
в ссылках и атрибутах источников во всех поддерживаемых типах блоков.
Схема `javascript:` MUST быть нейтрализована до рендера (NFR-35).

#### Scenario: javascript-URL в callout

- **GIVEN** пользователь вводит в callout ссылку с URL `javascript:…`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** схема `javascript:` нейтрализована; переход по ссылке не
  исполняет код (NFR-35)

#### Scenario: javascript-URL в ссылке внутри таблицы

- **GIVEN** пользователь вводит в ячейку таблицы ссылку с URL `javascript:…`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** схема `javascript:` нейтрализована; исполнение кода невозможно
  (NFR-35)

### Requirement: Санитизация вложенного rich-контента

Вложенный rich-контент (блоки внутри колонок, callout, врезок) MUST проходить
ту же санитизацию, что и блоки верхнего уровня: XSS-векторы нейтрализуются на
любой глубине вложенности (NFR-35, FR-127).

#### Scenario: Скрипт в таблице внутри колонки

- **GIVEN** пользователь вводит в таблицу, вложенную в колонку многоколоночного
  блока, разметку с `<script>`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** исполняемый скрипт отсутствует в DOM; текст отображается
  безопасным образом (NFR-35, FR-127)

#### Scenario: Код в код-блоке отображается буквально

- **GIVEN** пользователь вводит в код-блок строку `<script>alert(1)</script>`
- **WHEN** страница сохраняется и открывается на просмотр
- **THEN** содержимое код-блока отображается как буквальный текст с
  подсветкой; скрипт не исполняется и отсутствует в DOM как элемент (NFR-35)

### Requirement: Сохранение существующих sanitize-тестов

Расширение санитизации на rich-контент MUST NOT ослаблять существующую
санитизацию wiki: существующие sanitize-тесты wiki продолжают проходить без
правок на ослабление (NFR-35, прецедент BUG-AF-RECHECK-004).

#### Scenario: Существующие sanitize-тесты проходят

- **GIVEN** пакет add-rich-editor внедрен
- **WHEN** выполняется существующий sanitize-сьют wiki (script/on*/
  javascript:/iframe не проходят; whitelist-разметка проходит)
- **THEN** все существующие sanitize-тесты проходят без ослабления правил
  (NFR-35)
