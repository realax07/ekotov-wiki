# Proposal: add-rich-editor

## Change ID

`add-rich-editor`

## Why

Пакет **P12 «Продвинутое редактирование»** — requirements.md пакета, статус
**УТВЕРЖДЕН Заказчиком** (санкция «Давай прогоним rich-редактор», флоу 1,
2026-10-15; утверждение r1 — 2026-10-16). Все открытые вопросы этапа 1 решены:
ОВ-1 drag-порядок — Won't (вне скоупа); ОВ-2 состав графических блоков —
врезка/спойлер/код с подсветкой; ОВ-3 вложенность — SHOULD (FR-127); ОВ-4
порог NFR-37 подтвержден: 2 с / 50 блоков. Плюс закрытие незакрытого долга
волны add-wiki — image-scale (FR-123) без новых лимитов (NFR-34).

## What Changes

Rich-редактор страниц wiki: таблицы (FR-117), многоколоночные блоки (FR-118),
callout-блоки info/warn/success (FR-119), графические блоки — врезка (FR-120),
спойлер (FR-121), код с подсветкой (FR-122), масштабирование изображений
(FR-123). WYSIWYG-соответствие (FR-124), обратная совместимость рендера без
миграций (FR-125, NFR-36), вложенность блоков SHOULD (FR-127), производительность
(NFR-37), сохранение поведения wiki (NFR-38). Sanitize rich-контента —
отдельная глава (FR-126, NFR-35): XSS-сценарии по каждому вектору, существующие
sanitize-тесты — без ослабления.

Дельты по **2 capability** (обе новые):

| Capability | Тип | Содержание |
|---|---|---|
| `wiki-editor` | ADDED | блоки, image-scale, WYSIWYG, совместимость, вложенность, perf (FR-117..125, FR-127, NFR-36..38) |
| `wiki-sanitize` | ADDED | санитизация rich-контента, XSS-векторы (FR-126, NFR-35) |

## Approach

Модель хранения — **блочный markdown-диалект** (GFM-таблицы, `:::columns`/
`:::callout`/`:::aside`/`:::spoiler`, fenced code, `{width=N}` для изображений),
гибридно с legacy-HTML: рендер диспатчит блоки диалекта через новый парсер,
старый контент идет существующим sanitize-путем без изменений. Обоснование
(sanitize / совместимость / диффы / без миграций) — design §1.

**Декомпозиция по директиве Заказчика** (пакет L без монолитов): frontend —
10 модулей `frontend/static/js/wiki/rich/` (block-parser / renderer / toolbar /
highlight + по модулю на тип блока: tables, columns, callout, aside, spoiler,
code, image-scale); backend — два новых модуля `rich_blocks.py` (парсер/
валидатор диалекта) и `sanitize_rich.py` (санитизация rich-контента, отдельно
от существующего `sanitize.py`), тонкий шов в `wiki.py`. Подробно — design §2–§4.

Один change-пакет, **две волны dev**: волна 1 — ядро диалекта + таблицы +
колонки + sanitize + регресс совместимости; волна 2 — callout + графика +
image-scale + вложенность + perf. Обоснование неделимости ядра — design §5.

## Scope

- **In:** FR-117..FR-127, NFR-35..NFR-38.
- **Out (Won't):** drag-порядок блоков (ОВ-1); миграция контента; новые лимиты
  изображений (NFR-34).
