# tasks.md — p23-fastline (P23 «фастлайн — отдельная линия сверху доски»)

Формат: волны по design.md §8. Каждая задача — проверяемый шов с файлами и
сценарием приемки. Мокапы-эталоны: `design/p23-fastline/v2-*.png` (empty /
busy / blocked / dnd-move / dnd-blocked) — соответствие виду проверяется в
каждой волне и финально в 4. Ограничение конвейера: пакет реализуется как
**1 задача (один change-PR)** — задачи ниже атомарные шаги внутри него.

## Волна 1. Фундамент: константы, разделение, скелет зоны

- [ ] 1.1 `frontend/static/js/board/state.js`: константы зоны —
  `FASTLINE_STAGES` (Ожидает=todo, В работе=in_progress, Выполнено=done),
  признак fast-карты по `is_fast`. Проверка: импорт cards.js без циклов.
- [ ] 1.2 `frontend/templates/board.html`: разметка зоны над канбаном —
  подложка/рамка (класс `.fastline`), шапка FASTLINE (serif, без счетчика),
  3 столбца-этапа с data-атрибутами статусов, кнопка «+ Fast-задача»,
  контейнер чипа-запрета. Проверка: страница открывается, канбан не сломан.
- [ ] 1.3 `frontend/static/js/board/cards.js` + `frontend/static/css/board.css`:
  разделение задач из GET /api/board по `is_fast` (fast — в столбцы зоны,
  обычные — в канбан), рендер карточек зоны переиспользует renderCard.
  Проверка (jsdom + мокап v2-busy): fast-карта только в зоне, в канбане ее
  нет; обычные в зоне не появляются.
- [ ] 1.4 Пустое состояние: зона отображается полностью, подсказок в пустых
  столбцах нет (никаких «Перетащите карточки»/пунктирных заглушек). Проверка:
  тест пустой доски + мокап v2-empty.

## Волна 2. Состояния: вставка, занято, выполнение

- [ ] 2.1 Кнопка «+ Fast-задача»: открытие формы создания с предотмеченным
  fast (приоритет high заблокирован — существующий priority-lock UI).
  Проверка: на пустой зоне кнопка активна, создание кладет карточку в
  «Ожидает» зоны.
- [ ] 2.2 Состояние «занято»: при наличии активной fast-задачи кнопка
  disabled (cursor not-allowed) + чип «В фастлайне уже есть задача —
  выполните текущую»; состояние вычисляется из последнего GET /api/board.
  Проверка: мокап v2-blocked, jsdom-тест disabled+чип.
- [ ] 2.3 Негатив-пути 409: ответ «fast line occupied» (создание через API
  при гонке, включение fast через PATCH edit-формы, возврат fast из done)
  показывает то же сообщение у чипа (api.js, текст переформулирован под
  зону), доска перерисовывается из серверного состояния; сценарий «гонка
  двух вкладок» — кнопка/чекбокс могли быть активны на устаревшем
  GET /api/board, закрывает серверный 409 + чип (O2 ревью №1). Проверка:
  тест 409-путей, существующие `tests/api/test_tasks.py` остаются
  зелеными.
- [ ] 2.4 Выполнение: drop/селект в «Выполнено» зоны = POST /move status=done;
  карточка остается в «Выполнено» зоны до автоархивации, слот освобождается
  (кнопка активна). Проверка: сценарий «Выполнение освобождает зону» спеки.
- [ ] 2.5 Гейт edit-формы — третий путь вставки (design §4.2, FR-89): при
  занятой зоне чекбокс fast в режиме редактирования ОБЫЧНОЙ задачи disabled
  + причина чипа (гейт аналогичен кнопке 2.2); на самой fast-задаче чекбокс
  доступен всегда (выключение освобождает слот, включение идемпотентно —
  exclude_task_id); приоритет-блокировка high при включении — существующий
  priority-lock UI. Проверка: jsdom-тест гейта + PATCH-путь 409 (слот заняла
  вторая вкладка).

## Волна 3. DnD: перемещение и запреты

- [ ] 3.1 Перемещение единственной fast-карты между тремя столбцами зоны:
  переиспользование HTML5 DnD cards.js, drop → POST /api/tasks/{id}/move.
  Проверка: тест DnD todo→in_progress (мокап v2-dnd-move), refreshBoard;
  ассерт «ровно один POST move на один drop» — двойной dragend/fire,
  классический квирк HTML5 DnD (O1 ревью №1).
- [ ] 3.2 Цвета приемников (ОВ-4): столбцы зоны — голубой пунктир
  (`--p-blue-*`), канбан — терракота (без изменений). Проверка: классы
  drop-target зон в jsdom, визуальная сверка с мокапами.
- [ ] 3.3 Запреты: drag обычной карты — столбцы зоны не-приемники (красный
  пунктир + знак запрета + not-allowed, запрос не отправляется; пустая зона
  так же, Э2); drag fast-карты — канбан не-приемник; негатив «drag
  выполненной fast назад в этап при новой активной → 409, карточка
  возвращается» (design §4, spec-сценарий). Проверка: тест
  v2-dnd-blocked-сценария (fetch не вызван), обычный DnD канбана — регресс
  зелен.
- [ ] 3.4 Мобильная укладка (design.md §6): столбцы зоны стеком на узких
  экранах, поведение блокировок идентично. Проверка: ручная проверка 375px,
  существующие responsive-тесты зелены.
