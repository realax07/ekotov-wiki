# Дельта specs: p23-fastline (новая capability — зона FASTLINE над канбаном)

## ADDED Requirements

### Requirement: Зона FASTLINE над канбаном (вариант A)

Доска MUST отображать над основным канбаном отдельную горизонтальную зону
FASTLINE (вариант A, ОВ-1): подложка, рамка и заголовок FASTLINE. Шапка зоны
MUST НЕ содержать счетчик задач (ОВ-2). Зона MUST быть явно заметна как
отдельная линия доски (заявка: «чтобы явно заметно было что он есть»).

#### Scenario: Зона отображается над канбаном

- **GIVEN** пользователь авторизован и открыл доску
- **WHEN** пользователь просматривает доску
- **THEN** над основным канбаном отображается зона FASTLINE (подложка + рамка
  + заголовок) с тремя столбцами, визуально отделенная от канбана (мокап
  v2-empty.png)

#### Scenario: Шапка зоны без счетчика

- **GIVEN** пользователь просматривает зону FASTLINE при любом числе задач
- **WHEN** пользователь просматривает шапку зоны
- **THEN** в шапке нет счетчика задач — только заголовок FASTLINE и кнопка
  вставки fast-задачи (ОВ-2)

### Requirement: Столбцы зоны — этапы одной fast-задачи

Зона MUST состоять из трех столбцов-этапов «Ожидает», «В работе», «Выполнено»
(утвержденные мокапы v2). В зоне MUST находиться не более одной задачи
одновременно (ограничение Заказчика 2026-10-20): три столбца — этапы
жизненного цикла одной fast-задачи.

#### Scenario: Единственная fast-задача на этапах зоны

- **GIVEN** пользователь создал fast-задачу
- **WHEN** пользователь просматривает зону
- **THEN** fast-задача находится ровно в одном столбце зоны, остальные
  столбцы пусты (мокап v2-busy.png)

### Requirement: Выполнение fast-задачи освобождает зону

Выполнение fast-задачи (перевод в «Выполнено» зоны) MUST освобождать зону
для новой fast-задачи. Выполненная fast-задача MUST оставаться видимой в
столбце «Выполнено» зоны до автоархивации (МСК-день, существующее правило
доски) — решение Э1 design.md.

#### Scenario: Выполнение освобождает зону

- **GIVEN** в зоне есть fast-задача в «В работе»
- **WHEN** пользователь переводит ее в «Выполнено»
- **THEN** слот зоны освобожден — создание новой fast-задачи доступно, а
  выполненная карточка отображается в «Выполнено» зоны до автоархивации

### Requirement: Таски фастлайна отображаются только в зоне

Fast-задачи MUST отображаться только в зоне FASTLINE и MUST быть исключены
из столбцов основного канбана (заявка: «таски фастлайна только на нем»).
Обычные задачи MUST отображаться только в канбане и никогда — в зоне.

#### Scenario: Fast-задача отсутствует в канбане

- **GIVEN** в зоне есть fast-задача в «Ожидает»
- **WHEN** пользователь просматривает основной канбан
- **THEN** во всех трех столбцах канбана fast-задачи нет (мокап v2-busy.png)

#### Scenario: Обычные задачи отсутствуют в зоне

- **GIVEN** на канбане есть обычные задачи, в зоне — fast-задача
- **WHEN** пользователь просматривает зону FASTLINE
- **THEN** в столбцах зоны только fast-задача; обычных задач там нет

### Requirement: Пустое состояние зоны — без подсказок

При отсутствии fast-задач зона MUST отображаться полностью (ОВ-3): три
пустых столбца видны, зона не сворачивается. Пустые столбцы зоны MUST НЕ
содержать подсказок («Перетащите карточки», пунктирные заглушки, «Пока
пусто») — заявка: «подсказки показывать не надо если ничего нет».

#### Scenario: Пустая зона отображается без подсказок

- **GIVEN** активных fast-задач нет (зона пуста)
- **WHEN** пользователь открывает доску
- **THEN** зона FASTLINE отображается полностью с тремя пустыми столбцами,
  подсказки в столбцах отсутствуют (мокап v2-empty.png)

### Requirement: Вставка fast-задачи и блокировка при занятой зоне

Вставка fast-задачи MUST выполняться кнопкой «+ Fast-задача» в шапке зоны
(создание с назначением на fast line). Кнопка MUST быть активна только при
пустой зоне; при наличии в зоне задачи кнопка MUST быть заблокирована
(disabled, cursor not-allowed) рядом с чипом-запретом в error-цветах: «В
фастлайне уже есть задача — выполните текущую» (мокап v2-blocked.png).
Повторный серверный контроль — существующий 409 «fast line occupied».

#### Scenario: Кнопка активна на пустой зоне

- **GIVEN** зона пуста
- **WHEN** пользователь нажимает «+ Fast-задача» и создает задачу с
  назначением на fast line
- **THEN** задача создается и отображается в первом столбце зоны (мокап
  v2-empty.png — активная кнопка с голубой рамкой)

#### Scenario: Кнопка заблокирована и чип показан при занятой зоне

- **GIVEN** в зоне есть задача (любой этап до «Выполнено»)
- **WHEN** пользователь просматривает шапку зоны
- **THEN** кнопка «+ Fast-задача» disabled (cursor not-allowed) и рядом
  отображается чип-запрет «В фастлайне уже есть задача — выполните текущую»
  (мокап v2-blocked.png)

#### Scenario: Негативный: вторая fast-задача через API отклонена

- **GIVEN** в зоне есть активная fast-задача
- **WHEN** авторизованный вызывающий отправляет API-запрос создания задачи с
  is_fast=true
- **THEN** API отвечает 409 «fast line occupied» — задача не создается
  (существующий инвариант ≤1 переиспользуется)

### Requirement: Перемещение fast-задачи между этапами зоны (ОВ-5)

Единственную fast-задачу зоны пользователь MUST уметь перемещать между
тремя столбцами зоны перетаскиванием (DnD, ОВ-5) и существующими путями
перевода статуса (карточка/селект). Перемещение MUST использовать
существующий POST /api/tasks/{id}/move; ограничение ≤1 при этом нарушиться
не может. Перемещение в «Выполнено» зоны = выполнение задачи.

#### Scenario: DnD fast-задачи между этапами

- **GIVEN** в зоне есть fast-задача в «Ожидает»
- **WHEN** пользователь перетаскивает карточку в столбец «В работе»
- **THEN** отправляется POST /api/tasks/{id}/move со статусом in_progress и
  карточка отображается в «В работе» (мокап v2-dnd-move.png)

#### Scenario: Перемещение в «Выполнено» выполняет задачу

- **GIVEN** в зоне есть fast-задача в «В работе»
- **WHEN** пользователь перетаскивает карточку в «Выполнено» зоны
- **THEN** задача переводится в done (быстрое выполнение, тот же move), слот
  зоны освобождается

### Requirement: Цветовая кодировка DnD и блокировки

DnD-приемники MUST различаться цветом по направлению (ОВ-4): столбцы зоны —
голубой пунктир (цвет зоны), столбцы канбана — терракотовый (как сейчас).
Запрещенное перетаскивание обычной задачи в зону MUST отображаться красным
пунктиром и знаком запрета с cursor not-allowed, без отправки запроса
(мокапы v2-dnd-blocked.png; пустая зона — тоже не-приемник, Э2 design.md).

#### Scenario: Приемники подсвечены цветом направления

- **GIVEN** пользователь перетаскивает fast-карту внутри зоны либо обычную
  карту по канбану
- **WHEN** курсор над столбцом-приемником
- **THEN** столбец зоны подсвечен голубым пунктиром, столбец канбана —
  терракотовым (направления не спутать, ОВ-4)

#### Scenario: Негативный: обычная задача не вставляется в занятую зону DnD

- **GIVEN** в зоне есть fast-задача, пользователь тащит обычную карту
- **WHEN** пользователь наводит обычную карту на столбец зоны
- **THEN** столбец зоны отвечает красным пунктиром и знаком запрета (cursor
  not-allowed), drop не приводит к запросу и обычная задача остается в
  канбане (мокап v2-dnd-blocked.png)
