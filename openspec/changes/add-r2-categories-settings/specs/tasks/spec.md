# Delta: tasks

## ADDED Requirements

### Requirement: Автодополнение тегов в форме задачи

Форма задачи MUST иметь автодополнение в поле «Теги» (FR-26): при вводе пользователю показываются уже заведенные значения — объединение тегов и категорий существующих задач (set-семантика, без дублей; решение Заказчика: «саджест формировался по двум столбцам, теги и категория, и выбирался типом set(), множество, только из уже заведенных вариантов»). Механизм подсказок MUST быть единым с подсказками поиска (Д-3). В отличие от подсказок поиска (там создание новых значений запрещено — FR-17), в форме задачи пользователь MUST иметь право выбрать существующее значение ИЛИ создать новое.

#### Scenario: Подсказки показывают заведенные значения

- **GIVEN** пользователь авторизован, открыл форму задачи; на существующих задачах заведены теги «home» и «urgent» и категория «work»
- **WHEN** пользователь вводит текст в поле «Теги»
- **THEN** подсказки содержат значения «home», «urgent», «work» (объединение тегов и категорий)

#### Scenario: Set-семантика — без дублей

- **GIVEN** значение «home» заведено и как тег, и как категория на существующих задачах
- **WHEN** пользователь открывает подсказки поля «Теги»
- **THEN** «home» присутствует в списке подсказок ровно один раз

#### Scenario: Выбор существующего значения

- **GIVEN** подсказки содержат значение «work»
- **WHEN** пользователь выбирает «work» из подсказок
- **THEN** значение «work» добавляется как тег задачи

#### Scenario: Создание нового значения, отсутствующего в подсказках

- **GIVEN** значения «newtag» нет среди подсказок (ни на одной существующей задаче)
- **WHEN** пользователь вводит «newtag» в поле «Теги» и сохраняет задачу
- **THEN** задача сохраняется с тегом «newtag» — в форме (в отличие от поиска) новое значение допустимо

#### Scenario: Негативный: подсказки формы требуют авторизации

- **GIVEN** вызывающий не имеет действующей сессии
- **WHEN** вызывающий запрашивает подсказки через API
- **THEN** API отвечает отказом авторизации (401); значения не возвращаются (следствие NFR-7 основного ТЗ)

### Requirement: Крестик закрытия формы в правом верхнем углу

Модальное окно формы задачи MUST иметь крестик закрытия, расположенный в правом верхнем углу окна (FR-28).

#### Scenario: Крестик закрывает форму

- **GIVEN** пользователь авторизован и открыл модальное окно формы задачи
- **WHEN** пользователь просматривает окно
- **THEN** крестик закрытия отображается в правом верхнем углу окна

#### Scenario: Нажатие крестика закрывает окно без сохранения

- **GIVEN** открыто модальное окно формы задачи с заполненными полями
- **WHEN** пользователь нажимает крестик в правом верхнем углу
- **THEN** окно закрывается без сохранения введенных значений

### Requirement: Визуал формы: приоритеты цветом и иконкой, состояния ошибок

Приоритеты (low/medium/high) MUST визуально различаться цветом и иконкой как в форме задачи, так и на карточке задачи (FR-29); иконки MUST быть выполнены inline SVG без внешних библиотек (ОГР-8, Д-4). Форма MUST отображать состояния ошибок: невалидные поля подсвечиваются, включая категорию при отклонении по жесткой валидации (FR-21). Форма MUST иметь единый визуальный стиль (сетка полей, типографика, анимация открытия/закрытия). Конкретный стиль выбирается Заказчиком из 2–3 вариантов до начала задачи 2.5 (Д-5); без выбора — текущий стиль плюс обязательный минимум (FR-28, цвета/иконки приоритетов, состояния ошибок).

#### Scenario: Приоритеты различимы цветом и иконкой

- **GIVEN** в системе есть задачи с приоритетами low, medium, high
- **WHEN** пользователь открывает форму задачи (список выбора приоритета) и карточки этих задач
- **THEN** каждый приоритет визуально различается и цветом, и иконкой — в форме и на карточке

#### Scenario: Иконки приоритетов не требуют внешних библиотек

- **GIVEN** страница формы задачи открыта
- **WHEN** пользователь просматривает загруженные ресурсы страницы
- **THEN** иконки приоритетов отрисованы inline SVG, внешние библиотеки иконок/шрифтов не подключаются (ОГР-8)

#### Scenario: Подсветка невалидной категории

- **GIVEN** пользователь заполняет форму задачи с категорией, которая была удалена из справочника (или значение отклонено серверной валидацией по FR-21)
- **WHEN** пользователь пытается сохранить задачу и сохранение отклоняется
- **THEN** поле категории визуально подсвечено как невалидное с сообщением об ошибке; задача не сохранена

#### Scenario: Анимация открытия и закрытия формы

- **GIVEN** пользователь авторизован и находится на доске
- **WHEN** пользователь открывает и закрывает форму задачи
- **THEN** окно открывается и закрывается с анимацией в рамках единого визуального стиля формы
