## 1. Справочник категорий + миграция (задача 2.1)

- [x] 1.1 Backend: создать таблицу `categories (id INTEGER PK, name TEXT UNIQUE NOT NULL)` и API CRUD категорий — `GET /api/categories` (список, 200/401), `POST /api/categories` (201; 422 пустое имя; 409 дубль), `PATCH /api/categories/{id}` (200; 404; 409/422 дубль; переименование применяется ко всем задачам, ссылающимся по значению), `DELETE /api/categories/{id}` (200; 404; 409 «используется задачами» — удаление используемой категории блокируется по Д-1); все пути за auth-middleware (401 без сессии). (FR-19, FR-20, Д-1 → categories: Справочник категорий; Управление справочником)
- [x] 1.2 Backend: серверная валидация категории — при `POST /api/tasks` и `PATCH /api/tasks/{id}` непустая `category`, отсутствующая в `categories`, отклоняется 422 `{"error": "validation", "details": {"category": "not in categories"}}`; пустая категория проходит; UI-ограничение выбора списка не отменяет серверной проверки (обход через API невозможен). (FR-21 → categories: Жесткая валидация категории задачи)
- [x] 1.3 Backend: одноразовый идемпотентный скрипт миграции — снимок «до», `INSERT DISTINCT` непустых `category` в categories (1:1, пустые не создают записей), задачи не изменяются, автоматическая сверка «после» (каждое непустое значение задач в справочнике; число категорий = числу уникальных непустых значений «до»; расхождение = провал); плюс приведение fast-задач к инварианту `is_fast ⇒ priority='high'`. Запуск — при внедрении (ОГР-9), отчет сверки — в отчете задачи. (FR-22, NFR-8, FR-27-приведение → categories: Миграция; Миграция без потери данных)
