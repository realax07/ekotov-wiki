# Дельта specs: contracts (новая capability — машиночитаемые контракты межсервисного взаимодействия)

## ADDED Requirements

### Requirement: Единый формат и место контрактов сервисов

Каждый выделенный сервис MUST иметь машиночитаемый контракт: OpenAPI 3.x
JSON в `contracts/openapi-<svc>.json` — источник истины, полученный
экспорт-скриптом из живого app-кода (ручное редактирование запрещено);
рядом MUST быть yaml-якорь `services/<svc>/openapi.yaml` по образцу
search (ОВ-2). Контракт MUST быть экспортом живой схемы сервиса 1:1 —
все path-items живого `/openapi.json` без фильтрации — и фиксировать
модель auth (exempt — `/api/health` и `GET /api/videos/authcheck`)
(FR-137).

#### Scenario: Структура контрактов после пакета

- **GIVEN** пакет слит в main
- **WHEN** просматривается `contracts/` и `services/<svc>/`
- **THEN** в `contracts/` лежат `openapi.json` (ядро) и
  `openapi-{search,video,images,weather}.json`, все с `"openapi": "3.*"`;
  у каждого из 4 сервисов есть `services/<svc>/openapi.yaml` с точным
  списком путей контракта

#### Scenario: Повторный экспорт стабилен

- **GIVEN** контракты заморожены на HEAD
- **WHEN** выполняется `python scripts/export_openapi_<svc>.py` без правок кода
- **THEN** `git diff --exit-code -- contracts/` пуст (повторный экспорт не
  меняет ни одного замороженного файла)

### Requirement: Контракты — снимок фактического поведения

Контракты MUST быть снимками фактического поведения сервисов: маршрут,
статус-код и схема ответа этим пакетом не меняются (ОГР-29); расхождение
«спека vs код» на момент заморозки решается перегенерацией спеки, не
правкой кода. Существующие потребители (браузерные JS, nginx authcheck)
и тесты остаются зелеными без правок ассертов поведения — допускается
только добавление схемных проверок (NFR-45).

#### Scenario: Поведение API не меняется пакетом

- **GIVEN** до и после слияния пакета один и тот же запрос к маршруту
  сервиса
- **WHEN** сравниваются статус-код и структура ответа
- **THEN** они совпадают; `git diff` пакета не содержит правок кода
  `services/*/app/**` и `backend/app/**`

### Requirement: Контракт search — эталон формата с полным охватом живой схемы

Контракт search `contracts/openapi-search.json` MUST оставаться источником
истины в едином формате пакета и MUST быть живой схемой сервиса 1:1:
волна 1 упраздняет фильтрацию экспорта — полный экспорт живого
`/openapi.json` (5 path-items с `/api/health`; замороженный контракт —
4), переэкспорт, синхронная правка path-ассертов TC-openapi-201…210
(множества путей — оговорка к NFR-45) (FR-133, FR-137). После приведения
экспорт на HEAD дает пустой дифф; код сервиса не правится (ОГР-29).

#### Scenario: Переэкспорт приводит контракт к живой схеме 1:1

- **GIVEN** живой `/openapi.json` сервиса search отдает 5 путей
  (включая `/api/health`), а замороженный контракт содержит 4
- **WHEN** выполняется правленный экспорт и переэкспорт контракта
- **THEN** множество путей контракта = живой схеме 1:1 (5 path-items,
  `/api/health` присутствует); TC-openapi-201…210 зеленые после
  синхронной правки path-ассертов

#### Scenario: Экспорт на HEAD подтверждает заморозку

- **GIVEN** HEAD после волны 1 без правок search-кода с даты заморозки
- **WHEN** выполняется экспорт и `git diff --exit-code -- contracts/openapi-search.json`
- **THEN** дифф пуст; существующие тесты TC-openapi-201…210 зеленые

#### Scenario: Расхождение решается перегенерацией спеки

- **GIVEN** экспорт на HEAD не совпал с замороженным файлом
- **WHEN** выполняется приведение контракта к единому формату
- **THEN** замороженный файл переэкспортирован тем же PR, множество
  путей контракта = множеству путей живого `/openapi.json`, поведение
  сервиса не изменилось, TC-openapi-201…210 зеленые

### Requirement: Контракт video — все маршруты с internal-пометкой authcheck

Замороженная спека `contracts/openapi-video.json` MUST содержать все
маршруты живой схемы сервиса video — 14 операций (`videos.py` 7,
`social.py` 6, `/api/health`) со схемами ответов (успех и ошибки
401/404/409/422) и MUST содержать `GET /api/videos/authcheck` с пометкой
«internal: потребитель — nginx auth_request, не браузер» (FR-135).
Модель auth: exempt — `/api/health` и authcheck. Сверка множества —
path-items живого `/openapi.json` (path-items < операций: несколько
методов на путь).

#### Scenario: Пути спеки равны живой схеме сервиса

- **GIVEN** сервис video поднят
- **WHEN** контрактный тест сверяет множество path-items спеки с живым
  `/openapi.json` под сессией
- **THEN** множества равны 1:1 (14 операций), authcheck присутствует с
  internal-пометкой в описании

### Requirement: Контракт images — все маршруты живой схемы

Замороженная спека `contracts/openapi-images.json` MUST содержать все
маршруты живой схемы сервиса — 11 операций (`gallery.py` 10: CRUD,
like/dislike, comments, rename + `/api/health`) со схемами 200-ответов и
ошибок (401 сессия, 404, 422, 409 реакций) и моделью auth (FR-134,
arch-review-001 Д-З1).

#### Scenario: Пути спеки равны живой схеме сервиса

- **GIVEN** сервис images поднят
- **WHEN** контрактный тест сверяет множество path-items спеки с живым
  `/openapi.json` под сессией
- **THEN** множества равны 1:1 (11 операций, включая `/api/health`)

### Requirement: Контракт weather — без внешнего API Open-Meteo

Замороженная спека `contracts/openapi-weather.json` MUST содержать
`GET /api/weather` (схема карточки «Сегодня» + 7 дней, null-метрики «—»)
и `/api/health` (FR-136). Внешний вызов Open-Meteo в спеку сервиса НЕ
входит — он фиксируется как документированная зависимость в карте
(Д-17); спеки контейнера games нет (ОВ-9).

#### Scenario: Пути спеки равны живой схеме сервиса

- **GIVEN** сервис weather поднят
- **WHEN** контрактный тест сверяет множество путей спеки с живым
  `/openapi.json` под сессией
- **THEN** спека содержит ровно `GET /api/weather` и `/api/health`;
  упоминаний Open-Meteo в paths спеки нет

### Requirement: Единая error-схема через $ref

Каждая из спек MUST определять общую схему ошибки
`{"error": "<message>"}` (`components.schemas.Error`) и ссылаться на неё
через `$ref` во всех описанных ответах ошибок (ОВ-7); без
`additionalProperties: false` (ОВ-1б).

#### Scenario: Ошибка сервиса валидируется по общей схеме

- **GIVEN** контрактный тест получает ответ 401 без сессии от сервиса
- **WHEN** payload валидируется по схеме Error из спеки
- **THEN** валидация проходит (объект с обязательным строковым полем
  `error`)

### Requirement: Схемная валидация ответов в сервисных тестах

Ответы сервисов в существующих сервисных тестах MUST валидироваться по
схемам замороженной спеки (jsonschema draft-07 и выше) минимум на
happy-path 200 каждого маршрута и на типовую ошибку (401/422) (FR-138,
ОВ-1б). Существующие ассерты множеств путей сохраняются (первый уровень);
схемная валидация добавляется, существующие ассерты поведения не правятся
(NFR-45).

#### Scenario: Ответ валиден по $ref-схеме из замороженной спеки

- **GIVEN** сервисный тест выполняет happy-path запрос к маршруту
- **WHEN** ответ валидируется helper'ом по схеме 200 из
  `contracts/openapi-<svc>.json` (резолв `$ref`)
- **THEN** валидация проходит, тест зеленый

#### Scenario: Дрейф поля ответа ловится тестом

- **GIVEN** в тестовом стенде ответ сервиса отличается по типу/наличию
  поля от схемы замороженной спеки
- **WHEN** выполняется схемная валидация
- **THEN** тест падает с сообщением, указывающим маршрут и несовпавшее
  поле (drift-ловушка второго уровня)

### Requirement: Замедление сервисных тестов не более 20 процентов

Добавление схемной валидации MUST замедлять прогоны сервисных тестов не
более чем на 20% против текущего прогона (NFR-46); стоимость CI-гейта —
не более 30 секунд на PR (дифф-сверка impact-правил, без сборки образов
и подъема сервисов).

#### Scenario: Замер до и после волны схемной валидации

- **GIVEN** зафиксировано время `pytest services/*/tests` до волны 5
- **WHEN** волна 5 слита и время замерено повторно
- **THEN** прирост ≤ 20%, факты замеров записаны в PR задачи 5.5

### Requirement: Карта «Контракты и зависимости»

В `architecture/map.md` MUST существовать раздел «Контракты и
зависимости»: для каждого сервиса — nginx-маршруты (пары «точный +
префикс», порты), потребители (браузерные JS, nginx authcheck для video),
деградации (`@*_down` → 503 + `Retry-After: 5`), файлы контрактов,
внешние зависимости (weather → Open-Meteo — Д-17; games — standalone,
вне скоупа — ОВ-9) (FR-139). Раздел MUST фиксировать правило «ядро
(backend/app) не ходит в выделенные сервисы по HTTP» (ОГР-30).

#### Scenario: Ссылки карты на контракты существуют

- **GIVEN** раздел «Контракты и зависимости» в map.md
- **WHEN** каждый упомянутый в разделе контракт-файл проверяется на
  существование
- **THEN** все ссылки (`contracts/openapi-*.json`, якоря,
  экспорт-скрипты) указывают на существующие файлы

#### Scenario: Правило отсутствия сервер-сервер вызовов зафиксировано

- **GIVEN** раздел карты
- **WHEN** раздел прочитан
- **THEN** в нем есть правило ОГР-30 «сервер-сервер вызовов нет» с
  указанием единственного внутреннего потребителя (nginx authcheck → video)

### Requirement: Сужение существующих правил IR-01 и IR-07 до волн заморозки

Существующие правила ворот IR-01 и IR-07 в `scripts/impact_rules.json`
MUST быть сужены волной 0 — ДО первой волны с якорем или контрактом
(иначе волны заморозки немержибельны: ложные DENY доказаны симуляцией —
Д-Б1/Д-Б2). Триггер IR-01 MUST сузиться до
`^services/[^/]+/openapi\.json$` (yaml-якоря не триггерят), IR-07 — до
`^contracts/openapi\.json$` (сервисные контракты и ОГР-31-PR не
триггерят; контроль — IR-08…IR-11/IR-12). Сужения гейт НЕ включают:
новые правила — последняя волна.

#### Scenario: Якорь и сервисный контракт проходят ворота волны заморозки

- **GIVEN** дифф волны заморозки добавляет `services/video/openapi.yaml`
  и `contracts/openapi-video.json` (ядерный контракт в диффе отсутствует)
- **WHEN** ворота прогоняют суженные IR-01 и IR-07
- **THEN** DENY нет — триггеры сужены до
  `^services/[^/]+/openapi\.json$` и `^contracts/openapi\.json$`

#### Scenario: ОГР-31-PR сервиса проходит ворота без ядерного контракта

- **GIVEN** дифф PR содержит правку маршрута
  `services/video/app/**` и перегенерированный
  `contracts/openapi-video.json`, ядерный `contracts/openapi.json`
  не менялся
- **WHEN** ворота прогоняют суженный IR-07
- **THEN** DENY от IR-07 нет (перегенерация ядра при неизменном ядре
  не требуема); после волны 7 контроль такого диффа — IR-08

### Requirement: CI-гейт дрейфа контрактов — механический DENY

PR, меняющий код сервиса (`services/<svc>/app/**`) или ядро
(`backend/app/**`) без соответствующего изменения контракта в диффе,
MUST получать механический DENY с подсказкой «перегенерируй контракт»
(FR-140, ОВ-5). Реализация — декларативные правила в
`scripts/impact_rules.json`, исполняемые существующим CI-шагом
pr_validate; код ворот не меняется.

#### Scenario: Правка handler'а без контракта — красный PR

- **GIVEN** дифф PR содержит новый маршрут в `services/video/app/**`
- **WHEN** diff не содержит `contracts/openapi-video.json`
- **THEN** ворота возвращают DENY с id правила и hint «перегенерируй
  контракт»

### Requirement: Охват и границы срабатывания гейта

Гейт MUST охватывать 4 сервиса + монолитный `contracts/openapi.json`
ядра (ОВ-6). Правка кода и перегенерация контракта одним PR — зеленый
гейт (ОГР-31). Триггер ядерного правила MUST быть точным: правки без
добавления декоратора маршрута (static_v-бампы `pages.py`, миграции) не
срабатывают (content_when по добавленной строке декоратора).

#### Scenario: Правка + перегенерация одним PR — зеленый

- **GIVEN** дифф PR содержит и правку маршрута сервиса, и
  перегенерированный контракт того же сервиса
- **WHEN** ворота прогоняют impact-правила
- **THEN** DENY нет, PR проходит ворота

#### Scenario: static_v-бамп не триггерит ядерное правило

- **GIVEN** дифф PR меняет только `backend/app/pages.py` (static_v) без
  добавления декораторов маршрутов
- **WHEN** ворота прогоняют правило ядра (content_when по добавленной
  строке декоратора)
- **THEN** правило не срабатывает, DENY нет

### Requirement: nginx-тест проксируемых маршрутов

Набор проксируемых префиксов (`/api/search*`, `/api/suggestions*`,
`/api/images*`, `/api/videos*`, `/api/weather*`) MUST фиксироваться
тестом против `services/frontend/nginx/ekotov-wiki.conf` (парсинг
location-строк): ровно ожидаемые location-семейства для каждого сервиса,
включая пары «= точный + ^~ префикс» и named-локации деградаций (FR-141,
ОВ-8).

#### Scenario: Тест зелен на текущем конфигурации

- **GIVEN** nginx-конф без правок маршрутизации
- **WHEN** выполняется тест проксируемых маршрутов
- **THEN** все ожидаемые location-семейства найдены, лишних /api-семейств
  нет, тест зеленый

#### Scenario: Правка маршрутизации ловится тестом

- **GIVEN** из nginx-конфа удалена или переименована location-пара
  сервиса
- **WHEN** выполняется тест
- **THEN** тест падает с указанием сервиса и отсутствующего семейства
