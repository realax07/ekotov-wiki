## 2. Не затрагивается (гейты молчат)

- Код `backend/app/**` и `services/*/app/**` — НОЛЬ правок (ОГР-29):
  IR-08…IR-12 после включения на них не срабатывают (нет диффа).
- `frontend/**` — не трогается: IR-03/static_v НЕ срабатывает, бампа нет.
- `deploy/**`, compose, Dockerfile — не трогаются: IR-02/IR-05/IR-06
  молчат; deploy-матрица и RUNBOOK без изменений (новых сервисов нет).
- Миграции — нет (IR-04 молчит).
- `.github/workflows/flow.yml` — НЕ меняется: правила исполняются
  существующим шагом pr_validate.

## 3. Риски

- **Ложный DENY гейта на переходных PR** — снят design §5: content_when
  по декораторам маршрутов (static_v-бампы/миграции не триггерят);
  сужения IR-01 (`^services/[^/]+/openapi\.json$` — якоря .yaml не
  триггерят) и IR-07 (`^contracts/openapi\.json$` — новые сервисные
  контракты и ОГР-31-PR сервисов не триггерят) — волной 0, ДО волн
  заморозки (Д-Б1/Д-Б2: без них волны 2–4 немержибельны в CI).
- **Тишина гейта на дрейф payload без изменения декораторов** — осознанно:
  второй уровень ловит схемная валидация (волна 5); гейт = поверхность
  маршрутов, тесты = payloads.
- **Служебные тесты конвейера на число сценариев/маршрутов** — новая
  capability `contracts`, ADDED-only; сверка покрытия flow_check после
  архива — ответственность волны архивации (не этого пакета).

## 4. Порядок включения

Гейт (волна 7) — ПОСЛЕ заморозки всех 4 контрактов (ТЗ §10.3): до этого
новые правила IR-08…IR-12 отсутствуют, гейт DENY-ить не может. Волны 1–6
гейта не содержат; волна 0 (сужения IR-01/IR-07) правит существующие
правила декларативно и гейт НЕ включает — false-positive-окно волн
заморозки закрыто до первого якоря/контракта (Д-Б1/Д-Б2).
