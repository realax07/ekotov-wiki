# Design: p12-rich-tools

Архитектура P12 «rich-контент wiki» — переделка с нуля (решение Заказчика
2026-10-16). Эталон вида — утвержденные мокапы `design/p12-rich/`
(edit+view для каждого инструмента) и README с решениями ОВ-1…ОВ-5.
Прошлая наработка (ветка `rich`, 901428c, откачена 92bd2c8) НЕ переиспользуется,
но её баги — обязательный вход (§7).

## §1. Хранение: блочный синтаксис в существующем поле content

Уточнение к постановке: делегация называет поле «markdown-полем», фактически
wiki хранит контент как **санитизированный HTML** в TEXT-поле `content`
таблицы `pages` (sanitize_html на записи, app/wiki.py; миграций нет).
Markdown-хранилище отвергнуто (§10) — блоки хранятся тем же HTML, новыми
**блочными конструкциями на data-атрибутах фиксированного словаря**:

```html
<!-- спойлер -->
<div data-block="spoiler" data-title="Скрытые детали">
  <div data-block-part="body">…любой контент…</div>
</div>

<!-- код-блок -->
<div data-block="code" data-lang="python"><pre><code>def f(): …
</code></pre></div>

<!-- табуляция: N частей data-block-part="tab" -->
<div data-block="tabs">
  <div data-block-part="tab" data-title="Обзор">…</div>
  <div data-block-part="tab" data-title="Детали">…</div>
</div>
```

Словарь (единственный источник истины — константа в sanitize.py, продублирована
в JS-модулях с тестом согласования):

| Атрибут | Значения |
|---|---|
| `data-block` | `spoiler` \| `code` \| `tabs` |
| `data-block-part` | `body` (спойлер) \| `tab` (табы) |
| `data-title` | произвольный текст, экранируется |
| `data-lang` | `python` \| `js` \| `bash` \| `json` \| `sql` \| `plain` |

Принципы:
- **Никаких id** — ни `id=`, ни `data-block-id` в сохраняемом контенте
  (урок rich-v1: дубли id). Все связи — структурные (вложенность DOM).
- Состояние отображения (свернут/развернут, активная вкладка) НЕ хранится —
  при открытии спойлер развернут, вкладка 1 активна.
- Код-блок содержит чистый экранированный текст; спанов подсветки в БД нет
  (подсветка — только при отображении, §5). Это же снимает XSS-поверхность
  подсветки: лексер работает с уже декодированным текстом и эмитит
  экранированные спаны.
- Таблицы, списки, цитаты, изображения — прежний HTML whitelist, без изменений.

## §2. Санитайзер (backend/app/sanitize.py)

Расширение существующего потокового фильтра (html.parser stdlib, ОГР-8):

- `ALLOWED_ATTRS` пополняется: `div` → (`data-block`, `data-block-part`,
  `data-title`, `data-lang`); значения валидируются по словарю §1
  (`_safe_block_attr`): невалидное значение → атрибут снимается → блок
  деградирует в контент (NFR-39). `data-title` — без ограничений по
  содержимому, экранируется при эмите.
- **Счетчик глубины блоков**: парсер уже держит стек; блок-теги
  (`div[data-block]`) увеличивают глубину на входе, снимают на выходе;
  глубина >5 → тег разворачивается (unwrap, содержимое остается).
- Код-блок: внутри `div[data-block="code"]` разрешены только `pre`/`code`
  и текст — остальные теги unwrap'ятся (смывание разметки кода безопасно:
  текст экранируется).
- Теги/атрибуты вне блоков не меняются: страницы без блоков проходят
  байт-в-байт (регресс-тест на фикстуре старого контента).
- `script`/`style` с содержимым, `on*`, URL-фильтр — без изменений.

## §3. JS редактора (frontend/static/js/wiki/)

Модули rich — новые ES-модули `frontend/static/js/wiki/rich/`:
`model.js` (словарь атрибутов, константы — единый с sanitize.py словарь),
`spoiler.js`, `codeblock.js`, `tabs.js`, `tabletools.js`, `headings.js`.
editor.js подключает их при сборке тулбара; page.js — при активации статьи.

- **Тулбар один** (урок rich-v1 «конфликт toolbar»): блоковые кнопки
  («Спойлер», «Блок кода», «Табуляция») только вставляют блок в позицию
  курсора (insertHTML аккуратным фрагментом + установка фокуса в зону
  содержимого). Контекстные контролы — inline-панели внутри блока: шапка
  спойлера (переименование), таб-бар («+», «×», dblclick-переименование),
  таблица («+»/«−» строк/столбцов, «Удалить таблицу»). Никаких плавающих
  вторых тулбаров.
- **Сохранение — сериализация DOM как есть**: contenteditable-область →
  innerHTML → PUT. Никакой перестройки дерева при сохранении (урок rich-v1:
  потеря контента при вложении). Round-trip гарантируется инвариантом:
  редактируемый DOM структурно совпадает с сохраняемым.
- **Вставка внутрь элементов**: спойлер в ячейку таблицы — вставка в текущий
  block-контекст курсора; в ячейке используется компактный класс
  (определяется по `closest('td,th')` при активации, не хранится).
- **H-toggle (headings.js)**: замена `document.execCommand('formatBlock')`
  «вслепую» на управляемый toggle: определение текущего блока курсора
  (Selection.anchorNode → closest h1/h2/h3/p), снятие = замена тега на `p`
  с переносом детей (текст не теряется), замена уровня = h_x → h_y.
  aria-pressed синхронизируется по движению курсора. Backspace в пустом H:
  keydown-перехват (ключ: блок h*, textContent пуст) → тот же механизм
  снятия формата (ОВ-5).
- **Таблица (tabletools.js)**: контекстная панель от фокуса в таблице
  (CSS :focus-within + позиционирование по целевой строке/столбцу);
  «−» неактивен (disabled + title-подсказка) на последней строке/столбце;
  «Удалить таблицу» — отдельная кнопка панели; Enter в ячейке → `<br>`
  (не новая строка), Tab — штатная навигация ячеек.

## §4. Рендер (page.js + rich/*)

Статья `GET /api/wiki/pages/{id}` вставляется в `.article-body`, затем
однократная активация: делегированные слушатели на контейнере
(клик по шапке спойлера, клик по вкладке), `data-block` обход для
инициализации (компактный спойлер в td, таб-бар скролл-индикация),
подсветка кода (§5). Неизвестный `data-block` — пропускается (контент
виден). Ошибка активации одного блока не роняет остальные (try/catch
per-block) — деградация NFR-39.

## §5. Подсветка: самописный лексер (решение + обоснование)

**Решение: самописный компактный лексер** (`rich/highlight.js`, ~250 строк)
вместо библиотеки. Обоснование:
- ОГР-8/NFR-33 прямо запрещают внешние CDN/библиотеки — highlight.js/Prism
  потребовали бы вендоринга ~80–120 КБ в статику и собственного апдейта
  CVE-цикла; лексер — ~6 КБ без зависимостей.
- Языков всего 6 (ОВ-2), «бумажная» палитра мокапа — кастомные токены
  (терракота/олива/amber/blue) — библиотечные темы пришлось бы переписывать.
- Лексер — набор приоритетных regex-правил на язык (комментарии → строки →
  числа → ключевые слова → функции), `plain` — без правил; правило «не
  распознал токен — выдал как текст» гарантирует отсутствие потери символов;
  на входе декодированный текст, на выходе экранированные `<span class="tok-*">`.
- Производительность (NFR-40): подсветка только видимых блоков (лениво,
  IntersectionObserver не нужен — блоков мало; порог: код ≥1000 строк —
  подсветка через requestIdleCallback / чанками), тест-замер на 20 блоках.

Альтернатива «серверная подсветка при рендере» отвергнута (§10): нагревает
API, ломает «в БД чистый текст», дублирует sanitize-поверхность.

## §6. Вложенность: матрица

| Внутри ↓ \ Что вставляем | спойлер | код | табы | таблица |
|---|---|---|---|---|
| спойлер | ДА | ДА | ДА | ДА |
| ячейка таблицы | ДА (компакт) | ДА | ДА | **НЕТ** |
| вкладка табов | ДА | ДА | ДА | ДА |
| код-блок | **НЕТ** | **НЕТ** | **НЕТ** | **НЕТ** |

- Разрешено всё, кроме: таблица в таблице (contenteditable-инварианты
  colspan/rowspan + контекстные панели — источник потери контента rich-v1),
  любых блоков внутри код-блока (содержимое кода — плоский текст).
- Глобальный лимит глубины — 5 уровней (санитайзер §2; редактор дополнительно
  не предлагает вставку кнопками на 5-м уровне).
- «Спойлер в спойлере» и «табс в табе» — разрешены осознанно (запрос
  Заказчика «вставлялся по тексту или в другие элементы»; сценарии FR-118/FR-120).

## §7. Уроки rich-v1 (ветка rich, откат 92bd2c8) — как не повторяем

| Баг rich-v1 | Решение P12 |
|---|---|
| Дубли id при копировании/вставке блоков | id не существуют: только data-атрибуты словаря, связи структурные (§1) |
| Потеря контента при вложении (пересборка дерева при сохранении/загрузке) | сохранение = innerHTML как есть; round-trip-тесты на вложенные матрицы §6 (FR-118/120 сценарии) |
| Конфликт toolbar (плавающие панели, гонки фокуса) | тулбар один, контекст — inline-панели; вставка блока не крадет фокус (§3) |
| Осиротевшие тесты после отката (aaa1900) | новые web-тесты не импортируют откаченные модули; имя `test_rich_tools.py` — не `test_rich_editor.py` |

## §8. XSS-безопасность (сводка)

Пользовательский контент в блоках проходит тот же sanitize_html на записи:
- data-атрибуты — enum-словарь (§2), экранирование при эмите;
- `data-title` и текст кода — текстовые узлы/значения, экранируются;
- подсветка эмитит только фиксированные классы над экранированным текстом;
- кликовые зоны (шапка спойлера, вкладки) — слушатели на контейнере,
  inline `on*` невозможен (снимается санитайзером);
- «Копировать» — Clipboard API над textContent (без HTML).
Дополнительно: contenteditable-инъекции (`<img onerror>`) покрыты прежним
whitelist-фильтром; новые сценарии — в tests/api/test_sanitize.py.

## §9. Порядок волн

1. **Фундамент**: model.js-словарь + sanitize-расширение + round-trip
   (сохранить/загрузить без искажений, страницы без блоков байт-в-байт).
2. **Спойлер** (FR-118): вставка, переименование, toggle, вложенность,
   компактный вариант в ячейке.
3. **Код-блок** (FR-119): шапка/язык/нумерация/копирование + highlight.js.
4. **Табуляция** (FR-120): таб-бар, лимит 8, скролл, вложенность.
5. **H-toggle + таблица** (FR-121, FR-122): замена execCommand-логики,
   контекстная панель таблицы.
6. **Интеграция**: page.js-активация целиком, стили мокапов в wiki.css,
   бамп static_v (IR-03), расширение тестов, regress.

Волны 2–4 независимы после 1 (разные модули), порядок — по приоритету
Заказчика (нумерация его списка); 5 — после 1; 6 — последняя.

## §10. Отвергнутые альтернативы

1. **Markdown/фенс-хранилище блоков** (`:::spoiler` в md): поле content —
   HTML с релиза add-wiki; конверсия = миграция всех страниц + двойной
   парсер (md+html) в редакторе и рендере — риск потери контента, ради
   которого пакет и затевался. Отвергнуто.
2. **`<details>/<summary>` для спойлера**: нативный toggle, но
   contenteditable плохо держит интерактив внутри details (фокус-прыжки),
   переименование и компактный вариант в td требуют тех же обвязок;
   лишний тег вне whitelist. Отвергнуто в пользу div+data (uniform со
   всеми блоками).
3. **Библиотека подсветки (highlight.js/Prism, вендоренная)**: 80–120 КБ,
   кастомная палитра всё равно переписывается, CVE-цикл чужого кода —
   против ~6 КБ лексера на 6 языков (§5). Отвергнуто.
4. **Серверная подсветка в GET /pages/{id}**: нагрев API, спаны в ответе
   (= в версиях/откатах), дублирование sanitize-поверхности. Отвергнуто.
5. **iframe-sandbox для блоков**: ломает WYSIWYG-инлайн-редактирование,
   высоты/стили не наследуют «бумагу». Отвергнуто.
6. **Хранение состояния вкладок/спойлеров в контенте**: плодит diff-шум
   версий и конфликты revert; состояние — только отображения (§1).
