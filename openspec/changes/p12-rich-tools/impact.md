# Impact: p12-rich-tools (P12 rich-контент)

Первая impact-карта по **J58** (гейт `scripts/pr_validate.py` →
`check_impact_gate` + механическая сверка диффа с `scripts/impact_rules.json`).
Карта — обязательный артефакт change-PR с маркером `[p12-rich-tools]`.

## Затронутые сервисы

| Зона | Файлы | Характер |
|---|---|---|
| Монолит backend (wiki-рендеринг) | `backend/app/sanitize.py` | РАСШИРЕНИЕ whitelist'а блоками (запись + чтение); API-слоя не касается |
| Монолит backend (страницы) | `backend/app/pages.py` | ТОЛЬКО бамп `static_v` (IR-03); роуты не меняются |
| Frontend JS редактора | `frontend/static/js/wiki/editor.js`, `frontend/static/js/wiki/rich/*` (новые) | Тулбар + 5 инструментов |
| Frontend JS рендера | `frontend/static/js/wiki/page.js`, `frontend/static/js/wiki/rich/*` | Клиентская активация блоков, подсветка |
| Frontend CSS | `frontend/static/css/wiki.css` | Стили блоков по утвержденным мокапам `design/p12-rich/` |

Сервисы `services/*` не затрагиваются; контейнеры/deploy-контур не меняются.

## Контракты

- `contracts/openapi.json` — **НЕ меняется**: новых/измененных эндпоинтов нет.
  Сохранение блоков идет существующим `PUT /api/wiki/pages/{id}` (content —
  HTML-строка), рендер — существующим `GET /api/wiki/pages/{id}` + клиентская
  активация. Правило IR-01 («контракт изменился → openapi.json
  перегенерирован») НЕ срабатывает: дифф не трогает `services/*/openapi` и
  `contracts/`.
- Косвенный контракт внутри content-строки: блочный синтаксис data-атрибутов
  (design.md §1) — фиксированный словарь значений, валидируется санитайзером
  (NFR-39). Это контракт хранения, а не OpenAPI; обратная совместимость —
  страницы без блоков проходят байт-в-байт (тест round-trip).

## Статика (static_v)

- Меняется кешируемая статика: `frontend/static/**` → правило **IR-03
  срабатывает**: в диффе ОБЯЗАН быть `backend/app/pages.py` — бамп
  `static_v` (предлагаемый маркер: `p12-rich-1`), иначе DENY ворот.
- **Разведение по волнам**: гейт считает дифф накопительно
  (`git diff --name-status main...HEAD`, scripts/pr_validate.py), поэтому
  КАЖДЫЙ dev-PR, трогающий `frontend/static/**` (стили волн 2.5, 3.4, 4.5,
  5.3), обязан нести бамп `static_v` в том же диффе — бамп дешевый и
  идемпотентный, IR-03 на промежуточных PR закрывается им же (урок R7
  video-1.1: static_v не бамплен — деплой остановлен; бамп «потом» = DENY
  промежуточного PR). Волна 6.3 — ФИНАЛЬНЫЙ бамп маркером `p12-rich-1`
  и проверка, что после мержа всех волн в релизный дифф requirement
  IR-03 выполнен; SA-дифф (только openspec/**) статику не трогает —
  правила молчат.

## Deploy-матрица и RUNBOOK

- **НЕ трогаются.** Новых сервисов нет (IR-02 молчит), миграций нет (IR-04
  молчит). Релиз — существующий деплой монолита по `deploy/deploy.sh`
  без изменений матрицы.

## Миграции

- **НЕТ.** Блоки хранятся в существующем TEXT-поле `content` таблицы
  `pages` (HTML с data-атрибутами). Существующий контент совместим:
  страницы без блоков не меняются, старый `<pre>` код-блок продолжает
  рендериться (деградация к текущему виду).
