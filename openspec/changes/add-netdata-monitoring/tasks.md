## ЭТАП A. Инфраструктура мониторинга (последовательно, одно инфраизменение в шаге)

- [x] 1.2 [P] [S] Devops: сервис `netdata` в `deploy/compose.yaml` и `deploy/compose.test.yaml` (паритет топологии NFR-10) — образ `netdata/netdata`, `mem_limit: 256m`, порты НЕ публикуются, маунты `/proc` и `/sys` **ro** (метрики железа) + `/var/run/docker.sock:ro` (контейнеры через docker-коллектор), healthcheck (wget внутри образа), logging json-file 10m×3, `restart: unless-stopped`. Замер фактического RAM после подъема стенда — в отчет задачи (стабильное превышение 256m = эскалация до 1.5). Границы: только deploy/compose*.yaml. (design §1, §4, §5; FR-75 → monitoring: «Метрики собираются…», «Netdata не публикуется…»; NFR-19 → monitoring: «Ресурсы мониторинга ограничены»)
- [ ] 1.3 [M] Devops: nginx-локации `/netdata` в образе frontend — `= /netdata` → 301 на `/netdata/`; `= /netdata/` и `^~ /netdata/` → `auth_basic` + `auth_basic_user_file /etc/nginx/netdata.htpasswd` → proxy на `http://netdata:19999` с вырезанием префикса (официальный паттерн Netdata subpath: named capture + `proxy_pass …/$ndpath$is_args$args`), resolver 127.0.0.11 + переменная (анти-stale-DNS, паттерн search-семейства); маунт htpasswd ro в compose (+ bind на стенде); `.gitignore` для htpasswd-артефакта; генерация тест-htpasswd для стенда. Проверка на стенде: `/netdata` → 301; `/netdata/` без кредов → 401; с тест-кредами → 200 и дашборд собирается (assets грузятся). Одно инфраизменение: только frontend-образ + compose-маунт. (design §1, §2; FR-75 → monitoring: «Netdata не публикуется…»; FR-76 → monitoring: «Доступ к дашборду…»)
