# Research: add-r3-visual-foundation

Альтернативы ключевых техрешений до design. Источники: PRODUCT_BACKLOG (доработки ПМ к P7/P8/P3), архитектурная карта (map.md, допущения и риск-зоны), sdd.md r8.

## 1. Технология DnD (FR-31)

| Вариант | Оценка |
|---|---|
| **HTML5 Drag and Drop API (нативно, без библиотек)** — принят | Ноль зависимостей (укладывается в легковестный стек ОГР-1); события `dragstart`/`dragover`/`drop` покрывают поведение дословно («прикрепляется к курсору» — setDragImage/CSS-клон; «исчезает с доски» — opacity/display). Продукт — десктоп-мышь по ОВ-19, слабое место API (touch) не задействовано |
| Библиотека (SortableJS/драг-фреймворки) | Отклонено: новая фронтенд-зависимость несоразмерна; touch-поддержка библиотек не нужна (ОВ-19 — перенос на телефоне прежним способом) |
| Pointer Events (самописный DnD) | Отклонено: полная самописная механика (capture, пороги, зоны) — заметно больше кода при тех же возможностях на десктопе |

## 2. Механика «прикрепить к курсору / исчезнуть с доски» (FR-31)

| Вариант | Оценка |
|---|---|
| `setDragImage` с клоном карточки | Стандартный путь; в паре со скрытием оригинала (opacity) дает дословное поведение вводных |
| CSS-клон, следующий за курсором (pointer-слежение) | Требует самописной аналитики координат — избыточно при HTML5 DnD |
| Транспортировка самой плитки (перенос DOM-узла) | Отклонено: сложная синхронизация с refresh доски; возврат на место при отказе 409 проще через сохранение исходной позиции |

## 3. Место в коде фронтенда (FR-31/FR-32)

Релиз 1 разбил board.js на ES-модули (api/dom/state/cards/task-form/task-detail/board-init) — DnD и эффекты пишутся в `cards.js`/CSS, рефакторинг не нужен (PRODUCT_BACKLOG: зависимость P7 «после P6» уже закрыта Релизом 1). Альтернатива (отдельный dragdrop.js-модуль) — приемлема, решается на design/tasks по объему.

## 4. Источник эффектов визуала (FR-32)

| Вариант | Оценка |
|---|---|
| **Чистый CSS (transitions/keyframes) поверх переменных app.css** — принят | Ноль зависимостей; токены V3 «Бумага» уже в app.css; prefers-reduced-motion встроен в CSS |
| JS-анимации (Web Animations API) | Отклонено: для hover/появления/перемещения достаточно CSS; JS нужен только для оркестрации move-анимации при drop |
| Библиотека анимаций | Отклонено: зависимости и вес, несоразмерно |

## 5. Профиль (FR-33): источник данных о текущем пользователе

| Вариант | Оценка |
|---|---|
| **Новый `GET /api/auth/me` (login из сессии)** — принят | Прямо указан в вводных Заказчика; read-only, без изменений схемы; UI не знает сессионного пользователя — эндпоинт нужен в любом случае (PRODUCT_BACKLOG P3) |
| Прокидывание login в контекст шаблона (Jinja2) без API | Отклонено: сайдбар живет на всех страницах (в т.ч. обновляется клиентской логикой), дословное требование Заказчика — эндпоинт; API-вариант переиспользуем будущими пунктами P3 |
| Кладывать login в куку (клиент-readable) | Отклонено: кука HttpOnly (NFR-7), трогать ее атрибуты ради UI — ослабление безопасности |

## 6. DEF-001/FR-35: как доводить «спека закрыта — значений в UI нет»

| Вариант | Оценка |
|---|---|
| **Сначала диагностика на проде с сессией Заказчика, затем фикс по установленной причине** — принят | FR-35 прямо требует диагностики до фикса; версии причин известны (ошибка JS на /search, select не привязан к данным, формат ответа), но фикс вслепую — риск повторного расхождения «спека/прод» (прецедент DEF-001) |
| Фикс всех трех версий сразу без диагностики | Отклонено: переделка /search и формы без установленной причины — лишний объем и риск регрессии |
| Пересмотр требований (другой механизм подсказок) | Отклонено: FR-30 подтвержден, механизм верный — не исполнен |

Общий механизм: единый «источник значений из данных» (уникальные значения столбцов; предвычисление/кэш допустимы) для селектов и подсказок — он же задел под будущие справочники (P5).

## 7. Дефекты кеша статики (FR-34, урок DEF-002/DEF-003/DEF-004)

При любом изменении CSS/разметки форм — бамп `static_v` в pages.py (кеш-бастинг) и QA-проверка «все интерактивные элементы покрыты стилями» (урок DEF-004). Альтернатив (content-hash и т.п.) на этом релизе не вводим — зафиксировано как техдолг карты (§6.3).
