## FINDINGS

### F1 (must) — Коллизия сквозной нумерации FR/NFR с мастер-спеками и активными пакетами

proposal.md: «нумерация продолжается с FR-98/NFR-22 … FR-99…FR-112». Фактически:

- мастер-спеки уже используют **FR-107…FR-116** (openspec/specs/wiki/spec.md:
  FR-107 дерево, FR-108 создание страницы, FR-109…116 rich/история;
  navigation/spec.md:27 прямо ссылается на «FR-107…FR-116»);
- активный пакет **add-responsive-mobile** уже застолбил **FR-100…FR-106 и
  NFR-23…NFR-26** (requirements.md:56–94, specs/board: NFR-23/24 и др.);
- **video-hosting** — FR-116/FR-117; **p12-rich-tools** — NFR-39/40.

Прямые коллизии дельт: design-tokens/navigation/board/wiki/gallery (FR-99…106) ↔
add-responsive-mobile; video-ui FR-107 / weather-ui FR-108 ↔ мастер-wiki
(FR-107 = дерево wiki, FR-108 = создание страницы); заявленный диапазон
FR-109…112 ↔ мастер-wiki; accessibility NFR-23…26 ↔ add-responsive-mobile.
При архивации пакета дельты сольются с чужими требованиями — трассировка
«задача → FR» и будущие ссылки сломаются. Ссылки дельт на реально существующие
FR (FR-44/45/109/7 и т.п.) корректны и не трогаются.

**Fix**: перенумеровать новые требования от свободных значений — FR-118+
(video-ui, weather-ui, design-tokens, board-эффекты, gallery, wiki-стиль) и
NFR-41+ (accessibility); обновить proposal (диапазон и фразу «последние
использованные FR-98/NFR-22» — она фактически неверна), tasks.md:9, design.md,
impact.md и теги FR в spec-дельтах.

### F2 (must) — Проверка задачи 1.1 невыполнима в своей волне (секвенирование миграции токенов)

Задача 1.1 заменяет блок `:root` (V3-примитивы удаляются) и гейтится «grep
frontend/static/css/** на --p-paper-|--p-ink-|--p-clay-|--p-blue-|--p-red-|--p-olive- =
0». Фактические ссылки на V3-примитивы на базлайне: app.css — 31, board.css — 25,
wiki.css — 23, gallery.css — 4. Эти файлы мигрируют только в волнах 2.2/2.3/2.5.
Если 1.1 удаляет примитивы — сайт в промежутке сломан (var() без значения), а
гейт 1.1 красный до конца ЭТАПА 2. Кроме того, design.md §D1 указывает проверку
grep-ом «в задаче 1.2» — это favicon, cross-reference ошибочен.

**Fix**: в 1.1 либо сохранить V3-примитивы как deprecated-алиасы (удаление —
в конце ЭТАПА 2, напр. в 2.7), либо ограничить гейт 1.1 файлом app.css и
перенести full-tree grep=0 в проверку волны 2.7 (финальный проход); исправить
ссылку D1 на корректную задачу.

### F3 (must) — `openspec validate --strict` красный; REPORT-0.1 утверждает PASS

`openspec validate redesign-console` — valid (exit 0), но `--strict` — **exit 1**:
11 предупреждений «Requirement text is very long (>500 characters)»
(design-tokens ×3, board, gallery, navigation-мобильная, video-ui, weather-ui,
wiki ×2, accessibility), которые в strict-режиме роняют валидацию. Заявленные
ворота конвейера — «openspec validate --all --strict green», REPORT-0.1
утверждает «validate strict PASS» — не соответствует действительности.

**Fix**: перенести перечисления значений/приемов из тел требований в scenarios
или сократить тела до одного поведения, пока `--strict` не зеленый; исправить
отчет REPORT-0.1.

### F4 (must) — Устаревшие V3-сценарии внутри MODIFIED-дельт (самопротиворечие)

- **fastline/spec.md**, сценарий «Fast line отображается на доске»: THEN
  сохраняет старый текст «(светло-синяя прозрачная подсветка)» — противоречит
  сценарию «Фастлайн — сигнальный янтарный канал» того же MODIFIED-требования
  (янтарная граница/подложка/glow). Оба сценария одновременно пройти не могут.
- **settings/spec.md**, сценарий «Единая карточка V3» («сверка с мокапом V3»)
  оставлен рядом с «Единая карточка "Пульта"» в том же MODIFIED-требовании —
  V3-темы после редизайна не существует.

**Fix**: удалить/заменить оба устаревших сценария (MODIFIED заменяет требование
целиком, включая сценарии).

### F5 (should) — Несуществующий токен `--p-bg-surface` в settings/spec.md

Сценарий «Карточка профиля на токенах "Пульта"»: «поверхность карточки =
`--p-bg-surface` (bg2)». Такого примитива в tokens-console.html нет (примитивы —
`--p-bg-000…300`); семантическое имя — `--color-bg-surface`. Автотест по этому
сценарию упрется в пустой токен.

**Fix**: заменить на `--p-bg-200` или `--color-bg-surface`.

### F6 (should) — Список сохраняемых DOM-хуков (ОГР-28) неполон относительно JS

D2/out-of-scope перечисляют `.nav-item`, `.task-card`, `.fastline`, `#sidebar`,
`#burger-button`. Фактические JS-точки входа (grep querySelector/getElementById/
classList по frontend/static/js/) шире: `.task-card-fast`, `.board-column`,
`.fastline-column`, `.fast-row`, `.board-column-title`, `.sidebar-backdrop`,
`.sidebar-footer`, `.spoiler-title`, `.codeblock-head`, `.codeblock-nums`,
`.wiki-content`, `.wiki-layout`, `.g-card`, `.v-card`, `.breadcrumb a`, класс
`sidebar-open`,rich-хуки `.rich-active`/`.rich-compact`. Волны 2.2/2.3 правят
именно эти шаблоны и CSS — при редизайне фастлайна/карточек/спойлера риск
переименовать хук (и сломать JS, а не только CSS) реален.

**Fix**: дополнить D2 явным списком JS-хуков; в проверку волн 2.2/2.3 добавить
пункт «все JS-селекторы зоны резолвятся после правки» (прогон нецветовых тестов
это частично ловит, но явный чек дешевле).

### F7 (should) — Карта сломанных тестов неполна внутри файлов (важно для 3.4)

Все 8 файлов из impact.md существуют, цитаты строк точные (проверено grep-ом),
дополнительных цветовых файлов в tests/web/ не найдено. Но внутри файлов карта
неполна: test_p12_ui_polish_r8.py также читает и ассертит `--p-blue-200`
(строки 95, 112) — в impact только пара `--p-blue-050`; в
test_qa21_netdata_sidebar_ui.py есть еще V3-зависимые ассерты: строка 172
(focusRing содержит rgba(168,67,44,…)), 177 (hover rgba(255,253,249,.08)), 193
(focus-shadow) — impact указывает только 166–171, 201–202. Задача 3.4 требует
правку «строго по impact.md» — неполнота карты даст пропущенные падения.
Мелочь: board/spec.md называет тест «dev_smoke_board_swipe» — фактическое имя
`dev_smoke_p14_21_board_swipe.py`.

**Fix**: дополнить §«Сломающиеся тесты» impact.md перечнем всех затронутых
ассертов каждого файла; поправить имя теста в board/spec.md.

### F8 (should) — kbd-подсказки для несуществующих хоткеев

Навигационная дельта требует kbd-футер («n новая задача, / поиск, f фастлайн»).
Глобальных обработчиков n///f в JS нет; «новые функции» — out of scope. Блок
подсказок к несуществующим клавишам — ложный аффорданс в проде.

**Fix**: либо ограничить подсказки реально существующими хоткеями, либо явно
зафиксировать в спеке, что блок декоративен (aria-hidden) и отражает только
действующие клавиши; появление самих хоткеев — отдельный change-пакет.
