# Дельта specs: board — доска «Пульт»

## MODIFIED Requirements

### Requirement: Отображение канбан-доски

Канбан-доска MUST отображаться как прежде (3 фиксированных столбца, карточки,
счетчики, состав данных карточки — действующие контракты без изменений) в
визуале утвержденного мокапа `design/redesign-pro/board-console.html` §board:
сетка колонок 3×1fr с зазором 16px; колонка — панель `--p-bg-100` с границей
`--p-border`, радиус 8px и HUD-уголками; заголовок колонки — LED-точка статуса
(нейтраль t500 / янтарь blink «в работе» / teal «выполнено»), название капсом
12px (`--p-text-600`), mono-код (QUE-01/RUN-02/DN-03 стиль) и mono-счетчик
справа; карточка — поверхность `--p-bg-200` с границей `--p-border`, hover —
граница `--p-border-2` + фон `--p-bg-300`, заголовок 14px `--p-text-900`,
мета-строка (приоритет, категория, срок) — mono 11px `--p-text-500`
(на hover-подложке `--p-text-600` — AA 5.6:1); приоритет — контурный бейдж
(coral/violet/teal по высокому/среднему/низкому); fast-карточка — янтарная
граница + подложка `--p-amber-900` + мягкое янтарное свечение + маркер «▲»;
выполненная карточка — зачеркнутый заголовок `--p-text-500`. Заголовок страницы
(pagehead) — h1 22px + терминальный readout (mono: дата, ACT/DONE счетчики,
teal-LED) + янтарная кнопка «Новая задача» справа. Раскладка доски на ≤ 860px —
одна колонка, кнопка на всю ширину (мокап).

#### Scenario: Открытие доски с задачами

- **GIVEN** пользователь авторизован и в системе есть задачи в разных столбцах
- **WHEN** пользователь открывает страницу доски
- **THEN** все задачи отображаются в столбцах, соответствующих их текущему статусу; на каждой карточке отображаются assigned и creator (FR-45)

#### Scenario: Открытие пустой доски

- **GIVEN** пользователь авторизован и в системе нет ни одной задачи
- **WHEN** пользователь открывает страницу доски
- **THEN** доска отображается с тремя пустыми столбцами без ошибок

#### Scenario: Строка исполнителя на карточке без assigned

- **GIVEN** существует задача без исполнителя (assigned пуст, ОВ-23/nullable FR-37)
- **WHEN** пользователь открывает доску
- **THEN** на карточке этой задачи строка исполнителя отображается всегда, курсивом «Unassigned» (ОВ-24)

#### Scenario: Строка исполнителя на карточке с assigned

- **GIVEN** существует задача с назначенным исполнителем
- **WHEN** пользователь открывает доску
- **THEN** на карточке отображается имя исполнителя (FR-45)

#### Scenario: Tooltip карточки показывает assigned и creator

- **GIVEN** пользователь авторизован; существует задача с creator «owner» и исполнителем «wife»
- **WHEN** пользователь наводит курсор на карточку задачи
- **THEN** появляется всплывашка с assigned («wife») и creator («owner») задачи (FR-44)

#### Scenario: Единый механизм всплывашек

- **GIVEN** на доске есть карточки задач; блок профиля внизу сайдбара присутствует
- **WHEN** пользователь наводит курсор на карточку и на блок профиля
- **THEN** обе всплывашки выполнены одним и тем же механизмом (ОГР-17)

#### Scenario: Уменьшение движения отключает анимации всплывашек

- **GIVEN** в системе пользователя включена настройка уменьшения движения (prefers-reduced-motion)
- **WHEN** пользователь наводит курсор на карточку и на блок профиля
- **THEN** всплывашки появляются без анимации; содержание всплывашек не изменяется (ОГР-17, TC-vis-105)
#### Scenario: Доска в визуале «Пульта»

- **GIVEN** пользователь открыл доску
- **WHEN** страница отображается
- **THEN** три колонки-панели с HUD-уголками и LED в заголовках, карточки на
  `--p-bg-200`, мета — mono, вид соответствует мокапу board-console.html

#### Scenario: Статусы колонок читаются по LED

- **GIVEN** на доске есть колонки «Ожидает», «В работе», «Выполнено»
- **WHEN** проверяются LED-точки заголовков
- **THEN** цвета соответствуют состояниям (t500/amber blink/teal); при
  prefers-reduced-motion blink отключен

#### Scenario: Приоритеты различимы на темной теме

- **GIVEN** есть карточки с приоритетами высокий/средний/низкий
- **WHEN** проверяются бейджи приоритетов
- **THEN** высокий — coral, средний — violet, низкий — teal, все пары
  текст/фон ≥ 4.5:1 (AA)

#### Scenario: Fast-карточка сигнальна

- **GIVEN** на доске есть fast-задача
- **WHEN** проверяется её карточка
- **THEN** янтарная граница, подложка `--p-amber-900`, свечение и маркер «▲»;
  остальных отличий от обычной карточки нет

#### Scenario: Существующее поведение доски не деградировало

- **GIVEN** редизайн применен
- **WHEN** прогоняются тесты доски (board_tasks_ui, r3_dnd_ui, bug013,
  bug014, dev_smoke_p14_21_board_swipe — нецветовые ассерты)
- **THEN** все проходят: DnD, быстрое «Выполнено», модалка, жесты — без
  изменений (DOM-хуки сохранены)

## ADDED Requirements

### Requirement: Визуальные эффекты доски на токенах «Пульт» (FR-122)

Декоративные эффекты доски MUST выполняться на токенах «Пульт» (приемник
удаленного V3-требования): hover-состояния — ступенями фона (bg2→bg3) и
границей `--p-border-2`, без теней-«глубины»; выделение fast-карточки —
только янтарный сигнал, окраска столбца запрещена (преемственность P12 п.5);
акцент cyan на доске не используется (кроме фокуса — accessibility); анимации
переходов отключаются при prefers-reduced-motion.

#### Scenario: Нет окраски столбца и cyan-декора

- **GIVEN** доска с fast-задачей в столбце «В работе»
- **WHEN** инспектируются столбец и карточки
- **THEN** столбец не окрашивается (псевдоэлементы столбца без контента),
  cyan на декоративных поверхностях доски отсутствует

#### Scenario: Hover карточки — ступенями фона

- **GIVEN** карточка на доске
- **WHEN** курсор наводится на карточку
- **THEN** фон меняется на `--p-bg-300`, граница на `--p-border-2`; мета-текст
  поднимается до `--p-text-600` (AA на новой подложке)
