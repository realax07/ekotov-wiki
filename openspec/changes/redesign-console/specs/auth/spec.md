# Дельта specs: auth — экран входа «Пульт»

## MODIFIED Requirements

### Requirement: Вход по логину и паролю

Вход по логину и паролю MUST работать как прежде (действующий контракт: форма
логина, сессии, ошибки авторизации — без изменений) на визуале «Пульт»
(заявка 1 «профессиональный редизайн фронта»; приемы мокапа
board-console.html, tokens-console.html): страница на фоне `--p-bg-000`
с микро-сеткой, форма — панель `--p-bg-100` с HUD-уголками и границей
`--p-border`, бренд ekotov.wiki с teal-LED над формой, поля ввода на
`--p-bg-200` с границей `--p-border` (focus — cyan-фокус-ринг), кнопка входа —
янтарная (`--p-amber-400`, текст `--p-bg-000`, hover `#f6c17a` + янтарное
свечение), сообщение об ошибке — `--p-coral-400` на подложке (контраст AA),
микро-лейблы полей капсом (mono). `color-scheme: dark` обеспечивает темные
нативные контролы. DOM-хуки формы (id полей, кнопки, блока ошибки) MUST
сохраниться (ОГР-28).

#### Scenario: Успешный вход существующего пользователя
- **GIVEN** пользователь с корректной парой логин/пароль существует в системе
- **WHEN** пользователь вводит корректные логин и пароль в форму входа и отправляет ее
- **THEN** вход выполняется успешно, пользователь получает доступ к функционалу системы

#### Scenario: Неверный пароль
- **GIVEN** пользователь существует в системе
- **WHEN** пользователь вводит корректный логин и неверный пароль
- **THEN** вход отклоняется, пользователю показывается сообщение об ошибке входа, доступ к функционалу не предоставляется

#### Scenario: Несуществующий пользователь
- **GIVEN** логин не принадлежит ни одному пользователю системы
- **WHEN** пользователь вводит несуществующий логин и любой пароль
- **THEN** вход отклоняется с сообщением об ошибке входа, не раскрывающим причину (существование логина не раскрывается)
#### Scenario: Форма входа в визуале «Пульта»

- **GIVEN** пользователь не авторизован и открыл /login
- **WHEN** страница отображается
- **THEN** темная панель с HUD-уголками, поля на `--p-bg-200`, янтарная кнопка
  входа, микро-лейблы капсом; вид соответствует токенам tokens-console.html

#### Scenario: Фокус в поле читается по cyan

- **GIVEN** страница входа открыта
- **WHEN** пользователь табом фокусируется в поле «Логин»
- **THEN** вокруг поля виден cyan-фокус-ринг (`--focus-ring`), рамка поля не
  исчезает при клике мышью (focus-visible семантика)

#### Scenario: Ошибка авторизации в новом визуале

- **GIVEN** пользователь ввел неверный пароль
- **WHEN** отправляет форму
- **THEN** существующее сообщение об ошибке отображается в стиле `--status-error`
  (coral, AA-контраст), форма не очищает логин, функциональное поведение прежнее

#### Scenario: Хуки формы входа сохранены

- **GIVEN** редизайн применен
- **WHEN** прогоняется tests/web/test_auth_ui.py
- **THEN** тесты проходят без правок (селекторы формы не менялись)
