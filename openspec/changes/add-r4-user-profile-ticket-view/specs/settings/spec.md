# Delta: settings — страница настроек пользователя

## ADDED Requirements

### Requirement: Страница настроек пользователя

Система MUST содержать страницу настроек пользователя, отдельную от общего раздела «Настройки» со справочником категорий (FR-39, ОГР-20): страница показывает настройки профиля СВОЕГО аккаунта — форму профиля (display_name, роль, bio; FR-40), смену пароля (FR-41) и загрузку аватара (FR-42). Доступ — только авторизованному пользователю; без сессии — редирект на страницу входа (NFR-7). Страница настроек пользователя MUST NOT изменять общие настройки (справочник категорий) и MUST NOT давать доступ к профилю другого пользователя.

#### Scenario: Открытие страницы настроек пользователя

- **GIVEN** пользователь авторизован
- **WHEN** пользователь переходит на страницу настроек пользователя (клик по профилю внизу сайдбара, FR-39)
- **THEN** открывается страница с формой профиля, сменой пароля и загрузкой аватара — данными своего профиля

#### Scenario: Негативный: неавторизованный доступ

- **GIVEN** вызывающий не имеет действующей сессии
- **WHEN** вызывающий открывает страницу настроек пользователя
- **THEN** доступ отклоняется редиректом на страницу входа; содержимое не отображается (NFR-7)

#### Scenario: Настройки пользователя — только свои данные

- **GIVEN** пользователь авторизован (логин «owner»)
- **WHEN** пользователь открывает страницу настроек пользователя
- **THEN** на странице отображаются и редактируются данные профиля «owner»; профиль второго пользователя недоступен с этой страницы

#### Scenario: Независимость от общих настроек

- **GIVEN** пользователь находится на странице настроек пользователя
- **WHEN** пользователь просматривает состав страницы
- **THEN** управление справочником категорий на странице отсутствует — оно остается в общем разделе «Настройки» сайдбара (FR-23, ОГР-20)

### Requirement: Форма профиля на странице настроек пользователя

Страница настроек пользователя MUST содержать форму редактирования display_name, роли и bio с сохранением (FR-40). Роль выбирается из фиксированного списка значений «Product manager» и «Product engineer» (ОВ-21); свободный ввод роли недоступен. После успешного сохранения новые значения отображаются в блоке профиля и в его tooltip'е (FR-43, Д-10).

#### Scenario: Редактирование и сохранение профиля

- **GIVEN** пользователь находится на странице настроек пользователя
- **WHEN** пользователь заполняет display_name, выбирает роль «Product manager», вводит текст «о себе» и сохраняет
- **THEN** значения сохраняются; после обновления страницы блок профиля показывает display_name, tooltip — display_name, роль и bio (FR-40, FR-43)

#### Scenario: Роль — только выбор из справочника

- **GIVEN** пользователь открыл форму профиля
- **WHEN** пользователь раскрывает поле роли
- **THEN** доступны ровно два значения: «Product manager» и «Product engineer»; ввод произвольного текста роли невозможен (ОВ-21)

#### Scenario: Очистка display_name — показывается логин

- **GIVEN** пользователь ранее задал display_name
- **WHEN** пользователь очищает display_name и сохраняет профиль
- **THEN** сохранение выполняется успешно; в местах отображения имени показывается логин (Д-10)
