# Delta: tasks

## MODIFIED Requirements

### Requirement: Создание задачи

Пользователь MUST иметь возможность создать задачу, указав как минимум ее название (FR-5). Создание задачи с прочими признаками или без них MUST быть возможно. В форме создания задачи поле исполнителя (assigned) MUST быть опциональным: при создании можно выбрать исполнителя из пользователей системы или оставить задачу без исполнителя (ОВ-26). Создатель задачи (creator) MUST устанавливаться сервером автоматически = пользователю сессии и MUST НЕ быть доступен для выбора/изменения в форме (FR-37).

#### Scenario: Создание задачи только с названием

- **GIVEN** пользователь авторизован и открыл форму создания задачи
- **WHEN** пользователь вводит название и подтверждает создание
- **THEN** задача создается и появляется на доске в столбце «Ожидает»; creator задачи = авторизованный пользователь, assigned пуст (FR-37, ОВ-26)

#### Scenario: Создание задачи с заполненными признаками

- **GIVEN** пользователь авторизован и открыл форму создания задачи
- **WHEN** пользователь вводит название, заполняет другие признаки (описание, приоритет, категория, срок, теги), выбирает исполнителя и подтверждает создание
- **THEN** задача создается со всеми введенными признаками, включая выбранного исполнителя; creator = авторизованный пользователь (FR-37, ОВ-26)

#### Scenario: Создание задачи без исполнителя

- **GIVEN** пользователь авторизован и открыл форму создания задачи
- **WHEN** пользователь вводит название, не выбирая исполнителя, и подтверждает создание
- **THEN** задача создается без исполнителя (assigned пуст); на карточке и в поиске строка исполнителя отображается курсивом «Unassigned» (ОВ-24, FR-45)

#### Scenario: Негативный: создание без названия

- **GIVEN** пользователь авторизован и открыл форму создания задачи
- **WHEN** пользователь оставляет название пустым и подтверждает создание
- **THEN** задача не создается, пользователю показывается сообщение о необходимости названия

#### Scenario: Creator не выбирается в форме

- **GIVEN** пользователь открыл форму создания или редактирования задачи
- **WHEN** пользователь просматривает состав формы
- **THEN** поля creator в форме нет — создатель определяется системой автоматически (пользователь сессии, FR-37)

### Requirement: Признаки задачи

Задача MUST иметь признаки: название, описание, приоритет, категория, срок, комментарии, теги (FR-9), а также исполнителя (assigned_to_id, nullable) и создателя (creator_id) (FR-37). Признаки MUST отображаться в карточке задачи; assigned и creator отображаются во всех карточках задач и в выдаче поиска (FR-45), в tooltip'е карточки (FR-44) и учитываются в поиске (FR-46, дельта search).

#### Scenario: Просмотр признаков в карточке

- **GIVEN** существует задача с заполненными признаками
- **WHEN** пользователь открывает карточку задачи
- **THEN** все заполненные признаки отображаются в карточке, включая creator и assigned

#### Scenario: Редактирование признаков

- **GIVEN** пользователь открыл карточку существующей задачи
- **WHEN** пользователь изменяет значения признаков и сохраняет
- **THEN** измененные значения сохраняются и отображаются при последующем открытии карточки

#### Scenario: Комментарии к задаче

- **GIVEN** пользователь открыл карточку существующей задачи
- **WHEN** пользователь добавляет комментарий
- **THEN** комментарий сохраняется и отображается в карточке

#### Scenario: Creator задачи неизменяем

- **GIVEN** существует задача с creator
- **WHEN** любой пользователь редактирует задачу через интерфейс или API
- **THEN** creator задачи не изменяется (изменение creator API-запросом отклоняется — поле не входит в контракт редактирования, FR-37)

#### Scenario: Негативный: assigned — только существующий пользователь

- **GIVEN** вызывающий авторизован
- **WHEN** вызывающий отправляет API-запрос создания или редактирования задачи с assigned, ссылающимся на несуществующего пользователя
- **THEN** API отвечает ошибкой валидации (4xx); задача не создается/не изменяется (FR-37)

### Requirement: Редактирование задачи

Пользователь MUST иметь возможность редактировать свою задачу (FR-7). В форме редактирования задачи MUST присутствовать поле исполнителя (assigned): select из пользователей системы (ОВ-26) — можно выбрать исполнителя, сменить его или очистить (задача без исполнителя). Редактирование assigned доступно любому авторизованному пользователю — общая доска, разграничения прав нет (ОВ-26, ОГР-6).

#### Scenario: Изменение названия существующей задачи

- **GIVEN** существует задача с известным названием
- **WHEN** пользователь изменяет название в форме редактирования и сохраняет
- **THEN** новое название сохраняется и отображается на доске и в карточке

#### Scenario: Назначение и смена исполнителя в форме редактирования

- **GIVEN** пользователь открыл форму редактирования задачи
- **WHEN** пользователь выбирает в поле исполнителя пользователя из списка (или меняет одного на другого) и сохраняет
- **THEN** assigned задачи обновлен; на карточке, в tooltip'е и в поиске отображается новый исполнитель (ОВ-26, FR-44, FR-45, FR-46)

#### Scenario: Очистка исполнителя в форме редактирования

- **GIVEN** существует задача с назначенным исполнителем
- **WHEN** пользователь очищает поле исполнителя в форме редактирования и сохраняет
- **THEN** задача сохраняется без исполнителя; строка исполнителя на карточке отображается курсивом «Unassigned» (ОВ-24)

#### Scenario: Select исполнителя — из пользователей системы

- **GIVEN** пользователь открыл поле исполнителя в форме редактирования
- **WHEN** пользователь раскрывает список
- **THEN** список содержит пользователей системы (owner, wife) — не произвольный текст (ОВ-26)

## MODIFIED Requirements

### Requirement: Формы создания и редактирования по дизайну V3

Формы создания и редактирования задачи MUST быть приведены к дизайну V3 по всем зонам расхождения (FR-34, FR-48, DEF-005): (1) вид выбранных тегов в форме; (2) оформление полей ввода (input/textarea) по токенам полей V3 — радиус, рамки, фокус-кольцо; (3) отображение выбранного приоритета (селект/иконки/цвет); (4) форма редактирования целиком — сверка с мокапом V3. Критерий приемки: формы создания/редактирования соответствуют мокапу V3 pixel-consistent по токенам — цвета, радиусы, типографика, состояния; все интерактивные элементы форм MUST быть покрыты стилями (урок DEF-004). Соответствие не вводит новых функций и не меняет валидацию — только визуал и состояния. Поле исполнителя в форме редактирования (ОВ-26, дельта «Редактирование задачи») проектируется сразу по мокапу V3 — новое поле не создает нового расхождения.

#### Scenario: Форма редактирования соответствует мокапу V3

- **GIVEN** пользователь открыл форму редактирования существующей задачи
- **WHEN** форма сверяется с мокапом V3 по токенам
- **THEN** цвета, радиусы, типографика и состояния формы соответствуют мокапу V3, включая поле исполнителя (select, ОВ-26) — оно оформлено по токенам V3 и не создает нового расхождения (FR-48)

#### Scenario: Поля ввода оформлены по токенам полей V3

- **GIVEN** пользователь авторизован и открыл форму создания задачи
- **WHEN** пользователь осматривает поля ввода (input/textarea) и фокусируется на поле
- **THEN** поля оформлены по токенам полей V3 — радиус, рамки, фокус-кольцо; фокус отображается фокус-кольцом

#### Scenario: Выбранные теги отображаются по дизайну V3

- **GIVEN** пользователь открыл форму задачи и выбрал в поле «Теги» значения
- **WHEN** пользователь осматривает выбранные теги
- **THEN** выбранные теги отображаются по дизайну V3 (оформление выбранных значений — одна из зон расхождения DEF-005 устранена)

#### Scenario: Выбранный приоритет отображается по дизайну V3

- **GIVEN** пользователь открыл форму задачи
- **WHEN** пользователь выбирает приоритет (low/medium/high)
- **THEN** выбранный приоритет отображается по дизайну V3 (селект/иконки/цвет)

#### Scenario: Негативный: все интерактивные элементы покрыты стилями

- **GIVEN** открыта форма создания или редактирования задачи
- **WHEN** пользователь осматривает все интерактивные элементы формы (поля, кнопки, крестики, селекты)
- **THEN** ни один интерактивный элемент не остался с дефолтным браузерным оформлением без стилей (урок DEF-004)
