# Delta: search

## ADDED Requirements

### Requirement: Вкладка поиска старых задач
В системе MUST быть отдельная вкладка поиска по архивным (старым) задачам, доступная через сайдбар (FR-10).

#### Scenario: Переход на вкладку поиска через сайдбар
- **GIVEN** пользователь авторизован и видит сайдбар
- **WHEN** пользователь выбирает в сайдбаре раздел поиска
- **THEN** открывается вкладка поиска по старым задачам

### Requirement: Фильтр-конструктор по признакам задачи
Вкладка поиска MUST содержать фильтр-конструктор — выбор значений признаков задачи для фильтрации (FR-11): «аналог JQL, вариант с выбором». Пользователь MUST иметь возможность комбинировать условия по нескольким признакам.

#### Scenario: Фильтр по одному признаку
- **GIVEN** в системе есть задачи с разными значениями признака «приоритет»
- **WHEN** пользователь выбирает в конструкторе значение приоритета и выполняет поиск
- **THEN** в результатах отображаются только задачи с выбранным приоритетом

#### Scenario: Комбинация условий по нескольким признакам
- **GIVEN** в системе есть задачи с различными комбинациями признаков
- **WHEN** пользователь задает условия по двум признакам одновременно (например, категория + тег) и выполняет поиск
- **THEN** в результатах отображаются только задачи, удовлетворяющие обоим условиям

#### Scenario: Поиск без заданных условий
- **GIVEN** в системе есть архивные задачи
- **WHEN** пользователь выполняет поиск, не задавая ни одного условия
- **THEN** отображаются все задачи (пустой фильтр не ограничивает выборку)

### Requirement: Режим advanced с SQL-подобным синтаксисом
Фильтр-конструктор MUST иметь кнопку переключения в режим advanced: текстовое поле с фильтром в SQL-подобном синтаксисе, доступное для просмотра и правки (FR-12). Переключение MUST синхронизировать фильтр между режимами: условие, собранное в конструкторе, отображается в advanced как текст; отредактированный текст применяется при поиске.

#### Scenario: Переключение конструктора в advanced
- **GIVEN** пользователь задал в конструкторе условия поиска
- **WHEN** пользователь нажимает кнопку переключения на advanced
- **THEN** отображается текстовое поле с текущим фильтром в SQL-подобном синтаксисе, соответствующим заданным условиям

#### Scenario: Правка фильтра в advanced и применение
- **GIVEN** пользователь находится в режиме advanced с отображенным фильтром
- **WHEN** пользователь правит текст фильтра и выполняет поиск
- **THEN** результаты соответствуют отредактированному фильтру

#### Scenario: Негативный: некорректный фильтр в advanced
- **GIVEN** пользователь находится в режиме advanced
- **WHEN** пользователь вводит синтаксически некорректный текст фильтра и выполняет поиск
- **THEN** система показывает сообщение об ошибке синтаксиса фильтра; данные при этом не изменяются и не удаляются

### Requirement: Поиск через API
Поиск MUST быть доступен программно через API в дополнение к веб-интерфейсу (FR-8): API-запрос поиска принимает условия фильтра и возвращает совпадающие задачи.

#### Scenario: Поиск через API с фильтром
- **GIVEN** вызывающий авторизован и в системе есть задачи с разными признаками
- **WHEN** вызывающий отправляет API-запрос поиска с условием по признаку
- **THEN** API возвращает только задачи, удовлетворяющие условию

#### Scenario: Негативный: поиск через API без авторизации
- **GIVEN** вызывающий не авторизован
- **WHEN** вызывающий отправляет API-запрос поиска
- **THEN** API отвечает 401 Unauthorized, результаты не возвращаются
