# Delta: regression

## ADDED Requirements

### Requirement: Регрессионный прогон обязателен для изменений

Автотест-сьют `tests/` (82 теста по 80 approved-кейсам `test-model/approved/add-kanban-core/`) MUST иметь статус **регрессионного набора** — постоянного артефакта проекта — и быть обязательным этапом рабочего процесса для каждого последующего изменения (change) проекта. Каждый будущий change MUST быть подтвержден полным зеленым регресс-прогоном `tests/` до архивации своего пакета. Новые тест-кейсы будущих изменений MUST добавляться в регрессионный набор.

Источник: распоряжение Заказчика (2026-09-18) — внедрение сьюта в пакете add-kanban-core было частью задач 5.x/7.x; с завершением релиза 1 сюит переходит в постоянный регресс для всех следующих релизов/изменений. Запуск — `pytest` из venv-окружения проекта (backend/venv, зависимости из `backend/requirements.txt`), переменные окружения — по `tests/README.md`.

#### Scenario: Регресс зеленый — change может быть заархивирован

- **GIVEN** изменение (новый change) реализовано: задачи его tasks.md выполнены, QA пройден
- **WHEN** выполнен полный регресс-прогон сьюта `tests/` и все тесты зелены (0 failed)
- **THEN** change подтвержден и может быть заархивирован (дельты слиты в master-spec, пакет перенесен в changes/archive/)

#### Scenario: Регресс красный — change не архивируется, дефект фиксируется

- **GIVEN** изменение (новый change) реализовано
- **WHEN** регресс-прогон `tests/` падает (хотя бы один тест красный) при корректном коде теста
- **THEN** change НЕ архивируется; дефект продукта фиксируется баг-репортом (`test-model/bugs/`), изменение дорабатывается, после чего прогон повторяется до зеленого результата

#### Scenario: Новые кейсы последующих изменений пополняют регрессионный набор

- **GIVEN** очередное изменение вводит новый функционал со своими одобренными тест-кейсами
- **WHEN** кейсы автоматизированы (автотесты с трассировкой TC-N в docstring, скилл test-automation)
- **THEN** их автотесты добавляются в регрессионный набор `tests/` и участвуют во всех последующих регресс-прогонах проекта
