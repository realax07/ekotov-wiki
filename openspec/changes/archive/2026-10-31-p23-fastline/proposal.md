# Proposal: p23-fastline

## Change ID

`p23-fastline`

## Why

P23 «Фастлайн — отдельная линия сверху доски» (PRODUCT_BACKLOG.md, заявлено
2026-10-20). Дословная заявка Заказчика (является requirements — роль BA
выполнена Заказчиком лично, решение ПМ 2026-10-20; BA-артефакт не создается):

> «Давай сделаем фастлайн в борде отдельной линией сверху из трех столбцов.
> Чтобы явно заметно было что он есть. Таски фастлайна только на нем. Если
> тасок нет, линия пустая, но отображается. Там подсказки показывать не надо
> если ничего нет. Нам нужен дизайн в этом релизе».

Дизайн-фаза завершена: мокапы `design/p23-fastline/v2-*.png` (вариант A —
подложка + рамка + шапка FASTLINE) УТВЕРЖДЕНЫ — решения Заказчика ОВ-1…ОВ-5
(2026-10-20):

1. Вариант отделения — **A** (подложка + рамка + заголовок).
2. Счетчик в шапке — **убрать**.
3. Пустой фастлайн — **полная зона** (как в мокапе).
4. Цвета DnD-приемников (голубой фастлайн / терракота канбан) — **подходят**.
5. Перемещение fast-задач между 3 столбцами фастлайна — **нужно**.

Новое ограничение Заказчика (2026-10-20): в фастлайне **ТОЛЬКО 1 задача**
одновременно (до выполнения). 3 столбца = этапы одной fast-задачи. Новая
fast-задача не вставляется, пока предыдущая не выполнена (дизайн учесть:
состояние «занято» — мокапы `v2-blocked`, `v2-dnd-blocked`).

Сегодня fast line — это подсветка плитки (`task-card-fast`) ВНУТРИ обычных
столбцов канбана (spec `fastline`, FR-3): fast-задача стоит первой в столбце
(ORDER BY is_fast DESC), отдельной зоны нет, «заметности» линии нет, этапы
не выражены. Инвариант ≤1 активной fast-задачи и priority-lock (fast ⇒ high)
на бэке уже есть (409 «fast line occupied», 422 «fast requires high»).

## What Changes

Отдельная горизонтальная зона **FASTLINE** над основным канбаном доски:
подложка `--p-blue-050` + рамка `--p-blue-200` + серифный заголовок FASTLINE
(без счетчика, ОВ-2), три столбца-этапа «Ожидает» / «В работе» / «Выполнено».
Fast-задачи отображаются ТОЛЬКО в зоне — из основного канбана исключены.
Пустая зона отображается полностью, без подсказок. Вставка второй fast-задачи
заблокирована: кнопка «+ Fast-задача» disabled + чип-запрет; DnD обычной
задачи в занятую зону — красный пунктир + not-allowed. Единственная fast-карта
свободно перемещается DnD между тремя столбцами зоны (приемник — голубой
пунктир; канбан остается терракотовым). API не меняется: этапы зоны —
существующие статусы todo/in_progress/done, перемещение — существующий
POST /api/tasks/{id}/move, ограничение ≤1 — существующие 409/инварианты.
Миграция НЕ нужна (флаг is_fast и статусы есть). Релиз-инфраструктура
(deploy/RUNBOOK, сервисы, контейнеры) не трогается.

## Scope

### In

- Разметка зоны FASTLINE в `frontend/templates/board.html` (шапка, 3
  столбца-этапа, кнопка «+ Fast-задача»).
- Рендер/разделение задач по `is_fast` (зона ↔ канбан), DnD внутри зоны,
  запрет DnD канбан→зона и зона→канбан, блокировки — `frontend/static/js/board/`
  (`cards.js`, `state.js`, `task-form.js`, `api.js`) и `frontend/static/css/board.css`.
- Бамп `static_v` в `backend/app/pages.py` (IR-03).
- Спецификация: дельты домена `p23-fastline` (новая capability) + MODIFIED
  домена `fastline` (линия больше не подсветка внутри канбана).

### Out

- Бэкенд-логика `backend/app/board.py` / `tasks.py` — БЕЗ изменений
  (инварианты переиспользуются, см. impact.md §2); правки только по
  результатам ревью.
- `contracts/openapi.json` — не меняется (новых/измененных эндпоинтов нет).
- Миграции БД — нет (is_fast, status, done_at, archived_at существуют).
- deploy/RUNBOOK, сервисы `services/*`, контейнеры — не трогаются.
- P21 пп.5–7 (fastline UI-кластер) — стилистически смежно, реализуется
  отдельно/после (PRODUCT_BACKLOG, «Связь»).
- Мобильная раскладка зоны — мокапы только 1440×900; минимальная адаптация
  (вертикальная укладка столбцов) без нового дизайна, эскалация в design.md §7.

## Approach

Данные не меняются: принадлежность зоне = `is_fast = 1 AND archived_at IS NULL`;
этап зоны = существующий `status` (Ожидает=todo, В работе=in_progress,
Выполнено=done). Вся новая логика — клиентская (разделение, рендер, DnD,
блокировки); серверные правила (409 ≤1, priority-lock, автоархивация МСК-дня)
уже покрывают поведение зоны. Подробные решения и отвергнутые альтернативы —
`design.md`; карта влияния и гейты J58/IR — `impact.md`.
