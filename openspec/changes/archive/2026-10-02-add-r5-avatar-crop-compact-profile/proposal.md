# Proposal: add-r5-avatar-crop-compact-profile

## Change ID

`add-r5-avatar-crop-compact-profile`

## Why

Доработка профиля Релиза 4 по ТЗ `docs/ba/requirements-r5.md` (черновик, готов к передаче СА; дословные вводные Заказчика 2026-09-30): FR-49…FR-56, NFR-11…NFR-15, ОГР-21…ОГР-24 (+ОГР-25 из конвейера J25), Д-12…Д-13. Открытые вопросы ОВ-СА-1…ОВ-СА-6 адресованы СА и решены в `design.md` этого пакета (раунд вопросов Заказчику не открывался — 0 ОВ к Заказчику).

Цель: (1) при загрузке нового аватара пользователь сам выбирает область отображения в кружке — фото двигается под круглой маской, зумируется, итог виден в предпросмотре до применения; вместо автоматического center-crop «что попало в центр»; (2) страница настроек пользователя (FR-39 Р4) приводится к единой карточке V3 — аватар, имя, роль, bio, смена пароля в одном визуальном блоке («более красивой и компактной» — дословно Заказчика).

База: аватар Р4 на проде (main 529cd4e + hotfix; статика r4.0) — загрузка `POST /api/profile/avatar` png/jpg ≤2 МБ, серверный center-crop 256×256 (Д-8), хранение `/var/lib/ekotov-wiki/avatars/<user_id>.png`, кеш-бастинг `?v=avatar_updated_at` (B-3), отображение в сайдбаре/профиле/tooltip'ах. Р4-пакет (`add-r4-user-profile-ticket-view`) на момент старта не заархивирован — дельты этого пакета строятся поверх контрактов Р4 как «нового as is».

## What Changes

Дельты по доменам (все — в `specs/` этого пакета):

| Домен | Тип дельты | Требования | Содержание |
|---|---|---|---|
| `auth` | MODIFIED (1) | FR-54, NFR-11, NFR-12, NFR-14, ОГР-21, Д-8/Д-13 (Requirement «Загрузка аватара») | При наличии JS-canvas клиент сам формирует кадрированный квадрат (вариант А, ОВ-СА-1); сервер сохраняет контракт и ОБЯЗАТЕЛЬНО повторно валидирует/ресайзит пришедший файл (недоверие клиенту); при недоступности canvas/JS — прежнее поведение (серверный center-crop, NFR-14); существующие аватары не перекроиваются (ОГР-21) |
| `settings` | MODIFIED (1) + ADDED (2) | FR-55 (карточка V3 — Requirement «Страница настроек пользователя»), FR-49…FR-53 (кроп-виджет), FR-56 (адаптив), NFR-13 (тач), NFR-15 (клавиатура/aria) | Единая карточка профиля V3; кроп-виджет (маска, drag, зум слайдер/колесо, предпросмотр, «Применить»/«Отмена»); адаптив одной колонкой; тач-жесты и клавиатурная доступность |

API-контрактов новых нет (ОВ-СА-3: `POST /api/profile/avatar` сохраняется as-is, multipart `file`, png/jpg ≤2 МБ; `avatar_updated_at` и кеш-бастинг не меняются — ОГР-23). Схема БД не меняется. Новых python-зависимостей нет (Pillow/python-multipart уже в requirements с Р4); новых фронтенд-зависимостей нет (ОГР-1) — виджет на ванильном JS/Canvas.

## Scope

### In scope

- FR-49 (Must): загруженное фото под круглой маской = итоговый кружок; перемещение фото drag-ом.
- FR-50 (Must): зум — слайдер и колесо мыши; пределы зума и поведение мелких исходников — решение СА (ОВ-СА-4, design §3).
- FR-51 (Must): предпросмотр результата в реальном времени — ровно то, что станет аватаром.
- FR-52 (Must): кнопка «Применить» — аватар заменен выбранной областью; актуализация кружка сайдбара/профиля/tooltip'а по `?v=avatar_updated_at` (ОГР-23).
- FR-53 (Must): отмена (кнопка «Отмена», закрытие виджета, уход со страницы) — прежний аватар без изменений, на сервер ничего не уходит, `?v=` не меняется.
- FR-54 (Must): вариант передачи результата — **А (фронт-кроп, canvas → готовый квадрат)**; вердикт СА — design §1 (ОВ-СА-1/2).
- FR-55 (Must): единая карточка V3 — аватар, display_name, роль, bio, смена пароля в одном визуальном блоке по токенам V3 и мокапу `design/form-style-v3.html`; состав полей Р4 не меняется (FR-40/41/42 сохранены).
- FR-56 (Must): адаптив — одна колонка на узких экранах, кроп-виджет полнофункционален на таче (NFR-13).
- NFR-11 (Must): на сервер уходит только итоговый квадрат (≤ ~40–150 КБ), исходник остается в браузере.
- NFR-12 (Must): лимит исходника ≤2 МБ png/jpg — без изменений; серверная валидация обязательна.
- NFR-13 (Must): тач — touch-drag, pinch-to-zoom (ОВ-СА-5, design §4), слайдер зума работает на таче обязательно.
- NFR-14 (Should): fallback без JS-canvas — простая загрузка файла как сейчас (серверный center-crop Р4), виджет не показывается, ошибки JS не ломают страницу.
- NFR-15 (Must): слайдер зума с клавиатуры, клавиатурный аналог drag, aria-атрибуты, reduced-motion (ОГР-17 Р4).
- ОГР-21: существующие аватары не перекраиваются и не мигрируют; кроп только при новой загрузке.
- ОГР-22: релизный бамп `static_v` (одно значение, формат `r5.x`, урок DEF-002/003, C-5 ревью Р4).
- ОГР-23: механизм отображения аватара и раздел «Настройки» (FR-23/ОГР-20 Р4) не затрагиваются; страница профиля — переработка верстки существующей `GET /settings/profile`.
- ОГР-25: дизайн на токенах V3; живой макет (J25) кроп-виджета + компактной карточки — артефакт `design/avatar-crop-v3.html` до dev-задач.
- Д-12: виджет открывается сразу после выбора файла в той же карточке; «Применить» завершает и кроп, и загрузку.
- Д-13: итог — квадрат 256×256 PNG (Д-8) при любом варианте.

### Out of scope

- Перекадрирование уже сохраненных аватаров без перезагрузки (Won't ТЗ; ОГР-21).
- Серверное распознавание лиц/автокадрирование (Won't).
- Кроп-виджет вне страницы профиля (в tooltip'ах/сайдбаре кропа нет).
- Новые поля профиля (состав Р4 не расширяется); новые API-эндпоинты и параметры кропа (ОВ-СА-3 — контракт сохранен); смена WebP-стратегии, темы, общего раздела «Настройки».

## Approach

Brownfield-дельты поверх «as is» (master + Р4-пакет). Вариант А (ОВ-СА-1): кроп-интерактив целиком клиентский — модуль `frontend/static/js/avatar-crop.js` + CSS в `profile-settings.css` (токены V3); пользователь двигает фото под круглой маской, зумирует (слайдер/колесо/pinch), видит live-предпросмотр; «Применить» рендерит выбранную область в canvas 256×256 → PNG blob → существующий `POST /api/profile/avatar`. Сервер НЕ доверяет клиенту (ОВ-СА-2): повторная Pillow-валидация (формат PNG/JPEG, ≤2 МБ, квадратность не гарантируется) + безусловный resize до 256×256 LANCZOS и сохранение как PNG — путь, имя, `avatar_updated_at`, кеш-бастинг и ответы API не меняются. Fallback (NFR-14): нет canvas/FileReader — прежний input file без виджета, сервер сам center-crop (ветка Р4 сохраняется). Страница `GET /settings/profile` переверстывается в единую карточку V3 (FR-55): аватар-зона с кропом, поля профиля, блок смены пароля внутри того же блока (момент подтверждения пароля — ОВ-СА-6, design §5); адаптив одной колонкой (FR-56). Дизайн — по живому макету `design/avatar-crop-v3.html` (J25, ОГР-25) с дизайн-проходом design_validator (E13) до dev и после. Деплой: релизный бамп `static_v` = `r5.x` одним значением (ОГР-22); миграций БД и правок nginx нет.

## Assumptions (дефолты Д-12/Д-13 с правом возражения + решения СА по ОВ-СА-1…6)

- Д-12: виджет открывается сразу после выбора файла в той же карточке; «Применить» завершает кроп и загрузку — принято без возражений.
- Д-13: итог — 256×256 PNG независимо от варианта — принято; согласуется с Д-8/ОГР-23.
- ОВ-СА-1: вариант А (фронт-кроп) — вердикт и сравнение в research §1 / design §1.
- ОВ-СА-2: серверная повторная валидация + resize 256×256 обязательны (design §2).
- ОВ-СА-3: контракт `POST /api/profile/avatar` сохраняется as-is, без поля параметров кропа (design §2).
- ОВ-СА-4: пределы зума — min = cover (фото закрывает маску), max = ×3 от cover; мелкие исходники — апскейл до cover с предупреждением о потере качества (design §3).
- ОВ-СА-5: тач — touch-drag + pinch-to-zoom + слайдер (обязательно); клавиатура — слайдер (стрелки), фокус на виджете — стрелки двигают фото, +/− зум (design §4).
- ОВ-СА-6: смена пароля — в той же карточке ниже профиля, подтверждение по кнопке «Сменить пароль» (не по blur) (design §5).
