## Рекомендации к нарезке (швы)

Пакет делится на **5 делегационных швов** (по зонам файлов):

1. **Миграция + backend-API** (2.1 + 2.2 + 2.3): `backend/app/migrate_wiki.py`,
   `sanitize.py`, `wiki.py`, `pages.py` — один сабагент, зона монолита.
2. **Фронт-рендер + дерево + поиск** (3.1 + 3.2): `frontend/static/js/wiki/`
   (tree/page/search) + `wiki.css` + шаблоны.
3. **WYSIWYG-редактор** (3.3): `frontend/static/js/wiki/editor.js` — самый
   сложный фронтовый кусок, можно параллелить с швом 2 ПОСЛЕ стабилизации
   API-контрактов §3 (мокает `fetch` в юнит-проверках).
4. **Версии + откат** (3.4): `frontend/static/js/wiki/history.js` — тонкий
   клиент готового API; параллелен швам 2/3.
5. **Deploy** (4.4 + 4.5): репетиция миграции, стенд, прод — последовательная
   цепочка с участием Заказчика.

**Неразделимые зоны** (не делить между агентами):

- `backend/app/sanitize.py` + `backend/app/wiki.py` — санитизация вызывается
  на записи в каждом API-методе; контракт sanitizer меняется синхронно с
  API → один агент (шов 1).
- `frontend/static/css/wiki.css` — общий файл стилей швов 2/3/4: стилистические
  токены фиксирует первым шов 2, швы 3/4 только дополняют селекторами своих
  блоков (без перекройки общих правил); конфликт правок недопустим.
- `frontend/templates/wiki.html` — каркас создает 2.3, волнами 3.x
  дополняется; правки шаблона не параллелить (последовательно 3.1 → 3.2 →
  3.3 → 3.4 по разделам шаблона).
- `[design]`-задача 1.1 — вне швов (ui_designer, `design/**`), всегда первой.

Параллельность: 1.1 ∥ (2.1 → 2.2 → 2.3); после утверждения мокапов И
завершения 2.2/2.3 — (3.1 → 3.2) ∥ 3.3 ∥ 3.4; затем 4.1 → 4.2 → 4.3 → 4.4 →
4.5. Тестовые наборы — строго раздельными делегациями-раннерами (см. план
прогонов в шапке); падение набора останавливает следующий.

## Ворота и правила

- `openspec validate --all --strict` — green на каждом шаге.
- Дизайн-фаза Р4/Р5: ui_designer (`design/wiki-*.html`) → Заказчик
  (развилка) → dev по мокапам → design_validator (review-NNN-design.md).
  СА/dev мокапы не рисуют. J10: приемка мокапа — утверждение Заказчика.
- Волна 3 не стартует без утверждения мокапов 1.1 (approval_ref
  оркестратора) — директива Заказчика «Не забывай что нам макеты дизайна
  нужны».
- Без внешних библиотек (ОГР-8): редактор — contenteditable/vanilla,
  sanitizer — stdlib `html.parser`; никаких CDN.
- Токены V3 «Бумага» (`app.css :root`) — без хардкода цветов.
- Права: паттерн `board.py` (сессионные куки, middleware 401/redirect),
  без ролевых различий (решение 7).
- Репетиция миграции на копии прод-БД — обязательный шаг 4.4 до боевой
  накатки 4.5 (урок Р4).
- [ops]-задача 4.5 — только с явным участием Заказчика; протокол приемки
  обязателен.
- Тестовые наборы (api / web-mobile / web-desktop / смок) — каждая отдельной
  делегацией-раннером; порядок и REPORT-файлы — в шапке этого файла.
