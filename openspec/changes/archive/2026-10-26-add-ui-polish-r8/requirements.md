## 1. Общее описание

UI-полировка по 12 заметкам Заказчика после QA-прогона галереи: fastline-UI
(подсветка плитки вместо столбца, блок в форме создания по макету, галочка в
редактировании), модалка просмотра тикета по общему дизайну (дизайн-фаза),
шапка комментария — автор и человекочитаемая дата вместо id и timestamp,
остаточный UX-фикс таг-combobox (сброс текста поля после выбора), единый
стиль кнопок поиска/фильтрации, иконки всех разделов сайдбара, favicon
(inline-SVG data-URI, стиль V3), фикс смещения текста кнопки настроек,
переименование файла галереи (новая API-операция PUT + форма в лайтбоксе),
ритм сетки галереи при разнопропорциональных изображениях (дизайн-фаза,
варианты превью).

Нумерация продолжает сквозную: последние использованные — FR-86
(add-gallery-service), NFR-21.

## 2. Аудитория

Пользователи — оба пользователя системы (owner и PE) паритетно: все правки
видимы обоим без разделения прав. Исполнители пакета: ui_designer (мокапы
B/J, зона `design/**`), dev (фронтенд + бэкенд-join автора + API images),
QA (web-сьют, design_validator), Заказчик (утверждение мокапов, приемка).

## 3. Функциональные требования (FR)

- **FR-87** (Must) — P12 п.5: подсветка fast line применяется ТОЛЬКО к плитке
  fast-задачи; фоновая окраска/рамка всего столбца при наличии fast-задачи
  убирается (дословно: «Fastline красит весь столбец в синий цвет — убрать
  эту логику, синяя только сама плитка»). Позиция, порядок и все прочие
  свойства fast line не меняются.
- **FR-88** (Must) — P12 п.6: блок fastline в форме создания задачи приводится
  к утвержденному макету (мокап V3): расположение, отступы, состояния галочки
  соответствуют макету; поведение (блокировка приоритета high, одна fast-задача)
  сохраняется без изменений.
- **FR-89** (Must) — P12 п.7: форма редактирования задачи содержит переключатель
  fast line: текущее состояние is_fast задачи отображается; переключение
  подчиняется тем же инвариантам, что и при создании (fast ⇒ priority=high;
  не более одной fast-задачи в активных статусах — 409 «fast line занята»
  обрабатывается). Серверная поддержка is_fast при редактировании — техрешение
  design §2 (существующие инварианты fast-спеки не ослабляются).
- **FR-90** (Must) — P12 п.2 [design]: модальное окно просмотра тикета на борде
  приводится к общему дизайну — ВИД строго по мокапу ui_designer, утвержденному
  Заказчиком ДО dev; read-only семантика, кнопка «Редактировать» и сценарии
  закрытия сохраняются. После dev соответствие мокапу проверяет design_validator.
- **FR-91** (Must) — P12 п.3: в шапке каждого комментария отображаются автор
  комментария (имя пользователя, по author_id) и человекочитаемые дата и время
  (вместо id и сырого timestamp). Данные автора доставляются API списка
  комментариев (join users); контракт записи комментария не меняется.
- **FR-92** (Must) — P12 п.4: после выбора или создания тега в комбобоксе
  введенный текст MUST убираться из поля ввода (остается только визуальная
  метка-чип с крестиком ниже поля). Множественное добавление подряд и удаление
  тегов по одному работают: чип удаляется, текст поля не блокируется.
- **FR-93** (Must) — P12 п.8: кнопка «Найти» advanced-поиска получает отступы
  и единый стиль кнопок действия на токенах V3; тот же паттерн проверяется и
  приводится для кнопок поиска/фильтрации во всех разделах (поиск, галерея).
- **FR-94** (Must) — P12 п.9: каждый раздел сайдбара (доска, поиск, wiki,
  настройки) получает иконку inline-SVG в едином стиле с иконками «Мониторинг»
  и «Галерея» (эталон — иконка «Мониторинг», мокапы 1.1 галереи); токенная
  окраска, состояния разделов не меняются.
- **FR-95** (Must) — P12 п.10: страница получает favicon — inline-SVG data-URI
  в `base.html` (БЕЗ внешних файлов, ОГР-8), в стиле V3 «Бумага» с
  терракотовым акцентом. Кеш-политика favicon учитывается (браузеры кешируют
  агрессивно; при изменении иконки — смена URL, design §3).
- **FR-96** (Must) — P12 п.1: нажатие (active/focus-состояние) кнопки настроек
  НЕ смещает ее текст; визуальные состояния приводятся к токенам V3.
- **FR-97** (Must) — P12 п.11: авторизованный пользователь может переименовать
  загруженный файл галереи (original_name): операция `PUT /api/images/{id}/name`
  (непустое имя; 401 без сессии; 404 для несуществующего изображения), форма
  переименования — в full-screen лайтбоксе; новое имя отображается в сетке и
  лайтбоксе без перезагрузки страницы.
- **FR-98** (Must) — P12 п.12 [design]: сетка галереи держит визуальный ритм
  при изображениях разных пропорций — ячейки сетки выровнены (вариант
  фикс-высота/кроп/masonry выбирается Заказчиком из вариантов мокапа);
  ВИД превью строго по утвержденному варианту мокапа; после dev соответствие
  проверяет design_validator.

## 4. Нефункциональные требования (NFR)

- **NFR-22** (Must): правки UI не деградируют доступность и производительность
  действующих паттернов: aria-атрибуты комбобокса сохраняются (NFR-17/18
  преемственно), иконки — inline-SVG без внешних запросов, favicon — data-URI
  без внешних файлов (ОГР-8); токены V3 (не хардкод цветов); DOM-контракты —
  идентификаторы элементов форм не переименовываются (ОГР-28).

## 6. Ограничения

- Дизайн-фаза (Д-паттерн Р4/Р5): мокапы — ui_designer (зона `design/**`),
  утверждение — Заказчик ДО dev (развилка; dev-задачи B/J не стартуют без
  утверждения, прецедент Д-5), ревью вида — design_validator.
- Без внешних файлов и библиотек (ОГР-8): иконки и favicon — inline-SVG /
  data-URI; стили — токены V3 «Бумага» (app.css :root).
- Инварианты fast-спеки не ослабляются: fast ⇒ priority=high, одна fast-задача
  в активных статусах, назначение вручную.
- Read-only семантика модалки просмотра и кнопка «Редактировать» сохраняются
  (FR-47, Д-9); DOM-id форм не меняются (ОГР-28).
- Rename — только original_name (отображаемое имя); физические имена файлов в
  томе images-data не меняются.
- П.4 — остаточный UX-фикс поверх починенного BUG-009 (выбор тега уже работает);
  спека комбобокса (NFR-17/18) сохраняется.
