# Дельта specs: tasks — шапка комментария и сброс поля таг-combobox (P12 пп.3, 4)

## MODIFIED Requirements

### Requirement: Признаки задачи

Задача MUST иметь признаки: название, описание, приоритет, категория, срок,
комментарии, теги (FR-9), а также исполнителя (assigned_to_id, nullable) и
создателя (creator_id) (FR-37). Признаки MUST отображаться в карточке задачи;
assigned и creator отображаются во всех карточках задач и в выдаче поиска
(FR-45), в tooltip'е карточки (FR-44) и учитываются в поиске (FR-46, дельта
search). Шапка каждого комментария MUST отображать автора комментария (имя
пользователя по author_id) и человекочитаемые дату и время — вместо id и
сырого timestamp (P12 п.3, FR-91); данные автора доставляются API списка
комментариев (join users, только добавление поля в ответ); контракт записи
комментария MUST NOT меняться (author_id — из сессии, как прежде).

#### Scenario: Просмотр признаков в карточке

- **GIVEN** существует задача с заполненными признаками
- **WHEN** пользователь открывает карточку задачи
- **THEN** все заполненные признаки отображаются в карточке, включая creator и assigned

#### Scenario: Редактирование признаков

- **GIVEN** пользователь открыл карточку существующей задачи
- **WHEN** пользователь изменяет значения признаков и сохраняет
- **THEN** измененные значения сохраняются и отображаются при последующем открытии карточки

#### Scenario: Комментарии к задаче

- **GIVEN** пользователь открыл карточку существующей задачи
- **WHEN** пользователь добавляет комментарий
- **THEN** комментарий сохраняется и отображается в карточке

#### Scenario: Шапка комментария — автор и человекочитаемая дата

- **GIVEN** в задаче есть комментарии от обоих пользователей
- **WHEN** пользователь открывает список комментариев
- **THEN** в шапке каждого комментария отображаются имя автора (по author_id)
  и человекочитаемые дата и время — id и сырой timestamp не показываются
  (P12 п.3, FR-91)

#### Scenario: Контракт записи комментария не изменился

- **GIVEN** клиент добавляет комментарий существующим запросом
- **WHEN** сравнивается контракт до и после изменения
- **THEN** POST-запрос и его ответ не изменились (author_id — из сессии);
  в ответе GET списка ДОБАВЛЕНО поле имени автора — существующие поля на
  месте (обратная совместимость, FR-91)

#### Scenario: Creator задачи неизменяем

- **GIVEN** существует задача с creator
- **WHEN** любой пользователь редактирует задачу через интерфейс или API
- **THEN** creator задачи не изменяется (изменение creator API-запросом отклоняется — поле не входит в контракт редактирования, FR-37)

#### Scenario: Негативный: assigned — только существующий пользователь

- **GIVEN** вызывающий авторизован
- **WHEN** вызывающий отправляет API-запрос создания или редактирования задачи с assigned, ссылающимся на несуществующего пользователя
- **THEN** API отвечает ошибкой валидации (4xx); задача не создается/не изменяется (FR-37)

### Requirement: Кастомный комбобокс подсказок тегов

Автодополнение поля «Теги» MUST быть кастомным комбобоксом — полноценной заменой нативного datalist (ОВ-2, NFR-17): отклик на ввод ≤100 мс — фильтрация локальная, без запроса на каждый символ; навигация стрелками вверх/вниз + выбор Enter; Escape закрывает дропдаун; клик вне — закрытие. При сбое загрузки подсказок ввод тегов MUST НЕ блокироваться (преемственность FR-26). На тач-устройствах тап по пункту MUST выбирать значение; дропдаун MUST НЕ ломать скролл страницы (NFR-17). Доступность (NFR-18): поле «Теги» несет роль combobox, дропдаун — listbox с пунктами option; состояние раскрытия отражается aria-expanded; активный пункт навигации клавиатурой — aria-activedescendant; количество подсказок озвучивается скринридером. Значения в DOM MUST попадать только через textContent — не через innerHTML (XSS, преемственность dom.js и правил FR-29/FR-34). После выбора или создания тега введенный текст MUST убираться из поля ввода (P12 п.4, FR-92): остается только визуальная метка-чип с крестиком; множественное добавление подряд и удаление тегов по одному MUST работать.

#### Scenario: Отклик фильтрации локальный и быстрый

- **GIVEN** дропдаун комбобокса открыт, подсказки загружены
- **WHEN** пользователь вводит символы в поле «Теги»
- **THEN** фильтрация дропдауна выполняется локально на клиенте (без запроса на каждый символ) с откликом ≤100 мс (NFR-17)

#### Scenario: Клавиатурная навигация и выбор

- **GIVEN** дропдаун показывает подсказки
- **WHEN** пользователь перемещается стрелками вверх/вниз и нажимает Enter
- **THEN** активный пункт подсвечивается и перемещается, Enter выбирает активную подсказку (NFR-17, СЦ-6)

#### Scenario: Escape и клик вне закрывают дропдаун

- **GIVEN** дропдаун комбобокса открыт, форма задачи открыта
- **WHEN** пользователь нажимает Escape первый раз
- **THEN** закрывается только дропдаун — форма остается открытой; второе нажатие Escape закрывает форму (FR-61, СЦ-8); клик вне дропдауна также закрывает его (NFR-17)

#### Scenario: Тач — тап по пункту, скролл не сломан

- **GIVEN** форма задачи открыта на тач-устройстве (или в эмуляции)
- **WHEN** пользователь тапает по пункту дропдауна и скроллит страницу
- **THEN** тап выбирает значение; скролл страницы вне дропдауна не нарушен (NFR-17, СЦ-6)

#### Scenario: Aria-атрибуты комбобокса

- **GIVEN** пользователь открыл форму и фокусируется на поле «Теги»
- **WHEN** дропдаун раскрывается и пользователь navigирует стрелками
- **THEN** поле имеет роль combobox с aria-expanded, дропдаун — listbox с пунктами option, активный пункт — aria-activedescendant; количество подсказок озвучивается скринридером (NFR-18, ОВ-2, СЦ-6)

#### Scenario: Значения в DOM только через textContent

- **GIVEN** заведен тег, содержащий HTML-специальные символы (например, `<b>x</b>`)
- **WHEN** значение попадает в пункты дропдауна и чипы
- **THEN** значения отрисованы как текст через textContent — разметка не исполняется (XSS-safe, NFR-18)

#### Scenario: Поле очищается после выбора тега

- **GIVEN** пользователь ввел текст в поле «Теги» и дропдаун показывает
  подсказки
- **WHEN** пользователь выбирает подсказку (кликом или Enter)
- **THEN** введенный текст убран из поля ввода — осталась только метка-чип
  с крестиком ниже поля (P12 п.4, FR-92)

#### Scenario: Поле очищается после создания нового тега

- **GIVEN** пользователь ввел новое значение тега, отсутствующее в подсказках
- **WHEN** пользователь создает тег
- **THEN** текст убран из поля ввода — созданный тег виден только чипом
  с крестиком (P12 п.4, FR-92)

#### Scenario: Множественное добавление и удаление по одному

- **GIVEN** пользователь добавил в форму три тега подряд
- **WHEN** пользователь проверяет поле и список чипов, затем удаляет теги
  крестиками по одному
- **THEN** после каждого добавления поле пусто (текст не копится), все три
  чипа присутствуют; каждое удаление крестиком убирает ровно один чип,
  остальные остаются; поле ввода работает (FR-92)
