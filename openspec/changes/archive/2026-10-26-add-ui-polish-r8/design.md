## §2. Fastline в редактировании (FR-89) — техрешение

Форма редактирования: ряд `.fast-row` показывается с чекбоксом в текущем
состоянии задачи (`is_fast` приходит в данных задачи). Правила:

- Включение галочки в редактировании: приоритет блокируется на high
  (существующая логика 4.3/FR-27 переиспользуется); сохранение — существующий
  `PATCH/PUT` задачи с `is_fast: true`; конфликт «fast line занята» (409) —
  существующая обработка «fast line занята».
- Выключение: is_fast=false, приоритет разблокируется.
- Если серверное API не принимает is_fast при редактировании (проверка на
  стенде в задаче dev) — минимальная дельта API задач (расширение контракта
  редактирования полем is_fast, инварианты fast-спеки не ослабляются).
  Альтернатива «read-only отображение состояния» — только по решению
  Заказчика на утверждении ТЗ (эскалация в REPORT-0.1).
- Инварианты сохраняются: fast ⇒ high (API-валидация), ≤1 fast в активных,
  назначение вручную.

## §4. API-контракт rename (FR-97)

- **`PUT /api/images/{id}/name`** — сервис `images` (паттерн существующих
  операций, сессия обязательна).
- Тело: `{"name": "<непустая строка ≤255>"}` (новое отображаемое имя,
  original_name).
- Ответы: `200 {"id", "name", …метаданные}`; `401` без сессии; `404` изображение
  не существует; `422` пустое/отсутствующее имя или >255 символов
  (валидационный обработчик сервиса — паритет ядру `{"error", "details"}`).
- Семантика: меняется ТОЛЬКО отображаемое имя (original_name в БД); физические
  файлы (filename/thumb_name) и путь `/images/…` НЕ меняются — ссылки и кеш
  файлов не инвалидируются.
- Права: оба пользователя паритетно (ОВ-4 галереи — доступ общий; разделения
  прав нет). Юнит-тесты — `services/images/tests/` (happy/401/404/422).
- UI: в full-screen лайтбоксе кнопка-иконка «переименовать» у имени; инлайн-поле
  + Enter/✓; обновление имени в карточке сетки и лайтбоксе через textContent
  (XSS-дисциплина).

## §5. Шапка комментария (FR-91) — техрешение

- `GET /api/tasks/{id}/comments`: SELECT join `users` по `author_id` →
  поле `author_name` (display_name; fallback — login). Только ДОБАВЛЕНИЕ поля
  в ответ (обратная совместимость); POST-контракт (author_id из сессии) —
  без изменений.
- Клиент: человекочитаемый формат даты/времени из `created_at` (ISO 8601) —
  `Intl.DateTimeFormat` ru-RU («дд.мм.гггг, чч:мм»); рендер textContent.
- Модалка просмотра (B) использует ту же шапку — единый компонент разметки.
