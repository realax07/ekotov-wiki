# Research: add-p20-contracts

Альтернативы ключевых техрешений зафиксированы ДО выбора; выбор по каждой
развилке сделан Заказчиком (ОВ-1…ОВ-9, §7a ТЗ, «давай по рекомендациям ba»).
СА выбирает только механику исполнения внутри рамок решений.

## Р-1. Форма и место контрактов (ОВ-2)

| Вариант | За | Против |
|---|---|---|
| **JSON в `contracts/` + yaml-якорь у сервиса (выбран)** | Уже отработан на search (2026-10-04): единое место для гейта, стабильный дифф, экспорт скриптом | Якорь — второй файл (но он навигационный, 12 строк) |
| YAML-спеки в `services/<svc>/` | Спека рядом с кодом | Ломает существующий образец search; истина размазывается по 4 местам; гейту сложнее сверять |
| Только `contracts/` без якорей | Меньше файлов | Теряется навигационный якорь структуры monorepo (services/README) |

## Р-2. Строгость схемной валидации (ОВ-1)

- (а) только множества путей — как сейчас: не ловит дрейф полей (реальная
  проблема — BUG-026 менял семантику реакций при живых тестах путей).
- **(б) выбрано: схемы 200 happy-path + типовая ошибка 401/422**, без
  `additionalProperties: false` — ловит реальные дрейфы полей, не ломает
  существующие тесты на гибкость ответов (NFR-45).
- (в) полная (все ошибки + additionalProperties:false) — дороже в
  сопровождении при 2 пользователях (ОГР-6).

## Р-3. Жесткость и реализация гейта дрейфа (ОВ-5, FR-140)

| Вариант | За | Против |
|---|---|---|
| **DENY декларативными impact-правилами (выбран)** | Механический запрет по практике IR-01/IR-07; false-positive ≈ 0 (перегенерация одним скриптом); код ворот не меняется — только JSON | Требует точного `when`-триггера (см. design §5) |
| DENY отдельным CI-скриптом (прогон экспорт-скриптов + git diff) | Ловит и «тихое» расхождение экспорт↔файл | Подъем 4 сервисов в CI — минуты против ≤30 сек (NFR-46); правило-подход ловит тот же класс дрейфа (код без контракта) |
| warn-комментарий | Дешевле | warn перестают читать (практика конвейера) |

## Р-4. Точность триггера правила ядра

Грубый триггер `when: ^backend/app/` → require `contracts/openapi.json`
дает ложные DENY: `backend/app/pages.py` правится каждым static_v-бампом
(IR-03), `migrate_*.py` — миграциями; require нельзя выполнить
«пустой» перегенерацией (нет диффа файла — требование не засчитано).
Отвергнутые альтернативы: исключения списком файлов в коде ворот (меняет
код гейта — против декларативности) и require через pr_body-маркер
(адвокатура вместо механики). Выбрано: `content_when`-триггер по
добавленной строке декоратора маршрута (`+@router.get|post|…`) — штатный
механизм схемы impact_rules.json (АУД-4/Н25), патч читается воротами.

## Р-5. nginx-тест (ОВ-8, FR-141)

- **Тест + карта (выбрано)**: маршрутизация — часть контракта потребителя;
  правка nginx-локаций сегодня ничем не защищена.
- Только карта — документ без гейта не ловит правки.

## Р-6. Порядок волн (ОВ-4)

- **Д-16 с заменой: search → video → images → weather (выбрано)**:
  search — эталон формата (подтверждение экспортом), дальше сервисы по
  одному за волну — дельты не пересекаются, каждая волна зеленая
  независимо; video сразу после search — самый живой код (волна 7 +
  BUG-026 в октябре-ноябре), спека ловит дрейф раньше.
- Альтернатива «все 4 сервиса разом» отвергнута: риск гейта и ревью на
  4 сервисах разом, против паттерна «эталон выделения» services/README.

## Р-7. Скоуп внешних зависимостей (Д-17, ОВ-9)

Open-Meteo и games — вне скоупа: чужие API не контролируем, стоимость
спеки не оправдана; в карте — документированные зависимости. Отвергнуто
«полная спека games»: код вне монорепо, контракт не тестируем в CI.
