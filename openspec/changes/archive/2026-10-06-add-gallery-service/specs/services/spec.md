# Дельта specs: services — сервис-писатель images (ADDED)

## ADDED Requirements

### Requirement: Сервис images пишет в общую БД

Сервис `images` MUST работать с общей БД в **read-write профиле своей
схемы**: создает/читает/пишет только таблицы галереи (изображения,
категории галереи, теги, реакции, комментарии) и MUST NOT изменять схему
и данные существующих таблиц ядра (users — только чтение). Схему таблиц
галереи MUST создавать ядро миграцией (один владелец миграций —
преемственность deploy: «Миграции БД — one-shot до подъема нового app»);
сам сервис images миграций НЕ выполняет. Файлы изображений MUST храниться
в именованном томе `images-data` (не в общем томе wiki-data, не в БД).

#### Scenario: RW-маунт общей БД

- **GIVEN** сервис images смонтирован
- **WHEN** конфигурация контейнера инспектируется
- **THEN** том `wiki-data` подключен в режиме RW (в отличие от search:
  images пишет реакции/комментарии/метаданные в свои таблицы)

#### Scenario: Границы записи — только таблицы галереи

- **GIVEN** сервис images работает, пользователь ставит лайк и комментирует
- **WHEN** инспектируются записи БД
- **THEN** изменены только таблицы галереи (реакции, комментарии,
  метаданные изображений); таблицы ядра (tasks, comments, categories,
  sessions) не изменены; users — только читался

#### Scenario: Схему создает ядро, сервис не мигрирует

- **GIVEN** деплой нового релиза с галереей
- **WHEN** контейнер images стартует
- **THEN** миграционные шаги images не выполняются — таблицы галереи
  созданы one-shot-миграцией ядра до подъема (паритет search: схема —
  зона ядра)

#### Scenario: Данные изображений в отдельном томе

- **GIVEN** изображения загружены
- **WHEN** тома инспектируются
- **THEN** файлы изображений находятся в томе `images-data`; том
  `wiki-data` содержит только БД и аватары — как прежде
