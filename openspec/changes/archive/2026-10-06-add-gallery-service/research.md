# Research: add-gallery-service

Альтернативы ключевых техрешений (полный разбор — design.md):

1. **Размещение сервиса**: отдельный контейнер `images` по образцу
   `services/search` (FastAPI :8379, свой том images-data) vs монолитный
   роутер в ядре app. Выбор — **отдельный сервис** (вводные задачи пакета:
   «сервис по образцу services/search»; масштабируемая топология p12;
   файлы в отдельном томе, не в wiki-data).
2. **Профиль записи в общую БД**: RW-профиль images (пишет свои таблицы
   gallery, читает users) vs копия search-паттерна «только ядро пишет».
   Выбор — **RW для своей схемы** (гарантия — maунт БД RW, но владельцем
   схемы gallery объявлен images: ядро таблицы gallery не трогает; ядро
   выполняет только их первичное создание миграцией — владение схемой
   остается за одним сервисом).
3. **Теги изображений**: переиспользование таблиц `tags`/`task_tags` через
   переименование в универсальные vs собственные `gallery_tags`/
   `image_tags` по тому же образцу. Выбор — **собственные таблицы gallery
   с тем же механизмом** (task_tags привязаны к задачам каскадом; «обобщать»
   существующие таблицы — риск для регресса трекера без требования
   Заказчика; механизм «словарь + связка» воспроизводится, не разделяется).
4. **Категории галереи**: отдельный справочник `image_categories` vs
   переиспользование справочника задач `categories`. Выбор — **отдельный
   справочник** (семантика категорий изображений и задач разная; слияние
   сужает свободу обеих сущностей; переименование/удаление — вне ТЗ).
5. **Превью**: генерация Pillow на upload (хранение рядом с оригиналом в
   images-data) vs on-the-fly при каждом запросе. Выбор — **на upload**
   (одноразовая цена, стабильная отдача из тома nginx'ом без участия
   сервиса; Pillow уже в requirements).
6. **Отдача файлов**: nginx `location /images/` alias в том (паритет
   `/avatars/`) vs прокси на FastAPI. Выбор — **nginx alias** (сервис не
   в горячем пути статики; кеш-заголовки как у аватаров).
7. **Авторизация загрузки**: любая сессия (ОВ-4) vs role-рендер/ограничения
   по роли. Выбор — **равноправно для обеих учеток** (ОВ-4 дословно).
