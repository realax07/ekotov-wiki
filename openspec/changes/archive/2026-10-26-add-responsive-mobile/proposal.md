# Proposal: add-responsive-mobile

## Change ID

`add-responsive-mobile`

## Why

Пакет **P14 «Адаптивная верстка (mobile-first)»** (PRODUCT_BACKLOG.md, P14,
строки 242–263; решение Заказчика 2026-10-06). Вводные проработаны БА
(`openspec-drafts/p14-responsive-requirements-draft.md`), все развилки закрыты
ответами Заказчика ОВ-1…ОВ-6 (2026-10-08, Флоу-канал ОВ; решение о старте
`decisions/2026-10-08-p14-responsive-start.md`, action `create_change`):

- **ОВ-1** — сценарии подтверждены: «вечером с телефона глянуть/закрыть задачи»
  и «быстро найти задачу/заметку» первичны; галерея с телефона вторична;
- **ОВ-2** — мобильная навигация: **бургер/drawer** (не таб-бар);
- **ОВ-3** — доска на мобиле: **свайп колонок со scroll-snap**; санкция на
  дельту FR-62 («без горизонтальной прокрутки» — про страницу, не про жест-
  контейнер колонок) дана;
- **ОВ-4** — модалка тикета на мобиле: **fullscreen**, просмотр → кнопка
  «Редактировать» — одной модалкой;
- **ОВ-5** — планшет 768px вторичен: гарантируем только «не разваливается»;
- **ОВ-6** — целевые устройства: **iPhone 11** (жена, минимальный вьюпорт
  **375px** portrait) и **Samsung Galaxy Z Fold 7** (Заказчик; раскрытое
  состояние ~600–700px+ трактуем как узкий планшет — «не разваливается»).

Прод — матричный стек p12-rc1; r8-polish-3 на проде (зависимость P14 ← P12
выполнена). Продукт — личная wiki на двоих фиксированных пользователей (owner
и wife, доступ общий — прецедент галереи ОВ-4): критерий приемки — «вживую на
проде с телефона» (как у галереи), а не лабораторные метрики. Ключевой
наблюдаемый результат: **«Открываю https://…:10443 с телефона — все разделы
читаются без зума и горизонтальной прокрутки, до любого действия дотягиваюсь
большим пальцем»**.

## What Changes

Адаптив — **представление существующего UI, не новые функции**: мобильные
ветки CSS/JS поверх отполированного desktop-вида r8-polish (токены V3), без
переписывания существующего поведения. Дельты по **6 capability**:

| Группа | Что меняется | Тип дельты | Capability | Источник |
|---|---|---|---|---|
| Каркас и навигация | Бургер/drawer ≤768px (переиспользует `.sidebar`), индикация активного раздела | ADDED | navigation | FR-99, FR-100, ОВ-2 |
| Доска ≤480px | Свайп-колонки со scroll-snap и индикатором (вместо случайного стека) | MODIFIED | board | FR-101, ОВ-3 (санкция FR-62) |
| Модалка тикета ≤480px | Fullscreen; просмотр → «Редактировать» одной модалкой | MODIFIED | board | FR-102, ОВ-4 |
| Форма задачи ≤480px | Тач-таргеты, инпуты ≥16px, клавиатура — дополнение FR-62 | MODIFIED | tasks | FR-62, NFR-23/24 |
| Поиск ≤480px | Одна колонка, крупный инпут (сейчас 0 @media) | ADDED | search | FR-103 |
| Настройки ≤480px | Одна колонка; 768px-ветка FR-56 сохраняется | ADDED | settings | FR-104 |
| Лайтбокс | Свайпы по изображению (порог ~50px), без зум-жестов | MODIFIED | gallery | FR-105, ОВ-1 (С3) |
| Мобильный вид в целом | По утвержденным мокапам ui_designer (дизайн-фаза волна 0) | ADDED | navigation | FR-106, преемственность FR-86/FR-90 |

Сквозные NFR: тач-таргеты ≥44px (NFR-23), инпуты font-size ≥16px (NFR-24),
safe-area (NFR-25), без горизонтальной прокрутки страницы на 375px — кроме
осознанного свайп-контейнера колонок (NFR-26), единая система брейкпоинтов
480/768 (NFR-27), `<meta viewport>` без запретов масштабирования (NFR-28).

Нумерация продолжает сквозную: последние использованные — **FR-98, NFR-22**
(add-ui-polish-r8). Полное ТЗ — `requirements.md` этого пакета (статус ставит
Заказчик).

## Scope

### In scope

- Брейкпоинт-каркас: mobile-ветка `app.css` + `base.html` + `app.js` — сцена
  на всю ширину, сайдбар → drawer по бургеру (DOM не дублируется), safe-area.
- Доска ≤480px: колонки фиксированной ширины (~80–85vw), scroll-snap,
  индикатор точек; быстрое «Выполнено» остается главным тач-действием.
- Модалка тикета ≤480px: fullscreen-оболочка; read-only просмотр →
  «Редактировать» открывает редактирование в той же оболочке.
- Mobile-ветки `search.css` и `settings.css` (сейчас 0 @media) — одна колонка,
  инпуты ≥16px, тач-таргеты.
- Лайтбокс галереи: свайп листает по touchstart/move/end (порог ~50px,
  только по области изображения); стрелки-зоны и клавиатура desktop остаются.
- Смоук-проверки wiki и login на 375px; ревизия 768px-ветки profile-settings
  (FR-56 без регресса).
- Дизайн-фаза (волна 0, обязательна — прецедент Д-5): мокапы ui_designer →
  утверждение Заказчиком → dev по мокапам → design_validator.
- Автотесты с мобильным viewport (Playwright device-эмуляция 375×812 и
  480×800) + приемка Заказчиком вживую на проде с телефона (С1–С3).

### Out of scope (anti-scope, утвержден Заказчиком)

- Планшет-макеты: 768px — только «не разваливается»; новых планшетных
  макетов не проектируем (ОВ-5). Z Fold 7 раскрытый — та же трактовка (ОВ-6).
- Landscape: гарантируем только portrait; landscape — «не разваливается,
  скроллится», без отдельных макетов.
- PWA / manifest / «на весь экран без браузера».
- Dark mode / theme-переключатель.
- Тач-drag-and-drop карточек — мобильный перенос через существующие действия
  (меню перемещения, быстрое «Выполнено»); фиксируется в дельте board.
- Зум-жесты: double-tap zoom и pinch-zoom своей реализацией НЕ строим
  (нативный pinch браузера остается); запрет `user-scalable=no` не вводится.
- Новые функции, виджеты, resize-drag — P14 меняет только представление.
- Браузеры старше ~2022 — вне рассмотрения (2 пользователя, личные устройства).

## Impact

- **Код:** `frontend/static/css/{app,board,search,settings,gallery,profile-settings}.css`
  (mobile-ветки), `frontend/templates/base.html` (бургер, safe-area),
  `frontend/static/js/app.js` (drawer), `frontend/static/js/board/*`
  (индикатор свайп-колонок), `frontend/static/js/gallery.js` (touch-свайпы).
  Backend НЕ меняется (только представление).
- **Спеки:** дельты 6 capability — navigation (ADDED ×2), board (MODIFIED ×2),
  tasks (MODIFIED ×1), search (ADDED ×1), settings (ADDED ×1), gallery
  (MODIFIED ×1); после архивации — обновление master-спек.
- **Данные/инфра:** без изменений (ни БД, ни compose, ни nginx).
- **Пользователи:** desktop-вид обоих пользователей не меняется; на телефоне
  появляется мобильное представление всех разделов.
- **QA:** новая мобильная секция web-сьютов (device-эмуляция); приемка «вживую».

## Risks

- **Каркас — самая широкая зона** (app.css/base.html опираются все страницы):
  риск регресса desktop-верстки. Смягчение: правки только внутри @media-веток;
  desktop-регресс (смоук всех разделов на ≥1024px) — в каждой волне.
- **Свайп-колонки vs привычный стек**: текущий стек — работающее поведение
  (побочный эффект FR-62). Смягчение: санкция ОВ-3 зафиксирована; scroll-snap
  деградирует к обычному горизонтальному скроллу без JS.
- **Свайп лайтбокса vs скролл панели комментариев**: конфликт жестов.
  Смягчение: обработчик только на области изображения (design §5), панель
  скроллится независимо; desktop-стрелки не трогаются.
- **iOS-особенности** (авто-зум инпутов <16px, клавиатура поверх модалки,
  safe-area): закрываются NFR-24/25 и проверкой на 375×812 device-эмуляции.
- **Зависимость от дизайн-фазы**: dev-волны 1–4 не стартуют до утверждения
  мокапов Заказчиком (развилка волны 0; прецедент Д-5).
