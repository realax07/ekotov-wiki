# Design: add-responsive-mobile

Версия: r1 (2026-10-08). Источники: requirements.md пакета (FR-99…FR-106,
NFR-23…NFR-29), БА-проработка + ответы ОВ-1…ОВ-6, аудит research.md §1,
действующий код `frontend/` (app.css/base.html/board.css/gallery.css).

## §0. Дизайн-фаза (волна 0, обязательна — паттерн Р4/Р5, прецедент Д-5)

P14 — крупная видимая UI-дельта: мокапы рисует **ui_designer** (зона
`design/**`, продукт-код не пишет), Заказчик утверждает ДО dev, после dev
**design_validator** сверяет фактический вид с мокапами
(`test-model/reviews/add-responsive-mobile/review-NNN-design.md`). Мокапы —
standalone HTML по токенам V3 «Бумага», без внешних библиотек (ОГР-8),
контраст AA. Состав мокапов:

1. **каркас**: шапка с бургером, drawer поверх затемнения (открыт/закрыт),
   индикация активного раздела — 375px;
2. **доска**: свайп-колонки (видны текущая + край следующей), индикатор
   точек, карточка с быстрым «Выполнено» — 375px;
3. **модалка тикета**: fullscreen-просмотр read-only + состояние
   «Редактировать» той же оболочки — 375px;
4. **поиск и настройки**: одна колонка — 375px;
5. **лайтбокс**: изображение + панель вниз, зоны свайпа — 375px.

Развилка Заказчика — утверждение мокапов: волны 1–4 НЕ стартуют до
зафиксированного утверждения (approval_ref оркестратора).

## §1. Брейкпоинт-система (NFR-27)

| Точка | Диапазон | Трактовка |
|---|---|---|
| `≤480px` | телефон portrait (мин. 375px) | первичный мобильный макет: drawer, свайп-колонки, fullscreen-модалки |
| `481–768px` | большой телефон / узкий планшет (Z Fold 7 раскрытый ~600–700px+) | вторичная утилитарная ветка: drawer уже активен, колонки доски могут оставаться настольными при помещении; критерий «не разваливается» |
| `>768px` | desktop | текущий вид — без изменений |

Реализация: существующие `@media (max-width: 480px)`-ветки сохраняются и
дополняются; в `app.css` добавляется `@media (max-width: 768px)` для каркаса
(сайдбар→drawer). Новых одноразовых ширин не вводить; где это возможно —
CSS-переменные `--bp-*` не нужны (медиавыражения не параметризуются —
зафиксировано: два магических числа 480/768, комментируются в общем месте).

## §2. Каркас и drawer (FR-99, FR-100; зона волны 1)

- **DOM без дублирования**: `.sidebar` остается единственным источником
  навигации. На ≤768px CSS переводит его в фиксированную off-canvas панель
  (`transform: translateX(-100%)`, переход по классу `sidebar-open` на
  `<body>`). Бургер — кнопка в шапке `base.html` (видима только в
  мобильной ветке, тач-таргет ≥44px — NFR-23).
- **JS (`app.js`, ванильный)**: toggle класса, закрытие по: клику по пункту,
  клику по подложке-оверлею, Esc; подложка — элемент `base.html`
  (`.sidebar-backdrop`), display управляется тем же классом. Фокус-менеджмент
  минимальный: при открытии фокус на первый пункт, при закрытии — возврат на
  бургер (преемственность доступности NFR-18-паттернов).
- **Индикация активного раздела (FR-100)**: заголовок раздела в шапке
  (серверный шаблон уже знает раздел) — дешевый и читаемый вариант; активный
  пункт drawer подсвечивается существующим стилем `.active`.
- **Safe-area (NFR-25)**: `padding` футера/шапки с
  `env(safe-area-inset-bottom|left|right)`; `viewport-fit=cover` в
  `<meta viewport>` — проверить и добавить при отсутствии.
- **Сцена**: на ≤768px `margin-left` сцены обнуляется — контент на всю
  ширину.

## §3. Доска: свайп-колонки (FR-101, ОВ-3; зона волны 2)

- **CSS (`board.css`, ≤480px)**: контейнер колонок —
  `display: flex; overflow-x: auto; scroll-snap-type: x mandatory;` колонка —
  `flex: 0 0 82vw; scroll-snap-align: start;` (80–85vw — точное значение
  фиксирует dev по мокапу). Страница вне контейнера скролла по X не имеет
  (NFR-26). Деградация: без поддержки scroll-snap — обычный горизонтальный
  скролл (те же свайпы, без прилипания).
- **Индикатор точек**: JS (`board/*`) синхронизирует активную точку со
  scroll-позицией (слушатель `scroll` + расчет ближайшей колонки); тап по
  точке — скролл к колонке (`scrollIntoView({behavior:'smooth'})` —
  отключать при `prefers-reduced-motion`, преемственность ОГР-17).
- **Быстрое «Выполнено»** остается видимым на карточке (главное тач-действие,
  тач-таргет ≥44px). Тач-DnD не реализуется — anti-scope; перенос через
  существующие действия.
- **Форма тикета**: действующая 480px-ветка FR-62 (одна колонка, full-width)
  сохраняется; дополняется `font-size ≥16px` на полях (NFR-24) и тач-таргетами.

## §4. Модалка тикета fullscreen (FR-102, ОВ-4; зона волны 2)

- На ≤480px обе оболочки — просмотр (read-only, Д-9) и редактирование —
  получают общий fullscreen-контейнер: `position: fixed; inset: 0;` шапка с
  названием и крестиком, тело скроллится, футер с действиями.
- **Одна модалка, два состояния (ОВ-4)**: «Редактировать» заменяет
  содержимое на форму (существующую), возврат — обратно в просмотр;
  закрытие всегда возвращает на доску в прежнюю позицию (сохранение
  scroll-позиции доски — существующее поведение модалок, не регрессировать).
- **Клавиатура iOS**: при фокусе инпута прокрутка активного поля в видимость
  (нативный `scrollIntoView` на focusin); double-скролл (модалка+подложка) —
  подложка `overflow: hidden` при открытой модалке.
- Инпуты ≥16px (NFR-24), кнопки ≥44px (NFR-23).

## §5. Лайтбокс: свайпы (FR-105; зона волны 4)

- **Зоны жеста**: touch-обработчики (`touchstart/touchmove/touchend`)
  навешиваются ТОЛЬКО на элемент изображения — панель комментариев скроллится
  независимо (конфликт жестов снят зонированием).
- **Алгоритм**: фиксация start-точки; на touchend горизонтальный сдвиг ≥50px
  и |dx| > |dy| ⇒ следующий/предыдущий (циклично по текущей выдаче —
  паритет стрелок); иначе — считается тапом (существующее поведение тапа не
  меняется). Без зум-жестов (anti-scope); нативный pinch браузера
  сохраняется (NFR-28 — без запретов масштабирования).
- Стрелки-зоны и клавиатура (ArrowLeft/ArrowRight, Esc) — без изменений;
  свайп — дополнительный способ листания.

## §6. Search / settings / профиль / wiki / login (FR-103, FR-104; волна 3)

- `search.css`, `settings.css`: новые `@media (max-width: 480px)`-ветки —
  одна колонка, full-width, инпуты ≥16px, тач-таргеты ≥44px, без прокрутки
  страницы по X. Именованные требования — только наблюдаемое поведение;
  конкретная сетка — по мокапам волны 0.
- `profile-settings.css`: ревизия действующей 768px-ветки (FR-56) на 480px —
  ожидается донастройка отступов/таргетов, не переделка; кроп-виджет —
  полнофункционален на таче (существующие тач-жесты кропа не трогаются).
- wiki (заглушка) и login (узкая форма): смоук на 375px, точечные правки
  только если разваливается (NFR-26).

## §7. QA-стратегия (волна 5)

- **Автотесты**: web-сьют с device-эмуляцией (Playwright, профили 375×812 и
  480×800): smoke каждого раздела — отсутствие прокрутки страницы по X
  (`document.documentElement.scrollWidth <= innerWidth`), drawer
  открывается/закрывается, ключевые действия (создание тикета, «Выполнено»,
  поиск, загрузка/просмотр фото, свайп лайтбокса — синтетический
  touch-свайп).
- **design_validator** — фактический вид против утвержденных мокапов.
- **Приемка Заказчика** — вживую на проде с телефона, сценарии С1–С3
  (критерий галереи: «вживую»).
- **Desktop-регресс** в каждой волне: смоук всех разделов ≥1024px.

## §8. Осознанные не-цели

- Планшет-макеты, landscape-макеты, PWA, dark mode, тач-DnD, зум-жесты,
  новые функции (proposal Out of scope).
- Backend/API/БД/compose/nginx — без изменений: P14 меняет только
  представление.
- Внешние библиотеки адаптива (медиа-querи-фреймворки, gesture-библиотеки) —
  ОГР-8.
