# Дельта specs: board — мобильная доска и модалка тикета P14

## MODIFIED Requirements

### Requirement: Отображение канбан-доски

Приложение MUST показывать авторизованному пользователю страницу канбан-доски со всеми задачами, разложенными по столбцам (FR-1). На каждой карточке задачи (все столбцы и fast line) MUST отображаться исполнитель (assigned) и создатель (creator) (FR-45): при назначенном исполнителе — имя пользователя; при пустом assigned — строка исполнителя отображается всегда, курсивом «Unassigned» (ОВ-24). При наведении курсора на карточку MUST появляться всплывашка (tooltip) с assigned и creator задачи (FR-44) — единый механизм всплывашек с tooltip'ом профиля (ОГР-17); при системной настройке уменьшения движения анимации всплывашки MUST отключаться (ОГР-17). На ширинах ≤480px доска MUST отображаться как горизонтальный свайп-контейнер колонок: колонки фиксированной ширины (~80–85vw) листаются свайпом со scroll-snap (прилипание по колонке) и видимым индикатором текущей колонки (ОВ-3, FR-101); горизонтальная прокрутка ограничена контейнером колонок — страница вне него MUST оставаться без прокрутки по X (уточнение FR-62: «без горизонтальной прокрутки» относится к странице, санкция на жест-контейнер колонок — ответ Заказчика ОВ-3, 2026-10-08). Тач-DnD карточек НЕ реализуется — перенос на таче через существующие действия (меню перемещения, быстрое «Выполнено»); быстрое действие «Выполнено» MUST оставаться доступным без drag-and-drop. На ширинах >480px доска отображается как прежде (три колонки рядом, NFR-29).

#### Scenario: Открытие доски с задачами

- **GIVEN** пользователь авторизован и в системе есть задачи в разных столбцах
- **WHEN** пользователь открывает страницу доски
- **THEN** все задачи отображаются в столбцах, соответствующих их текущему статусу; на каждой карточке отображаются assigned и creator (FR-45)

#### Scenario: Открытие пустой доски

- **GIVEN** пользователь авторизован и в системе нет ни одной задачи
- **WHEN** пользователь открывает страницу доски
- **THEN** доска отображается с тремя пустыми столбцами без ошибок

#### Scenario: Строка исполнителя на карточке без assigned

- **GIVEN** существует задача без исполнителя (assigned пуст, ОВ-23/nullable FR-37)
- **WHEN** пользователь открывает доску
- **THEN** на карточке этой задачи строка исполнителя отображается всегда, курсивом «Unassigned» (ОВ-24)

#### Scenario: Строка исполнителя на карточке с assigned

- **GIVEN** существует задача с назначенным исполнителем
- **WHEN** пользователь открывает доску
- **THEN** на карточке отображается имя исполнителя (FR-45)

#### Scenario: Единый механизм всплывашек

- **GIVEN** на доске есть карточки задач; блок профиля внизу сайдбара присутствует
- **WHEN** пользователь наводит курсор на карточку и на блок профиля
- **THEN** обе всплывашки выполнены одним и тем же механизмом (ОГР-17)

#### Scenario: Tooltip карточки показывает assigned и creator

- **GIVEN** пользователь авторизован; существует задача с creator «owner» и исполнителем «wife»
- **WHEN** пользователь наводит курсор на карточку задачи
- **THEN** появляется всплывашка с assigned («wife») и creator («owner») задачи (FR-44)

#### Scenario: Уменьшение движения отключает анимации всплывашек

- **GIVEN** в системе пользователя включена настройка уменьшения движения (prefers-reduced-motion)
- **WHEN** пользователь наводит курсор на карточку и на блок профиля
- **THEN** всплывашки появляются без анимации; содержание всплывашек не изменяется (ОГР-17, TC-vis-105)

#### Scenario: Свайп колонок на мобильном

- **GIVEN** пользователь авторизован; на доске есть задачи в нескольких столбцах; вьюпорт ≤480px (проверка 375×812, device-эмуляция)
- **WHEN** пользователь свайпает колонки горизонтально
- **THEN** колонки листаются со scroll-snap (прилипание по колонке), виден край следующей колонки; индикатор точек показывает текущую колонку

#### Scenario: Индикатор синхронен позиции и управляет прокруткой

- **GIVEN** доска открыта на вьюпорте ≤480px
- **WHEN** пользователь свайпает на соседнюю колонку ИЛИ тапает точку индикатора
- **THEN** активная точка следует за прокруткой; тап по точке прокручивает к соответствующей колонке (без анимации при prefers-reduced-motion, ОГР-17)

#### Scenario: Страница без горизонтальной прокрутки вне контейнера колонок

- **GIVEN** доска открыта на вьюпорте ≤480px (проверка 375px)
- **WHEN** пользователь осматривает страницу
- **THEN** прокрутка страницы по X отсутствует — горизонтальное движение
  ограничено контейнером колонок (санкция ОВ-3 на уточнение FR-62)

#### Scenario: Быстрое «Выполнено» доступно с тача

- **GIVEN** доска открыта на вьюпорте ≤480px; в столбце есть задача
- **WHEN** пользователь нажимает быстрое действие «Выполнено» на карточке
- **THEN** задача перемещается без drag-and-drop; тач-таргет действия ≥44×44px (NFR-23)

#### Scenario: Desktop-доска не меняется

- **GIVEN** ширина вьюпорта >480px (проверка ≥1024px)
- **WHEN** пользователь открывает доску
- **THEN** три колонки рядом, drag-and-drop и tooltips работают как прежде (NFR-29)

### Requirement: Просмотр карточки задачи — модальное окно read-only

Просмотр карточки задачи MUST выполняться модальным окном read-only, отличным от форм создания и редактирования (FR-47, решение Заказчика «модальным окном»): все данные задачи — название, описание, приоритет, категория, срок, теги, assigned, creator, комментарии — отображаются только для чтения, без полей ввода и сохранения. Окно просмотра MUST визуально отличаться от форм создания/редактирования на действующих токенах V3 (ОГР-18). Из окна просмотра MUST быть доступен переход к редактированию — кнопка «Редактировать» открывает существующую форму редактирования (Д-9). Клик по карточке открывает окно просмотра; редактирование остается доступным через кнопку «Редактировать» (FR-7 не деградирует). На ширинах ≤480px окно просмотра и форма редактирования MUST открываться в общей fullscreen-оболочке: модалка занимает весь вьюпорт, шапка с крестиком, тело скроллится; переход «Редактировать» заменяет содержимое на форму редактирования в той же оболочке (одна модалка, ОВ-4, FR-102); закрытие возвращает пользователя на доску в прежнюю позицию. Инпуты в модалке на ≤480px имеют font-size ≥16px (NFR-24), кнопки — тач-таргет ≥44×44px (NFR-23). На ширинах >480px модалки отображаются как прежде (NFR-29).

#### Scenario: Клик по карточке открывает окно просмотра

- **GIVEN** пользователь авторизован; на доске есть задача со всеми заполненными признаками и комментариями
- **WHEN** пользователь кликает по карточке задачи
- **THEN** открывается модальное окно просмотра со всеми данными задачи, включая assigned, creator и комментарии; поля только для чтения — ввод и сохранение недоступны (FR-47)

#### Scenario: Окно просмотра отлично от форм создания/редактирования

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь сравнивает окно с формой создания/редактирования
- **THEN** окно просмотра визуально отлично от форм (ОГР-18) и не содержит элементов редактирования (полей ввода, кнопки сохранения), кроме кнопки «Редактировать» (Д-9)

#### Scenario: Переход к редактированию из окна просмотра

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь нажимает кнопку «Редактировать»
- **THEN** открывается существующая форма редактирования этой задачи; изменения после сохранения отображаются в окне просмотра и на карточке (Д-9, FR-7)

#### Scenario: Окно просмотра отображает assigned, creator и комментарии

- **GIVEN** существует задача с creator, назначенным исполнителем и комментариями
- **WHEN** пользователь открывает окно просмотра этой задачи
- **THEN** в окне отображаются creator, assigned (или «Unassigned») и все комментарии задачи — только для чтения (FR-47)

#### Scenario: Закрытие окна просмотра не изменяет данные

- **GIVEN** пользователь открыл окно просмотра задачи
- **WHEN** пользователь закрывает окно (крестик или клик вне окна)
- **THEN** окно закрывается; данные задачи не изменяются; доска отображается в прежнем состоянии (FR-47)

#### Scenario: Fullscreen-модалка на мобильном

- **GIVEN** вьюпорт ≤480px (проверка 375×812, device-эмуляция)
- **WHEN** пользователь открывает просмотр карточки, затем нажимает «Редактировать»
- **THEN** модалка занимает весь вьюпорт; просмотр и редактирование — в одной fullscreen-оболочке (ОВ-4); закрытие возвращает на доску в прежнюю scroll-позицию

#### Scenario: Поля без авто-зума и клавиатура не перекрывает поле

- **GIVEN** открыта fullscreen-модалка редактирования на вьюпорте ≤480px
- **WHEN** пользователь фокусирует поле ввода
- **THEN** поле имеет font-size ≥16px — авто-зум iOS не включается (NFR-24); активное поле прокручивается в видимую область (клавиатура не перекрывает ввод)

#### Scenario: Desktop-модалки не меняются

- **GIVEN** ширина вьюпорта >480px
- **WHEN** пользователь открывает просмотр карточки и редактирование
- **THEN** модалки отображаются в существующем desktop-виде (NFR-29)
