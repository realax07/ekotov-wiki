# Дельта specs: tasks — тач-требования формы задачи P14

## MODIFIED Requirements

### Requirement: Формы создания и редактирования по дизайну V3

Формы создания и редактирования задачи MUST быть приведены к дизайну V3 по всем зонам расхождения (FR-34, FR-48, DEF-005): (1) вид выбранных тегов в форме; (2) оформление полей ввода (input/textarea) по токенам полей V3 — радиус, рамки, фокус-кольцо; (3) отображение выбранного приоритета (селект/иконки/цвет); (4) форма редактирования целиком — сверка с мокапом V3. Критерий приемки: формы создания/редактирования соответствуют мокапу V3 pixel-consistent по токенам — цвета, радиусы, типографика, состояния; все интерактивные элементы форм MUST быть покрыты стилями (урок DEF-004). Соответствие не вводит новых функций и не меняет валидацию — только визуал и состояния. Поле исполнителя в форме редактирования (ОВ-26, дельта «Редактирование задачи») проектируется сразу по мокапу V3 — новое поле не создает нового расхождения. На узких экранах ≤480px форма MUST перестраиваться в одну колонку: все поля full-width, без горизонтальной прокрутки, все поля доступны (FR-62); дропдаун подсказок позиционируется корректно. На ≤480px поля формы (input, textarea, select) MUST иметь font-size ≥16px — без авто-зума iOS при фокусе (NFR-24); интерактивные элементы формы MUST иметь тач-таргет ≥44×44px (NFR-23). Тач-логика модалки подчиняется требованию board «Просмотр карточки задачи» в мобильной fullscreen-оболочке (ОВ-4).

#### Scenario: Форма редактирования соответствует мокапу V3

- **GIVEN** пользователь открыл форму редактирования существующей задачи
- **WHEN** форма сверяется с мокапом V3 по токенам
- **THEN** цвета, радиусы, типографика и состояния формы соответствуют мокапу V3, включая поле исполнителя (select, ОВ-26) — оно оформлено по токенам V3 и не создает нового расхождения (FR-48)

#### Scenario: Поля ввода оформлены по токенам полей V3

- **GIVEN** пользователь авторизован и открыл форму создания задачи
- **WHEN** пользователь осматривает поля ввода (input/textarea) и фокусируется на поле
- **THEN** поля оформлены по токенам полей V3 — радиус, рамки, фокус-кольцо; фокус отображается фокус-кольцом

#### Scenario: Выбранные теги отображаются по дизайну V3

- **GIVEN** пользователь открыл форму задачи и выбрал в поле «Теги» значения
- **WHEN** пользователь осматривает выбранные теги
- **THEN** выбранные теги отображаются по дизайну V3 (оформление выбранных значений — одна из зон расхождения DEF-005 устранена)

#### Scenario: Выбранный приоритет отображается по дизайну V3

- **GIVEN** пользователь открыл форму задачи
- **WHEN** пользователь выбирает приоритет (low/medium/high)
- **THEN** выбранный приоритет отображается по дизайну V3 (селект/иконки/цвет)

#### Scenario: Негативный: все интерактивные элементы покрыты стилями

- **GIVEN** открыта форма создания или редактирования задачи
- **WHEN** пользователь осматривает все интерактивные элементы формы (поля, кнопки, крестики, селекты)
- **THEN** ни один интерактивный элемент не остался с дефолтным браузерным оформлением без стилей (урок DEF-004)

#### Scenario: Полиш не меняет логику и валидацию

- **GIVEN** визуальный проход по форме выполнен (FR-60, Д-15)
- **WHEN** пользователь выполняет обычные операции формы — создание, редактирование, валидацию ошибок (422), fast line, комментарии
- **THEN** логика, состав полей и валидация работают как прежде — изменился только визуал и состояния; регресс формы зеленый (FR-60, DEF-005, СЦ-7)

#### Scenario: Escape закрывает чистую форму сразу

- **GIVEN** открыта форма задачи (создание или редактирование), поля не тронуты
- **WHEN** пользователь нажимает Escape
- **THEN** форма закрывается сразу, без вопроса; данные на сервере не изменились (FR-61, ОВ-3, СЦ-8)

#### Scenario: Escape на грязной форме требует подтверждения

- **GIVEN** открыта форма задачи с несохраненными изменениями (поля отличаются от состояния на момент открытия)
- **WHEN** пользователь нажимает Escape
- **THEN** показывается подтверждение «Закрыть без сохранения?» (паттерн `window.confirm` существующих модалок); отмена → форма осталась с введенными значениями; подтверждение → форма закрыта без сохранения; данные на сервере не изменились (FR-61, СЦ-8)

#### Scenario: Адаптив одной колонкой на узких экранах

- **GIVEN** пользователь открыл форму задачи
- **WHEN** форма просматривается на экране шириной ≤480px (проверка ~375px)
- **THEN** форма перестроена в одну колонку, все поля full-width, модалка без горизонтальной прокрутки, все поля доступны; дропдаун подсказок позиционируется корректно (FR-62, ОВ-3, СЦ-9)

#### Scenario: Поля без авто-зума на мобильном

- **GIVEN** открыта форма задачи на экране шириной ≤480px (проверка 375×812, device-эмуляция)
- **WHEN** пользователь фокусирует любое поле (input, textarea, select)
- **THEN** поле имеет font-size ≥16px — авто-зум iOS не включается (NFR-24)

#### Scenario: Тач-таргеты элементов формы

- **GIVEN** открыта форма задачи на экране шириной ≤480px
- **WHEN** пользователь осматривает интерактивные элементы (поля, кнопки, крестики, селекты, чипы тегов)
- **THEN** эффективная тач-область каждого элемента ≥44×44px (NFR-23)
