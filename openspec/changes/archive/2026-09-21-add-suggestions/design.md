# Design: add-suggestions

Ретроспективный пакет: решения фиксируются по факту реализации `1f11011` (арбитр — `backend/app/suggestions.py`). Спека (specs/search/spec.md) описывает наблюдаемое поведение; этот файл — как оно обеспечено внутри.

## 1. Источник множества подсказок: UNION DISTINCT через task_tags

Схема нормализованная (`tags`, `task_tags`, `tasks.category` — sdd §4); ТЗ упоминало разбор `tasks.tags`, фактическая схема — нормализованная, источник данных тот же (теги существующих задач), контракт не меняется (зафиксировано в requirements-p4.md §3 как допущение).

Один запрос:

```sql
SELECT DISTINCT tags.name
FROM tags
JOIN task_tags ON task_tags.tag_id = tags.id
UNION
SELECT DISTINCT category
FROM tasks
WHERE category IS NOT NULL AND category != ''
ORDER BY 1
```

- **JOIN через task_tags** отсекает осиротевшие теги (строки `tags`, не привязанные ни к одной существующей задаче) — FR-17.
- **UNION (не ALL)** снимает пересечение тегов и категорий: значение из обоих источников входит один раз — set-семантика, FR-16.
- **`category IS NOT NULL AND != ''`** исключает пустые/незаполненные категории — «заведенным вариантом» они не являются, FR-17.
- Сортировка ответа — `ORDER BY 1` в SQL плюс `sorted()` на стороне Python (контроль по кодовым точкам) — FR-16.

## 2. Авторизация: middleware-401, без собственного кода

`GET /api/suggestions` не входит в exempt-список `app/middleware.py` (исчерпывающий: `POST /api/auth/login`, `GET /api/health` — sdd §3). Проверка сессии выполняется единой middleware-точкой: без валидной сессии запрос отклоняется с 401 `{"error": "unauthorized"}` до передачи в роут (FR-18, Must). Роут собственной проверки авторизации не содержит — защита не может быть обойдена добавлением обработчика.

API-контракт (sdd §3.5a, по факту `1f11011`): `GET /api/suggestions` → 200 `{"suggestions": ["...", ...]}`; без сессии — 401. Метод только GET — новые значения эндпоинт не принимает (FR-17).

## 3. UI-механизм: один datalist на оба поля

- `frontend/templates/search.html`: `<datalist id="tag-hints">` + `list="tag-hints"` на обоих полях конструктора («Теги» и «Категория») — нативный механизм подсказок браузера, один общий список на оба поля (FR-15).
- `frontend/static/js/search.js`: `loadSuggestions()` — fetch GET /api/suggestions при открытии вкладки, заполнение `#tag-hints` элементами `option`; без SPA-фреймворков (соответствует sdd §1 — ванильный JS + fetch).

## 4. Альтернативы (рассмотрены, отклонены)

- **json_each по JSON-полю tags** — из формулировки ТЗ; схема нормализованная, потребовала бы денормализации или второго запроса.
- **Разные списки на каждое поле** — против решения Заказчика («по двум столбцам», одно множество).
- **Проверка сессии внутри роута** — дублирование middleware; риск расхождения с exempt-политикой sdd §3.
