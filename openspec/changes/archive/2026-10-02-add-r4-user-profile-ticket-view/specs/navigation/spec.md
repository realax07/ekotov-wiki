# Delta: navigation

## MODIFIED Requirements

### Requirement: Профиль текущего пользователя внизу сайдбара

Сайдбар MUST содержать внизу блок профиля текущего пользователя (FR-33): цветной кружок с первой буквой логина и текстовой подписью. Подписью является display_name, если задан, иначе логин целиком (Д-10). Аватар отображается в блоке профиля при его наличии; при отсутствии аватара используется кружок с первой буквой (fallback, FR-42). Блок профиля MUST быть кликабельным: клик открывает страницу настроек пользователя (FR-39; ОГР-13 отменено решением Заказчика 2026-09-28 — ОГР-15). Текущий пользователь MUST определяться через `GET /api/auth/me` (FR-33). Блок профиля MUST быть доступен на всех страницах функционала для авторизованного пользователя и не вытеснять существующие разделы сайдбара.

#### Scenario: Профиль отображается внизу сайдбара

- **GIVEN** пользователь авторизован (логин «owner», display_name не задан) и находится на любой странице функционала
- **WHEN** пользователь просматривает сайдбар
- **THEN** внизу сайдбара отображается профиль: кружок с буквой «o» (первая буква логина) и подпись с логином «owner» целиком (Д-10)

#### Scenario: Подпись профиля — display_name, если задан

- **GIVEN** пользователь авторизован и задал display_name в профиле (FR-40)
- **WHEN** пользователь просматривает сайдбар (после обновления страницы)
- **THEN** подписью блока профиля является display_name; логин остается идентификатором в tooltip'е (FR-43, Д-10)

#### Scenario: Аватар отображается в блоке профиля

- **GIVEN** пользователь авторизован и загрузил аватар (FR-42)
- **WHEN** пользователь просматривает блок профиля (после обновления страницы)
- **THEN** вместо кружка с первой буквой отображается загруженный аватар

#### Scenario: Клик по профилю открывает настройки пользователя

- **GIVEN** пользователь авторизован и видит блок профиля
- **WHEN** пользователь кликает по блоку профиля
- **THEN** открывается страница настроек пользователя (свой профиль, FR-39) — а не общий раздел «Настройки» со справочником категорий (ОГР-20)

#### Scenario: Профиль показывает сессионного пользователя

- **GIVEN** второй пользователь (жена владельца) авторизована в своей сессии
- **WHEN** второй пользователь открывает любую страницу функционала
- **THEN** внизу сайдбара отображается профиль второго пользователя — его подпись и его аватар (или кружок с первой буквой), не данные другого пользователя

#### Scenario: В профиле нет аватарок-файлов и смены пароля

- **GIVEN** пользователь авторизован и просматривает блок профиля (Релиз 4: ОГР-13 отменено решением Заказчика — ОГР-15)
- **WHEN** пользователь осматривает доступные действия блока профиля
- **THEN** загрузка аватарки, редактирование профиля и смена пароля доступны на открываемой кликом странице настроек пользователя (FR-39…FR-42) — прежнее исключение «в профиле НЕТ аватарок и смены пароля» (ОГР-13) больше не действует; сам блок профиля остается только отображением + переходом в настройки

#### Scenario: Профиль не нарушает верстку сайдбара

- **GIVEN** пользователь авторизован и находится на любой странице функционала
- **WHEN** пользователь просматривает сайдбар
- **THEN** блок профиля размещен внизу сайдбара и не вытесняет существующие разделы (доска, поиск, Wiki, настройки, выход)
