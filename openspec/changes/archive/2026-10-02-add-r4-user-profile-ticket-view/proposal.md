# Proposal: add-r4-user-profile-ticket-view

## Change ID

`add-r4-user-profile-ticket-view`

## Why

Релиз 4 «Карточка: просмотр + профиль пользователя» проекта ekotov-wiki. Источник требований — утвержденное Заказчиком ТЗ `docs/ba/requirements-r4.md` (УТВЕРЖДЕН 2026-09-29; дословные решения Заказчика 2026-09-28 через `PLAN-R4.md` + ответы раунда ОВ-21…ОВ-26 `docs/ba/answers_round4.md`): FR-36…FR-48, NFR-9/10, ОГР-15…ОГР-20, Д-8…Д-11; 6 открытых вопросов закрыты Заказчиком дословно (ов-раунд финальный).

Цель релиза: пользователь ведет профиль (display_name, роль, «о себе», аватар с серверным автосжатием), клик по блоку профиля внизу слева открывает настройки пользователя, при наведении на профиль и карточки — всплывашки (tooltip); задачи получают assigned и creator (с бэкфиллом при миграции), отображаются во всех карточках и в поиске; просмотр тикета — модальное окно read-only; формы приводятся к мокапу V3 (закрытие DEF-005).

## Scope

### In scope

- FR-36 (Must): поля users — display_name, role, bio, avatar; дефолты при пустых значениях (логин вместо display_name — Д-10, кружок вместо аватара — FR-33).
- FR-37 (Must): поля tasks — creator_id и assigned_to_id (nullable); assigned редактируется в форме редактирования (select из пользователей), при создании — опционально (ОВ-26); creator устанавливается сервером, не редактируется.
- FR-38 (Must): бэкфилл creator_id = owner при миграции; assigned_to_id = owner у всех существующих задач (ОВ-23).
- FR-39 (Must): клик по блоку профиля открывает страницу настроек пользователя; страница показывает только свой профиль; общий раздел «Настройки» не затрагивается (ОГР-20).
- FR-40 (Must): форма профиля — display_name, роль, bio с сохранением; роль — фиксированный справочник «Product manager»/«Product engineer», чисто отображение (ОВ-21).
- FR-41 (Must): смена пароля (текущий + новый; сессия сохраняется — Д-11). Отмена Won't Релиза 3 (ОГР-15).
- FR-42 (Must): загрузка аватара png/jpg, отклонение иных типов с понятной ошибкой; серверное автосжатие в квадрат ≤256px (Д-8); лимит исходника ≤2 МБ (NFR-10, ОВ-22); отображение в блоке профиля и tooltip'е.
- FR-43 (Must): tooltip профиля — аватар, display_name, логин, роль, bio (ОВ-25); единый механизм с tooltip'ами карточек (ОГР-17); reduced-motion (TC-vis-105).
- FR-44 (Must): tooltip карточки — assigned и creator (ОВ-25: имена; аватары в tooltip карточки — на усмотрение СА/дизайна, не нормируются).
- FR-45 (Must): assigned и creator во всех карточках (доска — все столбцы + fast line — и выдача поиска); без исполнителя — курсивом «Unassigned», строка отображается всегда (ОВ-24).
- FR-46 (Must): фильтры assigned/creator в конструкторе и advanced-синтаксисе; фильтр «без исполнителя»; подсказки значений из уникальных значений столбцов БД (механизм FR-35/DEF-001); поля в выдаче.
- FR-47 (Must): просмотр тикета — модальное окно read-only, отличное от форм; все данные включая комментарии, assigned, creator; переход к редактированию — кнопкой (Д-9).
- FR-48 (Must): закрытие DEF-005 — формы создания/редактирования по мокапу V3 pixel-consistent по токенам; все интерактивные элементы покрыты стилями (урок DEF-004).
- NFR-9 (Must): миграция без потерь, автоматическая сверка до/после, бэкап прода до накатки (ОГР-19).
- NFR-10 (Must): лимит исходного файла аватара ≤2 МБ, отказ с понятной ошибкой.

### Out of scope

- WebP-конвертация аватаров (Won't, PLAN-R4); внешние аватар-сервисы (Gravatar — Won't, PRODUCT_BACKLOG P3).
- Управление ролями/правами: роль — только отображение (ОВ-21), модель «общая доска» без разграничения прав сохраняется (ОГР-6, NFR-4).
- Смена логина (Won't, PRODUCT_BACKLOG P3; логины фиксированы по sdd).
- Полномочия на assigned: любой авторизованный пользователь (общая доска) — Ограничение модели, не расширение (ОВ-26: механика «кто» не оговорена Заказчиком; в границах ОГР-6).
- Общий раздел «Настройки» (справочник категорий) — не затрагивается (ОГР-20).
- Новые визуальные темы: база — токены V3 «Бумага» (ОГР-18).
- Приоритезация/сортировка по assigned/creator, массовые операции назначения — не заявлены Заказчиком (идея — не вносится; право предложения у БА).

## Approach

Brownfield-дельты поверх master-спек (10 доменов) без перезаписи существующих Requirements. Миграция SQLite — одноразовый идемпотентный скрипт (образец — `migrate_categories.py` Релиза 2) с автосверкой до/после (NFR-9) и обязательным бэкапом прода до накатки (ОГР-19: БД + каталог аватаров, C-3 ревью review-001); шаг миграции встроен в `deploy/deploy.sh` (после схемы, до рестарта, C-2 ревью). Профиль — три новых эндпоинта (GET/PUT профиля, смена пароля, загрузка аватара) в auth-роутере; `/api/auth/me` расширяется составом профиля; `GET /api/users` — read-only источник select исполнителя (B-1 ревью, контракт в sdd). Аватар — серверное автосжатие (Pillow + python-multipart, обе зависимости с пинами в requirements, research §1/§2), хранение — `/var/lib/ekotov-wiki/avatars/` вне rsync-корня прода с отдачей nginx `location /avatars/` и кеш-бастингом (ОГР-16, blocker C-1 ревью; бамп `static_v` — урок DEF-002/003, один финальный на релиз). Tooltips — единый CSS/JS-механизм для профиля и карточек (ОГР-17) с отключением анимаций при prefers-reduced-motion (TC-vis-105). View-модалка — новое read-only окно на действующих токенах V3 (ОГР-18) с кнопкой «Редактировать» (Д-9); переиспользование существующей формы редактирования по клику. Поиск — расширение фильтр-конструктора и advanced-парсера полями assigned/creator по действующему механизму «значения из БД» (FR-35, DEF-001). Техрешения — `design.md`, контракты и модель данных — `sdd.md` (§9), задачи — `tasks.md` (порядок из PLAN-R4).

Примечание о существующих маршрутах (I3): пакет сохраняет все действующие маршруты (sdd.md §3: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/health`, `GET /api/auth/me`, tasks CRUD + move + comments, `/api/categories*`, `/api/board`, `/api/search`, `/api/search/advanced`, `/api/suggestions`, страницы login/board/search/wiki/settings); новые — `GET/PUT /api/profile`, `POST /api/profile/password`, `POST /api/profile/avatar` (design §2), `GET /api/users` (read-only select исполнителя, B-1 ревью review-001; design §6, sdd §3.1a-кватер-бис) — перечислены в design.md/sdd.md и упомянуты в дельтах specs. Расширение `GET /api/board`, `GET /api/search`, `POST /api/search/advanced`, `GET /api/tasks/{id}`, `POST /api/tasks`, `PATCH /api/tasks/{id}` — состав ответов/запросов, пути не меняются.

## Assumptions (утверждены Заказчиком в answers_round4.md / дефолты Д-8…Д-11)

- ОВ-21: роль — фиксированный справочник «Product manager»/«Product engineer», чисто отображение; бэкфилл owner → PM, wife → PE.
- ОВ-22: лимит исходника аватара ≤2 МБ («да»).
- ОВ-23: бэкфилл assigned = owner у всех существующих задач («заполни owner»).
- ОВ-24: строка assignee отображается всегда; пустой assigned — курсивом «Unassigned»; фильтр «без исполнителя» — в границах FR-46 (предложение БА принято с ответом ОВ-24).
- ОВ-25: tooltip профиля включает bio («да»); tooltip карточки — имена assigned/creator (аватары — усмотрение СА/дизайна).
- ОВ-26: assigned редактируется в форме редактирования (select из пользователей), при создании — опционально («да»).
- Д-8: аватар — квадрат ≤256px (обрезка/вписывание — решение СА); Д-9: переход к редактированию из view-модалки; Д-10: пустой display_name → логин; Д-11: смена пароля требует текущий пароль, сессия сохраняется.
