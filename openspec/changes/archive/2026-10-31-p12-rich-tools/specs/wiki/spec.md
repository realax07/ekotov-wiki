## MODIFIED Requirements

### Requirement: WYSIWYG-редактор страниц

Редактирование контента MUST выполняться в WYSIWYG-редакторе на
contenteditable: vanilla JS, БЕЗ внешних CDN, библиотек и сборщиков (ОГР-8,
решение 2) (FR-110). Тулбар MUST содержать: заголовки H1–H3, жирный,
курсив, подчеркивание, нумерованный и маркированный списки, цитату,
код-блок, ссылку, таблицу, изображение (FR-110, FR-111), отмену/повтор
(undo/redo), а также инструменты rich-контента p12-rich-tools: спойлер,
блок кода с подсветкой, табуляцию (FR-118…FR-120). Кнопки H1–H3 MUST
работать как переключатели: повторный клик снимает форматирование, текст
не теряется; одновременное действие двух уровней заголовка недопустимо
(FR-121). Для таблицы MUST быть доступно контекстное управление строками и
столбцами и отдельная кнопка удаления таблицы (FR-122). Отредактированный
вид MUST соответствовать сохраненному (WYSIWYG). Работа редактора MUST
проверяться в актуальных Chrome и Firefox (NFR-33). Тулбар остается
единственным: контекстные контролы блоков — inline-панели внутри блоков,
новые ряды тулбара не создаются (урок rich-v1 «конфликт toolbar»).

#### Scenario: Тулбар применяет форматирование

- **GIVEN** пользователь авторизован и редактирует страницу в WYSIWYG-редакторе
- **WHEN** пользователь применяет инструменты тулбара (H1–H3, B/I/U,
  нумерованный/маркированный списки, цитата, код-блок, ссылка, таблица)
- **THEN** форматирование применяется к выделению в поле редактирования;
  сохраненная страница отображает тот же вид без расхождений (FR-110)

#### Scenario: Тулбар содержит инструменты rich-контента

- **GIVEN** пользователь редактирует страницу в WYSIWYG-редакторе
- **WHEN** пользователь открывает тулбар
- **THEN** доступны кнопки «Спойлер», «Блок кода», «Табуляция» и кнопка
  удаления таблицы; блоковые кнопки вставляют соответствующий блок (FR-118,
  FR-119, FR-120, FR-122)

#### Scenario: Кнопки заголовков не залипают

- **GIVEN** пользователь редактирует абзац, оформленный как H1
- **WHEN** пользователь повторно нажимает H1
- **THEN** формат снимается (текст → абзац), все кнопки H1–H3 отжаты;
  нажать H1 и H2 одновременно невозможно (FR-121)

#### Scenario: Undo/redo

- **GIVEN** пользователь внес правки в редакторе
- **WHEN** пользователь нажимает отмену/повтор тулбара
- **THEN** правка отменяется / повторно применяется (FR-110)

#### Scenario: Редактор без внешних зависимостей

- **GIVEN** страница редактора открыта в браузере
- **WHEN** проверяются сетевые запросы страницы
- **THEN** запросов к внешним CDN/доменам нет — редактор работает целиком на
  локальной статике (vanilla JS, ОГР-8; NFR-33)

### Requirement: Санитизация HTML контента

Контент страниц — HTML из редактора; при записи и отображении MUST
применяться серверная санитизация по whitelist тегов/атрибутов редактора
(FR-110) (NFR-31). Whitelist расширяется блочными конструкциями
p12-rich-tools: data-атрибуты фиксированного словаря с валидацией значений
(`data-block`, `data-block-part`, `data-title`, `data-lang` — design.md
§1–§2); глубина вложенности блоков ограничена (NFR-39). Скрипты (`script`),
обработчики `on*`, `javascript:`-URL, внешние embed и невалидные значения
data-атрибутов НЕ проходят санитизацию. Контент без блоков проходит без
искажений. Сессии — как у доски: сессионные куки, Secure в проде (паттерн
`board.py`).

#### Scenario: Скрипт вырезается при отображении

- **GIVEN** в контент страницы вставлен `<script>` или атрибут `onclick`
  (например, через вставку HTML)
- **WHEN** страница отображается
- **THEN** скрипт/обработчик в отдаваемом HTML отсутствует — санитизация по
  whitelist удаляет их до рендера (NFR-31)

#### Scenario: Разрешенные теги проходят

- **GIVEN** контент содержит только теги whitelist редактора (H1–H3, B/I/U,
  списки, цитата, код-блок, ссылки, таблицы, изображения)
- **WHEN** страница отображается
- **THEN** разметка сохраняется без искажений (NFR-31)

#### Scenario: Блочные конструкции проходят, подмененные значения снимаются

- **GIVEN** контент содержит спойлер, код-блок и таб-виджет с валидными
  data-атрибутами, а также `<div data-block="evil">` с подмененным значением
- **WHEN** страница сохраняется и отображается
- **THEN** валидные блоки сохраняются и активируются клиентом; блок с
  невалидным `data-block` деградирует в обычный контент (NFR-39, NFR-31)
