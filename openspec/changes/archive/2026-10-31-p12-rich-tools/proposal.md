# Proposal: p12-rich-tools

## Change ID

`p12-rich-tools`

## Why

Пакет **P12 «Продвинутое редактирование страниц (rich-контент)» — ПЕРЕДЕЛКА С
НУЛЯ** (решение Заказчика 2026-10-16: старая наработка rich_blocks не нужна,
прод откачен; баги прошлого — дубли id, потеря контента при вложении, конфликт
toolbar — не повторять, см. design.md §7).

Дословные описания 5 инструментов Заказчика (2026-10-19, PRODUCT_BACKLOG P12):

1. «Спойлер» — его надо мочь переименовать, и чтобы вставлялся по тексту или
   в другие элементы, например таблицу. Внутри — зона для текста.
2. Блок кода с подсветкой синтаксиса. На черном фоне в красивой рамке.
3. Табуляция, работающая.
4. Починить баг с отжиманием H заголовков. Форматирование должно очищаться.
5. У вставленных таблиц нужно уметь добавлять и убирать столбцы и строки.

Дизайн-фаза завершена: мокапы `design/p12-rich/` (5 инструментов ×
режим редактирования + отрендеренный вид) УТВЕРЖДЕНЫ — решения Заказчика по
открытым вопросам ОВ-1…ОВ-5 (2026-10-20, cf61f58):

1. Спойлер: кликабельна **вся шапка** (сворачивание/разворачивание).
2. Блок кода: языки **python/js/bash/json/sql/plain**; нумерация строк — **ДА**.
3. Табуляция: при переполнении таб-бара — **СКРОЛЛ**.
4. Таблица: удаление таблицы целиком — **ОТДЕЛЬНОЙ кнопкой**.
5. Backspace в пустом H — снимает формат (H → абзац), канон Notion/GDocs.

Сегодня WYSIWYG-редактор wiki (spec `wiki`, FR-110) умеет только базовое
форматирование: код-блок — голый `<pre>` без подсветки, таблица вставляется,
но не редактируется (ни строки, ни столбцы убрать нельзя), H-кнопки
залипают (можно нажать H1 и H2 одновременно — DON'T-состояние мокапа 4),
спойлера и табуляции нет вовсе.

## What Changes

5 инструментов rich-контента в существующем WYSIWYG-редакторе wiki
**монолита** (никаких новых сервисов/контейнеров). Блоки хранятся в
существующем HTML-поле `content` страниц `pages` — новыми блочными
конструкциями с data-атрибутами (design.md §1–§2); серверный санитайзер
(`backend/app/sanitize.py`) расширяется whitelist'ом блоков; рендер —
клиентская активация блоков в `page.js` + самописный лексер подсветки
(ОГР-8: без внешних библиотек, design.md §5).

Нумерация продолжает сквозную: последние использованные — **FR-117, NFR-38**
(video-hosting). Настоящий пакет: **FR-118…FR-122, NFR-39, NFR-40**.

## Scope

### In scope

- Спойлер, код-блок с подсветкой, табуляция, H-toggle, редактирование
  таблиц — режим редактирования И рендер статей (FR-118…FR-122).
- Расширение серверного санитайзера блоками + фиксированный словарь
  data-атрибутов (NFR-39).
- Матрица вложенности блоков (design.md §6): спойлер в спойлере, спойлер
  в ячейке таблицы, код в спойлере, табы в табах — разрешено с ограничением
  глубины 5; таблица в таблице и любые блоки внутри код-блока — запрещено.
- Клиентская подсветка кода самописным лексером (6 языков из ОВ-2).
- Совместимость: существующие страницы (без блоков) не меняются; контент
  в БД не мигрирует (миграций НЕТ).
- Бамп `static_v` в `backend/app/pages.py` (IR-03 — меняется статика).
- Тесты: расширение `tests/api/test_sanitize.py`, web-тесты редактора/рендера.

### Out of scope

- Новые сервисы/контейнеры, изменения `deploy/deploy.sh`, `deploy/RUNBOOK.md`
  (деплой-контур не трогается — релиз монолита по существующей матрице).
- Миграции БД (блоки живут в существующем TEXT-поле `content`).
- Изменения `contracts/openapi.json` (новых эндпоинтов нет — см. impact.md).
- Markdown-конверсия/импорт, коллаборативное редактирование, комментарии
  к блокам, подсветка языков вне списка ОВ-2.
- Верстка мокапов (дизайн-фаза завершена, `design/p12-rich/` — эталон).

## Approach

Кратко (детали — design.md):

- **Хранение:** блочный синтаксис на HTML + data-атрибуты фиксированного
  словаря (`data-block="spoiler|code|tabs"`, `data-block-part`, `data-title`,
  `data-lang`) в существующем поле `content`. Никаких генерируемых `id` —
  урок отката rich-v1 (дубли id).
- **Санитайзер:** расширение whitelist'а (`backend/app/sanitize.py`) — новые
  атрибуты только с валидацией значений по enum; глубина вложенности ≤ 5;
  содержимое код-блока — только экранированный текст.
- **Редактор:** тулбар не дублируется — блоковые кнопки только вставляют
  блок, контекстные контролы (табы, таблица, шапка спойлера) — inline-панели
  внутри блока; сохранение — сериализация DOM как есть, без перестройки
  дерева (урок «потеря контента при вложении»).
- **Рендер:** клиентская активация (`page.js`): спойлер/табы — делегирование
  событий, код — подсветка лексером на чистом тексте; неизвестный/битый
  блок деградирует в обычный контент без потери текста (NFR-39).
- **Волны:** 1 фундамент (синтаксис+санитайзер+round-trip) → 2 спойлер →
  3 код-блок → 4 табуляция → 5 H-toggle+таблица → 6 интеграция/static_v/qa.
