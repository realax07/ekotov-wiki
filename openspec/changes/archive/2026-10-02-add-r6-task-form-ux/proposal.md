# Proposal: add-r6-task-form-ux

## Change ID

`add-r6-task-form-ux`

## Why

Закрытие единственного реального пробела пункта **P1 «Карточка/форма задачи — детальная проработка UX»** бэклога по принятому ТЗ `docs/ba/requirements-r6.md` (ПРИНЯТО Заказчиком, решения ОВ-1…ОВ-4 закрыты 2026-10-01, коммит 67cbc6f; прод v=r5.2, main): FR-57…FR-63, NFR-17…NFR-18, ОГР-26…ОГР-28, Д-14…Д-15, СЦ-1…СЦ-11. Из пяти пунктов заметки Заказчика P1 три уже реализованы в Релизах 1–5 (крестик, приоритеты с цветом/иконкой, fast=high, категории списком — аудит раздела 2 ТЗ) и в объем не входят; пробел — UX автодополнения тегов («как в Jira»). По решениям Заказчика объем расширен побочными пробелами: полиш графики формы (ОВ-4, остаток пункта P1), Escape-закрытие с подтверждением и адаптив ≤480px (ОВ-3), консолидация кнопок управления задачей в единую зону (ОВ-4 — зафиксирована как дельта, не «полиш»).

База: форма задачи Р1–Р5 на проде (input + нативный `<datalist id="task-tag-hints">` из `GET /api/suggestions`, подсказки в обоих режимах — создание и редактирование; свободный ввод сохраняется тегом get-or-create; чипы FR-34, источник истины — input). Контракт `GET /api/suggestions` (без параметров: `{suggestions: [tags ∪ categories]}`) зафиксирован уточнением Заказчика и тестами TC-API-SUGG-001/004 — не меняется (ОГР-26). Дельты строятся поверх действующих master-спек `tasks` (автодополнение, визуал формы) и `search` (подсказки), т.к. Р1–Р5-пакеты частично не заархивированы — «as is» = master + действующие пакеты.

## What Changes

Дельты по доменам (все — в `specs/` этого пакета):

| Домен | Тип дельты | Требования | Содержание |
|---|---|---|---|
| `tasks` | MODIFIED (2) + ADDED (4) | FR-57…FR-59, NFR-17, NFR-18 (комбобокс); FR-60 (полиш); FR-61 (Escape); FR-62 (адаптив); FR-63, ОГР-28 (единая зона) | MODIFIED: «Автодополнение тегов в форме задачи» (нативный datalist → кастомный комбобокс, подсказки только теги), «Формы создания и редактирования по дизайну V3» (полиш графики, Escape, адаптив, единая зона действий). ADDED: «Кастомный комбобокс подсказок тегов», «Единая зона действий задачи», «Escape-закрытие формы», «Адаптив формы на узких экранах» |
| `suggestions` | ADDED (1) | FR-57, ОГР-26, Д-14 | Опциональный параметр `GET /api/suggestions?kind=tags` — только теги; дефолт «без параметра» = прежний UNION тегов и категорий (контракт поиска цел); неизвестный `kind` — 422. Capability `suggestions` в `openspec/specs/` отсутствует (подсказки живут в `search`) — дельта создает новую capability пакетом; после архивации появится `openspec/specs/suggestions/spec.md` с контрактом API подсказок |

Новых API-эндпоинтов нет: `?kind=tags` — опциональный параметр существующего `GET /api/suggestions` (Д-14: не отдельный `/api/tags` — один источник данных, контракт поиска цел, доработка S). Схема БД не меняется. Новых зависимостей нет (ОГР-1): комбобокс — ванильный JS (новый ES-модуль + правки `task-form.js`), CSS в `board.css`. Логика сохранения тегов не меняется (ОГР-27): источник истины — input, отправка строкой через запятую, get-or-create на сервере. Идентификаторы элементов формы не переименовываются (ОГР-28): меняется разметка/раскладка, не контракт DOM.

## Scope

### In scope

- FR-57 (Must): подсказки поля «Теги» — только существующие теги проекта; категории не участвуют (у категории свой select); `loadTagHints()` бьет по `?kind=tags`; контракт без параметра не меняется (ОГР-26, Д-14).
- FR-58 (Must): фильтрация подсказок по вводу + исключение уже введенных тегов; подсветка совпавшей части (как в Jira); бэкенд не трогается.
- FR-59 (Must): явные действия — клик по подсказке добавляет тег; при отсутствии совпадений — явный пункт «+ Добавить тег „‹ввод›“»; выбранные теги — чипами (UI FR-34 сохранен, источник истины — input не меняется).
- FR-60 (Should): полиш графики формы по токенам V3 — состояния полей (hover/focus/ошибка), кнопки, отступы, типографика; без изменения логики и валидации (рамка DEF-005); по чек-листу Д-15 с живым макетом.
- FR-61 (Could→включено ОВ-3): Escape закрывает форму без сохранения; грязная форма → подтверждение «Закрыть без сохранения?» (паттерн `window.confirm` существующих модалок), чистая — сразу; при открытом дропдауне первое нажатие закрывает дропдаун, второе — форму.
- FR-62 (Could→включено ОВ-3): адаптив формы ≤480px — одна колонка, поля full-width, без горизонтальной прокрутки; проверка на ~375px.
- FR-63 (Must): единая зона действий задачи в режиме редактирования — `[Столбец ▾] [Сохранить] [Отмена] │ [Удалить]` в одном визуальном блоке внизу формы; «Удалить» отделен отступом; подтверждение удаления сохраняется; в режиме создания зона `#task-actions` скрыта, ряд `[Создать] [Отмена]`; id всех элементов не менять (ОГР-28).
- NFR-17 (Must): дропдаун — полноценная замена нативному: отклик ≤100 мс (локальная фильтрация), стрелки + Enter/Escape, клик вне — закрытие; сбой загрузки подсказок не блокирует ввод тегов; тач — тап по пункту, скролл страницы не ломается.
- NFR-18 (Must): доступность — role=combobox на input + listbox/option, aria-expanded, aria-activedescendant; озвучивание количества подсказок; значения в DOM — только через textContent (XSS, преемственность dom.js).
- ОГР-26: контракт `GET /api/suggestions` без параметров не меняется; `?kind=tags` — опциональный параметр; неизвестный `kind` — 422.
- ОГР-27: логика сохранения тегов не меняется; релизный бамп `static_v` обязателен (одно значение на релиз).
- ОГР-28: id `#task-form-submit`, `#task-form-cancel`, `#task-delete-button`, `#task-move-select`, `#task-actions` не переименовываются при FR-63.
- Д-14: FR-57 вариантом `?kind=tags` (не отдельный `/api/tags`).
- Д-15: FR-60 — проход по чек-листу консистентности V3 с живым макетом в `design/` до dev, без редизайна сетки формы.

### Out of scope

- Управление тегами/категориями как справочником (P2/P5 — настройки; Won't ТЗ).
- Автодополнение в advanced-поиске (P4, отдельная история; Won't).
- Замена чипов/источника истины input на модель данных на фронте (Won't).
- Кастомизация нативного datalist браузера (Won't).
- Изменение контракта `GET /api/suggestions` без параметра (Won't, ОГР-26): дефолт = прежний UNION, поиск не затронут.
- Пункты P1, реализованные в Р1–Р5 (аудит раздела 2 ТЗ): крестик, цвет/иконки приоритетов, fast=high, категории списком.
- Изменение логики сохранения тегов (payload, get-or-create) — только слой ввода/подсказок (ОГР-27).

## Approach

Brownfield-дельты поверх «as is» (master + Р1–Р5). Backend — минимальная правка `GET /api/suggestions` (S): опциональный query-параметр `kind`; отсутствие параметра — прежний UNION (ОГР-26, тесты TC-API-SUGG-001/004 не меняются); `kind=tags` — только теги (ветка UNION только по tags); иной `kind` — 422 (явный отказ, не тихий UNION); фронт `loadTagHints()` бьет по `?kind=tags`. Frontend — кастомный комбобокс тегов (M, ОВ-2): новый ES-модуль (дропдаун, локальная фильтрация ≤100 мс, подсветка совпадений, исключение введенных, явный пункт «+ Добавить тег „…“», клавиатура стрелки/Enter/Escape, клик вне) + правки `task-form.js`; aria — role=combobox/listbox/option, aria-expanded, aria-activedescendant (NFR-18), DOM — только textContent. Единая зона действий (M, ОВ-4): перенос разметки `board.html` (`.form-actions` объединяется с `#task-actions` в один блок-ряд внизу формы, destructive «Удалить» — с отступом), CSS-сетка в `board.css`; обработчики JS не переписываются — переносится разметка; id не меняются (ОГР-28); комментарий `board.html` про «действия из окна деталей» обновляется. Полиш графики (S): проход по `.task-form` в `board.css` против мокапа V3 по чек-листу Д-15 — без изменения логики/валидации (DEF-005). Escape (S): keydown-обработчик на документ с guard'ом «форма открыта, view не открыта» (симметрично `task-detail.js`), снимок полей на открытие → признак «грязности» → `window.confirm` на грязной форме; первое Escape при открытом дропдауне закрывает только дропдаун. Адаптив (S): один `@media (max-width: 480px)` блок для формы — одна колонка, full-width. Деплой: релизный бамп `static_v` = `r6.x` одним значением (ОГР-27, урок DEF-002/003); миграций БД и правок nginx нет.

## Assumptions (решения Заказчика ОВ-1…ОВ-4 + дефолты Д-14/Д-15)

- ОВ-1: подсказки поля «Теги» — только теги; категории — в поле категории → FR-57, ОГР-26, Д-14.
- ОВ-2: кастомный комбобокс (не datalist) — фильтрация, подсветка, исключение введенных, явный «+ Добавить тег», клавиатура, aria, клик вне → FR-58, FR-59, NFR-17, NFR-18.
- ОВ-3: в Р6 включены побочные пробелы FR-61 (Escape + подтверждение на грязной форме) и FR-62 (адаптив ≤480px).
- ОВ-4: «кнопки управления задачей разбросаны» — фиксируется как дельта FR-63 (единая зона действий, destructive отдельно); прежняя формулировка «полиш» заменена.
- Д-14: реализация через `GET /api/suggestions?kind=tags`, не отдельный `/api/tags` — принят (один источник, контракт поиска цел, доработка S).
- Д-15: FR-60 — проход по чек-листу консистентности V3 с живым макетом в `design/` перед dev — принят (без редизайна сетки формы).
