# Design: add-r6-task-form-ux

Технические решения пакета «Task form UX». Наблюдаемое поведение — в дельтах `specs/`; здесь — как оно достигается. Стек не меняется (sdd.md §1: FastAPI + SQLite + Jinja2/ванильный JS + nginx). **Новых зависимостей нет** (ОГР-1): backend — stdlib FastAPI; фронт — ванильный JS/CSS. Схема БД не меняется; новых API-эндпоинтов нет — опциональный параметр существующего `GET /api/suggestions` (Д-14).

## 0. Резюме решений (по решениям Заказчика ОВ-1…ОВ-4 и дефолтам Д-14/Д-15)

| Вопрос | Решение |
|---|---|
| Источник подсказок «только теги» (ОВ-1) | **`GET /api/suggestions?kind=tags`**, не отдельный `/api/tags` (Д-14): один источник данных, контракт поиска цел (дефолт «без параметра» = прежний UNION, ОГР-26), доработка S. Отдельный `GET /api/tags` отклонен: дублировал бы SQL/роут ради одного потребителя |
| Механизм автодополнения (ОВ-2) | **Кастомный комбобокс** (новый ES-модуль), не нативный datalist и не кастомизация datalist: нативный не дает controllable-дропдауна, подсветки совпадений, исключения введенного, явного «+ Добавить тег». Доступность — aria-паттерн combobox/listbox (§2) |
| Escape (ОВ-3, FR-61) | keydown на документе с guard'ом, симметрично `task-detail.js:169–173`; «грязность» — снимок полей на открытие; подтверждение — `window.confirm` по паттерну существующих модалок (§4) |
| Адаптив (ОВ-3, FR-62) | Один `@media (max-width: 480px)` блок для формы в `board.css` — без перестройки сетки формы на широких экранах (§5) |
| Единая зона действий (ОВ-4, FR-63) | **Перенос разметки + CSS, JS-обработчики не переписываются**: объединение `.form-actions` и `#task-actions` в один блок-ряд внизу формы; id не менять (ОГР-28) (§6) |
| Полиш графики (FR-60, Д-15) | Проход по чек-листу консистентности V3 (состояния/отступы/типографика) с живым макетом в `design/` до dev — без редизайна сетки формы (§7) |

## 1. Backend: `?kind=tags` в GET /api/suggestions (FR-57, ОГР-26, Д-14)

- Точка: `backend/app/suggestions.py`, функция `suggestions()` — добавляется опциональный query-параметр `kind: str | None = None`. Ветка: `None` → существующий `_SUGGESTIONS_SQL` без изменений (дефолт — прежний UNION, тесты TC-API-SUGG-001/004 не меняются); `kind == "tags"` → запрос только по тегам (первая ветка UNION: `SELECT DISTINCT tags.name FROM tags JOIN task_tags …` — осиротевшие теги исключаются join через task_tags, преемственность FR-16/17); иное значение `kind` → 422 (явный отказ, не тихий UNION; тест на 422 добавляется).
- Ключ ответа при `kind=tags` — тот же `"suggestions"`: потребителю (комбобокс формы) без разницы, а расхождение форматов плодить не зачем. Контракт без параметра — дословно прежний (docstring модуля дополняется описанием параметра).
- Авторизация — без изменений: путь не в exempt-списке middleware, 401 без сессии при любом `kind`.
- «kind» — семантика фильтра множества, не новая сущность: задел на будущие значения не делается (YAGNI; новые значения — новым решением, ОГР-26 отклоняет тихий UNION для неизвестных).

## 2. Кастомный комбобокс тегов (FR-58, FR-59, NFR-17, NFR-18, ОВ-2)

- Новый ES-модуль `frontend/static/js/board/tag-combobox.js` + правки `task-form.js`: `loadTagHints()` бьет по `?kind=tags` (FR-57); источник истины — input «Теги» не меняется, чипы FR-34 сохраняются (ОГР-27) — комбобокс только слой ввода/подсказок.
- Разметка: input получает `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-autocomplete="list"`; дропдаун — `role="listbox"`, пункты — `role="option"` с id; активный пункт клавиатурной навигации — `aria-activedescendant` на input (aria-паттерн ARIA APG «Combobox with Listbox Popup», NFR-18). Количество подсказок — в `aria-live`-узел для озвучивания скринридером.
- Поведение: фокус/ввод → открытие дропдауна; фильтрация локальная по уже загруженному множеству (без запроса на каждый символ, отклик ≤100 мс, NFR-17); дедупликация — уже введенные (сплит input по запятой, как у чипов) исключаются из пунктов (FR-58); подсветка совпавшей подстроки — разметкой внутри option, но значения строк — только через textContent (XSS, преемственность dom.js и правил FR-29/FR-34; тег с `<b>` внутри не исполняется).
- Выбор: клик по option и Enter на активном пункте → дописать значение в input + перерисовать чипы; при отсутствии совпадений — явный пункт «+ Добавить тег „‹ввод›“» (FR-59). Механика сохранения (строка через запятую в POST/PATCH, get-or-create) не меняется (ОГР-27).
- Закрытие: Escape (первое нажатие — только дропдаун, см. §4), клик вне, выбор пункта. Тач: тап по пункту (click покрывает), дропдаун не перехватывает touchmove — скролл страницы не ломается (NFR-17).
- Сбой загрузки подсказок: try/catch → дропдаун не показан, ввод тегов работает как прежде (NFR-17, преемственность FR-26, СЦ-5).
- Позиционирование: absolute под input внутри модалки; пересчет при скролле/resize не нужен (модалка не скроллится на десктопе); на ≤480px — ширина 100% поля (см. §5).

## 3. Единая зона действий — перенос разметки (FR-63, ОГР-28, ОВ-4)

- Точка: `frontend/templates/board.html` (блоки `#task-actions`, строки ~168–186) + `frontend/static/css/board.css` (сетка `.task-actions`, `.form-actions`). Обработчики `task-form.js` (`initTaskActions`, сабмит, отмена, удаление) не переписываются — цепляются по id, id не меняются (ОГР-28): `#task-form-submit`, `#task-form-cancel`, `#task-delete-button`, `#task-move-select`, `#task-actions`.
- Разметка: `.form-actions` переносится внутрь/рядом с `#task-actions` так, что в режиме редактирования получается один визуальный блок-ряд внизу формы: `[Столбец ▾] [Сохранить] [Отмена] │ [Удалить]`; «Удалить» — визуально отделен отступом (margin-left/border-left по токенам V3) от безопасных действий (destructive-акцент). В режиме создания `#task-actions` остается скрытым (`hidden`, openCreateForm) — ряд `[Создать] [Отмена]` сохраняет нынешний вид.
- Комментарий `board.html` про «действия из окна деталей» (строки 168–172) обновляется: зона теперь консолидирована внизу формы (FR-63).
- Комментарии: блок `#task-comments` — соседний элемент с `#task-form` (не вложен — ограничение HTML на вложенные формы, комментарий в разметке) — не трогается; порядок «форма → комментарии» сохраняется.
- Риск регресса e2e — минимален (id те же), но перенос разметки меняет DOM-порядок: прогон e2e формы обязателен (СЦ-11).

## 4. Escape-закрытие с подтверждением (FR-61, ОВ-3)

- Точка: `task-form.js`. keydown-обработчик на документе с guard'ом «форма задачи открыта, view-модалка не открыта» — симметрично существующему нормированию Escape в `task-detail.js:169–173` (не глотать чужие Escape).
- «Грязность»: при открытии (`clearTaskForm`/`openEditForm`) снимок значений полей; при Escape — diff снимка с текущим input'ами/select/checkbox. Чистая → закрыть сразу; грязная → `window.confirm('Закрыть без сохранения?')` (паттерн «Удалить задачу?» в `task-form.js` и категории в `settings.js`); отмена → форма осталась.
- Взаимодействие с дропдауном §2: если дропдаун комбобокса открыт — первое Escape закрывает только дропдаун (обработчик комбобокса вызывает `stopPropagation`, форма не реагирует); второе — закрывает форму по правилам чистой/грязной.
- Закрытие по Escape — тот же путь, что «Отмена»/крестик: без отправки на сервер, данные на сервере не меняются (СЦ-8).

## 5. Адаптив ≤480px (FR-62, ОВ-3)

- Один `@media (max-width: 480px)` блок в `board.css` для `.task-form-sheet`/формы: `grid-template-columns: 1fr`, поля/кнопки/select'ы 100% ширины, дропдаун комбобокса — 100% ширины поля; модалка перестраивается без горизонтальной прокрутки. Проверка на ~375px (СЦ-9).
- Media-запросов ширины для формы сейчас нет (только `prefers-reduced-motion`) — блок новый, существующие правила не ломаются; desktop-сетка не меняется.

## 6. Полиш графики по V3 (FR-60, Д-15)

- Вход: живой макет в `design/` (по практике Д-15/J25: чек-лист консистентности V3 — состояния hover/focus/ошибка всех полей и кнопок, отступы по 8px-сетке, типографика) создается до dev-задачи полиша; правки — только `board.css` (+точечно разметка классов), логика/валидация не меняются (рамка DEF-005).
- Приемка: сверка с мокапом V3 (`design/form-style-v3.html`) и чек-листом Д-15; «все интерактивные элементы покрыты стилями» (урок DEF-004) — в чеклисте QA.

## 7. Деплой (ОГР-27, ОГР-28)

- Миграций БД нет, nginx-правок нет. Релизный бамп `static_v` (pages.py) — **один** финальный `r6.x` после всех фронт-задач, до деплоя (урок DEF-002/003, одно значение на релиз): меняются board.html, board.css, task-form.js, новый tag-combobox.js.
- Регресс перед деплоем: TC-API-SUGG-001/004 (контракт без параметра), новый тест 422 на неизвестный kind, e2e формы по id (ОГР-28), полный прогон `tests/` green.

## 8. Риски

- **Перенос разметки зоны действий ломает e2e по id**: id сохранены (ОГР-28), но DOM-порядок меняется — локаторы «внутри формы» могут зависеть от порядка; закрывается прогоном e2e формы (СЦ-11) до бампа.
- **Escape-конфликт между дропдауном, формой и view-модалкой**: три потребителя Escape на странице; guard'ы и stopPropagation разграничивают (§4); кейс «дропдаун поверх формы поверх доски» — в чеклисте QA (СЦ-8).
- **aria-activedescendant требует стабильных id пунктов**: id генерируются детерминированно (индекс в отфильтрованном списке); пересчет при каждом рендере — расхождений быть не должно, проверяется web-тестом aria (СЦ-6).
- **Регресс контракта подсказок поиска**: дефолтная ветка SQL не меняется; TC-API-SUGG-001/004 прогоняются как есть (СЦ-10).
