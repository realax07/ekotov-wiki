## Решения и границы

- Рекомендация ПМ по модели хранения — **блочный markdown-диалект** (GFM-таблицы,
  `:::columns`/`:::callout` контейнеры): sanitize проще, диффы читаемы, старый
  контент совместим. Финальное решение — design (СА); альтернатива — расширенный
  HTML-белый список (требует XSS-главы в спеке).
- Обратная совместимость: существующие страницы обязаны рендериться как раньше.
- Sanitize — отдельная глава спеки с XSS-сценариями.
- image-scale (долг add-wiki) входит в пакет.
- Разбивка на волны dev — решает СА в tasks.md (пакет L).

## Критерии готовности

- Спека пакета валидна (strict), сценарии покрывают каждый тип блока
- XSS-сценарии в спеке и в тестах
- Старые страницы рендерятся без изменений (тест регресса)
- image-scale реализован
- Живая приемка Заказчиком на стенде
