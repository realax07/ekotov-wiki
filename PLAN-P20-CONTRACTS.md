# PLAN-P20-CONTRACTS.md — сервисные контракты (P20, Флоу 1; решение Заказчика 2026-11-15 «давай контракты»)

Черновик P20 (2026-10-01) частично устарел: сервисы уже в контейнерах; в работе — формализация
межсервисных контрактов. Статус волны: **requirements (ba) → СТОП-ТОЧКА: утверждение ТЗ Заказчиком**.

## Замысел (черновик, уточняется ba-агентом)
Каждый HTTP-сервис (search, images, video, weather) имеет машиночитаемый контракт:
1. OpenAPI-спека на сервис (актуальная: endpoints, схемы ответов/ошибок, auth).
2. Карта вызовов: app → search/images/video/weather; nginx-маршруты; кто чей клиент.
3. Контрактные тесты: ответы сервисов валидируются по схемам (draft-проверка в автотестах).
4. CI-гейт дрейфа: правка handler'а без правки спеки — механический DENY (IR-01/IR-07 база;
   при необходимости новые IR-правила — декларативно в impact_rules.json).
5. architecture/map.md — раздел «Контракты и зависимости».

## Стадии (Флоу 1)
- requirements: ba — инвентаризация фактических API (сверка кода со спеками), черновик ТЗ → СТОП: Заказчик
- approve: Заказчик правит/утверждает
- create_change: sa — openspec-пакет (proposal/spec/design/tasks), gate validate --strict
- arch_review: архитектор (verdict «Одобрить»)
- design: НЕ нужен (без фронт-дельты) — optional, ожидается skipped
- dev: по задачам (contract-tests, openapi-приведение, CI-гейт, доки)
- code_review → qa_cases → qa_auto → regress-final → архив (Заказчик)
- deploy: после приемки (release-волна)

## Критерии закрытия
- у 4 сервисов актуальные openapi-спеки; дрейф ловится воротами; контрактные тесты в CI;
- карта зависимостей в map.md; П20 в бэклоге РЕАЛИЗОВАНО.
