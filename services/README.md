**В ядре app остаются** (осознанно, решение по плану P20): auth, wiki (pages), доска/задачи/комментарии, профиль/аватары, настройки/категории — плотная связность (сессии, FK, sanitize); выделение при 2–3 пользователях не дает выгоды. **auth выделению не подлежит** (сетевой хоп на каждый запрос, сессии в общей БД) — заготовка services/auth снята 2026-10-19.

**Критерий выделения нового сервиса** (из плана P20): изолируемое состояние (том/внешний API/RO-доступ) + реальная выгода (производительность, переиспользование, изоляция отказов) — иначе код живет в ядре. Паттерн выделения отработан на video/weather (спека → arch → dev → QA → regress → деплой ≤ 1 день).
