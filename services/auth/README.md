# services/auth — НЕ рекомендован к выделению

> Статус: ЗАГЛУШКА (не существует; выделение НЕ рекомендовано) | Источник: `docs/ba/architecture-services-plan.md` §1.2 | Границы определит архитектор-сабагент.

## Пометка

**Не рекомендован в обозримом горизонте.** Причины (план P11 §1.2):

- `middleware.py` вызывается каждым запросом → выделение превращает проверку сессии в сетевой хоп на **каждый** маршрут;
- сессии живут в общей SQLite → сервис получал бы RW-доступ к общей БД, т.е. граница без транзакционности;
- выигрыша нет при 2 пользователях; сложность выделения **L**.

Альтернатива внутри ядра: auth остается в `app` (см. план §1.2, строка «auth»).

## Если когда-нибудь будет выделяться

Контракт: `/api/auth/*`; вариант «проверка сессии на app превращается в вызов auth» **либо** auth остается в ядре. Решение — только через пересмотр плана архитектором и решение Заказчика.
