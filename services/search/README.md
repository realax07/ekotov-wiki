# services/search — сервис поиска (кандидат ЭТАПА 2)

> Статус: ЗАГЛУШКА (не существует) | Источник: `docs/ba/architecture-services-plan.md` §1.2 | Границы определит архитектор-сабагент.

## Назначение

Выделение поискового домена из монолита: `backend/app/search.py` (805 строк, один файл, 18 функций, свои роутеры) — простой + advanced-поиск, `/api/suggestions`.

## Контракт

Выделенные маршруты `/api/search*`, `/api/suggestions` — уходят из `app`; контракт фиксируется в OpenAPI **до** выделения. UI-фронт `search.js` продолжает звать те же URL — проксирует nginx, для браузера ничего не меняется.

## Данные

SQLite **только RO** (тот же том, mount `ro`) — единственный дешевый кандидат ЭТАПА 2: поиск только читает, риск нарушения транзакционных инвариантов низкий.

## Когда выделять

Первым в ЭТАПЕ 2, если поиск начнет тормозить доску или его будут дорабатывать часто (P4-направления). Причина выделения — операционная (ресурсы, изоляция отказов, частые релизы), не «потому что можно».

## Оценка

**M**: код изолирован, но общая БД → границы без транзакционности (компенсируется read-only профилем).
