## Решения дизайна (помечены `<!-- DECISION -->` в разметке где релевантно)

1. **Модалка — read-only строго**: никаких input/select; кнопка «Редактировать» — единственное действие (демо закрывает окно; в прод открывает существующую форму — Д-9, DOM-id не переименовывать, ОГР-28).
2. **Шапка комментария** (FR-91): `Автор (bold) · дата, время` — формат «дд.мм.гггг, чч:мм» (`Intl.DateTimeFormat('ru-RU')`, design §5); id и сырой timestamp не отображаются. Разметка — единый компонент для окна просмотра (модалка B) и будущих использований.
3. **Бейджи приоритета** — цвет + иконка + текст (не только цвет, правило 2 ui_designer_agent); fast line — отдельный бейдж на токене blue-700 (fast line палитра app.css).
4. **Высота превью в А/Б — 4:3** (как утвержденная сетка add-gallery-service); смена на 1:1/3:2 не меняет варианта, если Заказчик попросит плотнее.
5. **Порядок плиток в В отличается** от А/Б — намеренно, показать независимость masonry от порядка загрузки.

## Проверено вживую (браузер, file://)

- Оба HTML открываются без сборки и внешних запросов; скриншоты секций А/Б/В и модалки сняты — рендер соответствует замыслу.
- Модалка: Esc закрывает → фокус вернулся на карточку-триггер → повторное открытие работает (проверено JS-прогоном).
- Masonry: вычисленный column-count 4; при 6 демо-плитках Chrome балансирует 2/2/2 — эффект естественной высоты виден.

## Вопросы/эскалации

Блокирующих неоднозначностей в ТЗ не найдено — противоречий спеке нет. Неблокирующие замечания (решаются на утверждении, не ждут ответа):

- В FR-90/spec board сценарий закрытия упоминает «крестик или клик вне окна», вводная оркестратора — «Esc/крестик». В мокапе реализованы ВСЕ ТРИ (Esc + крестик + клик по подложке) — это надмножество обоих прочтений; прод-поведение подтверждает dev 2.2 (текущее поведение не меняется).
- Высота превью А/Б (4:3) и радиус скругления превью (10px, наследует карточке) — правятся без смены варианта, если у Заказчика другое предпочтение.

## Примечания для dev (2.2 / 2.4 / 2.6)

- Токены — только custom properties (эталон для design_validator 3.1(г)); сырые значения — внутри `:root`-блоков мокапов.
- Вариант А: `aspect-ratio: 4/3` + `object-fit: cover`; Б: то же + `background: var(--color-bg-subtle)` + `contain`; В: CSS columns + `break-inside: avoid` (grid-адаптив 2/3/4 из gallery.css сохраняется в А/Б; в В — columns с теми же брейкпоинтами).
- Favicon: data-URI из `<link>` мокапа переносится в `base.html` дословно, URL — с `?v=`; при любом изменении иконки — бамп `?v=` (design §3).
- Шапка комментария: `author_name` из API (задача 2.3, join users), время — клиентский `Intl.DateTimeFormat('ru-RU')` из `created_at`, рендер textContent (XSS).
