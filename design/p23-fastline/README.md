# Мокапы P23 — фастлайн на доске (волна 1, дизайн-фаза)

Отдельная горизонтальная зона «Фастлайн» НАД основным канбаном, 3 столбца
(Ожидает / В работе / Выполнено). Таски fast — ТОЛЬКО в ней (в основном
канбане их нет — заявка PRODUCT_BACKLOG.md P23). Пустое состояние — линия
отображается, подсказок НЕТ («Перетащите карточки» / пунктир / «Пока пусто —
задачи появятся здесь» скрыты). Эталон подачи — design/p12-rich/; стиль —
V3 «Бумага» (токены дословно из frontend/static/css/app.css + board.css;
голубые токены --p-blue-* — те же, что у существующих .task-card-fast /
.task-form .fast-row / .badge-fast; ОГР-8 — без внешних зависимостей).

## Два варианта отделения зоны (Заказчик выбирает)

- **Вариант A — подложка + заголовок** (`variant-a-*.png`): голубой тинт
  `--p-blue-050` (зона «собирает» цвет своих fast-карточек), тонкая рамка
  `--p-blue-200`, серифный заголовок «Фастлайн» + кикер FAST LINE + счётчик.
  Заметнее всего («чтобы явно заметно было что он есть»).
- **Вариант B — рамка-контейнер** (`variant-b-*.png`: поверхность карточки,
  обычная рамка V3 + голубая верхняя кромка 3px (как приоритетная полоса
  карточки), колонки на bg-subtle. Строже, меньше цветового шума.

## Интеракции (мокап DnD)

- Таск из основного канбана → фастлайн: зона-приемник подсвечивается
  **голубым** пунктиром (цвет зоны; канбан при этом подсвечивается
  терракотой, как сейчас — направления не спутать). Летящая карточка —
  полупрозрачная с тенью; исходная — drag-ghost (наклон 3°, 35%).
- Обратное направление (фастлайн → канбан) — тем же механизмом (в мокапе
  подписано в аннотации кадра).

## Файлы

- `p23-base.css` — токены/сайдбар/колонки/карточки (дословно app.css + board.css)
  + новый блок `.fastline` (варианты a/b, пустое состояние, DnD-отклик).
- `gen_mockups.py` — генератор 6 HTML (`../venvs/wiki/bin/python gen_mockups.py`).
- `render.py` — рендер 6 PNG (playwright, 1440×900, dsf=2;
