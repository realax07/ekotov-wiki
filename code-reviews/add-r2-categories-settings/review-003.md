## 3. Второй круг — best practices

- **XSS:** имена категорий вставляются только через `textContent` (settings.js:99), `render()` очищает список через `listEl.textContent = ""`; проверено браузерным смоком — категория `<script>alert("xss")</script>` отрисована как текст (`&lt;script&gt;…`), script не исполняется, отдельного innerHTML с пользовательскими данными нет. Соответствие: нет blocker.
- **Секреты/инъекции:** секретов в диффе нет; SQL не пишется (используется API), параметры fetch корректны (`credentials: "same-origin"`).
- **Обработка ошибок:** все контракты API (200/201/401/404/409/422) обработаны, невыпадающие случаи — общий текст «Не удалось…»; стек-трейсы пользователю не видны.
- **Изоляция:** IIFE + `"use strict"`, глобальное состояние не мутируется, `active_page` подсветка работает (класс `active` на /settings).
- **Читаемость:** имена по домену, функции короткие, комментариев-трассировки на FR достаточно.

### Отступление стенда от прода (не дефект диффа)

В проде статику отдает nginx до приложения (design.md §8), поэтому из коробки uvicorn-стенд без nginx отдает `/static/*` через auth-middleware → 302 (браузер не получает `login.js`/`settings.js`). Для стенда в worktree `/tmp` добавлены локальные правки (в git не коммитились, боевое дерево не задето): mount StaticFiles + env-гейт `EKOTOV_REVIEW_STAND=1` в exempt. Это ограничение локальной разработки, а не ветки; при желании можно оформить отдельной задачей «dev-стенд без nginx» (вне скоупа 2.2).
