## Проверено (по кругам)

**Круг 1 — спека.** D1–D4 реализованы как в design: диалект гибридный, декомпозиция 12 модулей + реестр (директива Заказчика выполнена), шов wiki.py тонкий (только `_sanitize_content` + 3 точки вызова), editor.js/page.js — интеграционные зоны без логики ядра. Модальность: MUST-сценарии покрыты тестами (включая негативные: fallback lookalike, whitelist callout/width, структурные ошибки validate). Вне спеки поведения не обнаружено.

**Круг 2 — безопасность (NFR-35, фокус задачи).**
- Все векторы NFR-35 нейтрализуются на записи (прогнано на реальном коде): `<script>/<iframe>/<object>` → экранирование в текст во всех типах блоков и на любой глубине; `on*=` — как текст; `javascript:`/`data:` в ссылках/картинках — URL вырезается, текст/alt остаются; `java\tscript:` — режется (junk-фильтр переиспользован из sanitize.py); в код-блоке — буквальный текст. Идемпотентность sanitize подтверждена (re-save не меняет).
- **Инвариант M-4 подтвержден фактом:** fuzz 3000 legacy-строк — `sanitize_rich(legacy) == sanitize_html(legacy)`; passthrough идет полным оригиналом (без roundtrip-потерь); смешанный контент — по сегментам корректно.
- **Фронт:** grep по wiki/ — innerHTML для пользовательского rich-контента отсутствует; единственные innerHTML — legacy-HTML-сегменты (серверно санитизированы, template.innerHTML — тот же путь, что до пакета) и статические SVG-иконки. renderer/highlight/blocks — только createElement/textContent. Второй слой `safeUrl` на фронте корректно зеркалит схемы.
- Recursion/DoS — см. замечание 1 (единственная дыра безопасности-устойчивости).

**Круг 3 — интеграция.** Импортеры новых модулей — только wiki.py (blast radius минимален); db/миграции/requirements не тронуты; NFR-38: 66 существующих sanitize/wiki-тестов проходят без правок. A-2 fallback подтвержден кодом и тестами: RichSyntaxError (ValueError) → sanitize_html + `logger.warning` с page_id, без 422; lookalike-фикстуры (7 кейсов, включая те, что я бы считал краевыми — ::: без типа, GFM без разделителя).

**Модульность/дубли.** Зеркалирование парсера бэк/фронт — осознанное design-решение (§4), покрыто fixture-тестом идентичности `test_parser_matches_backend_on_grammar_fixtures` и roundtrip-тестами; размножения логики сверх зеркала нет.

**Тесты.** Не мокируют: sanitize-тесты зовут реальные `sanitize`/`validate`, web-тесты — реальный playwright-стенд; XSS-тест рендера (`test_renderer_xss_vectors_no_executable_elements`) проверяет в реальном DOM отсутствие script/iframe/object/on*/javascript:. Perf-тест NFR-37 честный: реальный chromium+uvicorn+tmp-БД, фикстура 50 блоков (состав совпадает с REPORT-perf), замер goto→видимый рендер последнего блока, порог 2 с, факт 0.26 с, append-only REPORT. TC-ID трассировка присутствует.

**Персоны (adversarial, обязаны найти ≥1):** саботажник — замечание 1 (500 на crafted-контенте); новичок — замечание 2 (security-инвариант зеркала не помечен в коде как критичный); security-аудитор — замечание 2, XSS-ось чиста. Вердикт персон: CONCERNS → return.
