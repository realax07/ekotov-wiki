## Проверенные Scenario (первый круг — спека)

- **«Профиль отображается внизу сайдбара»**: блок `#sidebar-profile` в base.html после «Настройки»/«Выйти» — внизу; кружок `.profile-badge` = первая буква логина верхним регистром + подпись логином целиком (Д-7). Цвет кружка — один акцентный `--color-accent` (решение dev-задачи, допустимо design §3).
- **«Профиль показывает сессионного пользователя»**: данные из `GET /api/auth/me` (задача 1.1) — логин своей сессии; credentials: same-origin.
- **«В профиле нет аватарок-файлов и смены пароля»**: блок статичен, действий нет; настроек профиля нет (ОГР-13, Won't дословно).
- **«Профиль не нарушает верстку сайдбара»**: блок добавлен ПОСЛЕ существующих разделов (не вытесняет); до ответа API и при 401 скрыт (`display:none` без `.profile-filled`) — «при 401 блок не отображается» выполнено.
- **На всех страницах функционала**: ES-модуль подключен в base.html (board/search/wiki/settings наследуют; login.html не наследует base — корректно, страница входа). Задача 1.1/1.2 в NFR-1 укладывается (1 запрос/страницу).
- **Бамп static_v**: r2.1→r3.1 в `34e0261` (DEF-002, З-2 учтено — в задачах 1.x бамп был прописан).
