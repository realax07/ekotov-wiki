## Проверенные Scenario (лично, исполнением)

**TZ-механика (особое внимание 1):**
- `_msk_day_start_iso()` при server-TZ `UTC+14` (TZ=Pacific/Kiritimati) и UTC+0:
  возвращает ровно `00:00+03:00` текущего МСК-дня; `astimezone(MSK).replace(0,0,0,0)`
  корректна при любом server-TZ (момент `datetime.now(utc)` от локали не зависит). ✅
- Табличный прогон всех 24 часов МСК-дня с продакшн-форматом done_at: **часы
  00–03 МСК ошибочно архивируются** — воспроизведение blocker #1. ❌
- Граница `done_at = 00:00 МСК сегодня` → архивируется (должна оставаться). ❌ (#1)
- done вчера/раньше → archived_at проставлен, с доски исчезла. ✅

**Полный цикл TestClient (особое внимание 2, 7):**
- move в done → 200, `done_at` в БД, `archived_at` NULL, задача в done-столбце. ✅
- done_at сегодня (формат +03:00) → на доске после повторного GET. ✅
- Обратный move done→todo/in_progress → оба NULL, задача в целевом столбце. ✅
- Двойной GET подряд → идентичные ответы (ленивый UPDATE безобиден). ✅
- 8 параллельных GET /api/board → все 200, без busy/ошибок; нарушений
  инварианта sdd §4 (`done`+`archived IS NULL` без `done_at`) — 0. ✅

## Вывод

Реализация архитектурно соответствует sdd r5 (ленивый UPDATE одним запросом,
real done-столбец, идемпотентная миграция, регрессия чистая), но blocker #1 —
смешение UTC- и +03:00-форматов done_at/границы — нарушает календарную границу
МСК для первых ~4 часов каждого дня: задачи, выполненные сегодня ночью по МСК,
автоматически архивируются в тот же день, т.е. столбец «Выполнено» не
удовлетворяет спеке четверть суток ежедневно. **Return** деву: выровнять формат
done_at с границей (рекомендация в #1), обновить смоук (#2), повторное ревью.
