## Особое внимание (из постановки) — проверено лично

| Пункт | Результат |
|---|---|
| **Wiki — именно заглушка** | `/wiki` с сессией → 200: в теле нет `<form`, `<textarea`, `<input`, `contenteditable`, ссылок create/edit/new; есть `todo-note` и текст «wiki-функции … отсутствуют». Сценарий «Раздел Wiki не дает wiki-функций» (Won't) выполнен. ✅ |
| **active-подсветка** | На каждом из 3 путей ровно один `nav-item active`; классы сверены попарно: `/board` → active у Доски, `/search` → у Поиска, `/wiki` → у Wiki; остальные — чистый `nav-item`. Определяется серверно через `active_page` в context роутера (pages.py), не JS: app.js не содержит логики подсветки и не читает path. Сценарий «Сайдбар доступен со всех страниц» выполнен. ✅ |
| **Logout через fetch (app.js)** | Код: `fetch POST /api/auth/logout, credentials: same-origin` → `.then` → `window.location.href = "/login"`; `.catch` — разблокировка кнопки. Прогон: logout с сессией → `200 {"ok":true}` + Set-Cookie с `Max-Age=0`; после удаления куки `/board` → 302 `/login` (browser lands on login form), повторный logout → 401. Случай HTTP-ошибки (401) fetch резолвит → тоже redirect на /login — корректно (middleware сам перенаправит; причин не раскрывает). ✅ |
| **XSS через пути/параметры** | Роуты pages.py не читают query (в коде нет `.query_params`); 5 payload'ов (`<script>`, `<img onerror>`, `<svg onload>`, URL-encoded, `javascript:` iframe) на все 3 страницы × параметры q/next/redirect — отражений в теле нет; тело ответа с query и без — байт-в-байт идентично; app.js не читает `location.search`/`URLSearchParams`. ✅ |
| **Jinja2 autoescape** | `Jinja2Templates` → `select_autoescape` включен (инспекция env + прямой рендер `{{ v }}` с HTML → экранировано). Шаблоны принимают только литерал `active_page` из кода — пользовательских данных в рендере нет вовсе. ✅ |
| **Регрессия auth (круг 3)** | Без сессии: `/board`, `/search`, `/wiki`, неизвестная страница → `302 Location: /login`; `/login` → 200 (и с сессией тоже). API: `POST /api/auth/logout` без сессии → `401 {"error":"unauthorized"}` (текст middleware, не путается с login-текстом); login с неверным паролем и с несуществующим пользователем → идентичный `401 {"error":"invalid credentials"}` (NFR-7 цел); `/api/health` → 200. login.html не наследует base.html (без сайдбара на форме входа). Задачи 2.2/2.3 не сломаны. ✅ |
| **FR-13 соответствие** | Сайдбар: Доска → `/board`, Поиск → `/search`, Wiki + бейдж `todo` → `/wiki` — состав и пометка дословно из FR-13/дельты; logout-элемент — по подзаметке tasks 3.1 и примечанию review-2.3-001 №3. Пути совпадают с sdd §3.6 дословно. Поведения вне спеки в дифе нет (CSS — минимальная стилизация каркаса, не функциональность). ✅ |
