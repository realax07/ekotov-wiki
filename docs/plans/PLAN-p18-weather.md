# План: P18 «Погода» (Москва, сегодня + 7 дней)

**Флоу:** 1 (компактный, новый сервис). **Дизайн:** вариант A (сетка карточек, выбор Заказчика 2026-10-19, design/p18-weather/variant-a.*).

## Зафиксированные решения (ОВ-1…4)
Только после входа; пункт в сайдбаре; все метрики; кэш/обновление раз в час. Провайдер: Open-Meteo (без ключа).

## Волны
1. **СА** — openspec change weather-service: proposal/spec/design. Спека: auth-only (401 анониму), сайдбар-пункт, карточка «сегодня» (темп, описание, ощущается, макс/мин, осадки, ветер, влажность, давление), 7 дней (день/ночь, осадки %, ветер), Open-Meteo по координатам Москвы (55.7539, 37.6208), кэш 60 мин (провайдер недоступен → отдаем кэш, статус «данные устарели»), layout по мокапу A. Дизайн: сайдкар weather:8381 (паттерн video:8380), nginx auth_request-маршрут /weather + /api/weather, кэш-файл в томе, таймауты провайдера, compose-сервис.
2. **arch-ревью** — архитектор по канону (VALID_GATE).
3. **dev** — сервис + фронт (мокап A) + миграций нет (без БД-схемы, кэш-файл) + тесты api/web (TC-префикс weather).
4. **QA + regress** — доменный smoke + tests/api срез; regress-final по воротам релиза.
5. **Деплой** — static_v бамп (обязанность ПМ до диспетчеризации devops), deploy.sh матрица + weather, RUNBOOK-раздел.

## Границы
- БД-схемы нет (кэш-файл в volume) — миграция не требуется.
- Секретов нет (Open-Meteo без ключа) — но User-Agent/таймауты в конфиге.
- Один город (Москва) — параметризация городов вне скоупа (продуктовое решение на будущее).
