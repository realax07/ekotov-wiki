## 1. Общее описание

Change-пакет формализует машиночитаемые контракты четырех выделенных HTTP-сервисов (search, images, video, weather) и их потребителей. Сейчас контракт в явном виде есть только у search (заморожен в 2026-10-04); у images/video/weather контракт существует де-факто (FastAPI `/openapi.json` + тесты на наборы путей), но нигде не заморожен и дрейфом не управляется. Пакет дает:

1. **Замороженную OpenAPI-спеку на каждый сервис** (endpoints, схемы ответов/ошибок, auth) — в едином месте `contracts/`.
2. **Карту вызовов** в `architecture/map.md` (раздел «Контракты и зависимости»): кто чей клиент, nginx-маршруты, деградации.
3. **Контрактные тесты**: ответы сервисов валидируются по схемам спеки (не только «набор путей», как сейчас).
4. **CI-гейт дрейфа**: правка handler'а без правки спеки — механический DENY (база IR-01/IR-07; при необходимости новые IR — декларативно в `impact_rules.json`).

Назначение системы, аудитория (2 пользователя, ОГР-6), выделение сервисов (services/README.md: search 8378, images 8379, video 8380, weather 8381; auth выделению не подлежит) — не меняются.

### 2.2 Вызовы app→сервисы: их НЕТ (важно для скоупа)

Grep `httpx`/`requests`/`aiohttp`/`urllib` по `backend/app`: **сервер-сервер вызовов ядро в сервисы не делает** (urllib.parse — только парсинг URL). Единственный httpx-клиент в системе — `services/weather/app/provider.py`, и он ходит во **внешний** API Open-Meteo (таймауты 5с×2 попытки), не в чужие сервисы.

Фактические потребители сервисов:

| Потребитель | Как вызывает |
|---|---|
| Браузерный JS (search.js, галерея, video.js, inline-скрипт weather.html) | `fetch('/api/…')` → nginx → соответствующий сервис |
| nginx (internal) | `auth_request` → subrequest `/_video_auth` → video `GET /api/videos/authcheck` (защита `/videos/` стриминга) |
| nginx (деградация) | при недоступности сервиса — named-локации `@search_down`/`@images_down`/`@videos_down`/`@weather_down`: управляемый 503 JSON + `Retry-After: 5` |

Следствие для ТЗ: «карта вызовов app→сервисы» из плана P20 превращается в **карту «браузер→nginx→сервисы» + внутренний nginx-стык authcheck**. Правило «ядро не ходит в сервисы по HTTP» предлагается зафиксировать как ограничение (ОГР-30) — это сегодня инвариант теста TC-openapi-202, распространяемый на все сервисы.

### 2.3 nginx-маршрутизация (services/frontend/nginx/ekotov-wiki.conf)

Для каждого сервиса — пара локаций «= точный + `^~` префикс-слэш» с прокси через переменную + `resolver 127.0.0.11` (анти-stale-DNS): `/api/search*`, `/api/suggestions*` → search:8378; `/api/images*` → images:8379 (+ статика `/images/`); `/api/videos*` → video:8380 (+ `/videos/` стриминг с authcheck); `/api/weather*` → weather:8381; `/` → app:8377. Заголовки `X-Service` — через `*-headers.inc`. `/games/` — прокси на внешний standalone-контейнер (вне скоупа пакета, упоминается в карте).

### 2.4 CI-гейт дрейфа: ОТСУТСТВУЕТ

`.github/workflows/flow.yml` не содержит контракто-гейта. Заморозка search защищена только юнит-тестами; правка handler'а images/video/weather без спеки вообще нечем поймать (спеки нет). База для нового правила — IR-01/IR-07 `impact_rules.json` (декларативно, по практике конвейера).
