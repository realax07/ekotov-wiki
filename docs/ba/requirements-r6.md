## 1. Общее описание

Change-пакет закрывает единственный **реальный** пробел пункта P1 — UX автодополнения тегов в форме задачи («как в Jira») — и по решениям Заказчика добавляет: полиш графики формы, единое действие закрытия по Escape, адаптив формы на узких экранах и консолидацию кнопок управления задачей в одну зону (OV-4: «кнопки управления задачей разбросаны в разные места»). Остальные пункты P1 (крестик, приоритеты с цветом/иконкой, fast=high, категории списком) уже реализованы в Релизах 1–5 и из объема исключены (аудит — раздел 2).

Назначение системы, аудитория (2 пользователя, ОГР-6), модель «общей доски», дизайн-токены V3 «Бумага» не меняются.

## 3. Функциональные требования (FR)

### 3.1 Автодополнение тегов «как в Jira» (закрытие пробела P1)

Нативный `<datalist>` не дает требуемого UX: непод controllable-дропдаун, нет подсветки совпадений, нет исключения уже введенного, смешивает теги с категориями. **Решение Заказчика (ОВ-2): кастомный autocomplete-комбобокс — подтвержден.**

|| ID | Требование | Приоритет | Источник | Предложение по решению | Сложность |
|---|---|---|---|---|---|
| FR-57 | Подсказки тегов в форме задачи показывают **только существующие теги проекта** (не категории): начинаешь вводить — показываются совпадающие заведенные теги. Категории в подсказках поля «Теги» не участвуют (у категории свой select). | Must | P1: «показывает существующие теги проекта»; **ОВ-1: только теги** | Backend: источник только тегов, существующий GET /api/suggestions не ломается (ОГР-26): параметр `GET /api/suggestions?kind=tags` — «kind» уже семантика фильтра множества, дефолт «без параметра = прежний UNION тегов и категорий» сохраняет контракт поиска дословно (тесты TC-API-SUGG-001/004 не меняются). Frontend: `loadTagHints()` бьет по `?kind=tags` | S |
| FR-58 | Список подсказок **фильтруется по вводу и исключает уже введенные** теги задачи: введенный тег не предлагается повторно; совпадение с подсказкой визуально подсвечивается (как в Jira). | Must | P1: «начинаешь вводить — показывает существующие теги»; «как в Jira»; **ОВ-2** | Frontend: фильтрация/дедупликация на клиенте при рендере дропдауна (источник истины — input, как у чипов FR-34); бэкенд не трогается | S |
| FR-59 | Выбор подсказки и создание нового тега — **явными действиями**: клик по подсказке добавляет тег; при вводе значения, которого нет, dropdown показывает явный пункт «+ Добавить тег „‹ввод›“». Выбранные теги видны чипами (существующий UI FR-34 сохраняется, источник истины — input не меняется). | Must | P1: «можно выбрать или создать новый»; «как в Jira»; **ОВ-2** | Frontend: кастомный дропдаун под input (позиционирование, клик вне — закрыть, выбор → дописать в input + перерисовать чипы). Кнопка «Добавить тег» — аффорданс, механика сохранения (get-or-create) не меняется | M |

### 3.2 Побочные пробелы, включенные решением Заказчика (ОВ-3)

|| ID | Требование | Приоритет | Источник | Предложение по решению | Сложность |

Комментарий `board.html` про «действия из окна деталей» обновить | M |
