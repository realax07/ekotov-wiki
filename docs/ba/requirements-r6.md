## 1. Общее описание

Change-пакет закрывает единственный **реальный** пробел пункта P1 — UX автодополнения тегов в форме задачи («как в Jira») — и добавляет полиш графики формы. Остальные пункты P1 (крестик, приоритеты с цветом/иконкой, fast=high, категории списком) уже реализованы в Релизах 1–5 и из объема исключены (аудит — раздел 2).

Назначение системы, аудитория (2 пользователя, ОГР-6), модель «общей доски», дизайн-токены V3 «Бумага» не меняются.

## 3. Функциональные требования (FR)

### 3.1 Автодополнение тегов «как в Jira» (закрытие пробела P1)

Нативный `<datalist>` не дает требуемого UX: непод controllable-дропдаун, нет подсветки совпадений, нет исключения уже введенного, смешивает теги с категориями. Предлагается замена на кастомный autocomplete-комбобокс (решение — ОВ-2).

|| ID | Требование | Приоритет | Источник | Предложение по решению | Сложность |
|---|---|---|---|---|---|
| FR-57 | Подсказки тегов в форме задачи показывают **только существующие теги проекта** (не категории): начинаешь вводить — показываются совпадающие заведенные теги. Категории в подсказках поля «Теги» не участвуют (у категории свой select). | Must | P1: «показывает существующие теги проекта» | Backend: параметр/отдельный путь выдачи только тегов (GET /api/suggestions возвращает tags ∪ categories по зафиксированному контракту поиска — ломать его нельзя, ОГР-26). Вариант А: `GET /api/suggestions?kind=tags`; вариант Б: отдельный `GET /api/tags` (мин-список имен). Frontend: `loadTagHints()` бьет по новому источнику | S |
| FR-58 | Список подсказок **фильтруется по вводу и исключает уже введенные** теги задачи: введенный тег не предлагается повторно; совпадение с подсказкой визуально подсвечивается (как в Jira). | Must | P1: «начинаешь вводить — показывает существующие теги»; «как в Jira» | Frontend: фильтрация/дедупликация на клиенте при рендере дропдауна (источник истины — input, как у чипов FR-34); бэкенд не трогается | S |
| FR-59 | Выбор подсказки и создание нового тега — **явными действиями**: клик по подсказке добавляет тег; при вводе значения, которого нет, dropdown показывает явный пункт «Добавить новый тег „‹ввод›“». Выбранные теги видны чипами (существующий UI FR-34 сохраняется, источник истины — input не меняется). | Must | P1: «можно выбрать или создать новый»; «как в Jira» | Frontend: кастомный дропдаун под input (позиционирование, клик вне — закрыть, выбор → дописать в input + перерисовать чипы). Кнопка «Добавить новый» — аффорданс, механика сохранения (get-or-create) не меняется | M |
| FR-60 | **Полиш графики формы в целом** (остаток пункта P1 «проработать графику/визуал формы»): визуальный проход по форме задачи по токенам V3 — состояния полей (hover/focus/ошибка), кнопки, отступы, типографика, анимации уже есть (modal-in, reduced-motion учтено) — доводится консистентность без изменения логики и валидации (рамка DEF-005). | Should | P1: «проработать графику/визуал формы в целом»; P9 объединен с P1 | Frontend-only: проход по `.task-form` в `board.css` против мокапа V3 (`design/form-style-v3.html`); конкретный состав — по живому макету (J25 конвейера) | S–M |
