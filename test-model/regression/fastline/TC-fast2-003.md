# TC-fast2-003 — Поле приоритета заблокировано в форме fast-задачи

- **CHK:** CHK-129
- **Change:** add-r2-categories-settings
- **Источник:** fastline MODIFIED (FR-27, UI-часть) / Scenario: Поле приоритета заблокировано в форме fast-задачи
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** пользователь авторизован и отмечает в форме создания задачи назначение на fast line
  - **WHEN** пользователь просматривает поле приоритета
  - **THEN** поле приоритета показывает значение «высокий» (high) и заблокировано для изменения (FR-27, UI-часть)
- **Шаги:**
  1. Открыть форму задачи; зафиксировать состояние поля «Приоритет» ДО отметки (выбранное значение, disabled).
  2. `page.get_by_label("fast line").check()`.
  3. Зафиксировать состояние поля приоритета ПОСЛЕ: `sel.evaluate("el => el.value + '|' + el.disabled")`.
  4. Попытка изменить: `page.get_by_label("Приоритет").select_option("low")` — зафиксировать исключение/неизменность значения.
  5. Снять флажок fast → зафиксировать состояние поля (разблокировка и возврат значения — фактическое поведение в протокол; спекой не оговорено).
- **Ожидаемый результат:** шаг 3 — значение поля `high` (или локализованное «Высокий» с value=high), атрибут disabled=true; шаг 4 — сменить приоритет невозможно (Playwright падает на disabled select, значение не меняется) — блокировка поля (FR-27 UI-часть). Шаг 5 — фактическое поведение зафиксировано (разблокировка при снятии fast ожидаема).
- **Тестовые данные:** чекбокс fast line; поле «Приоритет»; попытка установки low.
