- **Маркер:** manual (НЕ автоматизируется; носитель протокола деплой-процедуры)
- **Предусловия:** доступ на прод-VPS по runbook (`deploy/RUNBOOK.md`); DRY_RUN-режим deploy.sh отработал ранее без ошибок предусловий; копия прода (репетиционный стенд) с актуальным снапшотом БД и аватаров.
- **Шаги:**
  1. **Репетиция (на копии прода):** развернуть копию (БД `/var/lib/ekotov-wiki/wiki.db` + каталог аватаров + код целевого релиза); на репетиционном стенде прогнать тесты миграции test_migration_r4 (снапшот «ноль потерь», бэкфилл, идемпотентность, негатив owner-missing) — копия, не прод.
  2. **Репетиция deploy.sh (DRY_RUN):** на копии `DRY_RUN=1 bash deploy/deploy.sh` — все 6 шагов печатаются, ничего не меняется; убедиться, что шаг 3 (бэкап БД) и шаг 4b/6 (миграция Р4) присутствуют и идут в правильном порядке (бэкап СТРОГО до миграции, миграция до рестарта).
  3. **Реальный бэкап на проде (до деплоя):** выполнить deploy.sh на проде; на шаге 3 зафиксировать путь бэкапа `BACKUP_FILE` (`/var/backups/ekotov-wiki/wiki-pre-r4-<дата>-<время>.db`); при релизах, трогающих аватары (Р4 — да), убедиться, что каталог `/var/lib/ekotov-wiki/avatars/` скопирован рядом с бэкапом БД (runbook §3).
  4. Проверить бэкап ДО продолжения: `ls -la $BACKUP_FILE` — размер > 0 (скрипт сам делает `[ -s "$BACKUP_FILE" ] || fail`); выборочно: `sqlite3 $BACKUP_FILE "SELECT count(*) FROM users; SELECT count(*) FROM tasks"` — цифры соответствую прод-состоянию (или сверка со снапшотом прогона).
  5. Продолжить деплой (миграция 4b/6 → рестарт → смоук). Негативный контроль страховки: при падении миграции (exit 1 = расхождение сверки NFR-9) — деплой ПРЕРВАН, БД восстановима из `$BACKUP_FILE` (сообщение скрипта), повтор деплоя после устранения причины; восстановление репетировать на копии один раз: `cp $BACKUP_FILE` → запуск приложения → вход owner/wife работает.
  6. Протокол (пути бэкапов, размеры, результаты шагов) — в отчет деплоя Р4.
- **Ожидаемый результат:** шаг 1–2 — репетиция на копии зеленая, порядок шагов «бэкап → схема → миграция → рестарт» подтвержден. Шаги 3–4 — файл `wiki-pre-r4-*.db` непустой и лежит в `/var/backups/ekotov-wiki/`, счетчики users/tasks соответствуют прод-состоянию; каталог аватаров скопирован рядом. Шаг 5 — деплой проходит, смоук зеленый; при падении миграции БД восстанавливается из бэкапа (вход работает, данные на момент до миграции). Любой запуск миграции на проде БЕЗ предварительного непустого бэкапа — нарушение ОГР-19, деплой запрещен.
