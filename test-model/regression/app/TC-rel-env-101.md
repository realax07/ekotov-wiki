# TC-rel-env-101 — РУЧНАЯ (релизная дисциплина): бамп static_v до r4.x — один финальный бамп на релиз

- **CHK:** CHK-R4-101 (чеклист Р4: релизный бамп `static_v` до `r4.x`; ОГР-16, урок DEF-002/003, review-001 C-5; impact §3 «НЕТ — прогонами не ловится (браузерный кеш), слепой контур — релизная дисциплина, отметка в deploy.sh»)
- **Change:** add-r4-user-profile-ticket-view
- **Источник:** deploy/RUNBOOK.md §5 («если релиз трогал статику — забампить `static_v` в backend/app/pages.py, иначе браузеры держат старый CSS 7 дней; один финальный бамп на релиз, формат `r4.x`»); backend/app/pages.py (`static_v = "r3.2"`); deploy/deploy.sh (напоминание в смоуке)
- **Тип:** НФТ, средовая (ручная релизная процедура — прогонами не ловится: браузерный кеш, прод-отдача статики) | **Приоритет:** Must
- **Маркер:** manual (НЕ автоматизируется; носитель — чек-лист релиза + curl-проверки в протоколе деплоя)
- **Предусловия:** деплой Р4 на прод; известен состав статических изменений релиза (tooltip, profile-settings JS/CSS, view-модалка, стили формы исполнителя — все заходили в `frontend/static/` в волне Р4).
- **Шаги:**
  1. До деплоя: убедиться, что в `backend/app/pages.py` `static_v` забамплен ровно ОДИН раз на релиз до значения формата `r4.x` (например `r4.0`), а не несколько промежуточных значений по ходу волн (дисциплина review-001 C-5).
  2. `grep -n "static_v" backend/app/pages.py` — значение одно для всех страниц (единый шаблонный контекст templates.env.globals).
  3. После деплоя открыть прод-страницы и сверить версии статики: curl страниц `/board`, `/search`, `/settings/user` (авторизованная сессия) — все ссылки на CSS/JS содержат `?v=r4.x` (одно и то же значение на всех страницах, нигде не осталось `r3.2`).
  4. Смоук нового файла: `curl -sI https://<прод-URL>/static/js/board/task-form.js` — 200; URL запроса в выдаче страницы содержит новый `?v=r4.x` (старый кеш браузера не будет переиспользован — URL другой).
  5. Контроль повторяемости: повторный деплой/рестарт БЕЗ изменений статики НЕ меняет значение `?v=r4.x` (не бампается «просто так» — иначе кеш рвется зря на каждом рестарте).
  6. Протокол — в отчет деплоя Р4.
- **Ожидаемый результат:** шаг 1–2 — единственный финальный бамп `r4.x` в репозитории релиза, без «набора» промежуточных значений. Шаг 3 — на всех прод-страницах ссылки на статику несут `?v=r4.x`, следов `r3.2` нет (иначе новые tooltip/profile-settings/view-стили залипают в 7-дневном кеше — риск DEF-002/003). Шаг 4 — новый файл отдается (200). Шаг 5 — значение стабильно между рестартами при неизменной статике.
- **Тестовые данные:** `backend/app/pages.py` (`static_v`); прод-URL; файлы `frontend/static/js/board/task-form.js`, CSS tooltip/profile-settings/view-модалки; runbook §5.
