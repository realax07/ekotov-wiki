# TC-ava-r5-107 — EXIF-портрет с телефона: jpg с EXIF-ориентацией принят и нормализован

- **CHK:** CHK-R5-13
- **Change:** add-r5-avatar-crop-compact-profile
- **Источник:** auth MODIFIED (нормализация «в любом случае»); design §7 «Риски» (EXIF-поворот — главный кейс пользователей: портретное фото с телефона); ТЗ СЦ-6 (вариант А: EXIF обрабатывает клиент, сервер обязан принять вход). Сервер НЕ обязан вращать (вращает браузер при декодировании), но НЕ должен отклонять EXIF-файл и обязан нормализовать к 256×256 PNG.
- **Тип:** гран. | **Приоритет:** Must
- **Маркер:** api
- **Среда/предусловия:** API-стенд tests/api; сессия owner; teardown-гигиена.
- **Шаги:**
  1. Сформировать JPEG 1200×800 с EXIF-тегом Orientation=6 (поворот 90°, типичный портрет с телефона; PIL/piexif или ручная вставка APP1-сегмента).
  2. `POST /api/profile/avatar` (photo.jpg, image/jpeg) от owner.
  3. Открыть сохраненный файл PIL (без apply_exif-трансформаций).
- **Ожидаемый результат:** 200 ok (не 422 — EXIF-содержимое валидный jpeg, Pillow декодирует); на диске PNG ровно 256×256. Ассерт на ориентацию пикселей НЕ ставится: по варианту А (ОВ-СА-1) ориентацию применяет браузер при декодировании в `<img>` — серверная нормализация геометрии «как декодировано» спекой разрешена.
- **Тестовые данные:** JPEG 1200×800 + EXIF Orientation=6.
