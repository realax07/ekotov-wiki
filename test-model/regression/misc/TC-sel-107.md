# TC-sel-107 — Единый механизм значений: категории и подсказки из двух общих эндпоинтов

- **CHK:** CHK-178
- **Change:** add-r3-visual-foundation
- **Источник:** search (MODIFIED): «Механизм MUST быть общим для селект-полей» (FR-35, DEF-001); Сценарий «Единый механизм для селект-полей и подсказок»
- **Тип:** поз. | **Приоритет:** Must
- **Среда/предусловия:** web-стенд tests/web; вход owner; страница /board (для формы) и /search открыты в ходе шагов.
- **Шаги:**
  1. Перехватить сетевые запросы страницы (page.on request): открыть форму задачи, затем /search.
  2. Зафиксировать URL-ы загрузки опций: из какого эндпоинта заполнился каждый из четырех источников (форма/фильтр × категории/подсказки).
  3. Осмотреть DOM: у опций селектов и datalist'ов нет значений, отсутствующих в ответах перехваченных запросов.
- **Ожидаемый результат:** категории (форма `#task-category` и фильтр `#search-category`) заполняются из `GET /api/categories`; подсказки (`#task-tag-hints`, `#tag-hints`) — из `GET /api/suggestions`; все четыре источника используют два общих эндпоинта, значений вне ответов API в DOM нет — отдельных статических списков не существует.
- **Тестовые данные:** эндпоинты `GET /api/categories`, `GET /api/suggestions`.
