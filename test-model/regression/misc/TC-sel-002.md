# TC-sel-002 — Select «Категория» фильтра-конструктора заполнен из фактического справочника

- **CHK:** CHK-124
- **Change:** add-r2-categories-settings
- **Источник:** search: Селект-поля из фактических данных (FR-30) / Scenario: Выбор категории в фильтре-конструкторе заполняется из справочника
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** в справочнике заведены `Дом`, `Работа`, `Личное` + `QAT-sel-filtr`
  - **WHEN** пользователь раскрывает поле «Категория» в фильтре-конструкторе поиска
  - **THEN** список значений содержит ровно фактическое содержимое справочника
- **Шаги:**
  1. `POST /api/categories` name=`QAT-sel-filtr` → 201.
  2. `GET /api/categories` → список `S`.
  3. Открыть `/search` (режим «Конструктор»); прочитать опции select «Категория» (исключив пустую опцию) → `O`.
  4. Сравнить `set(O) == set(S)`.
  5. Cleanup: DELETE категории `QAT-sel-filtr` → 200.
- **Ожидаемый результат:** шаг 4 — опции фильтра равны справочнику; свежая категория `QAT-sel-filtr` присутствует — фильтр из фактических данных (FR-30, sdd §4).
- **Тестовые данные:** справочник seed + `QAT-sel-filtr`.
