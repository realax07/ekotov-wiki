# TC-set-003 — Настройки общие: изменение одного пользователя видно другому

- **CHK:** CHK-105
- **Change:** add-r2-categories-settings
- **Источник:** settings: Настройки общие для всех пользователей (FR-24) / Scenario: Изменение настроек одного пользователя видно другому
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200; `BASE_URL` по умолчанию `http://127.0.0.1:8080`); выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed `tests/api/conftest.py`, куки в `owner_cookies.txt`); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** оба пользователя (`owner`, `wife`) авторизованы в разных сессиях; категория `QAT-общ-home` в справочнике есть
  - **WHEN** первый (owner) создает категорию `QAT-общ-work`, а второй (wife) обновляет страницу настроек
  - **THEN** второй видит `QAT-общ-work` в справочнике (изменения общие)
- **Шаги:**
  1. Вход wife: `curl -c wife_cookies.txt` (логин `wife`, пароль `QaWife_Pass_2!` — seed, как в conftest) → 200/редирект на доску.
  2. owner: `POST /api/categories` name=`QAT-общ-work` → 201.
  3. wife: `curl -s -b wife_cookies.txt {BASE_URL}/api/categories` → список содержит `QAT-общ-work`.
  4. wife (UI): `page.goto("{BASE_URL}/settings")` (сессия wife) → `QAT-общ-work` видна в списке справочника.
  5. Cleanup (CHK-140): DELETE категории `QAT-общ-work` → 200.
- **Ожидаемый результат:** шаги 3–4 — категория, созданная первым пользователем, видна второму в API и на странице настроек — настройки общие (FR-24), нет пер-пользовательской изоляции.
- **Тестовые данные:** сессии owner и wife; категория `QAT-общ-work`.
