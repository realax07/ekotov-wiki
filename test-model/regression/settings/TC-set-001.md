# TC-set-001 — Авторизованный пользователь открывает настройки

- **CHK:** CHK-103
- **Change:** add-r2-categories-settings
- **Источник:** settings: Страница настроек (FR-23) / Scenario: Авторизованный пользователь открывает настройки
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** пользователь авторизован
  - **WHEN** пользователь переходит в раздел «Настройки» (прямой `GET /settings` и через сайдбар)
  - **THEN** открывается страница настроек
- **Шаги:**
  1. `curl -s -i -b owner_cookies.txt {BASE_URL}/settings` → код, наличие заголовка страницы (HTML).
  2. UI: `page.goto("{BASE_URL}/settings")` → `page.get_by_role("heading", name="Настройки")` виден; URL `{BASE_URL}/settings`.
  3. На странице виден блок управления справочником категорий (список категорий seed: `Дом`, `Работа`, `Личное`).
- **Ожидаемый результат:** шаг 1 — HTTP **200**, в HTML — страница настроек; шаги 2–3 — страница открыта, заголовок «Настройки» виден, справочник отображается (sdd §3.3).
- **Тестовые данные:** URL `{BASE_URL}/settings`; сессия `owner`.
