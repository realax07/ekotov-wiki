# regression/ — as-is кейсы по доменам (будущим сервисам)

> Решение Заказчика (2026-10): кейсы — конечные артефакты as-is. Они
> группируются по сервисам/доменам, НЕ по релизам. Промежуточные
> артефакты конвейера (чеклисты, ревью, impact-вердикты закрытых
> пакетов) — в `../archive/workflow/`. Содержимое кейсов при переносе
> не менялось (git mv, история сохранена).

## Структура

```
regression/
  <domain>/            # поименованные кейсы: 1 файл = 1 кейс (TC-*.md)
    legacy/            # общие файлы R1-R3 с inline-TC (as-is документы)
  manifest.md          # манифест регресса (метки keep/candidate-archive)
```

**Домены = будущие сервисы.** Точные границы сервисов определит
архитектор; текущая группировка — по префиксу TC-ID (карта ниже) и
отражает естественные разрезы продукта. При выделении сервиса домен
переезжает целиком (git mv каталога).

## misc — что внутри и почему не разложено

36 кейсов с префиксами, у которых нет однозначного домена без решения
архитектора (границы сервисов еще не определены):

- `TC-dnd-101…106` (6) — drag-and-drop. Поведение доски (board), но
  механика — общая frontend-инфраструктура; при выделении
  «frontend-platform» уедет туда.
- `TC-form-001…011` (11), `TC-formv3-101…105` (5) — форма задачи
  (V1→V3). Форма принадлежит доске, но редактирование затрагивает
  категории/теги/подсказки — разрез решит архитектор.
- `TC-sel-001…004`, `TC-sel-101…108` (12) — селект-поля из фактических
  данных. Сквозной UI-компонент (форма + поиск + настройки).
- `TC-env-001…002` (2) — средовые (seed справочника, предусловия
  прогонов). Инфраструктура тестирования, не домен продукта.

Распределение — руками по содержимому после фиксации границ сервисов;
до тех пор misc гарантированно не теряет ни один кейс.

## legacy/ — почему лежит

Общие файлы Релизов 1-3 (`tasks-01.md`, `board-01.md`, `search-01.md`,
`auth-01.md`, `fastline-01.md`, `navigation-01.md`, `archive-01.md` из
add-kanban-core; `sugg-01.md` из add-suggestions; `ui-01.md` из
e2e-critical-path) содержат inline-TC (несколько кейсов в одном файле).
Это **документы as-is**: TC внутри остаются на месте, на живые
отдельные кейсы не раскладываются (правило «1 кейс = 1 файл» applies
только к новым кейсам). Файл переносится целиком в legacy/ того
домена, к которому относится его основная масса TC. Trассировка
автотестов на inline-TC из legacy-файлов сохраняется.

## Контроль сохранности

Жесткое требование: все TC-ссылки из `tests/` должны находить артефакт
в новой структуре. Проверка: см. отчет переноса (364 ссылки, 0
потерянных); содержимое всех файлов test-model/ побайтово совпадает с
main (проверено по git blob SHA). 42 TC-ID из docstring'ов тестов
R4/R5/R6 (TC-assign-1xx, TC-cmt-2xx, TC-r5*-Nxx, TC-r6-comb-0xx и др.)
не были оформлены как отдельные кейсы еще до переноса — их источники:
CHK-строки архивных чеклистов (`../archive/workflow/checklists/`, все
98 CHK из tests/ находятся) и дельты спек в
`openspec/changes/archive/`. Это пред-существующее состояние, миграция
его не изменила.

## Не переносилось сюда (намеренно)

- `regression/manifest.md` — живой манифест регресса (ссылки на тесты).
- `impact/`-вердикты живых пакетов — у закрытых пакетов уехали в
  `../archive/workflow/impact/`.
- `tests/`, `scripts/`, `openspec/`, `decisions/`, `releases/`,
  `skills/`, `contracts/`, `code-reviews/` — вне скоупа переноса.
