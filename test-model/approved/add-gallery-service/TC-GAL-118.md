# TC-GAL-118 — e2e: загрузка через форму (drag&drop happy + ошибки 422 в UI)

- **Change:** add-gallery-service
- **Источник:** gallery (ADDED): «Лимиты загрузки» (NFR-21) — web-сторона (человекочитаемые ошибки too_large/типа в UI); tasks 1.1(г) мокап gallery-upload.html, 1.5(в), 2.1(в); CHK-GAL-9, CHK-GAL-10, CHK-GAL-11, CHK-GAL-21
- **Тип:** ФТ, web/e2e, поз. + нег. | **Приоритет:** Must
- **Маркер:** ручной/стендовый — REPORT-2.1 (web/e2e, drag&drop happy); юнит-базис — `::test_upload_png_happy_path`, `::test_upload_too_large_422`, `::test_upload_bad_type_422`
- **Предусловия:** стенд поднят; сессия owner (и PE для паритета); валидный PNG ~3 МБ, файл 12 МБ, PDF, переименованный в .jpg
- **Шаги:**
  1. Открыть `/gallery`, форму загрузки; перетащить валидный PNG в drop-зону (drag&drop) — загрузка проходит, карточка появляется в сетке.
  2. Выбрать категорию «семья» и теги «лето»/«дача» в форме (список + новое значение по мокапу) — значения применены и видны на карточке.
  3. Повторить загрузку через кнопку выбора файла (input) — паритет drag&drop.
  4. Загрузить файл 12 МБ — UI показывает человекочитаемую ошибку too_large; файл не появляется в сетке.
  5. Загрузить PDF под видом .jpg — UI показывает ошибку типа; файл не появляется.
  6. Повторить шаги 1 и 4 под PE — паритет загрузки (ОВ-4).
- **Ожидаемый результат:** drag&drop и кнопка выбора файла загружают валидные изображения happy-path, карточка с категорией/тегами появляется без перезагрузки; ошибки 422 (too_large, bad_type) отображаются в форме человекочитаемо (по мокапу gallery-upload.html), отказные файлы не попадают в галерею; загрузка доступна и owner, и PE одинаково.
