# TC-p23-112 — Негатив: вторая fast-задача через API отклонена 409

- **Change:** p23-fastline
- **Источник:** p23-fastline: specs/p23-fastline/spec.md — R6 / Scenario: Негативный: вторая fast-задача через API отклонена
- **Тип:** негативный (API, серверный инвариант ≤1) | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!` (seed); доска без активных fast-задач (занятый слот освобождить: выполнить/выключить fast либо дождаться автоархивации МСК-дня); созданные кейсом задачи удаляются в cleanup (`web_cleanup_created`); Playwright (Python): `page`, `expect`, `api_request_context`; хелперы `tests/web/pages/board.py` (зона-агностик `BoardPage.card_in_column`), `tests/web/dnd_helpers.py` (`dnd_dispatch`, общий DataTransfer)
- **Шаги:**
  1. Создать fast-задачу через API (201).
  2. Отправить второй `POST /api/tasks` `{{"title": "FL-вторая", "is_fast": true}}`.
  3. Отправить `PATCH /api/tasks/{{id обычной}}` с `is_fast:true` (зона все еще занята).
  4. Отправить `POST /api/tasks` с `is_fast:true, priority:"medium"` после освобождения слота.
  5. Проверить `GET /api/board`.
- **Ожидаемый результат:** шаг 2 — 409 `{{"error": "fast line occupied"}}`, задача не создана; шаг 3 — 409 тот же инвариант (PATCH-путь под ним же); шаг 4 — 422 `{{"error": "fast requires high"}}` (priority-lock); шаг 5 — в доске ровно одна fast-задача, «FL-вторая» отсутствует. Регресс: существующий `tests/api/test_tasks.py` остается зеленым без изменений (бэкенд не меняется).
- **Тестовые данные:** коды 409/422; инвариант в `BEGIN IMMEDIATE` — гонка создания закрыта на сервере (клиентская гонка вкладок — TC-p23-120)
