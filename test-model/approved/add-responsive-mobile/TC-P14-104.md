# TC-P14-104 — Fullscreen-модалка тикета: просмотр → «Редактировать» в одной оболочке, возврат на доску

- **Change:** add-responsive-mobile
- **Источник:** board (MODIFIED): «Просмотр карточки задачи — модальное окно read-only» (FR-102, ОВ-4) — Scenario «Fullscreen-модалка на мобильном», «Поля без авто-зума и клавиатура не перекрывает поле», «Desktop-модалки не меняются»; design §4; CHK-P14-13, CHK-P14-14, CHK-P14-15, CHK-P14-16
- **Тип:** ФТ, UI/адаптив + НФТ (NFR-23/24) | **Приоритет:** Must
- **Маркер:** автоматизирован + DV — 5.1 mobile-сьют + design_validator review-001 (мокапы 04 ticket-modal-view, 05 ticket-modal-edit — APPROVE)
- **Предусловия:** пользователь авторизован; существует задача с заполненными признаками и комментариями; вьюпорт 375×812, device-эмуляция touch
- **Шаги:**
  1. Кликнуть по карточке на доске (375px): модалка занимает весь вьюпорт (`position: fixed; inset: 0`, radius 0), шапка с названием «Задача · STAND-1» и крестиком 44px, тело скроллится, подложка заблокирована (`overflow: hidden`).
  2. Нажать «Редактировать»: содержимое заменяется формой редактирования В ТОЙ ЖЕ fullscreen-оболочке (одна модалка, edit in place, ОВ-4); данные задачи read-only до этого момента (Д-9).
  3. Сфокусировать поле ввода: font-size ≥16px (авто-зум iOS не включается, NFR-24); активное поле прокручивается в видимую область (клавиатура не перекрывает ввод).
  4. Закрыть модалку крестиком: возврат на доску в прежнюю scroll-позицию.
  5. Вьюпорт ≥1024px: просмотр и редактирование — в существующем desktop-виде r4 (read-only семантика, «Unassigned», кнопка «Редактировать» — как прежде, NFR-29).
- **Ожидаемый результат:** на ≤480px одна fullscreen-оболочка обслуживает просмотр и редактирование, закрытие возвращает на прежнее место доски, поля без авто-зума; desktop-модалки не изменены. Факт 5.1: green (мокапы 04/05 APPROVE).
