# TC-rich-041 — Таблица в таблице запрещена: кнопки и paste-путь с сохранением текста ячеек

- **Change:** p12-rich-tools
- **Источник:** p12-rich-tools: design §6 (ячейка × таблица = НЕТ), §2 (table в td/th unwrap целиком, текст ячеек сохраняется, разделитель `<br>`), §7 (урок rich-v1); ревью №1 находка F3 — дискриминатор запрета
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!`, второй пользователь `pe/QaPe_Pass_1!` (seed); тестовая страница wiki, созданная через `POST {BASE_URL}/api/wiki/pages`; Playwright (Python): `page`, `expect`, `api_request_context`
- **Шаги:**
  1. В редакторе поставить курсор в ячейку таблицы и попытаться вставить таблицу (кнопка/панель).
  2. Осмотреть DOM ячейки.
  3. Через `PUT` записать paste-подобный контент: таблица с ячейкой td, внутри которой вложенная `table` с ячейками «A1» и «B1».
  4. Получить `GET`-контент, открыть статью, переоткрыть страницу в редакторе.
  5. Сохранить страницу из редактора повторно, сверить `GET`.
- **Ожидаемый результат:** шаг 1 — вставка таблицы в ячейку кнопками недоступна/игнорируется (матрица §6); шаг 2 — в DOM вложенной таблицы нет; шаг 4 — paste-путь: на санитайзере вложенная table unwrap'нута ЦЕЛИКОМ (теги table/tr/td вложенной таблицы не эмитятся), текст «A1» и «B1» сохранен в td с разделением `<br>`; в статье вложенности нет, текст обеих ячеек виден; шаг 5 — повторное сохранение идемпотентно, источник потери контента rich-v1 (вложенная таблица, вернувшаяся из сохраненной страницы в редактор) не воспроизводится.
- **Тестовые данные:** paste-HTML: внешняя таблица 1×1 + вложенная 1×2 («A1», «B1»)
