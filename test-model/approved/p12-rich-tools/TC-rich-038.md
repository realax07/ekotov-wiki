# TC-rich-038 — Гейт вставки блоков в код-блок: кнопки и paste-путь

- **Change:** p12-rich-tools
- **Источник:** p12-rich-tools: design §6 (матрица: код-блок — НЕТ для спойлера/кода/табов/таблицы), §2 (внутри code разрешены только pre/code/text — остальное unwrap); ревью №1 п.3 — дискриминатор запрета
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!`, второй пользователь `pe/QaPe_Pass_1!` (seed); тестовая страница wiki, созданная через `POST {BASE_URL}/api/wiki/pages`; Playwright (Python): `page`, `expect`, `api_request_context`; страница открыта в режиме редактирования (WYSIWYG-редактор)
- **Шаги:**
  1. Курсор внутрь код-блока; поочередно нажать «Спойлер», «Блок кода», «Табуляцию» и попытаться вставить таблицу.
  2. Осмотреть DOM код-блока после каждой попытки.
  3. Через `PUT` записать paste-подобный контент: `div[data-block="code"]`, внутри которого, кроме `pre/code`, вложен `div[data-block="spoiler"]` с текстом.
  4. Получить `GET`-контент, открыть статью и переоткрыть страницу в редакторе.
- **Ожидаемый результат:** шаг 1 — гейт: новые блоки в код-блок кнопками НЕ вставляются (кнопки неактивны или вставка игнорируется); шаг 2 — в DOM кода нет вложенных блоков; шаг 4 — paste-путь: на санитайзере вложенные в код теги unwrap'нуты, остался чистый текст кода (текст вложенного блока сохранен как текст), в контенте и в редакторе после загрузки внутри кода только `pre/code` — содержимое кода плоский текст (design §6).
- **Тестовые данные:** код-блок + попытки вставки 4 типов; paste-HTML со вложенным спойлером
