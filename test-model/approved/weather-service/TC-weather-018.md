# TC-weather-018 — Граница: ровно один автоматический повтор при ошибке провайдера

- **Change:** weather-service
- **Источник:** weather-service: «Таймауты провайдера и повтор при ошибке» / Scenario: Ровно один автоматический повтор
- **Тип:** граничный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!`, второй пользователь `pe/QaPe_Pass_1!` (seed); Playwright (Python): `page`, `expect`, `api_request_context`; unit/integration-уровень: `services/weather` pytest с httpx.MockTransport (провайдер мокается, т.к. URL Open-Meteo зашит в конфиге); кэш — временный файл через env `EKOTOV_WEATHER_CACHE_PATH`
- **Шаги:**
  1. Mock-провайдер: первый вызов — ошибка (5xx/таймаут), второй — успех. Счетчик вызовов на 0. Кэш пуст/истек.
  2. Вызвать `/api/weather`, снять счетчик и время.
  3. Повторить с mock «оба вызова — ошибка»; повторить с mock «три подряд ошибки».
- **Ожидаемый результат:** шаг 2 — провайдер вызван ровно 2 раза (1 попытка + 1 повтор с паузой ~1 с), данные сохранены в кэш, ответ без `stale`; шаг 3 (обе неудачи) — ровно 2 вызова, далее деградация (stale-кэш либо 503 при пустом кэше), третьего повтора нет; суммарное время двух попыток ≤ ~11 с.
- **Тестовые данные:** mock-счетчик с сценариями: fail→ok, fail→fail, fail→fail→fail.
