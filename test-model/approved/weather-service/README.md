## Приоритеты

- **Must** — 21 кейс: весь негатив/границы (401, TTL-границы, битый JSON, отказ провайдера, 503, ровно один повтор, «сегодня»↔прогноз) и основные позитивы.
- **Should** — 4 кейса: TC-weather-009 (таймзона), TC-weather-013 (отказ записи кэша), TC-weather-021 (процессный, без миграций), TC-weather-024 (NFR-лимиты).

## Готовность к автоматизации

- Уровни: e2e Playwright (`api_request_context` + `page`) для UI/nginx-сценариев; unit/integration pytest (`services/weather/tests`, httpx.MockTransport) для провайдера/кэша/TTL/повторов — URL Open-Meteo зашит в конфиге, отказы провайдера мокаются транспортом, e2e-имитация — блокировка egress на стенде.
- Управление кэшем: env `EKOTOV_WEATHER_CACHE_PATH` (unit) / том `weather-cache`, файл `/cache/weather.json` (стенд); возраст кэша — правка `fetched_at`.
- Операционные кейсы (019, 020, 022) требуют docker-доступа к стенду wiki-test; кейс 021 — процессный (осмотр артефактов деплоя).
- Слеф-моки для таймаутов/повторов (017, 018) — httpx.MockTransport с hang/fail-сценариями; счетчик вызовов обязательный.
