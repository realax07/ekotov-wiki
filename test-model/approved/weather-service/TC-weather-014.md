# TC-weather-014 — Провайдер недоступен при истекшем TTL: устаревший кэш со stale: true + баннер UI

- **Change:** weather-service
- **Источник:** weather-service: «Недоступность провайдера — кэш с флагом устаревания» / Scenario: Отдача устаревшего кэша при отказе провайдера
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!`, второй пользователь `pe/QaPe_Pass_1!` (seed); Playwright (Python): `page`, `expect`, `api_request_context`; unit/integration-уровень: `services/weather` pytest с httpx.MockTransport; e2e-имитация отказа провайдера — блокировка egress к api.open-meteo.com (сетевая политика стенда) либо остановка резолва DNS
- **Шаги:**
  1. Прогреть кэш, сместить его возраст за 60 минут (см. TC-weather-011), зафиксировать fetched_at T0 и хэш кэш-файла.
  2. Закрыть доступ к Open-Meteo (таймаут/5xx — оба варианта).
  3. Выполнить `/api/weather` и открыть `/weather` под owner.
- **Ожидаемый результат:** API — 200 из кэша с `stale: true` и прежним `fetched_at` = T0; кэш-файл не изменен (хэш совпал); UI показывает баннер «данные устарели» с временем последнего обновления T0; таймаут и 5xx ведут себя одинаково.
- **Тестовые данные:** блокировка egress / mock 5xx; хэш кэш-файла до/после.
