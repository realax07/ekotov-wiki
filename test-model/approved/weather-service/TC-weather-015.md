# TC-weather-015 — Битый JSON провайдера не затирает кэш — паритет отказу провайдера

- **Change:** weather-service
- **Источник:** weather-service: «Недоступность провайдера — кэш с флагом устаревания» / Scenario: Битый ответ провайдера не затирает кэш
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!`, второй пользователь `pe/QaPe_Pass_1!` (seed); Playwright (Python): `page`, `expect`, `api_request_context`; unit/integration-уровень: `services/weather` pytest с httpx.MockTransport (провайдер мокается, т.к. URL Open-Meteo зашит в конфиге); кэш — временный файл через env `EKOTOV_WEATHER_CACHE_PATH`
- **Шаги:**
  1. Прогреть кэш, сместить возраст за 60 минут, зафиксировать хэш кэш-файла и fetched_at.
  2. Настроить mock-провайдера: 200 с телом `not-json{{`.
  3. Выполнить `/api/weather`; повторить с валидным JSON, но урезанным (без current) — второй прогон.
- **Ожидаемый результат:** обоих прогонов: невалидный/неполный ответ отброшен (ProviderError), пользователь получает 200 устаревших данных с `stale: true` и прежним `fetched_at`; кэш-файл побайтово сохранен (хэш совпал) — битым ответом не затерт.
- **Тестовые данные:** mock: тело «not-json{{»; фикстура урезанного валидного JSON; хэш кэш-файла.
