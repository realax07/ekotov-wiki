# TC-wiki-402 — Производительность wiki-API: p95 на корпусе 1000 страниц / 10 000 версий (NFR-30)

- **Change:** add-wiki
- **Источник:** wiki (ADDED): Requirement «Производительность wiki-API» (NFR-30) — Scenario «Пороги на эталонном корпусе»; design §3; CHK-wiki-28
- **Тип:** НФТ, производительность | **Приоритет:** Must
- **Предусловия:** стенд nginx :18443 (REPORT-4.1 §1); сеялка корпуса `/tmp/qa41_perf_seed.py` (прямые sqlite INSERT: 1000 страниц — 500 корней + цепочки до глубины 4, content ~1.7 КБ HTML; 10 000 версий по первым 200 страницам); LocalhostSession-прием conftest (Secure-кука по http localhost)
- **Шаги:**
  1. Засеять корпус (сид ~1.3 с).
  2. Выполнить 20 повторов каждой операции через nginx: GET страницы (обычной и глубокой с breadcrumbs), GET /api/wiki/pages (дерево), GET версии read-only, GET списка версий (50 у лидера), GET поиска (частотное слово / нет совпадений / префикс заголовка / экранирование %_).
  3. Посчитать p95 (95-й перцентиль) по каждой операции; повторить второй круг.
- **Ожидаемый результат:** p95 открытия/дерева/версий < 300 мс, поиска < 500 мс. Факт прогона 4.1: открытие 26.2–37.8 мс, дерево 41.8–70.0 мс, версии 20.0–86.5 мс, поиск 32.3–109.8 мс (worst-case «нет совпадений» — полный LIKE-скан, запас ×4.5); ВСЕ ЦЕЛИ ДОСТИГНУТЫ, запас ×3–10, два круга стабильны.
- **Автотест:** автотеста нет — прогон 4.1 REPORT-4.1 §4 (скрипт-сеялка + замер p95, `/tmp/qa41_perf_seed.py`, 20 повторов × 2 круга)
