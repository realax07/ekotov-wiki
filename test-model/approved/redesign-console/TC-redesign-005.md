# TC-redesign-005: Вход по логину и паролю — функциональность без деградации

## Трассировка
- **CHK:** CHK-005
- **Тип:** поз./нег. | **Приоритет:** Must (по CHK-005)
- **FR/Требование:** auth MODIFIED — «Вход по логину и паролю» (функциональный контракт: форма, сессии, ошибки — без изменений)
- **Scenario:** «Успешный вход существующего пользователя», «Неверный пароль», «Несуществующий пользователь»

## Предусловия
- Поднят стенд (`GET {BASE_URL}/api/health` → 200); пользователь `owner` существует (seed).
- Playwright (Python); сессия/cookies очищены перед каждым шагом.

## Шаги
1. Открыть `/login`, ввести корректные логин `owner` и пароль, отправить форму.
2. Дождаться перехода: проверить URL и наличие каркаса (сайдбар, доска).
3. Выйти, снова открыть `/login`, ввести `owner` + заведомо неверный пароль, отправить.
4. Проверить: вход не выполнен, показано сообщение об ошибке входа.
5. Снова открыть `/login`, ввести несуществующий логин + любой пароль, отправить.
6. Сравнить сообщение шага 5 с сообщением шага 4: формулировка НЕ раскрывает, существует ли логин.

## Ожидаемый результат
- Шаги 1–2: вход успешен, доступ к функционалу получен (редирект на `/`, сессия установлена).
- Шаги 3–4: вход отклонен, показано сообщение об ошибке, функционал недоступен.
- Шаги 5–6: вход отклонен, сообщение не раскрывает существование/несуществование логина (единая формулировка с шагом 4).

## Примечания
