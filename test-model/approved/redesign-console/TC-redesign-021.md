# TC-redesign-021: Профиль в сайдбаре — отображение и переходы

## Трассировка
- **CHK:** CHK-021
- **Тип:** поз. | **Приоритет:** Must (по CHK-021)
- **FR/Требование:** navigation MODIFIED — «Профиль текущего пользователя внизу сайдбара» (FR-39…FR-43, Д-10)
- **Scenario:** «Профиль отображается внизу сайдбара», «Подпись профиля — display_name, если задан», «Аватар отображается в блоке профиля», «Клик по профилю открывает настройки пользователя», «Профиль показывает сессионного пользователя»

## Предусловия
- Поднят стенд; users seed: `owner` (display_name не задан), второй пользователь (жена). Aватар: возможность загрузить/сбросить аватар owner.
- Playwright (Python).

## Шаги
1. Войти как `owner` (display_name не задан, аватар не загружен), открыть `/board`: внизу сайдбара — блок профиля: кружок с буквой «o» (первая буква логина) и подпись «owner» целиком (Д-10).
2. Задать display_name в настройках пользователя (FR-40), обновить страницу: подпись блока = display_name; логин остается идентификатором в tooltip'е (FR-43).
3. Загрузить аватар (FR-42), обновить страницу: вместо кружка — загруженный аватар.
4. Кликнуть по блоку профиля: открывается страница настроек пользователя (свой профиль, FR-39), а НЕ общий раздел «Настройки» со справочником категорий (ОГР-20).
5. Выйти, войти как второй пользователь: внизу сайдбара — профиль второго пользователя (его подпись и его аватар/кружок), не данные owner.
6. Контроль: прогон `tests/web/test_r5_profile_card_ui.py` и существующих профильных тестов — green.

## Ожидаемый результат
- Блок профиля: кружок/аватар + подпись (display_name при наличии, иначе логин), логин в tooltip.
- Клик ведет в настройки пользователя; каждый пользователь видит свой профиль в своей сессии.
- Семантика FR-39…FR-43 сохранена, тесты green.
