# TC-migr-002 — Миграция: задачи сохраняют значения категорий

- **CHK:** CHK-98
- **Change:** add-r2-categories-settings
- **Источник:** categories: Миграция (FR-22) / Scenario: Задачи сохраняют значения категорий
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** тестовая БД приложения (env `EKOTOV_WIKI_DB_PATH`); доступ к `sqlite3` CLI; скрипт миграции из пакета (sdd §5); выполнен вход owner (куки `owner_cookies.txt`); **seed справочника в этом кейсе НЕ выполняется** — справочник должен быть пуст ДО миграции (миграция сама создает категории из значений задач). Кейс — разовая проверка внедрения (метка `candidate-archive`, impact §3 п.2).
- **Сценарий:**
  - **GIVEN** до миграции существует задача с категорией `QAT-m-work`
  - **WHEN** выполняется миграция
  - **THEN** эта задача имеет категорию `QAT-m-work`, и она является категорией справочника (значение не потеряно и не изменено)
- **Шаги:**
  1. До миграции создать задачу `QAT-m-носитель` с категорией `QAT-m-work` (как TC-migr-001, шаг 1); зафиксировать ее `id` из БД.
  2. Запустить миграцию.
  3. `GET /api/tasks/{id}` (с куками) → поле `category`.
  4. `GET /api/categories` → `QAT-m-work` присутствует.
  5. Cleanup (как TC-migr-001).
- **Ожидаемый результат:** шаг 3 — `category == "QAT-m-work"` (посимвольно, значение не изменено); шаг 4 — это значение есть в справочнике — задача ссылается на категорию справочника, а не на «осиротевший» текст (FR-22).
- **Тестовые данные:** задача `QAT-m-носитель` (category=`QAT-m-work`).
