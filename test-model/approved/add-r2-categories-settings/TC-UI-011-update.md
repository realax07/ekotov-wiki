Поведение формы изменилось: при отметке fast поле приоритета блокируется с подстановкой high (CHK-129); если реализация шлет priority=null/пусто — сервер ответит 422 по новой валидации до 409. Зависимость от нереализованной механики → проверка после реализации формы; ожидаемый порядок валидации — CHK-138 (TC-fast2-012).

## Критерий приемки обновления

- В тесте есть ассерт блокировки поля приоритета при отмеченном fast (новая механика формы).
- Ожидание 409 («fast line занята») явно закомментировано как зависящее от зафиксированного порядка валидации (CHK-138/TC-fast2-012, sdd §3.2); при 422 тест НЕ «подгоняется» — оформляется расхождение.
- Кейс исполняется только ПОСЛЕ реализации формы (пометка в docstring: «проверить после реализации формы»).
