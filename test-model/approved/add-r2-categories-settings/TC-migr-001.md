# TC-migr-001 — Миграция: уникальные значения становятся категориями 1:1 (регистр различим)

- **CHK:** CHK-97
- **Change:** add-r2-categories-settings
- **Источник:** categories: Миграция существующих категорий в справочник (FR-22, Д-2) / Scenario: Уникальные значения становятся категориями 1:1
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** тестовая БД приложения (env `EKOTOV_WIKI_DB_PATH`); доступ к `sqlite3` CLI; скрипт миграции из пакета (sdd §5); выполнен вход owner (куки `owner_cookies.txt`); **seed справочника в этом кейсе НЕ выполняется** — справочник должен быть пуст ДО миграции (миграция сама создает категории из значений задач). Кейс — разовая проверка внедрения (метка `candidate-archive`, impact §3 п.2).
- **Сценарий:**
  - **GIVEN** до миграции в системе есть задачи с категориями `QAT-m-home`, `QAT-m-Home`, `QAT-m-work` (три уникальных непустых значения, включая различие по регистру)
  - **WHEN** выполняется миграция
  - **THEN** справочник содержит ровно три категории с этими именами — слияние «синонимов» по регистру НЕ выполняется (ОГР-9)
- **Шаги:**
  1. До миграции создать три задачи с указанными категориями напрямую в БД (данные «до внедрения»: `sqlite3 "$EKOTOV_WIKI_DB_PATH" "INSERT INTO tasks (title, category, status, is_fast) VALUES ('QAT-m-з1','QAT-m-home','todo',0), ('QAT-m-з2','QAT-m-Home','todo',0), ('QAT-m-з3','QAT-m-work','todo',0);"` — схема столбцов сверяется с фактической перед запуском).
  2. Контроль «до»: `SELECT DISTINCT category FROM tasks WHERE category LIKE 'QAT-m-%';` → ровно 3 значения; таблица `categories` не содержит `QAT-m-%`.
  3. Запустить скрипт миграции (sdd §5).
  4. `GET /api/categories` (с куками) → выбрать имена с префиксом `QAT-m-`.
  5. Cleanup: удалить созданные задачи и категории `QAT-m-%` через API (DELETE задач по id, DELETE категорий по id; список категорий из шага 4).
- **Ожидаемый результат:** шаг 4 — ровно три записи: `QAT-m-home`, `QAT-m-Home`, `QAT-m-work` (сравнение точное, по регистру) — каждое уникальное непустое значение стало отдельной категорией 1:1; слияния по регистру нет (Д-2/ОГР-9). Cleanup очистил и задачи, и категории.
- **Тестовые данные:** категории `QAT-m-home`, `QAT-m-Home`, `QAT-m-work`; задачи `QAT-m-з1/з2/з3`.
