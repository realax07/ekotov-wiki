# TC-migr-003 — Миграция: пустые значения не создают записей справочника

- **CHK:** CHK-99
- **Change:** add-r2-categories-settings
- **Источник:** categories: Миграция (FR-22) / Scenario: Пустые значения не создают записей справочника
- **Тип:** граничный | **Приоритет:** Must
- **Среда/предусловия:** тестовая БД приложения (env `EKOTOV_WIKI_DB_PATH`); доступ к `sqlite3` CLI; скрипт миграции из пакета (sdd §5); выполнен вход owner (куки `owner_cookies.txt`); **seed справочника в этом кейсе НЕ выполняется** — справочник должен быть пуст ДО миграции (миграция сама создает категории из значений задач). Кейс — разовая проверка внедрения (метка `candidate-archive`, impact §3 п.2).
- **Сценарий:**
  - **GIVEN** до миграции существуют задачи с пустой категорией (NULL и пустая строка) и задача с непустой `QAT-m-home`
  - **WHEN** выполняется миграция
  - **THEN** справочник не содержит пустой категории; задачи с пустой категорией остаются без категории; задача с `QAT-m-home` — со своей
- **Шаги:**
  1. До миграции создать: задачу с `category=NULL` (`QAT-m-null`), задачу с `category=''` (`QAT-m-пустая`), задачу с `category='QAT-m-home'` (`QAT-m-с-дом`).
  2. Контроль «до»: `SELECT COUNT(*) FROM tasks WHERE category IS NULL OR category = '';` → ≥2.
  3. Запустить миграцию.
  4. `GET /api/categories` → проверить: записей с пустым/пробельным именем нет (ни `""`, ни `"   "`).
  5. `GET /api/tasks/{id}` для всех трех → `category`.
  6. Cleanup.
- **Ожидаемый результат:** шаг 4 — в справочнике нет пустой категории (INSERT DISTINCT непустых — sdd §5); шаг 5 — `QAT-m-null` и `QAT-m-пустая` остались без категории (NULL), `QAT-m-с-дом` — `QAT-m-home`; пустые значения не потеряли «пустоту» и не превратились в записи.
- **Тестовые данные:** задачи `QAT-m-null` (NULL), `QAT-m-пустая` (""), `QAT-m-с-дом` (`QAT-m-home`).
