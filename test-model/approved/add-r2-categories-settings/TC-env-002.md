# TC-env-002 — Изоляция и cleanup справочника: тесты не ломают общий справочник

- **CHK:** CHK-140
- **Change:** add-r2-categories-settings
- **Источник:** impact §4.2 (следствие FR-24, ОГР-7) — изоляция и cleanup справочника
- **Тип:** средовый | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд; выполнен вход owner; справочник содержит seed-категории `Дом`, `Работа`, `Личное` (TC-env-001); прогоняется набор кейсов, изменяющих категории.
- **Сценарий:**
  - **GIVEN** справочник общесистемный (FR-24, ОГР-7 — един на всех)
  - **WHEN** тесты переименовывают/удаляют категории
  - **THEN** они работают только с `QAT-*` категориями или восстанавливают состояние; cleanup фикстуры убирает и категории (cleanup задач категории из справочника не убирает)
- **Шаги:**
  1. Снимок справочника до прогона: `GET /api/categories` → список `S0`.
  2. Выполнить последовательность кейсов, меняющих категории (TC-cat-004..010, TC-migr-*, TC-form-001/002: создание/переименование/удаление `QAT-*`).
  3. Снимок после прогона: `GET /api/categories` → `S1`; сверить с `S0`.
  4. Аудит оставшихся `QAT-*`: в `S1` не должно остаться ни одной `QAT-*`-категории, созданной тестами (если тест не подтверждает намеренное сохранение).
  5. Контроль неснижаемого остатка: seed `Дом`, `Работа`, `Личное` присутствуют в `S1` (никакой cleanup не удалил их).
- **Ожидаемый результат:** шаг 3 — `S1 == S0` (справочник возвращен в исходное состояние) ИЛИ расхождения только там, где кейс явно документирует остаточное состояние; шаг 4 — 0 забытых `QAT-*` категорий; шаг 5 — seed цел. Нарушение — дефект тестовой инфраструктуры (cleanup фикстуры обязан убирать категории: cleanup задач категорий из справочника не убирает — impact §4.2).
- **Тестовые данные:** снимки `S0`/`S1`; множество `QAT-*`-категорий кейсов.
