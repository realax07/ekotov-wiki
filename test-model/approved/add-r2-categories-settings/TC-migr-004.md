# TC-migr-004 — После миграции все непустые категории задач валидны

- **CHK:** CHK-100
- **Change:** add-r2-categories-settings
- **Источник:** categories: Миграция (FR-22) / Scenario: После миграции все непустые категории задач валидны
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** тестовая БД приложения (env `EKOTOV_WIKI_DB_PATH`); доступ к `sqlite3` CLI; скрипт миграции из пакета (sdd §5); выполнен вход owner (куки `owner_cookies.txt`); **seed справочника в этом кейсе НЕ выполняется** — справочник должен быть пуст ДО миграции (миграция сама создает категории из значений задач). Кейс — разовая проверка внедрения (метка `candidate-archive`, impact §3 п.2).
- **Сценарий:**
  - **GIVEN** миграция выполнена (включая данные TC-migr-001..003)
  - **WHEN** выполняется автоматическая сверка значений category всех задач со справочником
  - **THEN** каждое непустое значение category каждой задачи присутствует в справочнике (FR-21 не нарушен ни для одной существующей задачи)
- **Шаги:**
  1. Запустить миграцию (если не выполнена ранее в цепочке).
  2. `GET /api/categories` → множество имен справочника `C`.
  3. Полный обход задач: `GET "/api/search?archived=false"` + `GET "/api/search?archived=true"` → собрать `category` ВСЕХ задач (включая архивные).
  4. Автосверка скриптом (Python в протоколе): для каждой задачи — если `category` непустая, то `category in C`; вывести число задач, число непустых, список нарушений.
- **Ожидаемый результат:** шаг 4 — 0 нарушений: каждое непустое `category` присутствует в справочнике; в протоколе — таблица сверки с нулем расхождений.
- **Тестовые данные:** полный массив задач тестовой БД (активные + архивные); справочник `C` из шага 2.
