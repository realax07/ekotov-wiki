# TC-sel-001 — Select категории формы заполнен из фактического справочника

- **CHK:** CHK-123
- **Change:** add-r2-categories-settings
- **Источник:** search: Селект-поля и подсказки заполняются из фактических данных (FR-30, DEF-001) / Scenario: Выбор категории в форме заполняется из справочника
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** в справочнике заведены `Дом`, `Работа`, `Личное` + `QAT-sel-finance` (4 категории)
  - **WHEN** пользователь открывает поле категории в форме задачи
  - **THEN** список значений поля содержит ровно фактическое содержимое справочника (источник `GET /api/categories`, sdd §4), не статический захардкоженный список
- **Шаги:**
  1. `POST /api/categories` name=`QAT-sel-finance` → 201 (гарантия известного 4-го элемента).
  2. `GET /api/categories` → зафиксировать список имен `S` (ровно: `Дом`, `Работа`, `Личное`, `QAT-sel-finance`).
  3. Открыть форму задачи; прочитать опции select «Категория» (исключив пустую опцию-плейсхолдер) → множество `O`.
  4. Сравнить: `set(O) == set(S)`; для доказательства «не статика» — `QAT-sel-finance` (заведенная только что) присутствует.
  5. Cleanup: DELETE категории `QAT-sel-finance` → 200.
- **Ожидаемый результат:** шаг 4 — опции формы равны справочнику один к одному; свежесозданная категория в списке — источник данных, а не захардкоженный список (DEF-001/FR-30).
- **Тестовые данные:** справочник seed + `QAT-sel-finance`.
