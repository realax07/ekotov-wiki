# TC-cat-002 — Поле «Категория» фильтра-конструктора: выбор только из справочника

- **CHK:** CHK-83
- **Change:** add-r2-categories-settings
- **Источник:** categories: Справочник категорий (FR-19) / Scenario: Поле категории в фильтре работает от справочника
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** пользователь авторизован; в справочнике заведены `Дом`, `Работа`
  - **WHEN** пользователь открывает фильтр-конструктор поиска и раскрывает поле «Категория»
  - **THEN** поле предлагает выбор только из значений справочника (select, не input с datalist)
- **Шаги:**
  1. `GET {BASE_URL}/api/categories` → зафиксировать список имен `S`.
  2. Открыть `{BASE_URL}/search`; убедиться, что активен режим «Конструктор» (`page.get_by_role("button", name="Конструктор")`).
  3. Осмотреть поле «Категория» конструктора (доступное имя «Категория», прежний id `#search-category`): зафиксировать тег элемента и наличие/отсутствие атрибута `list`.
  4. Прочитать опции поля (аналогично TC-cat-001, шаг 4); пустую опцию-плейсхолдер исключить.
- **Ожидаемый результат:** тег поля `SELECT`; атрибут `list` отсутствует; множество опций равно `S` из `GET /api/categories` — фильтр работает от справочника, не от datalist подсказок (sdd §4).
- **Тестовые данные:** справочник `Дом`, `Работа`, `Личное`.
