# TC-cat-009 — Негативный: дубль имени при POST и PATCH; регистр различим

- **CHK:** CHK-90
- **Change:** add-r2-categories-settings
- **Источник:** categories: Управление справочником (FR-20; дополнение: негативный класс, sdd §3.1)
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200; `BASE_URL` по умолчанию `http://127.0.0.1:8080`); выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed `tests/api/conftest.py`, куки в `owner_cookies.txt`); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** в справочнике есть категория `QAT-Case`
  - **WHEN** пользователь создает `QAT-Case` повторно; переименовывает другую категорию на имя `QAT-Case`; создает `QAT-case` (другой регистр)
  - **THEN** дубль по точному совпадению → 409 в обоих случаях; `QAT-Case` и `QAT-case` — разные записи
- **Шаги:**
  1. `POST /api/categories` name=`QAT-Case` → 201, зафиксировать `id_a`. `POST /api/categories` name=`QAT-case` → 201, зафиксировать `id_b` (регистр различим — обе созданы).
  2. Повторный `POST` name=`QAT-Case` → код и тело.
  3. `PATCH /api/categories/{id_b}` `{"name":"QAT-Case"}` → код и тело.
  4. `GET /api/categories` → ровно две записи `QAT-Case` и `QAT-case`, значения не изменились.
  5. Cleanup: DELETE `id_a`, `id_b` → 200/200.
- **Ожидаемый результат:** шаг 2 — HTTP **409** (дубль имени по точному совпадению, sdd §3.1); шаг 3 — HTTP **409** (PATCH на имя существующей категории); шаг 4 — обе записи на месте, переименование не применилось; сравнение по регистру точное (`"QAT-Case" != "QAT-case"`, Д-2/sdd §2: UNIQUE по name без коллапса регистра).
- **Тестовые данные:** `QAT-Case`, `QAT-case` (различие только регистром); повтор `QAT-Case`.
