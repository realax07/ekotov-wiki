## TC-nav-001 — Переход на доску через сайдбар
- **CHK:** CHK-77
- **Источник:** navigation: «Навигация через сайдбар» (FR-13) / Scenario: Переход на доску через сайдбар
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие.
- **Шаги:**
  1. Открыть `{BASE_URL}/search`.
  2. В сайдбаре выбрать раздел «Доска».
  3. Повторить из раздела `/wiki` (заглушка).
- **Ожидаемый результат:** переход на `{BASE_URL}/board` из обеих точек; отображается канбан-доска (три столбца с задачами/пустые); без ручного ввода URL.
- **Тестовые данные:** раздел сайдбара «Доска»; стартовые страницы `/search`, `/wiki`.

## TC-nav-003 — Сайдбар доступен со всех страниц функционала
- **CHK:** CHK-79
- **Источник:** navigation: «Навигация через сайдбар» / Scenario: Сайдбар доступен со всех страниц (FR-13)
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; выполнен вход.
- **Шаги:**
  1. Открыть каждую страницу функционала: `/board`, `/search`, `/wiki`.
  2. На каждой убедиться: сайдбар отображается и содержит разделы «Доска», «Поиск», «Wiki» (полный перечень разделов сайдбара — по факту UI; отсутствие раздела — дефект).
  3. С каждой страницы выполнить переход по каждому пункту сайдбара (матрица 3×3 переходов).
- **Ожидаемый результат:** на всех трех страницах сайдбар виден и идентичен по составу; все 9 переходов ведут в соответствующие разделы (URL и содержимое совпадают с прямыми `GET` этих страниц); ни одна целевая страница не отдает ошибку.
- **Тестовые данные:** страницы `/board`, `/search`, `/wiki`; пункты сайдбара «Доска», «Поиск», «Wiki».

## TC-nav-004 — Раздел Wiki отображается как заглушка с todo
- **CHK:** CHK-80
- **Источник:** navigation: «Пустой раздел Wiki с пометкой todo» (FR-13, Won't) / Scenario: Раздел Wiki отображается как заглушка
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие.
- **Шаги:**
  1. Осмотреть сайдбар: наличие раздела «Wiki» и пометки todo.
  2. Открыть раздел «Wiki».
  3. API-контроль: `curl -s -i -b owner_cookies.txt {BASE_URL}/wiki`.
- **Ожидаемый результат:** раздел «Wiki» присутствует в сайдбаре с пометкой `todo`; страница `/wiki` открывается как заглушка (текст-заглушка с упоминанием todo/«пустой раздел»); HTTP 200; содержимое wiki-статей отсутствует.
- **Тестовые данные:** раздел «Wiki»; страница `/wiki`.

## TC-nav-005 — Wiki не дает wiki-функций
- **CHK:** CHK-81
- **Источник:** navigation: «Пустой раздел Wiki с пометкой todo» / Scenario: Раздел Wiki не дает wiki-функций (FR-13)
- **Тип:** негативный | **Приоритет:** Must
- **Предусловия:** общие; открыт раздел `/wiki`.
- **Шаги:**
  1. Осмотреть страницу: поиск элементов «создать страницу», «редактировать», поле поиска по wiki, список статей.
  2. Попытаться ввести/сохранить что-либо в доступных на заглушке полях (если есть) — зафиксировать реакцию.
  3. Пробные API-запросы wiki-сущностей: `curl -s -i -b owner_cookies.txt {BASE_URL}/api/wiki` и `curl -s -i -b owner_cookies.txt -X POST {BASE_URL}/api/wiki -H "Content-Type: application/json" -d '{"title":"Тест-wiki"}'` → коды.
- **Ожидаемый результат:** элементов создания/редактирования/поиска wiki-страниц нет; список статей отсутствует; попытка действий не приводит к созданию/изменению контента (заглушка); API-пути wiki отсутствуют — ответы 404 (не 2xx, не 5xx; фактические коды зафиксировать в протоколе — контракт wiki API в спеке не определен, ожидание «нет wiki-функций» проверяется отсутствием 2xx-успеха).
- **Тестовые данные:** попытка создания: title=`Тест-wiki`; пути `/api/wiki` (GET и POST).
