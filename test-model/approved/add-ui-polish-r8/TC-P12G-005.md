# TC-P12G-005 — rename UI: закрытие формы без сохранения (Esc) НЕ закрывает лайтбокс, имя прежнее; отмена — сетка не задета

- **Change:** add-ui-polish-r8
- **Источник:** gallery (MODIFIED): «Full-screen просмотр» (FR-97) + Scenario «Закрытие окна просмотра» (Esc закрывает ОКНО, сетка в прежнем состоянии); конфликт клавиатурных сценариев Esc (cancel-инлайн vs закрыть-лайтбокс); CHK-P12-22 (гран.)
- **Тип:** ФТ, web/e2e, нег./гран. | **Приоритет:** Must
- **Маркер:** new (ветка 2.5); REPORT-3.1 — прогон R4, nginx-стенд. РИСК: если dev-реализация оставляет Esc = закрыть лайтбокс при активной rename-форме — это расхождение со спекой «отмена без сохранения», эскалация в REPORT-3.1
- **Предусловия:** стенд поднят; сессия owner; ≥1 изображение QAGAL-; открыто `/gallery`
- **Шаги:**
  1. Открыть лайтбокс, нажать иконку «переименовать», ввести в поле новое имя (НЕ подтверждать).
  2. Нажать Esc — зафиксировать: закрылась ли ТОЛЬКО rename-форма, остался ли лайтбокс открытым.
  3. Снова открыть rename, ввести имя, нажать кнопку отмены (✕/«отмена», если есть) и клик вне поля.
  4. После каждого пути отмены: имя в шапке лайтбокса и в `GET /api/images/<id>` — прежнее.
  5. Закрыть лайтбокс (Esc при НЕактивной rename-форме) — лайтбокс закрывается, сетка в прежнем состоянии (регресс-связка с TC-GAL-116).
- **Ожидаемый результат:** шаги 2–3 — Esc/отмена/клик вне закрывают только форму переименования, лайтбокс остается открытым; шаг 4 — имя не сохранилось ни в UI, ни в API (без «тихого» сохранения); шаг 5 — после выхода из режима редактирования Esc возвращает базовое поведение закрытия окна; сетка без перезагрузок и без потерянных фильтров.
