## Замечания (по ходу ревью)

### TC-redesign-007 — minor (выдуманный механизм)

Шаг 5: «Создать пустое состояние (стенд без задач **либо фильтр**)».
У доски фильтров нет ни в дельте, ни в мастер-спеке — сценарий «Открытие
пустой доски» задает условие «в системе нет ни одной задачи». Вариант
«либо фильтр» — не из спеки и на доске невоспроизводим. Исправить при
автоматизации: убрать «либо фильтр», пустое состояние — только отсутствие
задач на стенде. Не блокирует: основной вариант шага корректен.

### TC-redesign-008 — minor (двусмысленность отнесения сценария к CHK)

В трассировку включен сценарий «Существующее поведение доски не
деградировало», который в чеклисте не отнесен ни к CHK-007, ни к CHK-008
(в колонке «Источник» его нет); фактическая проверка вынесена в
TC-redesign-007 шаг 6 (кросс-ссылка в ожидаемом результате есть).
Формально это даже улучшает покрытие 105/105, но отнесение сценария к
визуальному CHK-008 при проверке в CHK-007-кейсе — неоднозначно. Вопрос
закрывается сам собой, если чеклист при очередном пересмотре явности
отнесет сценарий к CHK-007. Исправлений в кейсе не требует.

### TC-redesign-012 — minor (усиление над спекой)

Шаг 4: «единственный допустимый — трек отсчета фастлайна amber→cyan».
FR-129 требует «градиенты только на данных, не на декоративных
поверхностях», исчерпывающего перечня градиентов спека не дает
(единственный названный в дельтах градиент-на-данных — трек фастлайна).
Если мокап задаст еще один градиент на данных, кейс даст ложный фейл.
Рекомендация для 3.4: сформулировать как «градиентов на декоративных
поверхностях нет; известный градиент-на-данных — трек фастлайна».

### TC-redesign-017 — minor (шаг, условный по времени)

Шаг 4: «После фикса Д1 (3.4): повторить шаг 3». Шаг, отложенный во
время, в автотесте невоспроизводим напрямую. Ожидания по обе стороны
фикса зафиксированы корректно (известный red — не регресс), но при
автоматизации 3.4 шаг нужно превратить в условие/отдельный кейс
пост-фикса. Отмечено для плана 3.4.

### TC-redesign-026 — editorial (опечатка)

Шаг 5: «несталевые ассерты» → «нестилевые ассерты». На смысл не влияет.

### Несколько кейсов — minor, процессное (проверяемость автотестом)

Шаги вида «сверить с REPORT волны N» (TC-redesign-001 шаг 1, TC-009 шаг 5,
TC-011, TC-036 шаг 6 — гейты 1.1/2.7) опираются на ручной артефакт REPORT:
автотестом невоспроизводимы как сформулированы. При автоматизации (3.4)
их следует заменить прямым прогоном скриптов-гейтов (контраст-скрипт,
grep hex/var()) — REPORT оставить как evidence. Кейсы сами помечают себя
приемочными, поэтому замечание не блокирующее.

### TC-redesign-018 — observation (без правки)

Шаг 5: «у второй роли (жена) — нет [ссылки «Мониторинг»]». Дельта
формулирует «состав пунктов по ролям — без изменений» и не переописывает
состав по ролям; ожидание берется из действующего поведения. Это законно
для «без изменений»-сценариев и проверяемо сверкой с до-редизайн
поведением — замечание фиксирующее, исправлений не требует.
