# Review 001 — design_validator: волна 3 add-wiki против утвержденных мокапов

Проект: ekotov-wiki, ветка `pipeline/p15-stage-a` (рабочее дерево, без коммитов).
Проверка: DV-сверка реализации 3.1–3.4 (страницы Wiki) против мокапов
«Согласовано»: `design/wiki-tree.html`, `design/wiki-page.html`,
`design/wiki-editor.html`, `design/wiki-history.html`.

Метод: (1) построчная сверка классов/структуры/текстов js-модулей
(`frontend/static/js/wiki/{tree,search,page,editor,history}.js`), шаблона
`frontend/templates/wiki.html` и `frontend/static/css/wiki.css` с исходниками
мокапов; (2) живой стенд (uvicorn + seed-данные, статика через route-перехват
playwright — в проде nginx) — скриншоты и DOM/aria-снимки фактической верстки:
`test-model/reviews/add-wiki/screenshots/01…15*.png` (сняты dv_capture*.py,
лежат рядом).

Токены: в `wiki.css` нет ни одного хардкод-цвета (grep по `#hex` — пусто);
все значения — `var(--…)` из `app.css :root`. Допустимые исключения по
ревью: `color-mix(in srgb, var(--p-ink-900) 45%, transparent)` в
`.confirm-backdrop`/`.editor-dialog-backdrop` (эквивалент rgba-бэкдропа
мокапа) и инверсная подсветка `mark` (amber-700 + on-accent) — решение
дизайнера зафиксировано. NFR-33 — соответствуют.

Кеш-бастинг: все подключения статики в `wiki.html` — `?v={{ static_v }}`
(глобал из `pages.py`, сейчас `p14-responsive-1`; финальный релизный бамп —
задача 6.x, вне волны 3).

## Отклонения

### MAJOR

- **DV-1. Сниппет поиска показывает HTML-теги контента** (`search.js` +
  `backend/app/wiki.py`). Мокап: сниппет — чистый текст «…итоговая <mark>смета</mark>
  на материалы: крепеж…». Факт: сервер берет окно из сырого HTML (`content[...]`,
  wiki.py:409–411), клиент вставляет его как текст → в выдаче видно
  «&lt;p&gt;итоговая <mark>смета</mark> на материалы…» (скриншот 02-search.png,
  строка `<p>` перед текстом; падает и эстетика, и точность `match_offset` —
  оффсет считается по HTML-строке, подсветка может «разрезать» тег). Фикс:
  на сервере срезать теги перед поиском/сниппетом (или искать по plain-тексту с
  сохранением оффсета в plain-координатах). Блокер для приемки выдачи не
  является, но виден пользователю на каждом результате — править до выкатки.

### MINOR

- **DV-2. Нет h1 «Wiki» на /wiki** (`wiki.html`). Мокап tree: `<h1>Wiki</h1>`
  над тулбаром. Факт: каркас h1 не содержит (все разделы — board/search/gallery —
  h1 имеют). Заголовок раздела отсутствует и в режиме истории это компенсируется
  h1 «История версий» из history.js. Добавить `<h1>Wiki</h1>` в ветку не-истории
  шаблона (однострочная правка).
- **DV-3. tree-meta узлов с детьми без «обновлено …»** (`tree.js metaText`).
  Мокап: «6 страниц · обновлено 2 окт» у корней/узлов. Факт: только «N страниц»
  (дата показывается только у листьев). API (`GET /api/wiki/pages`) `updated_at`
  отдает — данных для мокапа достаточно. Сверстать «N страниц · обновлено {дата}».
- **DV-4. Заголовки undo/redo без хоткеев** (`editor.js`). Мокап:
  `title="Отменить (Ctrl+Z)"` / `title="Повторить (Ctrl+Shift+Z)"`. Факт:
  `title="Отменить"` / `title="Повторить"`. Подсказки хоткеев — часть утвержденной
  верстки тулбара.
- **DV-5. Кнопка «Изображение» без текстового лейбла** (`editor.js svgIcon`).
  Мокап: tb-media = иконка + текст «Изображение» (ключевое действие). Факт:
  только иконка (в DOM текста нет; на скриншоте 05 тулбар без лейбла). CSS
  `.tb-media` с `font-size: var(--font-size-label)` уже есть — добавить текстовый
  узел в кнопку.
- **DV-6. Ошибка формы редактора рендерится ВЫШЕ h1** (`editor.js init`:
  error-banner добавлен в контейнер раньше заголовка). На скриншоте 06 баннер
  «Заголовок не может быть пустым…» стоит над «Редактирование: …». В мокапе
  error-banner — под/ряд с формой. Сместить append errorBox после заголовка
  (или перед meta-card) — чисто визуальный порядок.

### NIT

- **DV-7. aria-pressed=false у всех кнопок тулбара в исходном DOM** (editor.js):
  мокап задает pressed только кнопкам состояний; для H1/H3/ссылка/таблица/
  изображение/undo/redo атрибут избыточен (у ссылок/вставки «нажатие» не
  состояние). Не видимо пользователю; допустимо, отмечено для чистоты ARIA.
- **DV-8. Диалог изображения показывает «Not Found» в баннере** при недоступном
  GET /api/images (05c-image-dialog.png — на стенде images-API не поднят, это
  артефакт стенда, не продукта; в проде эндпоинт существует). Текст «Not Found»
  — сырой detail ответа; стоит заменить на человеческое сообщение в handleApiError
  (малозначимо).
- **DV-9. Мокап задает `.content { max-width: 980px }`** для статьи/редактора/
  истории; в app.css `.content` max-width нет, wiki.css его не добавляет. На
  широких экранах контент растягивается шире мокапа. Единое решение (если
  принято дизайнером) — добавить max-width в зону шва wiki.css, иначе зафиксировать
  отступление как осознанное.
- **DV-10. Breadcrumb истории версий** («статья → История версий», мокап
  history) в реализации не рендерится — вместо него ссылка «← К статье» под
  layout. Навигационная функция покрыта, но вид отличается от мокапа. Решение
  дизайнера: добрать ol.breadcrumb в history.js или согласовать «← К статье».

### Отмечено, вне шва волны 3

- Бейдж «todo» у пункта «Wiki» в сайдбаре все еще виден (01-tree.png) — снятие
  бейджа отнесено к задаче 6.x релизного хвоста (см. pages.py docstring);
  на мокапе его нет. Напоминание оркестратору: к выкатке волны 3 бейдж снять.
