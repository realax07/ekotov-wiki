## Соответствие спеке и дискриминаторы

- **Трассировка и смысл.** Ожидаемые результаты кейсов не противоречат
  сценариям; расширения кейсов относительно THEN-частей спеки — законные
  усиления из требований/design: отсутствие `data-editor`/`tok-*`/
  compact-класса/атрибутов свернутости в GET (R1/R2, §1–§3), подсчет
  `data-block-part` при лимите вкладок (R3), `aria-pressed` вместо
  визуала для H-состояний (R4, регресс P12 п.4), сторожевые абзацы и
  посимвольная сверка rNcM (R5).
- **Дискриминаторы реально дискриминируют** (проверено по механике
  фиксов и фактам QA):
  - TC-037 (F-1): поймал бы и хранение `<br>` в code-контексте, и
    задвоение `\n` на втором round-trip — оба шага (br→\n на записи,
    идемпотентность normalizeCodeInput) ассертятся явно; пустой блок без
    мусора закрывает смежный класс.
  - TC-039 (F-2): гуттер «по блоку кода» с пустыми строками и синхронным
    скроллом отличает buildGutter от наивного счетчика непустых строк;
    ассерт отсутствия гуттера в GET ловит утечку editor-артефактов (F1).
  - TC-040 (F-3/D1): до фикса 8bbbcce кейс дал FAIL (коммит вместо
    отмены + 4 pageerror), после — PASS 4/4; rename-гейт статьи
    (клик = toggle, input не открывается) ассертится отдельно. Дискриминация
    доказана самим прогоном.
  - TC-041 (D2): до фикса — FAIL (вложенная table в DOM), после — PASS
    (кнопка disabled + title, `td table`=0, paste-unwrap `<td>A1<br>B1</td>`
    идемпотентен). Paste-ветка отделяет sanitize-инвариант от UI-гейта —
    ровно то, что требовалось после F3.
  - TC-038: гейт код-блока работает и без фикса (design-check #6) — кейс
    фиксирует инвариант регрессионно (кнопки + paste-unwrap с сохранением
    текста спойлера как текста).
- **Негатив/границы полны.** XSS-векторы: script с содержимым + onclick
  внутри блока (022), подмена data-словаря (023), script/onerror вне
  блоков (034) — все три сценария безопасности обеих дельт + вектор §8.
  Граница глубины взята с ОБЕИХ сторон (цепочки 5 и 7 — 024); лимит
  вкладок 8/9 (012); запрет удаления последней — вкладка (011) и строка/
  столбец 1×1 (019); Backspace в пустом H со сторожевым текстом (016);
  оба Enter-класса: ячейка «один<br>два» (021, дискриминатор против
  дублирования переноса) и код (037).
- **Допущения автора приняты** (в духе канона: операционализация, не
  правка спеки): компакт-класс вычисляется при активации по
  `closest('td,th')`, а не хранится (TC-003 — консистентно с §1 «состояние
  отображения не хранится»); снятие невалидного `data-lang` на записи с
  деградацией в plain (TC-009) — консистентное чтение §2-словаря; порог
  viewport 1024 px для переполнения таб-бара (TC-012); замер активации
  «JS-метками, max из 3 прогонов» (TC-027) — операционализация «≤150 мс
  без блокировки», честно помечена в QA как оценка сверху; граница ≥/=
  для лимита 8 зафиксирована детерминированно (ровно 8 частей в контенте).
- **Расхождение механики, не смысла (Minor):** TC-011 допускает формулировку
  «крестик неактивен/disabled с подсказкой», факт реализации — крестик
  последней вкладки скрыт (QA web::011). Существенный ассерт (удаление
  заблокировано, виджет не исчезает, «Обзор» удален → «Детали» осталась)
  от механизма не зависит.

   нет pageerror), но различающее значение усилило бы кейс.

   `pe/QaPe_Pass_1!` как seed — в сиде стенда его нет (QA, наблюдение 5);
