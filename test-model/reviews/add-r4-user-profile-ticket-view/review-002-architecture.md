## 2. Новые проблемы (проверка правок на регрессию)

- **nginx `location /avatars/` vs существующие location** — конфликта нет: в обоих конфигах точные/prefix-локации — `= /robots.txt`, `/static/`, `/`; `/avatars/` не пересекается ни с одной (длиннейший префикс wins, alias с хвостовыми слэшами в location и alias корректен). Секьюрити-заголовки серверного блока наследуются. `client_max_body_size 2m` достаточно для загрузки ≤2 МБ. Шаблоны `deploy/nginx-ekotov-wiki{,-10443}.conf` идентичны по блоку — рассинхрона между 80/443- и 10443-вариантами нет.
- **deploy-шаг 3c — нумерация/логика deploy.sh**: позиция шага (после rsync→pip→схемы, до рестарта, fail→abort с восстановимым бэкапом) логике deploy.sh соответствует; канонические шаги не перенумеровываются (вставка между 4 и 5). RUNBOOK описывает состав шагов синхронно. Содержательно логика верна; см. M-1 о метке.
- **`avatar_updated_at`: миграция ↔ SCHEMA_SQL** — согласованы: ALTER в migrate_r4.py для существующих БД + колонка в SCHEMA_SQL (sdd §4) для свежих — тот же паттерн, что done_at в db.py (проверено по фактическому коду db.py); идемпотентность через PRAGMA table_info сохранена. NULL-семантика (нет аватара → нет URL) едина в design §2, sdd §3.1a-кватер/§4, tasks 2.3.
- **Согласованность отредактированных разделов пакета** — proposal/design/research/tasks/sdd не противоречат друг другу ни по одному из 9 пунктов (проверено перекрестно); `openspec validate add-r4-user-profile-ticket-view --strict` — valid. Дельты specs правок не требовали (слово «статика» в auth-дельте — про механизм отдачи nginx, что сохраняется; конкретные пути в сценариях не фигурируют).
- **Сфера пакета не расширялась побочно**: правки 1f5e72c не трогают ничего вне закрытия 9 пунктов (по diff: 10 файлов, все — целевые).

## 4. Оценка расширения зоны записи СА (nginx-конфиги, RUNBOOK)

**Правомерно и минимально.** Review-001 сам требовал: «если nginx-конфиг меняется — в deploy-заметке с шагом правки конфига и reload nginx» (C-1) и «консистентность с RUNBOOK обязательна» (C-2). Проверка минимума: nginx — ровно один блок `location /avatars/` в каждом конфиге + 3 строки комментария; RUNBOOK — дополнение шагов 3/5 и новый шаг 6 с примером команд (mkdir/chown, location, nginx -t, reload) — без переписывания существующих процедур. Никакой сопутствующей «косметики» вне пунктов ревью в этих файлах нет (расхождение мета-цифр и стилистика не трогались). Расширение зоны признаю законным закрытием blocker/major, не самодеятельностью.
