## Соответствие спеке и дискриминаторы

- **Трассировка и смысл.** Ожидаемые результаты кейсов не противоречат
  сценариям; расширения относительно THEN-частей — законные усиления из
  design/ревью: инвариант ≤1 «считает только todo/in_progress» (103,
  115 — Э1/design §4), `done_at` и видимость выполненной до
  автоархивации МСК-дня (103/114), предотмеченный fast + priority-lock
  в форме создания (107 — существующий UI), идемпотентность
  exclude_task_id на самой fast (110 — spec-THEN), 422 priority-lock
  после освобождения слота (112), счетчик «ровно один POST» (113 —
  tasks 3.1/O1), состояние вычислено из последнего GET /api/board
  (108 — O2).
- **Дискриминаторы реально дискриминируют** (проверено по механике
  фиксов и фактам QA):
  - 109/110 (F1, решение «а»): PATCH-путь вставки FR-89 с payload
    `is_fast:true, priority:high` → 200 и обратный тоггл
    (выключение освобождает слот, повторное включение 200, а не 409)
    отличают полный переключение-контракт от «is_fast только при
    создании»; QA: оба гэпа сьюта закрыты новыми тестами, PASS.
  - 104/119 (F2): регресс-маркеры TC-UI-010 и TC-dnd-103 переведены
    на зону — кейс 104 ассертит отсутствие и карточки, и класса
    `task-card-fast` в `#board` (СТАРОЕ поведение p12); без правки
    маркеры падают.
  - 115 (F3): единственное 409-ребро DnD зоны — возврат выполненной
    при новой активной; ассерты на `#board-error` + refreshBoard из
    серверного состояния (карточка не «висит» в «Ожидает») ловили бы
    и отсутствующий 409, и полузависимое UI-состояние.
  - 113 (O1): «ровно один POST move на drop» через счетчик запросов —
    двойной dragend HTML5 DnD не задваивает.
  - 120 (O2): сабмит на устаревшем снимке во второй вкладке → 409,
    чип, перерисовка из сервера, дублей нет; шаг 5 закрывает
    PATCH-ветку той же логикой (не 500, не тихий провал).
- **Негатив/границы полны.** Оба 409-пути (создание и PATCH — 112;
  move из done — 115); клиентские гейты до запроса (108 force-клик,
  110 чекбокс); DnD-запреты без запроса на всех трех ветках
  (обычная→занятая зона 117, обычная→пустая 118, fast→канбан 119);
  граница слота с ОБЕИХ сторон (занят/освобожден — 108/103,
  выполненная+новая активная — 115); 422 priority-lock (112);
  XSS-векторы на оба контейнера — script/img-onerror в fast-title,
  svg-onload + кавычка-breakout в обычном (121), плюс позитив-контроль
  «`<b>` показан как текст».
- **Допущения автора приняты** (операционализация, не правка спеки):
  мокап-сверки скриншотом в визуальных кейсах (100/106/108/116)
  рядом с DOM-ассертами по классам/токенам; граница МСК-дня через
  `GET /api/board` без перевода часов (103/114); `dnd_dispatch`
  вместо нативного HTML5 DnD (Playwright не эмулирует — честно
  оговорено в README и кейсах).
