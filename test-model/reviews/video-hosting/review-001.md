## Эскалации автора: разбор и решения

- **E-1 — «500 МБ»: двоичные или десятичные.** Кейс TC-007 зафиксировал
  границу как 524 288 000 байт (500×1024×1024). Подтверждено прецедентом:
  `services/images/app/images.py:16` — `MAX_SIZE_BYTES = 10 * 1024 * 1024`
  (двоичные МБ). **Допущение принято.** Спеке недостает явного определения —
  рекомендация ПМ: при следующей правке спеки добавить «(МБ = 2^20 байт,
  паритет images)»; правку спеки сейчас не требую.
- **E-2 — количественный порог «быстрого 503».** Спека: «быстрый
  управляемый 503 (не таймаут)» без числа. Кейс TC-004 принял «< 2 с».
  **Допущение принято** — операционализация честная, порог заведомо щедрее
  любого таймаута nginx.
- **E-3 — код отказа при удалении чужого комментария.** Спека: «отклоняется
  (запрещено)» без кода. Кейс TC-028 принял 403. Подтверждено прецедентом:
  `services/images/app/gallery.py` (паттерн FR-82) — «только автор; чужой →
  403». **Допущение принято** (403). ПМ может закрыть эскалацию без правки
  спеки.
- **E-4 — серверный контракт невалидной категории при загрузке видео.**
  Спека требует «значения только из справочника галереи» и запрещает
  создавать новый справочник, но не определяет поведение при отправке
  невалидного значения (отказ 422/400 или игнорирование → «Без категории»).
  Прецедент images НЕ переносится: там строковое имя категории, наоборот,
  СОЗДАЕТ новую категорию (`_resolve_category`, gallery.py:196–213), что для
  видео прямо запрещено спекой. Это **дефект неполноты спеки — эскалирую
  ПМ**; спеку сам не правлю. Кейс TC-035 вправе держать двойное ожидание до
  решения; для автоматизации рекомендация: ассертить инвариант «видео с
  невалидной категорией не создано с этой категорией» (422/400 ИЛИ
  «Без категории»), точный код — после решения ПМ.
- **E-5 — порог ответа загрузки при NFR-37.** Спека задает p95 < 500 мс для
  загрузки/списка (сценарий «Замер отзывчивости на стенде») — он закрыт
  TC-039 дословно (20 списков + 5 загрузок, p95 по обоим наборам). TC-017
  (сценарий «Конвертация не блокирует сервис») принял для одиночной загрузки
  «< 5 с» как операционализацию «не ожидает конвертации». **Допущение
  принято**, но оформлено замечанием MIN-2 (см. таблицу).
- **E-6 — таймаут конвертации как класс «неудачи».** Спека требует «ровно
  один автоматический повтор» при неудаче, не определяя, считается ли
  прерывание по таймауту неудачей с ретраем, и не задавая значение таймаута.
  Кейс TC-016 принял «да, ретрай по таймауту; значение — из конфигурации
  сервиса». **Допущение принято** (семантика ретрая едина для любого класса
  неудачи); факт наличия и значения таймаута — эскалирую ПМ зафиксировать в
  конфигурации/REPORT до прогона кейса.
- **Инвариант «≤ 1 голос на пользователя» в гонке (TC-032).** Прямое
  следствие требования спеки «ровно один голос на видео от пользователя» —
  **подтверждаю**, кейс корректен; формулировка «не более чем на 1» для
  суммарных счетчиков согласована.

## Замечания

| Кейс | Серьезность | Дефект | Рекомендация |
|---|---|---|---|
| TC-vid-029 | **Major** | Предусловие «2 лайка / 1 дизлайк (создано голосами pe и seed)» невоспроизводимо как записано: при одном голосе на пользователя для состояния 2/1 нужно минимум 3 голосующих помимо owner, а определены только owner и pe («(seed)» в шапках — пометка о сидировании, не третий аккаунт; даже с третьим голосующим 2/1 не собирается: владелец лайка не может одновременно держать дизлайк). Ассерт «лайков = 3» зависит от этого престейта. | Определить данные детерминированно: либо (а) ввести 4-й сид-аккаунт/фикстуру прямого создания голосов и указать раскладку «лайк: pe, seed; дизлайк: qa3», либо (б) снизить GIVEN до достижимого «1 лайк (pe) / 1 дизлайк (seed)» и ассертить «лайков = 2, дизлайков = 1» — интенция сценария спеки (счетчик меняется ровно на единицу, голос = «+1») сохраняется. |
| TC-vid-008 | Minor | Тип кейса «негативный», хотя проверяется позитивное поведение (загрузка не блокируется чужой конвертацией). | Пометить «позитивный (неблокируемость)» или «НФТ» — на трассировку не влияет. |
| TC-vid-017 | Minor | Порог загрузки «< 5 с» слабее NFR-37 (p95 < 500 мс для загрузки); точный замер уже в TC-039. | Добавить перекрестную ссылку «точный p95-замер — TC-039» либо ужесточить до «< 500 мс» для 5 МБ. |
| TC-vid-030/031/032 | Minor | Предусловия не повторяют базовый набор (стенд `GET /api/health` → 200, аккаунты owner/pe), в отличие от остальных кейсов серии. | Дописать базовые предусловия — кейсы должны исполняться независимо при выборочном запуске. |

Blocker'ов нет. Негативные классы, границы (500/501 МБ, 255-байтное имя,
unicode/emoji), данные и ассерты конкретны; ожидаемые результаты дословно
следуют сценариям спеки; отклонения (403, < 2 с, < 5 с, инвариант ≤ 1) —
разумные допущения, разобранные выше.
