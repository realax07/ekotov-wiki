# requirements-p4.md — Ретроспективные требования R1.3 (P4: подсказки тегов/категорий в поиске)

> Статус: УТВЕРЖДЕН r1 пост-фактум | Автор: ba_agent | История: r1 ретроспектива (2026-09-21)
>
> **Характер документа.** Поведение P4 уже реализовано (коммит `1f11011`, PR#1, main) и покрыто автотестами; документ оформляет требования **post-фактум** для замыкания Флоу 1 по R1.3 (урок 2026-09-20: фича запущена по Флоу 2, QA проскочены — закрыто Флоу 5-ретроспективой). Требования сформулированы по факту реализации и сверены с кодом; отступлений от слов Заказчика нет.
>
> **Единственный первоисточник — дословная цитата Заказчика:**
> «я например хочу чтобы саджест формировался по двум столбцам, теги и категории, и выбирался типом set(), множество, только из уже заведенных вариантов»
>
> Нумерация FR продолжает основной пакет `requirements.md` (там последний — FR-14). Связь с основным ТЗ: развивает FR-11 (фильтр-конструктор вкладки поиска — «вариант с выбором»); авторизация — следствие NFR-7 (основной ТЗ).

## 1. Функциональные требования

| ID | Требование | Приоритет | Источник |
|---|---|---|---|
| FR-15 | Пользователь на вкладке поиска получает подсказки значений для полей фильтра-конструктора «Теги» и «Категория»; один общий список подсказок привязан к обоим полям. | Should | цитата Заказчика («по двум столбцам, теги и категории») |
| FR-16 | Множество подсказок — объединение значений тегов и категорий **существующих задач** (set-семантика): без дублей; значение, встречающееся и в тегах, и в категориях, входит в список один раз; список отсортирован по возрастанию. | Should | цитата Заказчика («типом set(), множество») |
| FR-17 | В подсказки попадают **только уже заведенные варианты**: теги удаленных задач (осиротевшие) не включаются; пустые/незаполненные категории не включаются; новые значения через подсказки не создаются (только выбор из существующих). | Should | цитата Заказчика («только из уже заведенных вариантов») |
| FR-18 | Получение подсказок требует авторизации: без валидной сессии — отказ 401 (следствие NFR-7 основного ТЗ: все API закрыты авторизацией). | Must | следствие NFR-7 (основной ТЗ, ОВ-12/ОВ-18) |

Приоритеты MoSCoW: FR-15…FR-17 — **Should** (P4 релиза: удобство поиска, не блокирует релиз без него); FR-18 — **Must** (безопасность, не подлежит смягчению). Could/Won't — нет.

## 2. Сценарии

| Сценарий | Шаги | Ожидаемый результат | Тест |
|---|---|---|---|
| СЦ-1. Подсказки при авторизации | Пользователь с сессией открывает /search и фокусируется на поле «Теги» или «Категория» | GET /api/suggestions → 200 `{"suggestions": [...]}`; datalist обоих полей показывает значения | TC-API-SUGG-001, TC-UI-SUGG-001 |
| СЦ-2. Без сессии | Запрос GET /api/suggestions без куки сессии | 401 `{"error": "unauthorized"}` | TC-API-SUGG-002 |
| СЦ-3. Set-семантика | Тег «home» и категория «home» заведены на задачах | «home» в списке подсказок ровно один раз | TC-API-SUGG-003, TC-UI-SUGG-002 |
| СЦ-4. Сортировка | Заведены значения в разном порядке | Список отсортирован по возрастанию | TC-API-SUGG-004, TC-UI-SUGG-002 |
| СЦ-5. Объединение источников | Есть и теги, и категории на существующих задачах | Список содержит И теги, И категории | TC-API-SUGG-005 |
