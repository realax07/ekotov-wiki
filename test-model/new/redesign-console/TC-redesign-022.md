# TC-redesign-022: Блок профиля — ограничения, верстка сайдбара, визуал «Пульта»

## Трассировка
- **CHK:** CHK-022
- **Тип:** нег./гран./виз. | **Приоритет:** Must (по CHK-022)
- **FR/Требование:** navigation MODIFIED — «Профиль текущего пользователя внизу сайдбара» (ОГР-15, снятие ОГР-13)
- **Scenario:** «В профиле нет аватарок-файлов и смены пароля» (инвертирован), «Профиль не нарушает верстку сайдбара», «Блок профиля в визуале «Пульта»»

## Предусловия
- Поднят стенд; вход owner; эталон board-console.html §sidebar. Playwright + `page.evaluate`.

## Шаги
1. Осмотреть блок профиля (без перехода): сам блок — только отображение + переход; внутри блока НЕТ форм загрузки аватарки, редактирования профиля, смены пароля (инвертированный сценарий: эти действия — на открываемой кликом странице настроек пользователя, прежнее исключение ОГР-13 снято решением ОГР-15 для блока, но не для страницы).
2. Задать owner длинный display_name (граничное значение ~60+ символов без пробелов), обновить страницу: блок профиля не ломает верстку сайдбара — пункты разделов (доска, поиск, Wiki, настройки, выход) не вытеснены, нет горизонтального переполнения/обрезки каркаса (перенос текста/ellipsis допустим).
3. Проверить визуал блока: панель на фоне сайдбара с верхней границей `--p-border`; имя `--p-text-900`; служебные подписи `--p-text-500`; аватар — существующая функциональность без изменений.
4. Сверить с мокапом §sidebar и с прогоном `test_r5_profile_card_ui.py` (fixed, green).

## Ожидаемый результат
- Блок профиля не содержит управляющих форм (только отображение + переход в настройки пользователя).
- Длинный display_name не ломает сайдбар; визуал — на токенах «Пульта» по мокапу.
