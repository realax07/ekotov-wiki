# TC-redesign-001: Контраст WCAG 2.1 AA на токенах «Пульт»

## Трассировка
- **CHK:** CHK-001
- **Тип:** НФТ | **Приоритет:** Must (по CHK-001)
- **FR/Требование:** accessibility ADDED — «Контраст WCAG 2.1 AA на токенах «Пульт»» (NFR-41)
- **Scenario:** «Программная проверка всех пар», «Подписи на hover-подложке не проседают»

## Предусловия
- Поднят стенд (`GET {BASE_URL}/api/health` → 200); редизайн применен (static_v=redesign-1).
- Прогон контраст-скрипта задачи 1.1 доступен (REPORT волны 1.1 с числами по парам).
- Playwright (Python): `page`, `page.evaluate`; вход owner (логин `owner`, seed-пароль).

## Шаги
1. Открыть REPORT задачи 1.1 и сверить числа контраст-скрипта: все текстовые пары токенов и ключевые составные поверхности (hover-подложки bg-300, бейджи приоритетов, янтарные кнопки) ≥ 4.5:1. Эталоны мокапа: text-900 15.4:1, text-600 8.87:1, text-500 5.98:1 на bg-000; текст на янтаре 9.86:1; cyan 10.7:1; статусные ≥ 6.67:1.
2. Открыть доску с задачей без исполнителя; навести курсор на карточку (подложка `--p-bg-300`).
3. Через `page.evaluate` прочитать computed `color` мета-подписи карточки (`--p-text-500` → на hover `--p-text-600`) и `background-color` подложки.
4. Посчитать контраст пары text-600/bg-300 по WCAG-формуле (или взять из REPORT, если пара там перечислена).

## Ожидаемый результат
- Шаг 1: каждая пара в REPORT ≥ 4.5:1; числа воспроизводимы (скрипт можно повторить локально).
- Шаги 2–4: на hover подпись мета-строки поднимается до `--p-text-600`, контраст text-600 на bg-300 ≥ 4.5:1 (эталон мокапа 5.6:1) — подпись не «проседает» на hover-подложке.
- Любая пара < 4.5:1 — дефект редизайна (блокер для релиза волны).

## Примечания
- Приемочный кейс поверх автоскрипта: скрипт (гейт 1.1) — регресс-пара, кейс фиксирует визуальную/приемочную сторону (hover-поведение подписи мокапа `.task:hover .task-meta`).
