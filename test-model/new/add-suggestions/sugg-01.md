## TC-sugg-006 — Осиротевшие теги и пустые категории исключены из подсказок
- **CHK:** CHK-S-6
- **Источник:** search: «Подсказки тегов и категорий в поиске» (FR-17) / Scenario: Только заведенные — осиротевшие теги и пустые категории исключены
- **Тип:** негативный | **Приоритет:** Should
- **Предусловия:** общие.
- **Шаги:**
  1. Создать задачу-носитель будущего осиротевшего тега: `curl -s -b owner_cookies.txt -X POST {BASE_URL}/api/tasks -H "Content-Type: application/json" -d '{"title":"QAT-SUGG-носитель","category":"QAT-SUGG-Кат-А","tags":["QAT-SUGG-Тег-Осирот"]}'` → 201, зафиксировать `id` из тела.
  2. Создать вторую задачу с пустой категорией и живым тегом: `curl -s -b owner_cookies.txt -X POST {BASE_URL}/api/tasks -H "Content-Type: application/json" -d '{"title":"QAT-SUGG-пустая-кат","tags":["QAT-SUGG-Тег-Б"]}'` → 201 (поле `category` не передано → NULL, sdd §3.2).
  3. Удалить задачу-носитель: `curl -s -i -b owner_cookies.txt -X DELETE {BASE_URL}/api/tasks/{id_из_шага_1}` → 204 (проверить `GET /api/tasks/{id}` → 404).
  4. Запросить подсказки: `curl -s -b owner_cookies.txt "{BASE_URL}/api/suggestions"` → код и тело.
- **Ожидаемый результат:** шаг 4 — HTTP **200**, тело — JSON-объект с единственным ключом `"suggestions"` (список строк). В списке:
  - `QAT-SUGG-Тег-Осирот` **отсутствует** (тег остался только у удаленной задачи — join через `task_tags` отсекает его);
  - `QAT-SUGG-Тег-Б` **присутствует** (живой тег существующей задачи);
  - пустой строки `""` **нет** (пустые/NULL категории не проходят в UNION);
  - `QAT-SUGG-Кат-А` отсутствует (ее единственный носитель удален — контроль, что осиротевшее значение категории тоже не всплывает);
  - список отсортирован по возрастанию (`suggestions == sorted(suggestions)`).
- **Тестовые данные:** задача-носитель `QAT-SUGG-носитель` (category=`QAT-SUGG-Кат-А`, tag=`QAT-SUGG-Тег-Осирот`); задача `QAT-SUGG-пустая-кат` (category — не задана, tag=`QAT-SUGG-Тег-Б`).

## TC-sugg-007 — Подсказки не создают новых значений: свободный ввод вне datalist
- **CHK:** CHK-S-7
- **Источник:** search: «Подсказки тегов и категорий в поиске» (FR-17) / Scenario: Подсказки не создают новых значений (+ замечание 3 чеклиста: поведение свободного ввода фиксируется явно)
- **Тип:** негативный | **Приоритет:** Should
- **Предусловия:** общие; открыта вкладка поиска `{BASE_URL}/search` (видима кнопка «Конструктор»); зафиксирован снимок подсказок: `curl -s -b owner_cookies.txt "{BASE_URL}/api/suggestions"` → список `S0` (HTTP 200).
- **Шаги:**
  1. В поле «Теги» фильтра-конструктора (поле ввода с плейсхолдером «home, urgent», атрибут `list="tag-hints"`, роль textbox — локатор по доступному имени «Теги», id `#search-tags`) ввести с клавиатуры значение, которого нет в datalist: `QAT-SUGG-Новый-Свободный`. Зафиксировать: ввод принимается полем (текст отображается, ввод не блокируется — свободный ввод сохранен по design FR-11).
  2. В поле «Категория» (роль textbox, доступное имя «Категория», атрибут `list="tag-hints"`, id `#search-category`) аналогично ввести `QAT-SUGG-Новая-Кат-Свободная`; зафиксировать прием ввода.
  3. Открыть вкладку заново (перезагрузить страницу `/search`, чтобы `loadSuggestions()` выполнилась повторно) и осмотреть datalist: опций со значениями из шагов 1–2 нет.
  4. API-контроль: `curl -s -b owner_cookies.txt "{BASE_URL}/api/suggestions"` → код и тело.
- **Ожидаемый результат:** шаг 4 — HTTP **200**, тело `{"suggestions": [...]}` **идентично снимку `S0`** (список не изменился): `QAT-SUGG-Новый-Свободный` и `QAT-SUGG-Новая-Кат-Свободная` **не появились** — ввод в поля подсказок не создает новых значений ни в `tags`/`categories` существующих задач, ни в источнике подсказок. Datalist (шаг 3) не содержит опций с этими значениями. Ожидаемое поведение свободного ввода (замечание 3 чеклиста): ввод в поле разрешен (фильтр со свободным значением — легитимный сценарий FR-11, «нет совпадений»), подсказки при этом остаются только из уже заведенных вариантов.
- **Тестовые данные:** свободные значения `QAT-SUGG-Новый-Свободный` (поле «Теги»), `QAT-SUGG-Новая-Кат-Свободная` (поле «Категория»); снимок `S0` из предусловия.

## TC-sugg-008 — Все категории пусты: в подсказках только теги, без пустых строк и null
- **CHK:** CHK-S-8
- **Источник:** search: «Подсказки тегов и категорий в поиске» (FR-17, дополнение: граничное)
- **Тип:** граничный | **Приоритет:** Should
- **Предусловия:** общие.
- **Шаги:**
  1. Создать задачу с категорией-пустой-строкой: `curl -s -b owner_cookies.txt -X POST {BASE_URL}/api/tasks -H "Content-Type: application/json" -d '{"title":"QAT-SUGG8-гран-пустая","category":"","tags":["QAT-SUGG8-Тег-1"]}'` → 201.
  2. Создать задачу без категории вовсе: `curl -s -b owner_cookies.txt -X POST {BASE_URL}/api/tasks -H "Content-Type: application/json" -d '{"title":"QAT-SUGG8-гран-null","tags":["QAT-SUGG8-Тег-2"]}'` → 201.
  3. Запросить подсказки: `curl -s -b owner_cookies.txt "{BASE_URL}/api/suggestions"` → код и тело; выбрать все значения с префиксом `QAT-SUGG8`.
- **Ожидаемый результат:** шаг 3 — HTTP **200**, тело `{"suggestions": [...]}`. В списке:
  - присутствуют ровно оба тега: `QAT-SUGG8-Тег-1` и `QAT-SUGG8-Тег-2`, и **ничего другого** с префиксом `QAT-SUGG8` (категории `""` и NULL в список не прошли — граница `category IS NOT NULL AND != ''`);
  - пустой строки `""` нет; строк-подобий null (`"null"`, `"None"`, `"[]"`) нет;
  - подвыборка с префиксом `QAT-SUGG8` отсортирована (`QAT-SUGG8-Тег-1` раньше `QAT-SUGG8-Тег-2`).
- **Тестовые данные:** задача `QAT-SUGG8-гран-пустая` (category=`""`, tag=`QAT-SUGG8-Тег-1`); задача `QAT-SUGG8-гран-null` (category — не задана, tag=`QAT-SUGG8-Тег-2`).

## TC-sugg-009 — Удаление задачи убирает её теги/категорию из подсказок
- **CHK:** CHK-S-9
- **Источник:** search: «Подсказки тегов и категорий в поиске» (FR-17, дополнение: состояние)
- **Тип:** негативный | **Приоритет:** Should
- **Предусловия:** общие. Значения задачи уникальны и нигде больше не заведены (уникальный префикс `QAT-SUGG9` — исключает «спасение» значения другими задачами).
- **Шаги:**
  1. Создать задачу с уникальными категорией и тегом: `curl -s -b owner_cookies.txt -X POST {BASE_URL}/api/tasks -H "Content-Type: application/json" -d '{"title":"QAT-SUGG9-исходная","category":"QAT-SUGG9-Кат","tags":["QAT-SUGG9-Тег"]}'` → 201, зафиксировать `id`.
  2. Контроль «до»: `curl -s -b owner_cookies.txt "{BASE_URL}/api/suggestions"` → 200; `QAT-SUGG9-Кат` и `QAT-SUGG9-Тег` присутствуют в списке.
  3. Удалить задачу: `curl -s -i -b owner_cookies.txt -X DELETE {BASE_URL}/api/tasks/{id_из_шага_1}` → 204.
  4. Контроль «после», без перезапуска приложения и без сброса кеша: `curl -s -b owner_cookies.txt "{BASE_URL}/api/suggestions"` → код и тело.
- **Ожидаемый результат:** шаг 4 — HTTP **200**, тело `{"suggestions": [...]}`; значений `QAT-SUGG9-Кат` и `QAT-SUGG9-Тег` **в списке нет** — состояние пересчитывается на каждый GET (никакого кеша/перезапуска не требуется). Прочие значения списка (снимок шага 2 минус удаленные два) не искажены; список по-прежнему отсортирован.
- **Тестовые данные:** задача `QAT-SUGG9-исходная` (category=`QAT-SUGG9-Кат`, tag=`QAT-SUGG9-Тег`).
