# TC-nav-008 — Раздел «Настройки» доступен со всех страниц функционала

- **CHK:** CHK-111
- **Change:** add-r2-categories-settings
- **Источник:** navigation: Раздел «Настройки» в сайдбаре (FR-23) / Scenario: Раздел настроек доступен со всех страниц функционала
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** пользователь авторизован
  - **WHEN** пользователь открывает любую страницу функционала (доска, поиск, настройки)
  - **THEN** раздел «Настройки» отображается в сайдбаре и позволяет перейти на страницу настроек
- **Шаги:**
  1. Для каждой из страниц `/board`, `/search`, `/settings` (открыть через `page.goto`): проверить `page.get_by_role("link", name="Настройки")` — виден.
  2. С `/board`: клик по «Настройки» → URL `/settings`, заголовок виден.
  3. С `/search`: вернуться в `/search`, снова клик «Настройки» → URL `/settings`.
  4. С `/settings`: раздел тоже отображается (ссылка может указывать на текущую страницу — зафиксировать фактическое поведение: активная/текущая разметка).
- **Ожидаемый результат:** шаг 1 — раздел виден на всех трех страницах; шаги 2–3 — переход работает с доски и из поиска (URL и заголовок настроек); шаг 4 — на самой странице настроек раздел присутствует (факт зафиксирован в протоколе).
- **Тестовые данные:** страницы `/board`, `/search`, `/settings`.
