# TC-cat-014 — Валидация следует за текущим содержимым справочника

- **CHK:** CHK-95
- **Change:** add-r2-categories-settings
- **Источник:** categories: Жесткая валидация (FR-21) / Scenario: Валидация следует за справочником
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200; `BASE_URL` по умолчанию `http://127.0.0.1:8080`); выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed `tests/api/conftest.py`, куки в `owner_cookies.txt`); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** категория `QAT-Врем` есть в справочнике и задача с ней валидна
  - **WHEN** категория удалена из справочника (после перевода задачи) и пользователь пытается сохранить задачу с `QAT-Врем`
  - **THEN** сохранение отклоняется — категория более не входит в справочник
- **Шаги:**
  1. `POST /api/categories` name=`QAT-Врем` → 201, зафиксировать `id`.
  2. Контроль «пока валидна»: `POST /api/tasks` `{"title":"QAT-до-удаления","category":"QAT-Врем"}` → 201, зафиксировать `id_t`.
  3. Перевести задачу: `PATCH /api/tasks/{id_t}` `{"category":"Дом"}` → 200.
  4. `DELETE /api/categories/{id}` → 200.
  5. `POST /api/tasks` `{"title":"QAT-после-удаления","category":"QAT-Врем"}` → код и тело.
  6. Cleanup: DELETE задач `id_t` и задачи шага 5 (если создалась — дефект) → 204.
- **Ожидаемый результат:** шаг 2 — 201 (пока категория в справочнике, значение валидно); шаг 5 — HTTP **422** `{"error": "validation", "details": {"category": "not in categories"}}`, задача не создана — валидация FR-21 следует за текущим содержимым справочника, а не за историческими значениями.
- **Тестовые данные:** категория `QAT-Врем` (создается и удаляется в кейсе); задачи `QAT-до-удаления`, `QAT-после-удаления`.
