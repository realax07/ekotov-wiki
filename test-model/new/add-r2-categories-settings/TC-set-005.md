# TC-set-005 — Справочник един: пер-пользовательских списков нет

- **CHK:** CHK-107
- **Change:** add-r2-categories-settings
- **Источник:** settings: Настройки общие (FR-24, ОГР-7) / Scenario: Справочник един — пер-пользовательских списков нет
- **Тип:** граничный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** первый пользователь (owner) видит в настройках справочник с `Дом`, `Работа`, `Личное`
  - **WHEN** второй пользователь (wife) открывает настройки и поле выбора категории
  - **THEN** второй видит тот же единственный справочник; отдельного личного списка у него нет (categories без user_id — sdd §2)
- **Шаги:**
  1. owner: `GET /api/categories` → список `S`; открыть `/settings` — виден `S`.
  2. Вход wife (отдельная сессия/контекст, куки `wife_cookies.txt`).
  3. wife: `GET /api/categories` → список `S_wife`; сравнить с `S`.
  4. wife (UI): открыть `/settings` → список категорий на странице равен `S`; открыть форму задачи → select категории содержит `S`.
  5. Контроль модели (обоснование, не ассерт): в БД таблица `categories` без столбца user_id — `PRAGMA table_info(categories);` (зафиксировать в протоколе).
- **Ожидаемый результат:** шаги 3–4 — `S_wife == S` (identично, включая те же имена `Дом`/`Работа`/`Личное`); единственный справочник для обоих (ОГР-7); второго «личного» списка не существует.
- **Тестовые данные:** сессии owner и wife; seed-справочник `Дом`, `Работа`, `Личное`.
