# TC-set-004 — Второй пользователь (не владелец) может менять настройки

- **CHK:** CHK-106
- **Change:** add-r2-categories-settings
- **Источник:** settings: Настройки общие (FR-24, ОГР-11) / Scenario: Второй пользователь может менять настройки
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200; `BASE_URL` по умолчанию `http://127.0.0.1:8080`); выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed `tests/api/conftest.py`, куки в `owner_cookies.txt`); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** второй пользователь (wife, не владелец) авторизован; в справочнике есть категория `QAT-меняемая`
  - **WHEN** второй пользователь переименовывает и затем удаляет категорию
  - **THEN** оба изменения выполняются успешно и применяются ко всей системе (нет ограничений «только owner»)
- **Шаги:**
  1. owner: `POST /api/categories` name=`QAT-меняемая` → 201, зафиксировать `id`.
  2. wife: `PATCH /api/categories/{id}` `{"name":"QAT-переименованная"}` → код и тело.
  3. owner (контроль): `GET /api/categories` → `QAT-переименованная` присутствует (изменение общесистемное).
  4. wife: `DELETE /api/categories/{id}` → код.
  5. owner (контроль): `GET /api/categories` → `QAT-переименованная` отсутствует.
- **Ожидаемый результат:** шаг 2 — HTTP **200** (не 403 — прав нет, ОГР-11 «права на настройки не проектируются», sdd §7); шаг 4 — HTTP **200**; шаги 3/5 — изменения видны/применены в сессии первого пользователя — общесистемный эффект.
- **Тестовые данные:** сессии owner и wife; категория `QAT-меняемая` → `QAT-переименованная`.
