# TC-nav-006 — Раздел «Настройки» отображается внизу слева рядом с выходом

- **CHK:** CHK-109
- **Change:** add-r2-categories-settings
- **Источник:** navigation: Раздел «Настройки» в сайдбаре (FR-23) / Scenario: Раздел настроек отображается внизу слева
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** пользователь авторизован и находится на любой странице функционала
  - **WHEN** пользователь просматривает сайдбар
  - **THEN** в сайдбаре присутствует раздел «Настройки», расположенный внизу слева, рядом с кнопкой выхода
- **Шаги:**
  1. Открыть `{BASE_URL}/board`; зафиксировать сайдбар: `sidebar = page.get_by_role("navigation")` (или контейнер сайдбара по семантическому якорю, соглашения селекторов ui-01.md).
  2. `link = page.get_by_role("link", name="Настройки")` (или button — по факту разметки; зафиксировать роль в протоколе) → виден.
  3. Геометрия (bbox-сравнение скриптом в протоколе): `link.bounding_box()` vs `page.get_by_role("button", name="Выйти").bounding_box()` — координаты Y близки (разница меньше высоты элемента), X совпадают (одна колонка).
  4. Вертикальная позиция: Y нижней границы link ≥ Y нижней границы ссылки «Доска» (раздел ниже остальных пунктов навигации).
- **Ожидаемый результат:** шаг 2 — раздел «Настройки» присутствует; шаги 3–4 — расположен внизу сайдбара, в непосредственной близости от кнопки выхода (соседство по вертикали: |Y_настройки − Y_выход| < высоты элемента + отступа, обе в одной колонке X).
- **Тестовые данные:** страница `/board`; элементы сайдбара «Настройки», «Выйти», «Доска».
