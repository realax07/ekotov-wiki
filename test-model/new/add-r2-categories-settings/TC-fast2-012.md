# TC-fast2-012 — Порядок валидации fast-дубля с невалидным приоритетом: 409 vs 422 зафиксирован

- **CHK:** CHK-138
- **Change:** add-r2-categories-settings
- **Источник:** fastline MODIFIED (FR-27; дополнение: порядок валидации, impact §4.3)
- **Тип:** граничный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200; `BASE_URL` по умолчанию `http://127.0.0.1:8080`); выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed `tests/api/conftest.py`, куки в `owner_cookies.txt`); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** существует активная fast-задача (fast line занята)
  - **WHEN** отправляется запрос создания второго fast с невалидным приоритетом (priority="low")
  - **THEN** зафиксирован ожидаемый порядок серверной проверки — ответ 409 «fast line occupied» ИЛИ 422 «fast requires high» — ожидание зафиксировано в sdd/кейсах до прогона (влияет на TC-UI-011/TC-UI-018)
- **Шаги:**
  1. Подготовка: активная fast `QAT-фаст-первая` (`is_fast:true`) → 201 (линия занята).
  2. **Проверка контракта sdd ДО прогона:** сверить `sdd.md` §3.2 / `tasks.md` пакета — в каком порядке описана валидация (fast line занятость vs priority-lock). Зафиксировать ожидаемый код `EXPECTED` (409 или 422) в протоколе ДО выполнения шага 3.
  3. `curl -s -i -b owner_cookies.txt -X POST {BASE_URL}/api/tasks -H "Content-Type: application/json" -d '{"title":"QAT-фаст-вторая-невалид","is_fast":true,"priority":"low"}'` → код и тело.
  4. Зафиксировать фактический код `ACTUAL`; сверить с `EXPECTED`.
  5. Контроль: `GET "/api/search?archived=false"` → задачи `QAT-фаст-вторая-невалид` нет.
  6. Cleanup: DELETE `QAT-фаст-первая`.
- **Ожидаемый результат:** шаг 3 — ответ либо **409** `{"error": "fast line occupied"}`, либо **422** `{"details": {"priority": "fast requires high"}}` — ОБА трактоваются как корректная серверная защита, но выбор ДОЛЖЕН совпадать с зафиксированным контрактом sdd (шаг 2) — детерминизм для web-кейсов TC-UI-011/TC-UI-018; шаг 5 — 0 совпадений (задача не создана при любом порядке проверок). Расхождение ACTUAL ≠ EXPECTED — дефект контракта sdd↔реализация, эскалация ПМ (не «подгонка» ожидания).
- **Тестовые данные:** активная fast `QAT-фаст-первая`; отклоняемая `QAT-фаст-вторая-невалид` (is_fast=true, priority="low").
