# TC-form-008 — Приоритеты различимы цветом и иконкой (форма + карточка)

- **CHK:** CHK-119
- **Change:** add-r2-categories-settings
- **Источник:** tasks: Визуал формы (FR-29) / Scenario: Приоритеты различимы цветом и иконкой
- **Тип:** позитивный | **Приоритет:** Should
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** в системе есть задачи с приоритетами low, medium, high
  - **WHEN** пользователь открывает форму задачи (список выбора приоритета) и карточки этих задач
  - **THEN** каждый приоритет визуально различается и цветом, и иконкой — в форме и на карточке
- **Шаги:**
  1. Создать три задачи: `QAT-приор-low` (low), `QAT-приор-med` (medium), `QAT-приор-high` (high) — `POST /api/tasks` ×3 → 201.
  2. Открыть `/board`; для каждой карточки: найти svg-иконку внутри бейджа приоритета (`card.locator("svg")` / `get_by_role("img")` — фактическую разметку зафиксировать); снять computed style бейджа: `evaluate("el => getComputedStyle(el).backgroundColor + ' / ' + getComputedStyle(el).color")`.
  3. Сравнить три значения стилей: попарно различны (цвет различает приоритеты).
  4. Форма: открыть форму создания; в select «Приоритет» последовательно выбрать low/medium/high — иконка приоритета присутствует/меняется (фактическую реализацию зафиксировать в протоколе).
  5. Скриншоты трех карточек приложить к протоколу.
  6. Cleanup: DELETE трех задач.
- **Ожидаемый результат:** шаги 2–3 — у бейджей трех приоритетов попарно различные цвета; svg-иконка присутствует у каждого бейджа; шаг 4 — в форме выбор приоритета сопровождается иконкой (различение и цветом, и иконкой — FR-29, оба признака). Бейдж может быть локализованным («Высокий», CHK-144) — критерий различимости, не текста.
- **Тестовые данные:** задачи `QAT-приор-low/med/high` (priority=low/medium/high).
