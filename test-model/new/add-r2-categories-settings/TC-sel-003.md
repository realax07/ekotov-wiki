# TC-sel-003 — Изменение справочника отражается в селект-полях

- **CHK:** CHK-125
- **Change:** add-r2-categories-settings
- **Источник:** search: Селект-поля из фактических данных (FR-30) / Scenario: Изменение данных отражается в селект-полях
- **Тип:** позитивный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** пользователь авторизован; в справочнике есть seed-категории
  - **WHEN** добавляется категория `QAT-sel-new-project` и пользователь обновляет форму/фильтр
  - **THEN** `QAT-sel-new-project` присутствует в обоих списках (селект-поля следуют за данными, не за статикой; кэш при введении инвалидируется при изменении справочника — design «Единый механизм»)
- **Шаги:**
  1. Открыть `/board` и `/search` — прочитать и зафиксировать опции обоих select-полей «до» (без `QAT-sel-new-project`).
  2. `POST /api/categories` name=`QAT-sel-new-project` → 201.
  3. Обновить страницу `/board` (перезагрузка), открыть форму → опции select; проверить наличие `QAT-sel-new-project`.
  4. Обновить `/search`, открыть фильтр-конструктор → опции; проверить наличие.
  5. Контроль отсутствия «застревания» (если введен кэш): без перезапуска приложения, только перезагрузкой страниц.
  6. Cleanup: DELETE категории → 200; убедиться, что после обновления страниц категория исчезла из обоих списков.
- **Ожидаемый результат:** шаги 3–4 — `QAT-sel-new-project` в обоих селект-полях после перезагрузки страниц (без перезапуска сервера); шаг 6 — после удаления категория исчезла из обоих списков — данные ведущие (FR-30).
- **Тестовые данные:** категория `QAT-sel-new-project` (создается и удаляется в кейсе).
