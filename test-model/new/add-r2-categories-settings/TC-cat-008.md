# TC-cat-008 — Негативный: создание категории с пустым названием

- **CHK:** CHK-89
- **Change:** add-r2-categories-settings
- **Источник:** categories: Управление справочником категорий (FR-20) / Scenario: Негативный: создание категории с пустым названием
- **Тип:** негативный | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200; `BASE_URL` по умолчанию `http://127.0.0.1:8080`); выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed `tests/api/conftest.py`, куки в `owner_cookies.txt`); seed справочника выполнен (CHK-139 / TC-env-001: `Дом`, `Работа`, `Личное` в справочнике до прогона).
- **Сценарий:**
  - **GIVEN** пользователь авторизован (на странице настроек)
  - **WHEN** пользователь пытается создать категорию с пустым названием и с названием только из пробелов
  - **THEN** создание отклоняется 422; категория в справочнике не появляется
- **Шаги:**
  1. `curl -s -i -b owner_cookies.txt -X POST {BASE_URL}/api/categories -H "Content-Type: application/json" -d '{"name":""}'` → код и тело.
  2. `curl -s -i -b owner_cookies.txt -X POST {BASE_URL}/api/categories -H "Content-Type: application/json" -d '{"name":"   "}'` → код и тело.
  3. `GET /api/categories` → сверить список «до» и «после».
  4. UI-контроль (если форма позволяет отправку): попытка создать пустую категорию из `/settings` → сообщение об ошибке, записи нет.
- **Ожидаемый результат:** шаги 1–2 — HTTP **422**, тело `{"error": "validation", "details": {…}}` (sdd §3.1: 422 на пустое/пробельное имя; граница «пустая строка» и «только пробелы» — оба отвергнуты); шаг 3 — справочник не изменился (новых записей нет, пустых записей нет); шаг 4 — ошибка показана, категория не создана.
- **Тестовые данные:** name=`""` (пусто) и name=`"   "` (три пробела) — обе отвергаются.
