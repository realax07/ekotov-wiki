# TC-set-006 — Состав настроек первого релиза: только управление категориями

- **CHK:** CHK-108
- **Change:** add-r2-categories-settings
- **Источник:** settings: Состав настроек первого релиза — справочник категорий (FR-25) / Scenario: В настройках доступно только управление категориями
- **Тип:** негативный (проверка отсутствия) | **Приоритет:** Must
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); Playwright (Python): `page`, `expect`; выполнен вход owner (логин `owner`, пароль `QaOwner_Pass_1!` — seed, как TC-UI-002 чеклиста e2e-critical-path); seed справочника выполнен (CHK-139 / TC-env-001).
- **Сценарий:**
  - **GIVEN** пользователь авторизован и находится на странице настроек
  - **WHEN** пользователь просматривает доступные действия на странице
  - **THEN** доступно только создание/переименование/удаление категорий; функций профиля, смены пароля, справочника тегов НЕТ (Won't релиза)
- **Шаги:**
  1. Открыть `{BASE_URL}/settings`.
  2. Проверить наличие функций категорий: элемент создания категории (поле + кнопка), действия переименования/удаления у записей списка — видны.
  3. Проверить отсутствие (обе проверки — по доступному имени и по тексту страницы): поля/кнопок с именами «Профиль», «Пароль»/«Сменить пароль», «Теги»/«Справочник тегов» — `to_have_count(0)` каждое.
  4. Дополнительно: инспекция HTML страницы на строки `password`, `profile`, `тег` — зафиксировать находки (допустимо совпадение в служебных местах, например `type="password"` у формы входа — на /settings ее быть не должно).
- **Ожидаемый результат:** шаг 2 — управление категориями присутствует и работает (детали — TC-cat-004..008); шаги 3–4 — ни одного элемента профиля, смены пароля, управления тегами (FR-25: состав ограничен справочником категорий, Won't отсутствуют).
- **Тестовые данные:** страница `{BASE_URL}/settings`.
