Источник: `test-model/checklists/add-kanban-core.md` (CHK-57…CHK-65).
Спека: `openspec/changes/add-kanban-core/specs/archive/spec.md`; контракт — `sdd.md` §3.2 (done_at), §3.3 (ленивая автоархивация), §4 (инвариант).

**Общие предусловия:** как в board-01.md (вход owner, пароль через seed). Календарная граница — МСК (UTC+3), фиксировано, независимо от TZ сервера (sdd §3.3). Текущая МСК-дата: `TZ=Europe/Moscow date +%F`; вчерашняя: `TZ=Europe/Moscow date -d yesterday +%F`.

## TC-arch-001 — Done-задача остается в «Выполнено» до конца МСК-дня
- **CHK:** CHK-57
- **Источник:** archive: «Автоархивация выполненных задач» (FR-4) / Scenario: Задача, выполненная сегодня, остается на доске до полуночи МСК
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; МСК-день D. Создана задача `Арх-сегодня`, перемещена в done.
- **Шаги:**
  1. `curl -s -b owner_cookies.txt {BASE_URL}/api/tasks/{id}` — `status`, `done_at`, `archived_at`.
  2. `GET /api/board` — расположение; открыть доску в UI повторно через несколько минут в тот же день.
- **Ожидаемый результат:** `status="done"`, `done_at` в день D, `archived_at=NULL` (инвариант sdd §4); задача в столбце «Выполнено» при каждом открытии доски в течение дня D; автоархивации «сразу после done» нет.
- **Тестовые данные:** title=`Арх-сегодня`; move `{"status":"done"}`.

## TC-arch-002 — В новый МСК-день done-задача архивируется автоматически
- **CHK:** CHK-58
- **Источник:** archive: «Автоархивация выполненных задач» / Scenario: С наступлением следующего дня МСК задача архивируется автоматически (FR-4)
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие. Задача `Арх-переход` в done с `done_at` предыдущего МСК-дня (подготовка: создать, move → done сегодня, затем `UPDATE tasks SET done_at = '<вчера>T18:00:00+03:00' WHERE title='Арх-переход';`). Доска после смещения не открывалась.
- **Шаги:**
  1. `curl -s -b owner_cookies.txt {BASE_URL}/api/board` — первое чтение доски после смены дня (ленивая автоархивация срабатывает здесь).
  2. `curl -s -b owner_cookies.txt {BASE_URL}/api/tasks/{id}` — `archived_at`, `done_at`.
  3. Обновить доску в UI.
- **Ожидаемый результат:** `archived_at` проставлен (не NULL, момент — время шага 1); `done_at` сохранен неизменным; задачи нет ни в одном столбце ответа `columns` (и в UI); из поиска по `archived=true` — доступна.
- **Тестовые данные:** title=`Арх-переход`; done_at=`<вчера>T18:00:00+03:00`.

## TC-arch-003 — Граница: done за минуты до полуночи МСК; граница — МСК, не локальное время
- **CHK:** CHK-59
- **Источник:** archive: «Автоархивация выполненных задач» (FR-4, дополнение: границы)
- **Тип:** граничный | **Приоритет:** Must
- **Метрика:** задача с done_at в 23:58 МСК дня D архивируется при первом `GET /api/board` в день D+1 по МСК; TZ сервера не влияет (проверка при TZ сервера, отличном от UTC+3).
- **Предусловия:** общие; известен TZ сервера: `date +%Z`/`timedatectl`. Вариант А (ожидание полуночи) или вариант Б (эмуляция смещением done_at, как в TC-arch-002, — допустимая замена, отметить в протоколе). Если TZ сервера ≠ UTC+3 — обязательно проверить, что граница сработала по МСК, а не по серверному полуночи.
- **Шаги (вариант А,.live):**
  1. В 23:55–23:58 МСК создать `Арх-граница` и переместить в done; зафиксировать `done_at`.
  2. Через 10 минут после 00:00 МСК: `GET /api/board`; `GET /api/tasks/{id}`.
  3. Зафиксировать: `archived_at` (не NULL?), TZ сервера (`date`).
- **Шаги (вариант Б, эмуляция):** как TC-arch-002 с `done_at = '<сегодня>D23:58:00+03:00'`; затем `GET /api/board` → архив.
- **Ожидаемый результат (порог):** `archived_at` не NULL после первого чтения доски в новый МСК-день; момент архивации соответствует МСК-границе: если локальная полночь сервера наступает раньше/позже МСК, архивация происходит именно по МСК-полуночи (сравнить `archived_at` с расчетной МСК-границей); доска в день D показывала задачу в «Выполнено» до границы.
- **Тестовые данные:** title=`Арх-граница`; done_at=`23:58` МСК дня D (либо эмуляция `D23:58:00+03:00`).

## TC-arch-005 — Перевод в done фиксирует done_at, без архивации
- **CHK:** CHK-61
- **Источник:** archive: «Архивация фиксирует момент перевода в done» (FR-4) / Scenario: Момент перевода в done зафиксирован
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; создана задача `Фиксация` (todo). МСК-день D, время T1.
- **Шаги:**
  1. `curl -s -b owner_cookies.txt -X POST {BASE_URL}/api/tasks/{id}/move -H "Content-Type: application/json" -d '{"status":"done"}'`.

- **Тестовые данные:** title=`Фиксация`; move `{"status":"done"}`; ожидаемый done_at — день D.

- **Источник:** archive: «Архивация фиксирует момент перевода в done» / Scenario: Обратный перевод из done снимает фиксацию (FR-4)
- **Тип:** позитивный | **Приоритет:** Must

- **Тестовые данные:** move `in_progress → done → in_progress`, задача `Фиксация`.

## TC-arch-007 — Повторный цикл done → В работе → done: отсчет от последнего перевода
- **CHK:** CHK-63
- **Источник:** archive: «Архивация фиксирует момент перевода в done» (FR-4, дополнение: состояние)
- **Тип:** граничный | **Приоритет:** Must
- **Предусловия:** общие; создана задача `Цикл`; известны `D1` — текущий МСК-день.
- **Шаги:**
  1. Move → done: `GET /api/tasks/{id}` → зафиксировать `done_at` = `DA1`.
  2. Move → in_progress: `done_at` стал NULL (проверить).
  3. Сместить done-момент для различимости: move → done заново; зафиксировать новый `done_at` = `DA2`.
  4. Сравнить `DA2` с `DA1`: у `DA2` момент перевода — текущий (последний), не `DA1`; затем эмуляция прошлого дня (`UPDATE tasks SET done_at='<вчера>…'`) + `GET /api/board` → задача архивируется от последнего перевода (т.е. смещенный done_at архирует; «свежий» реальный done_at — нет).
- **Ожидаемый результат:** на каждом шаге `done_at` корректен: `DA1` → NULL → `DA2`, где `DA2 ≠ DA1` и соответствует моменту второго перевода; признак архивации отсчитывается от `DA2` (последнего перевода), а не от первого: задача со свежим `DA2` не архивируется при чтении доски в тот же МСК-день.
- **Тестовые данные:** title=`Цикл`; последовательность `done → in_progress → done`; метки времени `DA1`, `DA2`.

## TC-arch-008 — Архивная задача находится поиском, карточка открывается
- **CHK:** CHK-64
- **Источник:** archive: «Доступ к архивным задачам через поиск» (FR-10, FR-4) / Scenario: Просмотр архивной задачи на вкладке поиска
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; в архиве есть задача `Арх-просмотр` с заполненными признаками (priority=`high`, category=`Дом`, тег `архив2026`, комментарий `Коммент в архиве`; подготовка — как TC-arch-002).
- **Шаги:**
  1. Открыть вкладку поиска в UI; применить фильтр (категория `Дом` или режим «все/архивные»).
  2. Найти `Арх-просмотр`, открыть карточку.
  3. API-контроль: `curl -s -b owner_cookies.txt {BASE_URL}/api/tasks/{id}`.
- **Ожидаемый результат:** задача найдена в списке поиска; карточка открывается: название, признаки (`high`, `Дом`, тег `архив2026`), комментарий `Коммент в архиве` видны; виден признак архивности (пометка «архив»/дата archived_at); API 200 с полным объектом.
- **Тестовые данные:** title=`Арх-просмотр`; priority=`high`; category=`Дом`; tag=`архив2026`; comment=`Коммент в архиве`.

## TC-arch-009 — Активные и архивные задачи в поиске различимы
- **CHK:** CHK-65
- **Источник:** archive: «Доступ к архивным задачам через поиск» / Scenario: Активные задачи не смешиваются с архивом (FR-10, FR-4)
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; есть ≥1 активная задача (`Актив-микс`, todo, тег `микс`) и ≥1 архивная (`Арх-микс`, тег `микс`, archived_at не NULL).
- **Шаги:**
  1. `curl -s -b owner_cookies.txt "{BASE_URL}/api/search?archived=all"` → в результатах есть обе.
  2. Открыть вкладку поиска в UI, поиск без ограничения (все задачи).
  3. Осмотреть отображение обеих задач.
- **Ожидаемый результат:** обе задачи в выдаче (поиск не прячет активные); каждая однозначно помечена: активная — без признака архивности, архивная — с различимым признаком архивности (бейдж/пометка/отдельная секция); спутать их по отображению невозможно.
- **Тестовые данные:** titles=`Актив-микс` (todo), `Арх-микс` (в архиве); общий тег `микс`.
