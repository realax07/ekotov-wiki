Источник: `test-model/checklists/add-kanban-core.md` (CHK-18…CHK-27).
Спека: `openspec/changes/add-kanban-core/specs/board/spec.md`; контракт — `sdd.md` §3.2, §3.3.

**Общие предусловия для всех кейсов файла:**
- Разворот и health — как в auth-01.md. Выполнен вход `owner` (пароль — через seed; см. auth-01.md), куки в `owner_cookies.txt`; где нужен второй пользователь — вход `wife`.

## TC-board-001 — Задачи отображаются в столбцах своего статуса
- **CHK:** CHK-18
- **Источник:** board: «Отображение канбан-доски» (FR-1) / Scenario: Открытие доски с задачами
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; созданы три задачи и разложены move'ом: `Доска-A` (status=todo), `Доска-B` (move → in_progress), `Доска-C` (move → done сегодня по МСК).
- **Шаги:**
  1. `curl -s -b owner_cookies.txt {BASE_URL}/api/board`.
  2. Открыть `{BASE_URL}/board` в браузере.
- **Ожидаемый результат:** API: в `columns.todo` ровно задача с title=`Доска-A`; в `columns.in_progress` — `Доска-B`; в `columns.done` — `Доска-C`; archived-задач в ответе нет. UI: каждая карточка в своем столбце, title совпадает.
- **Тестовые данные:** titles=`Доска-A`, `Доска-B`, `Доска-C`.

## TC-board-005 — Done-задача прошедшего МСК-дня отсутствует на доске
- **CHK:** CHK-22
- **Источник:** board: «Столбец "Выполнено" показывает задачи текущего МСК-дня» / Scenario: Выполненная вчера задача не видна (FR-4)
- **Тип:** негативный | **Приоритет:** Must
- **Предусловия:** общие. Задача `Вчера-Done` в done с `done_at` прошлого МСК-дня (подготовка: создать, move → done, затем `UPDATE tasks SET done_at = '<вчера>T15:00:00+03:00' WHERE title='Вчера-Done';` в SQLite), доска после этого не открывалась (ленивая автоархивация еще не срабатывала) либо archived_at уже проставлен предыдущим GET — оба варианта допустимы.
- **Шаги:**
  1. `curl -s -b owner_cookies.txt {BASE_URL}/api/board`.

- **Тестовые данные:** title=`Вчера-Done`; done_at=`<вчерашняя МСК-дата>T15:00:00+03:00`.

## TC-board-006 — Прямое перемещение по цепочке столбцов
- **CHK:** CHK-23
- **Источник:** board: «Перемещение задач между столбцами» (FR-6) / Scenario: Прямое перемещение по цепочке
- **Тип:** позитивный | **Приоритет:** Must
- **Предусловия:** общие; создана задача `Цепочка`.
- **Шаги:**
  1. `POST /api/tasks/{id}/move -d '{"status":"in_progress"}'` → проверить ответ.
  2. `GET /api/board` → задача в `in_progress`; в UI перетащить карточку «Ожидает» → «В работе» (или убедиться, что она уже там).

## TC-board-010 — Move несуществующего ID → 404, не 5xx
- **CHK:** CHK-27
- **Источник:** board: «Перемещение задач между столбцами» (дополнение: состояние, FR-8)
- **Тип:** негативный | **Приоритет:** Must
- **Предусловия:** общие; вход выполнен. Известно максимальное id задач: `sqlite3 $DB_PATH "SELECT max(id) FROM tasks;"` → `MAXID` (или заведомо отсутствующий 999999).
- **Шаги:**
  1. `curl -s -i -b owner_cookies.txt -X POST {BASE_URL}/api/tasks/999999/move -H "Content-Type: application/json" -d '{"status":"done"}'`.
  2. Повторить с `PATCH {BASE_URL}/api/tasks/999999` `-d '{"priority":"high"}'` и `DELETE {BASE_URL}/api/tasks/999999` — контроль смежных операций (см. Дефект спеки DS-3: код 404 — общепринятое ожидание, в спеке не зафиксировано; фиксирование фактического кода обязательно).
- **Ожидаемый результат:** каждый ответ — HTTP **404** (не 500/502), тело содержит `error` с сообщением о ненайденной задаче; в логах сервера нет трейсбека. Фактический код/тело зафиксировать в протоколе прогона; расхождение «не 404, но не 5xx» — эскалация ПМ (DS-3).
- **Тестовые данные:** id=`999999`; body move: `{"status":"done"}`; body patch: `{"priority":"high"}`.
