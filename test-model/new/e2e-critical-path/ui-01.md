# Тест-кейсы: E2E критический путь, домен ui (сьют Playwright)

Источник: `test-model/checklists/e2e-critical-path.md` (CHK-E-1…CHK-E-18).
Спеки: `openspec/specs/` (auth, board, tasks, fastline, navigation, search, archive) — дельты add-kanban-core слиты.
Regression-кейсы TC-UI-006/013/015 — продовые дефекты 2026-09-19 (фикс: коммит 79ceb7b «modals hidden on load + guard comment submit without task»).

## Общие предусловия и соглашения (для всех кейсов)

**Окружение:**
- Приложение развернуто и готово: `GET {BASE_URL}/api/health` → 200 `{"status": "ok"}`. `{BASE_URL}` — из env `EKOTOV_WIKI_BASE_URL`, по умолчанию `http://127.0.0.1:8080` (как в `tests/api/conftest.py`).
- Часовой пояс проверок — МСК (UTC+3): текущая МСК-дата `D` = `TZ=Europe/Moscow date +%F`, вчерашняя `D-1` = `TZ=Europe/Moscow date -d yesterday +%F`.
- Playwright (Python): `page`, `expect`. Сетка: перед шагами подписаться на запросы (`page.on("request")`) там, где кейс требует «запрос не уходит».
- Диалоги `window.confirm` (удаление задачи) — авто-принятие: `page.on("dialog", lambda d: d.accept())`.

**Seed и учетные данные (тестовые, без секретности — `tests/api/conftest.py`, NFR-7):**
- Пользователи заведены seed-скриптом `backend/app/seed_users.py`: логины `owner` (владелец) и `wife` (жена), ровно 2 (NFR-4).
- Пароли: `owner` / `QaOwner_Pass_1!`, `wife` / `QaWife_Pass_2!` (env-переопределение: `EKOTOV_WIKI_OWNER_PASSWORD`, `EKOTOV_WIKI_WIFE_PASSWORD`).
- DB-крюк (кейсы TC-UI-017, TC-UI-018): путь SQLite-БД приложения из env `EKOTOV_WIKI_DB_PATH` (без переменной кейсы пропускаются — skip, ограничение окружения; прямая правка БД вне процесса приложения иначе невозможна).

**Изоляция данных:** каждая тестовая задача создается через UI с уникальным названием из кейса; названия фиксированы (см. данные кейсов), префикс не требуется — сьют прогоняется на чистой тестовой БД (после прогона — очистка через API `DELETE /api/tasks/{id}` по списку созданных ID).

**Соглашения по селекторам (обязательны для автоматизатора):**
1. Рольные/семантические — основной инструмент: `page.get_by_role("button", name="...")`, `page.get_by_label("...")`, `page.get_by_text("...")`, `page.get_by_role("heading", name="...")`, `page.get_by_role("alert")`, `page.get_by_role("article")`.
2. `data-*`-атрибуты — контракт разметки приложения (аналог test-id): столбцы доски `page.locator('[data-status="todo"]')` / `in_progress` / `done`; контейнер карточек внутри столбца — `[data-cards]`. Эквивалент `get_by_test_id` при настройке `testIdAttribute`.
3. ID-локаторы (`#task-form-overlay` и т.п.) — только там, где рольного селектора не существует по природе элемента: скрытые (`hidden`) модалки не имеют ARIA-роли. Это стабильные semantic-якоря шаблона, НЕ хрупкие class/XPath.
4. Запрещены: селекторы по стилевым классам (`.modal-overlay`, `.task-card`), XPath, цепочки `div > p > span`.
5. Исключение по факту реализации: подсветка fast line ставится JS-классами `has-fast` / `task-card-fast` (board.js, FR-3); значение цвета спекой не зафиксировано (Дефект спеки №3 чеклиста E2E) — в TC-UI-010 факт подсветки фиксируется проверкой этих классов как наблюдаемого DOM-состояния, визуальный скриншот — приложением к протоколу.

**Дефект 2026-09-19 — контекст regression-кейсов (дословно, из истории прод-инцидента):** при загрузке `/board` оверлеи модалок (`.modal-overlay`) были ВИДИМЫ поверх доски: авторский `display:flex` в CSS побеждал атрибут `hidden`. Через «висящие» без карточки контролы уходили запросы на несуществующий ресурс: `POST /api/tasks/null/comments` и `POST /api/tasks/null/move` → 422 `int_parsing`, доска ломалась. Фикс 79ceb7b: CSS `[hidden]{display:none!important}` + guard `isValidTaskId` в `submitComment` / `moveCurrentTask` / `openTaskDetail`. Кейсы TC-UI-006/013/015 проверяют недостижимость всех трех путей.
