- **Предусловия:** nginx-стенд :18443 (app + search + images), merge-ветка со всеми волнами; сессия owner; в томе images-data загружено ≥1 изображение фикстурой QAGAL- (upload через `POST /api/images`, _upload_api-прецедент test_qa21_gallery_ui.py); зафиксированы до rename: filename/thumb_name из GET /api/images/{id}, URL `/images/<filename>`, байты файла из тома
- **Шаги:**
  1. `PUT /api/images/<id>/name` с телом `{"name": "QAGAL-Дача лето"}` — зафиксировать код и тело ответа.
  2. `GET /api/images/<id>` и `GET /api/images` (список) — найти изображение по id.
  3. Сравнить метаданные до/после: original_name/name, filename, thumb_name, url, created_at, mime.
  4. `GET /images/<filename>` — сверить код 200 и байты с зафиксированным оригиналом тома; параллельно `GET /images/<thumb_name>`.
  5. Повторный `PUT` с тем же именем (идемпотентность) — код и состояние.
- **Ожидаемый результат:** шаг 1 — 200, в теле `{"id", "name", …}` с новым именем; шаг 2 — новое имя в detail-ответе И в элементе списка; шаг 3 — filename/thumb_name/url/mime/created_at НЕ изменились (меняется только отображаемое имя); шаг 4 — `/images/<filename>` отдает тот же оригинал по прежнему пути (ссылки и кеш не инвалидированы); шаг 5 — повторный rename не создает дублей/побочных эффектов.
