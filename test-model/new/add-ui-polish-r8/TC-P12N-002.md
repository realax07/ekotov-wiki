# TC-P12N-002 — сайдбар: клики по разделам не перекрыты иконками (elementFromPoint на центре .nav-item)

- **Change:** add-ui-polish-r8
- **Источник:** navigation (MODIFIED): Scenario «Иконки у всех разделов сайдбара в едином стиле» + «Порядок разделов, их адреса и состояния MUST NOT меняться» (FR-94); CHK-P12-18 (16px-иконка внутри .nav-item не ломает переходы)
- **Тип:** ФТ, web/стендовый, поз./НФТ | **Приоритет:** Must
- **Маркер:** автотест (playwright, nginx-стенд, прогон R3) — new-кейс; complement TC-P12N-001 (стиль) — здесь интерактивность
- **Предусловия:** стенд поднят; сессия owner; волна 2.4 в merge-ветке
- **Шаги:**
  1. Открыть `/board`. Для каждого `.nav-item` (Доска, Поиск, Wiki, Галерея, Настройки) выполнить `document.elementFromPoint(centerX, centerY)` по центру bbox пункта: элемент — сам `<a>` или его потомок (svg/span-текст), а НЕ элемент другого слоя (оверлей, бейдж соседа, содержимое `.content`).
  2. Клик по центру каждого пункта → навигация на целевой адрес (`/board`, `/search`, `/wiki`, `/gallery`, `/settings`), URL и заголовок страницы соответствуют разделу (паритет TC-nav-007/TC-UI-016).
  3. Отдельно для Wiki: клик по зоне бейджа `todo` и по зоне иконки — переход происходит (иконка/бейдж не перехватывают клик мимо ссылки).
  4. Ховер/фокус-клавиатурой (Tab до пункта, Enter) — переход работает, focus-visible виден; тултипы не задеты (keep TC-tip-101…108 вне кейса, здесь — smoke одного пункта).
- **Ожидаемый результат:** elementFromPoint в центре каждого пункта возвращает элемент пункта (или его потомка) — клики не перекрыты новыми svg-иконками; все разделы открываются по клику и с клавиатуры; адреса и состояния разделов не изменились (MUST NOT по FR-94).
