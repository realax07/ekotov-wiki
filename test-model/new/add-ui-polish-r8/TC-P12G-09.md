# TC-P12G-09 — masonry FR-98 (Won't-часть): break-inside семантика — карточка НЕ разрывается между колонками, хвосты разной высоты колонок допустимы

- **Change:** add-ui-polish-r8
- **Источник:** gallery (ADDED): «Сетка галереи…» (FR-98) — «ячейки выровнены по единому макету»; design §1 J (masonry-колонки CSS: columns/break-inside техника); CHK-P12-25/26 (механика ритма)
- **Тип:** НФТ, web/e2e, поз. | **Приоритет:** Must
- **Маркер:** new (ветка 2.6 #52); REPORT-3.1 — прогон R4, nginx-стенд
- **Предусловия:** как TC-P12G-07; открыто `/gallery` в masonry при ширине 4-колоночного брейкпоинта
- **Шаги:**
  1. Computed Style каждой `.g-card`: `break-inside: avoid` (или эквивалент `page-break-inside`/grid-раскладка — фактическую технику masonry из dev-ветки зафиксировать в REPORT: CSS columns vs flex-колонки vs JS).
  2. Инвариант целостности: для каждой карточки bbox.width ≤ колонки, карточка целиком внутри одной колонки (ни одна не «перешивает» две колонки), вертикальных разрывов внутри карточки нет.
  3. Высоты колонок: при 10 разнопропорциональных карточках высоты колонок не обязаны сравняться (masonry-семантика) — фиксировать разброс; ассерт только на отсутствие визуального «провала» (низ сетки без пустой колонки высотой > 2× средней карточки).
  4. Ленивые превью (`loading="lazy"`): прокрутка сетки вниз — появляющиеся карточки не сдвигают уже выровненные (или сдвиг допустим только на высоту placeholder'а — зафиксировать факт и сопоставить с мокапом).
- **Ожидаемый результат:** карточки атомарны (break-inside семантика соблюдена выбранной техникой), ни одна карточка не разрывается между колонками; разброс высот колонок — в рамках masonry-семантики мокапа J; lazy-загрузка не порождает «прыжков» ритма, ломающих выравнивание.
