# TC-P12G-003 — rename файла, валидация 422: пустое/отсутствующее/пробельное имя, граница 255, разделители в имени

- **Change:** add-ui-polish-r8
- **Источник:** gallery (MODIFIED): «Full-screen просмотр» (FR-97) — Scenario «Негативный: пустое имя переименования отклоняется»; спека дельты «непустое имя ≤255 символов (422 при пустом или отсутствующем)»; design §4 (422 также >255, валидационный обработчик паритет ядру); CHK-P12-21 (гран.)
- **Тип:** ФТ, API, нег./гран. | **Приоритет:** Must
- **Маркер:** new (ветка 2.5); REPORT-3.1 — прогон R4, nginx-стенд с images
- **Предусловия:** стенд поднят; сессия owner; изображение QAGAL- загружено; исходные filename/URL зафиксированы (контроль неизменности файлов на каждом негативе)
- **Шаги:**
  1. `PUT /api/images/<id>/name` с телом `{"name": ""}` — код.
  2. `PUT` без поля name в теле (`{}` / пустое тело) — код.
  3. `PUT` с именем только из пробелов `"   "` — код (трактовка по спеке «непустое»: пробельное = пустое; факт зафиксировать в REPORT).
  4. Граница: `PUT` с именем ровно 255 символов — код; затем 256 символов — код.
  5. Разделители: `PUT` с именами `"QAGAL-подкаталог/имя"`, `"QAGAL-обратный\\имя"`, `"  QAGAL-пробелы по краям  "` — коды; после каждого — `GET /api/images` и `GET /images/<filename>`.
  6. После каждого отклоненного шага — `GET /api/images/<id>`: имя прежнее.
- **Ожидаемый результат:** шаги 1–3 — 422 (валидационный обработчик сервиса, тело `{"error", "details"}`); шаг 4 — 255 символов принимается (200), 256 — 422 (граница по спеке); шаг 5 — разделители `/` `\` хранятся как литералы отображаемого имени (200, original_name — текст), filename/thumb_name и `/images/…` НЕ интерпретируются и не меняются (имя — не путь); шаг 6 — после каждого 422 имя в API не изменилось (no partial write).
