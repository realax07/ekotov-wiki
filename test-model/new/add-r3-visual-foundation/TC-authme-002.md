# TC-authme-002 — GET /api/auth/me: 401 без сессии и с истекшей сессией

- **CHK:** CHK-149
- **Change:** add-r3-visual-foundation
- **Источник:** auth: «API текущего пользователя» (FR-33, NFR-7); Сценарий «Негативный: без сессии — 401»
- **Тип:** нег. | **Приоритет:** Must
- **Среда/предусловия:** тестовый стенд tests/api; для шага 2 — `EKOTOV_WIKI_DB_PATH` (прямой сдвиг expires_at в БД; без переменной шаг 2 пропускается, шаг 1 обязателен).
- **Шаги:**
  1. Свежая requests-сессия БЕЗ куки: `GET /api/auth/me`.
  2. Войти owner; в БД выполнить `UPDATE sessions SET expires_at = '2000-01-01T00:00:00+00:00' WHERE token = <токен куки>`; повторить `GET /api/auth/me` той же сессией.
  3. Повторная сверка шага 1: заголовки ответа `GET /api/auth/me` без сессии (проверка относится к шагу 1; шаг 2 на нее не влияет).
- **Ожидаемый результат:** шаг 1 — 401, тело ТОЧНО `{"error": "unauthorized"}`; заголовка `Set-Cookie` нет — усиление сверх CHK-149 (дополнение автора кейса, не требование чеклиста), проверяется в шагах 1 и 3; шаг 2 — 401 с тем же телом (просроченная сессия не принимается; эндпоинт вне exempt-списка, NFR-7).
- **Тестовые данные:** SQL-условие по токену куки сессии owner; просроченная метка `2000-01-01T00:00:00+00:00`.
