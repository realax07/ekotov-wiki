# TC-nav-103 — При 401 /api/auth/me блок профиля не отображается

- **CHK:** CHK-153
- **Change:** add-r3-visual-foundation
- **Источник:** navigation: «Профиль…внизу сайдбара» (FR-33; tasks.md 1.2 «при 401 блок не отображается»; код-ревью 1.2 №2); дополнение чеклиста (нег.)
- **Тип:** нег. | **Приоритет:** Must
- **Среда/предусловия:** web-стенд tests/web; вход owner с ВАЛИДНОЙ сессией; открытая страница /board.
- **Доработка по review-001 №1:** одна детерминированная ветка — 401 подмешивается перехватом маршрута, навигация middleware не мешает.
- **Шаги:**
  1. Войти owner, открыть /board, дождаться `data-loaded=true` и класса `profile-filled` у `#sidebar-profile` (блок был видим — позитивный фон).
  2. Подменить ТОЛЬКО ответ профиля: `page.route("**/api/auth/me", fulfill(status=401, body='{"error":"unauthorized"}', content_type="application/json"))` — сервер и middleware не затронуты, страница остается на /board.
  3. Перезагрузить /board (та же сессия); дождаться `data-loaded=true`; перехват гарантирует, что `fetch` профиля получил 401.
  4. Прочитать class у `#sidebar-profile`; собрать сообщения консоли страницы.
- **Ожидаемый результат:** fetch /api/auth/me получил 401 (перехват подтвержден маршрутом); у `#sidebar-profile` НЕТ класса `profile-filled` — блок скрыт CSS-ом (не отображается); ошибок в консоли нет (молчаливое скрытие — дизайн, код-ревью 1.2 №2).
- **Тестовые данные:** перехват маршрута `**/api/auth/me` → 401 `{"error": "unauthorized"}`; login `owner` / `QaOwner_Pass_1!`.
