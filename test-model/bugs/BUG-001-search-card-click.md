# BUG-001 (CLOSED 2026-09-20: fix f6baa75 merged, deployed): клик по карточке в результатах поиска не открывает карточку задачи

- **ID:** BUG-001
- **Кейс:** TC-UI-017 (CHK-E-17; approved/e2e-critical-path/ui-01.md, review-002 approve)
- **Дата:** 2026-09-19
- **Обнаружено:** автотест `tests/web/test_navigation_search_ui.py::test_search_archived_task_builder_advanced_card`, шаг 7

## Кейс (шаг 7, дословно)

«Открыть карточку архивной задачи: клик по карточке `Архивная-поиск` в результатах».

Ожидаемый результат кейса: «карточка архивной задачи открывается с признаками
(приоритет `high`, категория `Дом`, тег `архив2026`, бейдж „Архивная“)» —
FR-10 / CHK-E-17: «карточка архивной задачи открывается с признаками».

## Ожидание

После клика по карточке задачи в `#search-results` открывается модалка карточки
задачи (`#task-detail-overlay` виден, заголовок «Архивная-поиск», бейдж
«Архивная», атрибуты).

## Факт

Клик по карточке ничего не делает: модалка `#task-detail-overlay` не появляется
(`to_be_visible()` — 14 попыток, element not found), страница `/search` остается
в неизменном состоянии (aria-снимок в логе теста: карточки в результатах есть —
`high Архивная / Архивная-поиск / Дом архив2026`, — но открытия нет, ошибок в
консоли нет).

## Причина (по коду продукта, кейс-наблюдение ревьюера подтверждено)

`frontend/static/js/search.js`, `renderCard()` (строки 138–170): карточка
(`article.task-card`) строится и добавляется в `#search-results`, но
**click-обработчик на карточке не вешается** — в отличие от `board.js`
`renderCard()` (строка 199: `card.addEventListener("click", function () {
openTaskDetail(task.id); })`). В `search.js` нет ни делегирования клика на
`#search-results`, ни прямых обработчиков карточек; модалка карточки задачи
(`#task-detail-overlay` из board.html) на странице `/search` вообще не
размечена — открытие карточки из поиска невозможно в принципе текущей
реализацией.

## Окружение

- Локальный тест-стенд: uvicorn app.main:app (свободный порт) + статика
  (frontend/static, python -m http.server) — топология «nginx → app» воспроизведена;
  playwright headless chromium 153 (playwright 1.63.0), пустая seed-БД
  (owner/wife), SQLite.
- Прогон: `pytest tests/web` — 17 passed, 1 failed (этот).

## Статус

Дефект воспроизводится детерминированно (3 прогона подряд, падение на одном
шаге). Тест написан по кейсу дословно, код теста под дефект не подгонялся —
падение законно фиксирует невыполнение FR-10/CHK-E-17.
