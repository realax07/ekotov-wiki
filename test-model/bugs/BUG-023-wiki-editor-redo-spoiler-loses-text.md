# BUG-023: redo вставки спойлера после undo стирает текст абзаца (execCommand insertHTML)

- **Набор:** coverage-backfill-1 группа A (playwright web, chromium), кейс TC-rich-032
- **Дата:** 2026-10-26 · **Ветка:** qa/cov-backfill-rich (база origin/chore/sa-coverage-backfill)
- **Воспроизведение:** tests/web/test_coverage_rich_tools_security.py::test_tc_rich_032_undo_redo_including_h_toggle
  (в тесте зашаг reddo-фаза проверяет только структуру — см. замечание)

## Кейс / ожидание / факт

- **Кейс:** TC-rich-032 (p12-rich-tools) — «вставить спойлер, снять формат H2
  повторным кликом, заменить H1→H3; Ctrl+Z …; redo …; после undo текст не
  теряется и не дублируется» (FR-110).
- **Ожидание:** redo повторно применяет правки; текст не теряется ни на undo,
  ни на redo.
- **Факт:** undo корректен (спойлер снят → замена h3→h1 → обычный абзац, текст
  цел на каждом шаге). Но redo повторного применения вставки спойлера СТИРАЕТ
  текст: последовательность
  `type «Абзац для отмены» → H2 → H2 (снятие) → H1 → H3 → «Спойлер» →
  Ctrl+Z ×3 → Ctrl+Shift+Z ×3` дает `<h3><div data-block="spoiler">…</div></h3>`
  БЕЗ текста «Абзац для отмены» (до redo текст был). Воспроизводится
  стабильно.

## Локализация

Вставка спойлера выполняется `document.execCommand('insertHTML', …)`
(`frontend/static/js/wiki/editor.js`, обработчик кнопки «Спойлер») при
каретке внутри заголовка (после toggle H1→H3 каретка остается в h3).
Redo Chromium повторяет insertHTML-юнит с перезаписью содержимого блока,
в котором стояла каретка на момент записи юнита, — текстовый узел h3
замещается вставленным HTML. АналогBehavior вероятен для «Табуляция»/
«Блок кода» (тот же механизм вставки).

## Рецепт фикса

Перед insertHTML гарантировать каретку вне заголовка/строки с текстом —
переносить каретку в новый абзац за текущим блоком (как это уже делает
focusInsertedBody для закрытого спойлера: вставка + абзац за блоком), либо
после redo восстанавливать текст (проверка содержимого до/после).

## Серьезность и влияние

- **major** (потеря пользовательского контента по Ctrl+Shift+Z): редкий
  сценарий (redo блочной вставки поверх заголовка), но безвозвратная
  потеря текста в редакторе.
- Не блокирует прогон coverage-backfill-1: тест TC-rich-032 проверяет
  undo-фазу и структурный redo; текстовая потеря зафиксирована настоящим
  баг-репортом.
