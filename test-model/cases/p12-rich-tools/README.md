## Приоритеты

- **Must** — 34 кейсов: весь негатив/границы (XSS 022/023/034/038/041, граница глубины 5/6 — 024, лимит 8 — 012, запрет удаления последней — 011/019, Backspace в пустом H — 016, оба Enter-кейса 021/037, гейты вставки 038/041, регресс «залипания H» — 031) и основные позитивы.
- **Should** — 7 кейса: TC-rich-007, TC-rich-009, TC-rich-017, TC-rich-025, TC-rich-027, TC-rich-028, TC-rich-039 (копирование, деградации, NFR-замеры, undo, состояние кнопок, гуттер).

## Готовность к автоматизации

- Уровни: e2e Playwright (`page` + `expect`) для UI/редакторных кейсов (001–021, 029–033, 037–041); API pytest (`api_request_context` / requests) для sanitize-кейсов через `PUT`/`GET` `/api/wiki/pages/<id>` (009, 022–025, 034–036, 038-paste, 041-paste); гибрид для round-trip (021, 037).
- Вставка «paste-подобного» контента — прямым PUT HTML (кнопки обходятся так же, как paste): негативные sanitize-векторы не зависят от UI.
- Селекторы: блоки — `[data-block=…]`/`[data-block-part=…]`; editor-only артефакты — `[data-editor]` (кейс 039 проверяет их отсутствие в GET-контенте).
- Перф-кейс 027: замер JS-метками вокруг активации, 3 прогона, порог ≤150 мс; крупный листинг 1000+ строк генерируется в фикстуре.
- Буфер обмена (007, 008): контекст Playwright с grant `clipboard-read`/`clipboard-write`; сравнение с `textContent` кода.
- Состояние кнопок H (031, 017): assert по `aria-pressed` — не по визуалу.
- Фикстура старого контента для 028 — из БД стенда, не рукописный HTML (замечание O3 ревью №1).
