- **Change:** weather-service
- **Источник:** weather-service: «Кэш 60 минут» (атомарная запись; негатив по записи кэша)
- **Тип:** негативный | **Приоритет:** Should
- **Среда/предусловия:** поднятый стенд (`GET {BASE_URL}/api/health` → 200); owner `owner/QaOwner_Pass_1!`, второй пользователь `pe/QaPe_Pass_1!` (seed); Playwright (Python): `page`, `expect`, `api_request_context`; unit/integration-уровень: `services/weather` pytest с httpx.MockTransport (провайдер мокается, т.к. - **Шаги:**
  1. Сделать кэш-путь недоступным для записи: `EKOTOV_WEATHER_CACHE_PATH` в ro-каталог (или каталог-файл вместо dir).

  3. Проверить лог сервиса и повторный запрос.
- **Ожидаемый результат:** ответ пользователю — успешный 200 со свежими данными провайдера (`stale: false`); сбой записи кэша проглатывается (warning в логе «cache write failed», нет 500/трассировки); повторный запрос снова идет к провайдеру (кэш не появился) — сервис не впадает в ошибку.
- **Тестовые данные:** env-путь кэша в read-only каталог; mock-провайдер.
