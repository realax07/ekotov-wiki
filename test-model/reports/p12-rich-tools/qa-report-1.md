## Дефекты (эскалация, код не правлю)

### D1 — TC-rich-040 (Must): Escape в инлайн-rename спойлера коммитит вместо отмены + JS-ошибки в гонке Escape/blur

- **Репро (редактор):** вставить спойлер → клик по названию → ввести «Черновик» → **Escape** → название становится «Черновик».
- **Ожидание (кейс/фикс F-3):** Escape отменяет правку — название остается исходным («Спойлер»), input закрыт.
- **Факт (автотест web::040):** title после Escape = `'Черновик'` (коммит). Дополнительно в гонке Escape→blur: title = `'Гонка'` (результат недетерминирован, input закрыт), и в консоли **4 pageerror**: `Failed to execute 'replaceChild' on 'Node': The node to be removed is no longer a child of this node. Perhaps it was moved in a 'blur' event handler?`
- **Серьезность:** major (функциональное отклонение от ОВ кейса + повторяемые JS-ошибки консоли; данные не теряются — NFR-39 по тексту соблюден).
- **Затронуто:** frontend/static/js/wiki/rich/spoiler.js (обработчики rename/blur); фикс-раунд review-001 F-3 закрывает rename-гейт статьи (эта часть PASS: в статье клик по названию = toggle, input не открывается), но ветка Escape в редакторе — нет.

### D2 — TC-rich-041 (Must): нет гейта вставки таблицы в ячейку таблицы (матрица design §6: ячейка×таблица = НЕТ)

- **Репро (редактор):** вставить таблицу → каретка в ячейку → тулбар «Таблица» → в DOM ячейки появляется вложенная `<table>` (count=1).
- **Ожидание:** вставка игнорируется/кнопка недоступна (матрица §6; аналог гейта код-блока из design-check #6 — он работает, TC-rich-038 PASS).
- **Факт:** редактор показывает вложенную таблицу; при сохранении санитайзер unwrap'ивает её целиком корректно (paste-путь, api::041: `<td>A1<br>B1</td>`, повторный round-trip идемпотентен) — т.е. расхождение «редактор показал ≠ сохранилось» (тот же класс, что design-check #6 для кода).
- **Серьезность:** major (нарушение инварианта матрицы §6 в редакторе; потери данных нет — sanitize спасает).
- **Затронуто:** frontend/static/js/wiki/rich/tabletools.js / editor.js (гейт блоковых вставок при каретке в td).

## Наблюдения (факты, не дефекты)

1. **Кнопки «−» таблицы удаляют строку/столбец КАРЕТКИ** (проба: каретка в tbody tr0 → удалена tr0). Комментарий dev-теста «delRow удаляет строку ПОД кареткой» неточен; на кейсы не влияет — тест целит кареткой в добавленные строку/столбец.
2. **Enter после заголовка создает `<div>`, не `<p>`** (факт DOM); на сохранение/кейсы не влияет.
3. **Подсветка листингов > 64 КБ деградирует в plain** (`MAX_HIGHLIGHT_BYTES`, by design NFR-40); лексер на 1200-строчном листинге — 23 мс (прямой замер `highlight()`).
4. Обновление aria-pressed H-кнопок асинхронно (selectionchange) — мгновенное чтение сразу после клика может вернуть старое состояние (~до 100 мс).
5. В предусловиях кейсов указан второй пользователь `pe/QaPe_Pass_1!` — в сиде стенда его нет (owner/wife); кейсы второго пользователя не требуют, не влияет.
