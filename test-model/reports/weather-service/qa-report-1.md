## Эскалации / примечания

1. **E-QA-1 (инфраструктура стенда, не продуктовый код) — устранено в ходе прогона.** На момент начала проверки порты 8080 (ядро) и 8381 (weather) обслуживали зависшие процессы из **удаленного** worktree `/tmp/wt-wdesign` (cwd процессов → `/tmp/wt-wdesign/... (deleted)`), стартованные в 16:44–16:46, без шаблона `weather.html`: `GET /weather` отдавал `500 Internal Server Error` (лог ядра: `jinja2.exceptions.TemplateNotFound: 'weather.html' not found in search path: '/tmp/wt-wdesign/frontend/templates'`). Стенд «уплыл» от main — вероятно, leftover чужой волны перехватил порты до/вместо reset.sh. **Репро:** поднять процесс с cwd другого worktree до запуска reset.sh — health зеленый, а страницы/код чужие; pid-файлы при этом могут указывать на мертвые процессы (у search/images/video pid-файлы после reset.sh не соответствуют живым процессам — см. п.2). **Лечение:** `bash /tmp/vh9-stand/reset.sh` — перезапустил из main; далее все кейсы гнали на коде main (cwd процессов проверен: `/home/openclaw/ekotov-wiki/...`). **Рекомендация:** в reset.sh добавить проверку cwd слушателей портов перед health-пробами (или `pkill -f` по полному паттерну до старта).
2. **Мелочь стенд-скриптов:** после reset.sh pid-файлы `search.pid/images.pid/video.pid` указывают на несуществующие pid (setsid-двойной форк), фактические процессы (2366216–218) живут и работают из main. Не влияет на вердикты; на будущее для скриптов стопа.
3. **Подтверждена эскалация dev-волны 3 (E1):** у живого Open-Meteo нет daily-поля `wind_direction_10m_max` (код шлет `wind_direction_10m_dominant`); данные на стенде корректны. Термины design/spec — на правку ПМ/архитектору (вне QA).
4. Адаптации прогона (процессный стенд вместо docker, второй пользователь `wife` вместо отсутствующего в сиде `pe`) — см. раздел «Адаптации среды»; на выводы кейсов не влияют, кроме оговорки в TC-012/020/024 про docker-специфику.
