## Дефекты спеки

Не найдены. Замечания вне дефектов:

1. **Трассировочная дыра закрыта этим чеклистом.** В `requirements-p4.md` §3 FR-17 отнесен к TC-API-SUGG-005, который по impact-анализу (п.1) проверяет только объединение источников (СЦ-5); сценарии 6–7 не имеют собственного TC. CHK-S-6…9 — целевые пункты для новых TC в цикле 1.5 (qa_author → qa_automation).
2. **Замечание к ФР-таблице requirements-p4.md (не дефект спеки):** в §2 «Сценарии» перечислены только СЦ-1…5, а дельта спеки содержит 8 сценариев (СЦ-6…8 спеки = сценарии 6, 7 и datalist не отражены в ТЗ). Источник истины — дельта спеки; чеклист построен по ней.
3. **Наблюдение по формулировке FR-17 «новые значения не создаются»:** спека не уточняет, что происходит при свободном вводе значения вне подсказок в поле с datalist (datalist не запрещает произвольный ввод). CHK-S-7 проверяет создание через API-сторону (значение не появляется в источнике подсказок); поведение свободного ввода на фильтр зафиксировано в impact-анализе как design («свободный ввод сохранен», FR-11) — противоречия нет, но qa_author'у при развертке TC рекомендуется зафиксировать ожидаемый результат по этому случаю явно.
