## Дефекты спеки и эскалации (не блокируют чеклист; решение — ПМ/Заказчик)

1. **(а) fastline: явный null vs отсутствие поля.** Текст сценария «fast с приоритетом low/medium/или NULL → 422» против входа «fast без priority → high». Чеклист пишет оба случая раздельно (CHK-130 явный null → 422; CHK-134 отсутствие поля → автоподстановка high), но трактовку нужно зафиксировать в sdd/tasks до написания новых TC — иначе негативный TC на null невоспроизводим. Связано: порядок проверки 409 vs 422 (CHK-138, impact §4.3).
2. **(б) Источник категорий в /api/suggestions** после внедрения справочника дельтой не определен (значения задач vs справочник). Чеклист (CHK-112, CHK-142) написан по текущей реализации — подсказки из тегов+категорий задач (sdd §3.2: «GET /api/suggestions — без изменений»); пометка «уточнить в sdd». Если при реализации переведут категории подсказок на справочник — CHK-112/142 и TC-API-SUGG требуют внепланового revalidate.
3. **(в) Конфликт спек пакетов:** сценарий 7 спеки add-suggestions (свободный ввод легитимен) для поля «Категория» противоречит спеке справочника (FR-19: произвольный текст не допускается). Чеклист пишет по доменам: в ФОРМЕ задачи свободный ввод легитимен (CHK-115 — теги; категория формы — select, CHK-82); в поиске — только выбор (CHK-143). Сценарий 7 старой спеки сузить до поля «Теги» — решение ПМ/Заказчика.
