# PLAN-REDESIGN-UI-A — Редизайн интерфейса по направлению A «Доска и поток»

Заказчик утвердил направление A (бордо/золото, тёмная, PT Serif/Golos, округлая 10/18/28)
из дизайн-конвейера wd-forge. Мокапы утверждены («Первый давай» + «По макету ок», правки
по отступам/masonry/счётчикам внесены). Дизайн-контекст: `design-context/GUIDE.md`,
эталонные мокапы: `design-forge/a/`, `design-forge/extra/{wiki,gallery,video}/`.

## Флоу: 1 (полный — БА → СА → dev → QA → code-review → regress)

Редизайн главной рабочей страницы и трёх контентных разделов — полный цикл с QA-сабагентами.

## Состав

- **Страницы**: board (канбан + фастлайн), task (карточка), wiki, gallery, video
- **Характер работ**: рестайлинг через CSS-токены направления A; DOM/классы/data-атрибуты
  существующих страниц сохраняются (ОГР-28, стабильность селекторов тестов) —
  визуальный слой переписывается, функционал JS не трогается
- **Темы**: тёмная базовая + светлая (`data-theme="light"`), переключатель в base.html
- **Тесты**: инвентаризация затронутых визуальных ассертов; правка только визуальных
  ожиданий; функциональные тесты должны остаться зелёными без изменений логики

## Волны

- **Волна 0** — ветка `feat/redesign-ui-a`, коммит дизайн-артефактов (design-context,
  design-forge, этот план)
- **Волна 1 (БА)** — requirements: список сохраняемого функционала (все FR доски:
  fastline-гейт, dnd, валидация формы, комментарии), маппинг «деталь мокапа →
  существующий элемент DOM», инвентарь тестов с визуальными ассертами
- **Волна 2 (СА)** — sdd: CSS-архитектура (tokens.css по design-context поверх
  существующих переменных; что правится в app/board/gallery/wiki CSS; переключатель
  темы в base.html; точки правки JS — только если рендер требует новых классов)
- **Волна 3 (dev)** — вёрстка по wd-fit: board+base (приоритет), затем wiki/gallery/video;
  проверка в браузере обеих тем на 1440/768/390 после каждой страницы
- **Волна 4 (QA)** — прогон tests/web, правка визуальных ассертов, браузерные сверки
  с эталонными мокапами, regress-final
- **Волна 5** — code-review, merge

## Ограничения

- Селекторы тестов (классы/id/data-*) не менять без необходимост — приоритет: CSS-токены
- Секреты/данные — без изменений; API не трогается
- Контент мокапов (тексты задач/статей) в прод не переносится — это примеры

## Критерии готовности

- Все страницы соответствуют design-context (browser-проверка wd-fit) в обеих темах
- tests/web зелёные (с правками только визуальных ассертов)
- regress-final PASS
