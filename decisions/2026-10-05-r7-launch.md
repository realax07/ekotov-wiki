# Решение Заказчика: запуск R7 — Netdata-мониторинг и Галерея

## Контекст

После закрытия релиза add-microservices-full (решение
2026-10-05-release-microservices-full) Заказчик запускает следующий цикл
разработки (план PLAN-R7.md) — два change-пакета Флоу 1:

1. **add-netdata-monitoring** — мониторинг железа/контейнеров/сервисов в
   Netdata; ссылка в сайдбаре wiki (низ, слева); доступ — только учетка owner.
2. **add-gallery-service** — ЧЕТВЕРТЫЙ раздел сайдбара «Галерея»: сервис
   изображений с категориями и тегами; full-screen просмотр с листанием,
   лайк/дизлайк, скачивание, комментарии; доступ общий. Связь с трекером —
   только общий фронт сайдбара.

## Что решено

1. Цикл R7 запущен: оба пакета идут Флоу 1 (полный: SA → dev → QA → приемка).
2. Действие `create_change` (старт пакета SA) для обоих change-id
   (`add-netdata-monitoring`, `add-gallery-service`) разрешено; approval_ref
   стартовых делегаций SA = `2026-10-05-r7-launch`.
3. Вводные зафиксированы в PLAN-R7.md (f055263): ОВ-1 = Netdata (вариант в),
   ОВ-2 = доступ только owner, ОВ-3 = Галерея 4-й раздел сайдбара (full-screen,
   лайк/дизлайк, скачивание, комментарии), ОВ-4 = доступ общий.
4. Порядок: пакет 1 → пакет 2 (последовательно, ресурс сервера + приемки).
5. Роль SA на старте пакетов — sa, действие create_change, зоны — артефакты
   пакета (openspec/changes/<id>/**, sdd.md).

## Последствия

- Дальнейшие делегации пакетов (dev_task, code_review, ops) — через
  delegate_gate; для dev/QA-задач approval_ref уточняется решением Заказчика
  при диспатче (по прецеденту 2026-10-04-microservices-full-dev-tasks —
  одним decision на пул задач пакета, если Заказчик одобрит).
